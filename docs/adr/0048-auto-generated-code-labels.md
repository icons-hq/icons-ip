# 시스템이 만드는 상품·옵션 코드는 '자동코드'라 부르고 화면에서 잠근다

- Status: accepted (2026-11-19) — 사용자 지시(아래 인용). main 머지와 운영 배포는 별도 승인.
- 보완: [ADR-0014](./0014-admin-console-redesign.md)(어드민 라벨은 스마트스토어 어휘 — 코드 두 칸만 예외), [ADR-0038](./0038-system-product-number.md)(상품번호·상품 URL·코드 이름 정리 — 코드 이름을 바꾼다)
- 후속: [ADR-0050](./0050-goods-public-code-url.md)(2026-11-24) — 상품 자동코드의 소문자형이 고객 화면 주소 끝(`/shop/hsq-0059`)이 됐다. '직접 바꾸기'로 코드를 바꾸면 고객 주소도 바뀌고, 상품 화면의 고객 화면 주소 칸이 그 점을 알린다.

## 맥락

2026-11-19 MD가 홍실 상품을 등록하면서 코드 칸을 잘못 채웠다.

- 바코드를 '판매자상품코드' 칸에 넣었다(아크릴 휴대폰 키링, 홍기훈 응원 슬로건, 19금 상품 등).
- 받은 엑셀의 '코드'(ERP 품목코드, 예: HSQ0201100001)를 옵션의 '관리코드' 칸에 넣었다. 그래서 거래확정 엑셀의 ERP 코드가 비어 나왔다.
- 상품 화면에 코드처럼 보이는 칸이 여섯 개(판매자상품코드·관리코드·ERP 코드·바코드·상품번호·상품 URL)이고, 이름만으로는 무엇이 다르고 누가 넣는 값인지 알 수 없었다. 옵션 상세 정보 안내는 "반입된 ERP 품목", "선행 0을 유지", "비워 두면 미설정"처럼 개발 용어로만 쓰여 있었다.

사용자 지시 원문: "딱 봐도 판매자 상품코드가 뭔지 모르고 거기에 바코드 입력할 거 같지 않냐? 그런 헷갈리는 용어 다 지우고 바꾸거나 하라고. 그리고 자동 생성되면 기본적으로 입력 못하게 하고 자동생성인 거 확실하게 알려줘야지"

ADR-0014는 어드민 라벨을 스마트스토어 어휘(판매자상품코드·관리코드)로 맞췄다. 스마트스토어에서 이 두 칸은 판매자가 자기 코드를 넣는 칸이라, 같은 이름을 쓰면 MD는 "우리 코드"(ERP 코드·바코드)를 넣을 자리로 읽는다. ICONS에서는 두 값 모두 저장할 때 시스템이 만든다(`private.set_goods_code`·`private.set_goods_variant_code`, 2026-09-08). 운영에서 직접 넣을 실익도 거의 없다 — 김포 WMS 양식은 이름으로 짝짓고, 남양주(서원)는 바코드를 쓰며, 재고 대조(`lib/admin/stock-reconcile.ts`)는 ERP 코드·바코드로도 짝짓는다. 반면 거래확정·출고지시 엑셀에 찍히는 ERP 코드·바코드는 사람이 넣어야 하는 칸이다.

## 결정

1. **이름을 바꾼다.** `goods.code`는 **상품 자동코드**, `goods_variants.code`는 **옵션 자동코드**다(`lib/admin/vocabulary.ts`의 `goodsCode`·`optionCode`). 원칙: 사람이 넣는 'ERP 코드'·'바코드'와 같은 '○○ 코드' 꼴로 앞말이 출처를 말한다. '자동'이 들어가 받은 엑셀의 '코드'나 바코드를 넣을 칸으로 읽히지 않고, 숫자인 **상품번호**·고객 주소 끝 영문인 **상품 URL**과도 다른 이름이다. 화면·오류·상품 선택기·재고 대조 화면·안전재고 메일·상품 엑셀·가이드가 같은 이름을 쓴다.
2. **화면에서 기본으로 잠근다.** 상품 등록·수정의 상품 자동코드와 옵션 상세 정보의 옵션 자동코드는 읽기 전용으로 보이고 '자동 생성 · 입력할 필요 없음'을 붙인다. 새 상품·새 옵션은 '저장 시 자동 생성'과 예상 코드를 보인다. 잠긴 칸도 지금 값을 그대로 보내므로 저장 계약은 바뀌지 않는다 — 빈 값이면 트리거가 새로 만들고, 기존 상품의 저장은 지금 코드를 지킨다.
3. **'직접 바꾸기'는 남긴다.** 명시적인 버튼으로만 칸이 열리고, 열면 "창고 품번처럼 정해진 코드가 있거나 잘못 들어간 값을 고칠 때만 바꾼다, 바코드·ERP 코드는 여기에 넣지 않는다"를 함께 보인다. 남기는 이유: ADR-0038의 창고 품번 덮어쓰기를 막을 근거가 없고, 이미 잘못 들어간 값(바코드가 든 상품 자동코드)을 운영자가 고칠 길이 이것뿐이다(DB를 바꾸지 않는다). 저장 오류가 난 칸은 열린 채로 보인다.
4. **ERP 코드·바코드는 사람이 넣는 칸임을 드러낸다.** 옵션 상세 정보는 ERP 코드·바코드를 자동코드보다 앞에 두고, 머리글에 '직접 입력 · 거래확정·출고 엑셀에 찍힘'을 붙이며, 받은 엑셀의 '코드'(품목코드)는 ERP 코드 칸에, '바코드'는 바코드 칸에 넣는다고 안내한다.
5. **상품 엑셀은 버전을 올리지 않는다.** v8 양식의 머리글을 '상품 자동코드'·'옵션 자동코드'(KC 시트는 '적용 옵션 자동코드')로 쓰고, 올릴 때는 옛 머리글(판매자상품코드·관리코드·적용 관리코드)도 같은 열로 읽는다. 열의 순서·뜻·반입 키(상품번호 → 상품 자동코드)는 그대로다.
6. **바꾸지 않는 것.** 저장값·식별자·DB 오류 코드, 이미 저장된 코드 값(엑셀 반입 키와 주문 기록에 쓰여 자동으로 고치지 않는다), 출고지시 파일의 '옵션코드' 열과 사방넷 등 외부 양식의 열 이름(외부 계약), 재고 대조가 창고 파일에서 읽는 머리글 별칭(옛 이름을 남기고 새 이름을 더한다), 지난 업데이트 내역.

## 검토한 대안

- **이름만 바꾸고 칸은 열어 둔다.** 사용자가 "자동 생성되면 기본적으로 입력 못하게"를 요구했고, 이름만으로는 입력 실수를 막지 못한다. 기각.
- **직접 입력을 아예 없앤다.** 가장 단순하지만 이미 바코드가 들어간 상품 자동코드를 고칠 화면 수단이 없어지고, ADR-0038의 창고 품번 덮어쓰기도 사라진다. 직접 바꾸기를 명시적 버튼 뒤에 두는 쪽을 골랐다.
- **스마트스토어 이름을 유지하고 도움말만 보강한다.** 11/19 사고가 그 상태에서 났다. 기각.
- **상품 엑셀 양식 버전을 v9로 올린다.** 열의 뜻이 그대로라 버전을 올리면 KC·직접입력형·A/S·사이즈 시트의 버전 판정까지 넓게 바뀐다. 머리글 별칭으로 옛 파일과 새 파일을 같은 v8로 읽는 쪽이 작고 안전하다.

## 결과

- MD에게 이름이 바뀌었음을 알린다(업데이트 내역 2026-11-19). 예전에 내려받은 상품 엑셀도 그대로 올라간다.
- 이미 잘못 저장된 값은 목록으로만 남기고 운영자가 '직접 바꾸기'로 고친다. 바코드·ERP 코드는 옵션 상세 정보의 해당 칸에 다시 넣어야 거래확정·출고 엑셀에 찍힌다.
- 문구 규칙과 용어 대체표는 [어드민 문구 작성 규칙](../admin-copy-guide.md)에 있다.
