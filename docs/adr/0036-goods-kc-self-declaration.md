# KC는 운영자의 자가 신고로 공개 조건을 정하고, 기타 인증은 공개 조건 밖에서 고객에게 보인다

- Status: accepted (2026-11-12)
- 관련: [운영 절차 — 상품 KC 정보 검토](../runbooks/goods-kc-review.md), 영업 피드백 #477(KC 검토 도입), 2026-10-07 MD 피드백(해당 없음 간소화), 원장 1007-034·SHEET-014·TKT-006·TKT-086, migration `20261113020000_goods_kc_self_declaration`·`20261113020100_goods_other_certifications`

## 배경

2026-09-10에 KC 검토를 도입하며 신규 공개·재공개는 'KC 검토 완료'를 요구했다. KC 대상 제도의 완료 조건에는 고객에게 게시하는 항목(제품군·제도·품목 분류·모델명·사업자, 안전인증·안전확인의 인증·신고번호)과 함께 내부 검토 근거(적용 판단 사유·근거 참조·인증·신고문서·시험성적서·공급자 확인서 참조)가 모두 들어 있었다. 10/7 MD 회의에서 MD는 KC가 "필수로 들어가면 되는 정보가 아니라 선택해서 들어갈 수 있는 정보"여야 하고, 걸려 있으면 테스트도 못 한다고 했다(1007-034). 영업팀은 상품 등록에 KC 외 인증정보를 넣을 칸이 없다고 했다(SHEET-014).

2026-11-11 사용자는 두 질문에 업계 권장안을 골랐다.

- 1007-034: "자가 신고로 낮춤 (Recommended)" — 공개 조건을 '대상/대상 아님 선택, 대상이면 인증번호'로, 근거 참조는 선택 입력.
- SHEET-014: "기타 인증 여러 건 (Recommended)" — 기타 인증(종류·기관·번호·고객 노출 여부)을 여러 건 입력하고 고객 상세에 표시.

## 결정

**KC 자가 신고.** 공개 판정의 틀(`goods_kc_guard` → `goods_kc_review_current`, 공개 중 KC 편집 잠금, 검토 완료의 확인 체크 `attested`)은 그대로 두고, 검토 완료의 자료 조건만 바꾼다(`private.goods_kc_review_problems`, 앱 `goodsKcReviewProblems`).

- 내부 검토 근거 다섯 칸은 모든 제도에서 선택 입력이다. 비워도 검토를 완료할 수 있고, 넣으면 지금처럼 내부에만 남는다.
- 고객 게시 항목은 필수로 남긴다. 전기용품 및 생활용품 안전관리법 제9조④·제18조④·제25조④는 안전인증·안전확인·공급자적합성확인 대상 제품을 인터넷으로 팔 때 관련 정보를 게시하게 하고, 같은 법 시행규칙 제20조③·제37조③·제48조③이 그 정보를 '(안전인증번호·안전확인신고번호,) 제품명, 모델명(있는 경우), 제조업자명 또는 수입업자명'으로 정한다. 안전기준준수는 게시 의무가 없지만 다른 KC 대상 제도와 같은 칸을 요구한다(입력 규칙을 하나로 둔다).
- 안전인증·안전확인은 인증·신고번호가 필수이고, 공급자적합성확인·안전기준준수·해당 없음은 번호를 넣지 않는다(공통 번호를 발급하지 않는 제도).
- 화면은 'KC 인증 대상 여부'를 먼저 고른다. 대상 아님은 상품 전체 해당 없음(10/7 간소화 그대로, 고르면 확인 체크가 켜진다)이고, 대상은 사용 중인 옵션을 모두 연결한 모델 1개로 시작해 인증 종류(제품군·적용 제도)·번호·품목·모델·사업자를 넣고 확인 체크로 완료한다.
- 이미 검토 완료된 상품과 공개 상품은 바꾸지 않는다. 규칙이 느슨해질 뿐이라 기존 완료 검토는 그대로 유효하다.

**기타 인증.** KC와 별개인 판매자 자가 신고 기록이다.

- 원본은 `private.goods_other_certifications`(상품당 1행, 버전, `entries` 최대 20건: 종류·인증기관·인증번호·고객 노출 여부)다. 종류·인증번호는 필수, 인증기관은 선택이고, 같은 종류·번호는 한 번만 둔다.
- 고객 데이터는 `goods.other_certification_disclosures` 한 열이다. 고객 노출을 고른 항목의 종류·인증기관·인증번호만 담고, 트리거가 원본에서 다시 계산해 일반 writer·상품 복사·Data API 직접 갱신이 값을 넣지 못한다(`kc_disclosures`와 같은 방식). 상품 상세의 제품 안전정보는 KC 고지 뒤에 '기타 인증' 표로 보인다.
- 공개 조건이 아니고 검토 단계도 없다. 그래서 공개 중에도 고칠 수 있고, 저장마다 감사 로그에 전후 값을 남긴다. 보관 상품은 복원한 뒤 고친다. 상품 복사는 승계하지 않는다(KC처럼 상품마다 확인한다).
- 조회 `admin_read_goods_other_certifications`(catalog.read), 저장 `admin_save_goods_other_certifications`(catalog.manage, 버전 CAS). 등록 화면은 원자 저장 `admin_save_good_workspace`의 `otherCertifications` 섹션으로 상품과 함께 저장한다.

**KC 틀(TKT-006·TKT-086).** 등록 화면에서도 고시 프리셋의 KC 틀을 같은 화면 KC 입력에 미검토 모델로 채운다. 확인 체크를 켜지 않으므로 함께 저장해도 미검토 초안이고, 공개 판정은 그대로다.

## 고려한 대안

- **현행 유지(근거까지 필수)** — MD가 원본 문서 위치를 등록 시점에 모르는 일이 많아 KC 대상 상품 등록이 막혔다. 사용자가 고르지 않았다.
- **완전 선택(KC를 공개 조건에서 빼고 목록 경고만)** — 게시 의무가 있는 제품을 KC 표시 없이 공개할 수 있게 된다. 사용자가 고르지 않았다.
- **고객 게시 항목도 번호 외에는 선택** — 결정 문장 '대상이면 인증번호'를 글자 그대로 읽은 안이다. 시행규칙이 게시하라고 정한 모델명·제조/수입업자명이 빠질 수 있어 법적 고지를 약하게 만든다. 내부 근거만 낮췄다.
- **기타 인증을 `kc_disclosures`에 함께 싣기** — 앱 파일 몇 개를 덜 고치지만, 이전 앱 판의 엄격한 KC parser가 새 항목을 만나면 상세 읽기가 실패한다(배포 되돌리기 위험). 열을 나눴다.
- **기타 인증을 KC 검토(버전·잠금)에 묶기** — 기타 인증을 고치려고 KC를 재검토하거나 상품을 초안으로 내려야 한다. 공개 조건이 아닌 기록에 공개 잠금을 걸 이유가 없다.

## 사람이 정할 것

- 품목별 KC 대상 판정 책임자와 위험 수용(법무·품질 확인 권장, 국가기술표준원 1381 문의 가능). 이 결정은 운영자의 자가 신고를 받는 방식이며 법적 적합성 판정을 대신하지 않는다.
- MD의 품목별 기타 인증 종류 목록. 지금은 자유 입력과 자주 쓰는 종류 제안(방송통신기자재 적합성평가·어린이보호포장·생활화학제품 안전기준확인)만 있다.
