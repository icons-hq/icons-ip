# 19금 상품 주문도 토스페이먼츠로 결제한다

판매 제한 상품(성인/19금)이 담긴 주문은 카드사 업종 제한을 이유로 전용 PG(코페이 → 2026-11-06 나이스페이, ADR-0024 후속·PR #628)로만 결제하도록 파생해 왔다. 그런데 2026-11-25 운영 실측에서 19금 상품 8개가 '19 표시로 노출' 상태인데 운영 env에 나이스페이 MID·키가 없어(`NICEPAY configured=false`) 성인 인증을 마친 고객도 결제할 수단이 하나도 없었다(실운영 시나리오 원장 PAY-054·CAT-064·CUS-040). 같은 날 사용자 결정: "19금 상품은 일단은 전부 토스페이먼츠로 판매 진행한다 토스에서도 딱히 상관없다고 했다".

## 결정

- 판매 제한 상품이 담긴 주문의 카드 결제사를 **토스페이먼츠**로 파생한다(앱 `RESTRICTED_GOODS_CARD_PROVIDER = 'toss'`). 일반 주문과 같은 결제 UI(`ICONS`)를 쓰므로 카드·간편결제·가상계좌·계좌이체가 모두 열린다.
- DB `prepare_goods_payment_attempt`는 판매 제한 주문에 `toss`와 `nicepay`를 모두 받는다(`20261126100000_adult_goods_toss_card_provider.sql`). 어느 쪽을 쓸지는 앱 파생이 정하므로, 나이스페이로 되돌릴 때는 앱 상수 한 줄만 바꾼다. 일반 주문은 지금처럼 `toss`만, 코페이는 지금처럼 새 결제를 받지 않는다.
- 결제 확정 직전 재확인(`claim_goods_payment_attempt`)에서 "판매 제한 주문의 토스 캡처를 막는" 검사(#392)를 지운다. 토스가 19금 주문을 받으므로 결제 준비 뒤 상품이 19금으로 바뀌어도 막을 이유가 없다.
- 성인 인증(ADR-0024)·19금 노출 판정·주문 생성 차단은 결제사와 무관하게 그대로다. 결제사는 여전히 서버가 주문 단위로 파생하고 관리자가 고르는 값이 아니다.

## Considered Options

- **나이스페이 키를 등록할 때까지 19금 상품을 숨긴다** — 업종 제한 위험은 없지만 계약·심사 일정이 오픈과 맞지 않아 19금 판매가 무기한 밀린다. 토스가 취급에 이의가 없다고 확인해 준 이상 숨길 이유가 약하다.
- **19금 주문은 토스 카드만 열고 가상계좌·계좌이체는 막는다** — 결제 UI를 따로 만들어야 하고 현금성 결제를 원하는 고객을 돌려보낸다. 같은 결제 UI를 쓰는 쪽을 택했다.
- **DB를 '판매 제한 주문은 toss만'으로 좁힌다** — 규칙은 단순해지지만 나이스페이로 돌아갈 때 migration이 다시 필요하고, 나이스페이 거래번호 기록·재정합 시험이 픽스처를 직접 만들어야 한다. 앱 파생 한 곳에서 고르게 두었다.

## Consequences

- 토스 상점(iconsi0xvd) 계약·심사 범위와 맞는지는 사람이 확인해 둔다(사용자가 토스에 확인함 — 서면 기록이 있으면 `docs/runbooks/toss-production-rollout.md`에 남긴다). 토스가 이후 업종 제한을 이유로 거절하면 앱 상수를 `nicepay`로 되돌리고 나이스페이 runbook 순서를 따른다.
- 나이스페이 어댑터·콜백·재정합 경로와 runbook은 남는다(되돌릴 때 쓴다). 진행 중 나이스페이 결제는 없다(운영 결제 시도 1건, 토스).
- 주문서의 '19금 상품이 포함된 주문은 결제수단이 신용카드로 제한됩니다' 안내는 결제사가 나이스페이일 때만 보이므로 지금은 나오지 않는다.
- 19금 상품의 가상계좌 주문은 일반 주문과 같이 입금 대기·환불·에스크로 흐름(ADR-0049)을 탄다.
