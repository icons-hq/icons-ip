# 무상 카드 발급은 뽑기권(카드팩) 개봉 모델로 한다

무료 리워드 피벗([ADR-0003](./0003-free-reward-pivot.md))의 지급 방식을 확정한다. 실물 굿즈 주문 확정은 카드를 직접 지급하지 않고 **뽑기권**(UI 표기 "카드팩")을 발급하며, 카드는 사용자가 **개봉**하는 시점에 서버가 결정·발급한다(`open_draw_ticket` → `grant_cards`). 뽑기권은 발급 시점에 특정 카드풀에 묶이고(풀 바인딩), 만료되지 않으며, 천장(pity) 없이 `pool_odds` 순수 확률로 뽑는다. 유료 가챠 화면의 수집 연출(reveal·포일)은 차용하되 유상 요소(충전금·가격·천장 게이지·유상 확률 공시)는 제거한다. 용어는 [CONTEXT.md](../../CONTEXT.md)에 확정했다(가챠·충전금·천장 용어 폐기).

## Considered Options

- **자동 발급** — 주문 확정 순간 카드까지 지급, 바인더에서 확인. 가장 단순하고 규제 서사도 가장 깨끗하지만, 사용자가 "뽑는" 순간이 사라져 수집 UX의 핵심 재미를 잃는다. 폐기.
- **발급은 자동, 개봉은 연출** — 주문 확정 시 카드 확정(미개봉 상태), 개봉은 100% 코스메틱. 구현·멱등이 가장 단순하지만 획득의 긴장감이 연출로 격하된다. 폐기.
- **뽑기권 개봉 (채택)** — 주문 확정이 뽑기권을 발급하고, 개봉 시점에 서버 RNG로 카드를 결정. 수집 UX가 온전히 살고 기존 개봉 연출 자산을 재활용한다. 대가: 티켓 장부(`draw_tickets`)·개봉 RPC가 추가되고, "구매가 무작위 획득 기회를 준다"는 구조라 간접유상 실질판단 여지가 자동 발급보다 크다. 상품가를 뽑기권 유무와 무관하게 고정(무상 진정성, [03-roadmap §3](../online-popup/03-roadmap.md))하고 사용자-facing 표면에서 '가챠/뽑기/충전/확률' 어휘를 쓰지 않는 것(PG 컨펌 조건)으로 상쇄한다.

## Consequences

- **뽑기권 도메인 신설**: 낱장 모델(티켓 1행 = 개봉 1회 = 카드 1장) · 풀 바인딩 · 무기한(풀 운영 종료는 신규 발급 중단일 뿐, 미사용 티켓은 계속 개봉 가능 — "휘발이 아니라 아카이브" 원칙) · 천장 폐기. 발급 시 확률 snapshot을 만들지 않으며 미사용 카드팩은 개봉 시점의 최신 풀 구성·확률을 사용한다.
- **카드 획득 경로는 두 갈래로 고정**: ① 구매 → 뽑기권 → 개봉(`open_draw_ticket`), ② 참여형 게임 → 직접 발급(`play_game` → `grant_cards`; 게임 연출이 곧 개봉 경험이라 뽑기권을 끼우지 않는다). `reward_policies`는 뽑기권 발급 정책 전용이 된다.
- **"결과는 서버, 연출은 렌더러"([ADR-0002](./0002-cross-platform-popup-game-miniapps.md))가 개봉에도 적용된다**: 카드는 개봉 RPC가 결정하고 클라이언트 reveal은 코스메틱. `grant_cards`는 내부 호출 전용으로 유지된다(유상 경로 부재 코드 보장, ADR-0003).
- **기존 스펙 대체**: [02-prd §4.4](../online-popup/02-prd.md)·[04-dev-spec §2·§3](../online-popup/04-dev-spec.md)의 "주문 확정 시 카드 지급"은 본 ADR로 수정됐다.
- **되돌리기 비용**: 티켓 장부·개봉 UX·무상 진정성 서사가 얽혀 자동 발급 회귀·유상 전환 모두 비용이 크다 — 그래서 기록한다.
