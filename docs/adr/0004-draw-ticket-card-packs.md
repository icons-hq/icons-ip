# 무상 카드 발급은 뽑기권(카드팩) 개봉 모델로 한다

무료 리워드 피벗([ADR-0003](./0003-free-reward-pivot.md))의 지급 방식을 확정한다. 실물 굿즈 주문 확정은 카드를 직접 지급하지 않고 **뽑기권**(UI 표기 "카드팩")을 발급하며, 카드는 사용자가 **개봉**하는 시점에 서버가 결정·발급한다(`open_draw_ticket` → `grant_cards`). 뽑기권은 발급 시점에 특정 카드풀에 묶이고, 만료되지 않으며, 천장 없이 `pool_odds`로 카드를 정한다. 충전금·가격·천장 게이지 같은 유상 요소는 두지 않는다.

## Considered Options

- **자동 발급** — 주문 확정 순간 카드까지 지급하고 바인더에서 확인한다. 가장 단순하지만 사용자가 개봉하는 수집 경험이 사라져 폐기했다.
- **발급은 자동, 개봉은 연출** — 주문 확정 시 카드를 정하고 개봉은 코스메틱으로만 처리한다. 멱등 처리는 단순하지만 개봉 시점의 카드풀을 사용한다는 현재 운영 모델과 맞지 않아 폐기했다.
- **뽑기권 개봉 (채택)** — 주문 확정은 뽑기권을 발급하고, 사용자가 개봉할 때 서버가 카드를 결정한다. 티켓 장부와 개봉 RPC가 필요하고 구매와 무작위 카드 사이의 실질 관계를 별도로 검토해야 한다.

## Consequences

- **뽑기권 도메인**: 티켓 1행은 개봉 1회와 카드 1장에 대응한다. 미사용 카드팩은 풀 운영 종료 뒤에도 개봉할 수 있고, 발급 시 확률 snapshot을 만들지 않아 개봉 시점의 최신 풀 구성·확률을 사용한다.
- **카드 획득 경로는 두 갈래다**: ① 주문 → 뽑기권 → 개봉(`open_draw_ticket`), ② 무료 참여형 게임 → 직접 발급(`play_game` → `grant_cards`). `reward_policies`는 뽑기권 발급 정책 전용이다.
- **결과는 서버, 연출은 클라이언트다**: `open_draw_ticket`과 `play_game`이 DB 잠금·멱등 경계에서 결과를 확정한다. 브라우저 reveal·룰렛 물리는 확정 결과를 바꾸지 못한다. 이 계약은 전송 방식이나 폐기된 Expo 계획에 의존하지 않는다.
- **권한 경계**: `grant_cards`는 내부 신뢰 경로만 호출하고, 브라우저 직접 실행 권한을 열지 않는다. 발급·개봉·회수 이력은 추적 가능하게 보존한다.
- **법률 판단 분리**: "무료 카드"라는 명칭만으로 규제 적용 여부를 단정하지 않는다. 상품가·발급 조건·표현·실제 운영에 대한 최신 법률·결제사 증거가 활성화 조건이다.
- **승인 전 전역 차단**: 카드팩 모델의 법무·운영 검토가 완료되기 전에는 DB 전역 gate를 기본 OFF로 둔다. `draw_tickets` 신규 발급·`open_draw_ticket`·`play_game`·수동 발급과 정책/게임 활성화는 차단하고, `/packs`와 공개 게임 표면은 숨긴다. 기존 `user_cards` 바인더는 읽기 전용으로 남긴다.
- **실물 쿠지와 분리**: 카드팩 확률과 게임 결과를 유한 실물 경품 배정에 재사용하지 않는다. 실물 `prize_sale`은 [#212](https://github.com/icons-hq/icons-ip/issues/212)·[#213](https://github.com/icons-hq/icons-ip/issues/213)의 독립 원장과 검증 계약을 따른다.
- **되돌리기 비용**: 티켓 장부·개봉 UX·운영 확률이 맞물려 자동 발급이나 유상 판매로 바꾸려면 새 결정과 migration이 필요하다.
