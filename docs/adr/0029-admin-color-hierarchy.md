# 어드민에 색과 시각 위계를 입힌다

- Status: accepted (2026-11-09) — 제품 소유자 지시("전부 흰색이라 MD가 어디가 중요한지 모른다"). main 머지와 운영 배포는 별도 승인.
- 관련: [ADR-0028](./0028-admin-template-look.md)(결정 1을 대체한다 · 결정 2~6은 유지), [ADR-0014](./0014-admin-console-redesign.md)(결정 5의 S1~S5 인수 기준은 그대로), [ADR-0011](./0011-lfs-storefront-redesign.md)(공개 표면 White Catalog — 바뀌지 않는다)

## 맥락

ADR-0028로 전 화면이 shadcn/ui neutral 템플릿 룩이 됐고 구조는 호평이었다. 그러나 `--primary`가 거의 검정, 나머지는 회백색이라 화면이 전부 흰색이었다. 스마트스토어에 익숙한 MD 역할의 테스터가 변경 전 대표 16화면을 채점했을 때 15화면이 불합격이었고, 공통 지적은 이렇다.

- 검색·조회 버튼이 가장 눈에 띄어 정작 일하는 버튼이 안 보인다.
- 상태(신규·처리중·완료·위험)가 색 없이 같은 글자다. 빨간 숫자가 많아 급한 순서를 정할 수 없다.
- 설정 카드와 안내문이 첫 화면을 차지해 처리할 목록이 밀린다(발주확인 화면은 첫 화면에 주문이 없었다).
- 왼쪽 메뉴의 현재 위치가 옅은 회색이라 찾기 어렵다.

레퍼런스 템플릿(TailAdmin·Studio Admin·shadcn-admin 계열)을 실제로 열어 비교한 결론은 '색을 많이 쓰는 것'이 아니라 '바탕과 카드의 면 구분 + 주 색 하나 + 상태 전용 의미색'이었다.

## 결정

1. **색은 두 벌만 쓴다.** 주 색(`--primary`, 인디고)은 행동과 현재 위치에만, 의미색(success·warning·danger·info + neutral)은 상태에만 쓴다. 상태를 주 색으로 칠하지 않고, 행동을 의미색으로 칠하지 않는다(위험 행동의 빨강은 예외 — 그 행동이 상태를 만들기 때문이다).
2. **면으로 구역을 나눈다.** 앱 바탕(`--page`)은 옅은 청회색, 카드·팝업·입력은 흰색. 구역선(`--border`)은 옅게, 입력 칸 경계(`--input`)는 흰 바탕에서 3:1 이상으로 진하게 둔다(WCAG 2.2 비텍스트 대비).
3. **같은 상태는 모든 화면에서 같은 색이다.** 상태→tone은 `lib/admin/status-tone.ts` 한 곳에서 정한다. 화면은 tone을 고르지 않고 이 표를 거쳐 `AdminStatusBadge`에 넘긴다. 일회성 상태(오류 N건 등)만 tone을 직접 넘긴다.
4. **화면은 색을 고르지 않는다.** hex·oklch·Tailwind 팔레트 유틸리티(`text-green-600`)를 화면에 쓰지 않는다(`app/admin-kit-contract.test.ts`). 토큰과 공용 부품 — `AdminStatusBadge`·`AdminCountCard`·`AdminNotice`·`ConsoleGrid`·kit Button·Badge·Sidebar·차트 — 이 색을 책임진다.
5. **색만으로 뜻을 전하지 않는다.** 상태 배지는 항상 상태 이름을 글자로 보이고, 건수 카드는 숫자·단위·라벨을 글자로, 안내 상자는 아이콘과 글자를 함께 쓴다. 의미색 글자는 자기 옅은 바탕과 흰 바탕에서 4.5:1 이상이며 계약 테스트가 토큰 값을 계산으로 검사한다.
6. **버튼 위계로 '눌러야 할 것'을 정한다.** 한 영역에 실선 주 색(`default`) 버튼은 하나다. 조회·적용은 옅은 주 색(`soft`), 보조는 `outline`, 복구 가능한 위험은 옅은 빨강(`destructive`), 되돌릴 수 없는 위험의 주 행동(환불 실행 등)은 실선 빨강(`danger`).
7. **처리할 것을 먼저 둔다.** 건수·목록이 첫 화면에 오도록 설정 카드는 접고(자동 발주확인·검수용 도구), 메뉴설명은 기본 접힘, 엑셀 안내는 한 줄로 줄인다. 처리 건수는 0보다 클 때만 의미색이 켜져 0건은 조용하다.
8. **ADR-0028의 나머지는 유지한다.** kit 구조·서버 판정·URL 계약·운영 어휘·공개 표면은 그대로다. 토큰은 `.wc-admin` 안에만 둔다.

## 검토한 대안

- **neutral 유지 + 강조만 추가.** 작업량은 적지만 "전부 흰색"이라는 지적을 해소하지 못한다. 기각.
- **주 색 후보(인디고·블루·바이올렛).** 세 안을 홈·발주·상품 등록에 입혀 비교했고, 의미색(초록·호박·빨강·하늘)과 가장 잘 구분되고 대비 여유가 큰 인디고를 권장안으로 골랐다. 값은 토큰 몇 개라 언제든 바꿀 수 있다(`--primary`·`--primary-soft`·`--primary-soft-foreground`·`--ring`).
- **어두운 사이드바.** 틀과 본문의 대비는 강해지지만 레퍼런스 템플릿의 기본도 밝은 사이드바이고 활성 표시의 대비가 나빠져 기각.
- **`bg-background`를 회색으로 바꾸기.** kit 입력·outline 버튼이 전부 회색이 된다. `--page`를 새로 둬 패널 바탕만 바꾼다.

## 결과

- `--primary` 등 토큰은 `admin-kit.css`의 `.wc-admin`, Tailwind 유틸리티(`bg-primary-soft`, `text-success`, `bg-warning-soft` 등)는 같은 파일의 `@theme inline`에 있다. 기존 `--wc-success`·`--wc-warning`·`--wc-info` 이름은 새 토큰에 잇는다.
- 차트 범주색은 `--chart-1..5`를 앞번호부터 고정 순서로 쓰고(dataviz 검증), 비교 계열은 `--chart-comparison`(회색)이다.
- 상세 화면은 셸 제목에 상세 이름을 쓰고(`adminDetailTitleForPath`), MD가 못 알아듣는 내부 용어(정합화·환불 원장)는 운영자 말로 바꿨다.
- 상품 등록 단순화(카드 7장·접힘 그룹)는 같은 작업의 별도 PR이다. 10/27 회의 D6·R13의 "저장 뒤 입력 항목을 등록 화면에서" 요구는 비활성 카드 더미 대신 한 장의 이름 목록과 저장 직후 같은 자리 입력으로 지킨다.
- 합격 판정은 구현과 분리된 에이전트(사람 눈 테스터·UI/UX 검사·코드 리뷰)가 했다. 실제 MD의 판정은 아니며 ADR-0014 S1~S5 사람 인수가 남아 있다.
