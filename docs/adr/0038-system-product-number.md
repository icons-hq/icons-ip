# 상품번호는 시스템이 매기는 바뀌지 않는 숫자다

- Status: accepted (2026-11-12) — 사용자 결정(원장 재작업 묶음 11·12, 아래 인용). main 머지와 운영 배포는 별도 승인.
- 관련: [ADR-0014](./0014-admin-console-redesign.md)(어드민 운영 어휘), [ADR-0028](./0028-admin-template-look.md)(목록 화면 구조)

## 맥락

9/7 영업팀 원문 16행은 "상단-2 ID 부분 - 정확한 명칭 자동발급 방식인지 확인 필요, 차라리 순차 등록 코드로 표기하는 것이 나을 수 있음"이었다(S36-009·S36-X02). 그때 어드민은 같은 값에 이름이 여럿이었다.

- 상품 URL형 ID(`goods.id`, 영문 슬러그)를 목록·검색·주문 엑셀은 '상품번호', 등록 화면과 상품 엑셀은 '상품 URL'이라 불렀다.
- 판매자가 관리하는 코드(`goods.code`)를 화면은 '판매자상품코드', 상품 엑셀은 '상품코드'라 불렀다. 이 값은 창고 품번으로 덮어쓸 수 있어 고정된 번호가 아니다.
- 상품 엑셀의 가격 열(기준 판매가·소비자가·옵션 판매가)은 저장값 이름이라, 할인 상품의 화면 '판매가'가 엑셀에서는 '소비자가'였다(S36-012).

스마트스토어는 시스템이 발급하는 숫자 '상품번호'를 목록·검색의 기준으로 쓰고, 판매자가 넣는 '판매자상품코드'를 따로 둔다.

사용자 결정 원문:

- S36-009·S36-X02: "시스템 순번 신설 (Recommended)" — 원래=업계. 바뀌지 않는 숫자 상품번호 신설, 목록·검색·엑셀에 사용, URL형 ID는 '상품 URL', 코드는 '판매자상품코드'로 통일(상품 엑셀 양식 버전 올림). 게이트: '상품번호' 열 든 창고·외부 양식 확인.
- S36-012·S36-013: "회의 결정+엑셀 맞춤 (Recommended)" — 화면 판매가·즉시할인 유지, 상품 엑셀 열 이름을 화면과 맞춤(양식 버전 올림·구버전 읽기), 매입단가는 '공급가(매입단가)'로 함께 표기.
- SHEET-036: "상태별 건수 칸 (Recommended)" — 건수 칸에 판매대기·판매중지·판매종료 추가, 누르면 그 목록(검색 RPC 건수 확장).

## 결정

1. **`goods.product_no`를 둔다.** `bigint`·NOT NULL·UNIQUE, 기본값 없음. 기존 상품은 등록 순서(`created_at`, 같은 시각이면 `id`)대로 1번부터 채웠다. 새 상품은 저장할 때 `private.goods_product_no_seq`의 다음 번호를 받는다. 번호는 BEFORE INSERT 트리거 `private.assign_goods_product_no`(트리거 이름 `zz_goods_assign_product_no` — 다른 BEFORE INSERT 검사 뒤에 돈다)가 **새 행에만** 준다. 상품 저장(`admin_upsert_good`)은 수정도 `INSERT … ON CONFLICT (id) DO UPDATE`라, 같은 상품 URL(`id`)의 행이 이미 있으면 그 번호를 실어 순번을 쓰지 않는다. 그래서 수정 저장·엑셀 수정은 번호를 쓰지 않고 다음 새 상품은 바로 다음 번호다.
2. **바꿀 수 없고 다시 쓰지 않는다.** 발급 트리거는 직접 넣은 번호를 `goods_product_no_system_assigned`로 거절하고, `private.guard_goods_product_no` 트리거가 번호 변경·비우기를 `goods_product_no_immutable`로 막는다. 순번은 되돌리지 않으므로 지운 상품의 번호도 다시 나오지 않는다. 번호가 비는 경우는 새 상품 저장이 DB에서 실패하거나(순번은 트랜잭션을 되돌려도 돌아가지 않는다) 같은 상품 URL을 동시에 새로 저장하는 드문 경합뿐이다. 순번은 Data API에 드러나지 않는 private 스키마에 두고 사용·변경 권한을 anon·authenticated·service_role에서 거뒀다.
3. **상품 URL·판매자상품코드는 그대로다.** 상품번호는 식별자를 하나 더할 뿐 `goods.id`(공개 주소·외래키)와 `goods.code`(창고 품번으로 덮어쓰는 코드)의 뜻·제약을 바꾸지 않는다.
4. **상품번호를 쓰는 곳은 상품 조회/수정 목록·상품 검색·상품 엑셀이다.** 목록 첫 열(수정 화면 링크), 검색 대상 '상품번호'(값 전체 일치, 여러 개), 정렬 '상품번호순', 전체 검색의 번호 일치, 상품 엑셀 첫 열. 그 밖의 화면·엑셀에서 `goods.id`를 '상품번호'로 부르던 머리글은 '상품 URL'로 바꿨다(값 불변). 취소·반품·교환 검색의 같은 라벨·입력 칸 안내·설명·가이드 문장은 같은 배포에 들어가는 클레임 일괄 처리 작업(T11b, 브랜치 `ps/feat/claim-bulk-steps` — 83b72c21·cce88864)이 '상품 URL'로 바꿨다.
5. **창고·외부 양식의 '상품번호' 열은 양식 확인 전까지 그대로다.** 스마트스토어형 배송 목록·출고 파일 등은 외부 계약이라 사람 게이트(그 열을 쓰는 창고·외부 양식 확인)를 통과한 뒤 바꾼다.
6. **상품 엑셀 v8은 열 이름을 화면과 맞춘다.** 첫 열 상품번호, 판매자상품코드·관리코드·재고수량·상품 표시문구·판매상태·공급가(매입단가). 가격은 화면처럼 판매가(할인 전)·즉시할인(원, 빈칸·0은 할인 없음)·옵션가(판매가 또는 할인가에 더하는 추가금액)이고, 저장값(`price`=고객 결제 기준 금액·`compare_at_price`=할인 전·옵션 금액)은 바뀌지 않는다. v3~v7 파일은 그때의 열 이름으로 읽고 가격 열을 v8 뜻으로 옮긴다.
7. **엑셀 반입 키는 상품번호 → 판매자상품코드다.** 상품 URL은 키가 아니다(구형 v3~v7 파일도 같다). 번호·코드가 모두 빈 행은 새 상품이고, 그 행의 상품 URL을 이미 다른 상품이 쓰면 덮어쓰지 않고 오류다 — 기존 행을 복사해 새 상품을 만들며 URL만 남긴 행이 원래 상품을 덮지 않게 한다. 상품번호와 판매자상품코드가 서로 다른 상품을 가리키면 오류이며, 판매자상품코드는 상품 수정 화면에서 바꾼다. 판매자상품코드 없이 상품번호로 찾은 수정은 미리보기 경고로 알린다.
8. **판매대기·판매중지·판매종료 건수 칸을 더한다.** 각 숫자는 그 칸의 조건 축만 뺀 같은 검색 조건으로 센다(판매중지 = 판매상태 축, 판매대기·판매종료 = 판매기간 축). 그래서 숫자가 곧 그 칸을 눌렀을 때의 목록 개수다.

## 검토한 대안

- **판매자상품코드를 대표 식별자로 올리고 '상품번호'는 '상품 URL'로 이름만 바꾸기.** migration이 없지만 코드는 창고 품번으로 덮어쓸 수 있어 '바뀌지 않는 번호'가 아니다. 원래 요청(순차 등록 코드)과 업계 방식과 다르다. 기각.
- **별도 표(`private.goods_product_numbers`)에 번호 두기.** `goods` 행 모양을 바꾸지 않지만 목록·엑셀·검색이 매번 조인해야 하고, 번호와 상품 생성이 한 트랜잭션에 묶이지 않는다. 기각.
- **상품 URL을 엑셀 반입 키로 쓰기(번호·코드가 모두 빈 행만이라도).** 기존 행을 복사해 새 상품을 만들며 상품번호·판매자상품코드만 지우고 URL을 남긴 행이 원래 상품의 이름·가격·옵션을 덮었다(리뷰 재현). v7까지는 같은 행이 새 상품으로 분류돼 저장 때 `catalog_id_taken`으로 실패했으므로 구형 파일의 뜻도 바뀐다. 기각 — 이미 쓰는 URL이면 미리보기에서 오류로 막는다.
- **identity 열(`GENERATED ALWAYS AS IDENTITY`).** 상품 저장의 `INSERT … ON CONFLICT (id) DO UPDATE`가 수정 때도 기본값을 계산해 수정 저장·엑셀 수정마다 번호가 하나씩 비었다(리뷰). 기각 — private 순번과 새 행에만 번호를 주는 트리거로 바꿨다. 저장 함수를 수정·신규로 나누는 방법은 뒤 작업들이 같은 함수를 앵커 치환하므로 고르지 않았다.

## 결과

- 기존 상품의 `goods_import_fingerprint`(행 전체를 해시)가 배포 때 한 번 바뀐다. 배포 전에 미리보기한 일괄등록 작업(24시간)은 "미리보기 이후 상품 정보가 바뀌었습니다"로 다시 검증을 요구한다. 그 작업의 실패 행 파일은 v8 열로 다시 쓴다.
- 상품 엑셀 양식이 바뀌었으므로 MD에게 공지한다(사람 게이트). 구형 파일은 계속 올라간다.
- 전시 상품 선택기의 여러 줄 붙여넣기(`admin_resolve_goods_references`)는 아직 상품 URL·판매자상품코드만 받는다. 상품번호도 받게 하려면 그 함수를 따로 고친다.
