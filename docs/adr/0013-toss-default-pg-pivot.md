# 기본 결제 provider를 토스페이먼츠 주문서형 v2로 재전환한다

코페이(Korpay)는 19금 실물 판매 계획 때문에 선택됐지만, 연동을 마친 뒤에야 기본 PG로 운영이 불가능한 제약이 확인됐다(2026-09-01 설계 세션, 에픽 #384·스펙 #398): **취소 API가 없어** 결제 취소가 건별 메일 요청(수동)뿐이고 — 전자상거래법상 환급 기한을 시스템으로 보장할 수 없다 — **주문 상태 조회 API가 없어** 콜백이 유실되면 정합화 수단 없이 모든 모호 상태가 수동 검토로 쌓이며, **간편결제가 불가능**(신용카드만)해 결제 단계 이탈을 만들고, 무통장(가상계좌) 경로도 계약에 없다. 일반 상품이 매출의 95% 이상인데 전체 결제가 19금 때문에 선택된 PG의 제약에 묶여 있었고, 첫 실판매(에픽 #319, ≈2026-11)가 두 달 앞이었다.

기본 결제 provider를 **토스페이먼츠 주문서형 결제(구 결제위젯) v2**로 재전환하고, 토스가 취급하지 않는 **판매 제한 상품**(성인(19금), 추후 랜덤박스)만 코페이로 분기한다. 토스에는 "같은 사이트에서 일반 상품은 토스, 19금은 별도 PG" 구조를 고지하고 서면 확인을 받았다(재계약 성립 조건). 분기는 관리자가 PG를 고르는 방식이 아니라 상품의 도메인 사실(`goods.sale_restriction`)에서 **주문 단위로 provider가 파생**되는 방식이며, 서버 2층(prepare 액션 라우팅 + DB RPC 파생 가드)이 강제한다. 레거시 토스 v1 코드는 재사용하지 않고 전부 제거한 뒤(#397) 공식문서 기반으로 새로 작성했다.

## ADR-0007과의 관계

[ADR-0007](./0007-bank-transfer-payments.md)은 "가상계좌만을 위해 두 번째 PG 계약·어댑터·원장 분기를 들이는 것은 provider-neutral seam을 만든 직후에 복잡도를 되돌리는 일"이라며 두 번째 PG를 기각했다. 이 결정은 그 논지를 뒤집지 않는다 — 이번 근거는 결제수단 하나의 공백이 아니라 **카드사 업종 제한**(토스가 19금을 취급하지 않는 사업 제약)이고, PG 수는 여전히 2를 유지하되 역할이 역전된다(토스=기본, 코페이=판매 제한 전용). ADR-0007의 무통장 결정(자체 법인계좌 + `provider='bank_transfer'` 원장)도 그대로 유효하며, 무통장 허용과 판매 제한 유형은 독립 플래그 조합이다.

## Considered Options

- **코페이 유지 + 운영 보강** — 취소·조회 API 부재는 운영 절차로 보강할 수 있는 종류의 공백이 아니다. 자동 취소가 불가능한 채 실판매를 시작하면 환급 기한 보장이 사람 손에 걸린다. 폐기.
- **토스 단일화 + 19금 판매 철회** — 19금 실물(쿠지형)은 확정된 사업 방향이고 코페이 계약·연동은 이미 완성돼 있다. 철회할 이유가 없다. 폐기.
- **토스 기본 + 코페이 판매 제한 전용 (채택)** — 기존 provider-neutral seam(prepare/confirm/reconcile/refund → 5-outcome) 위에 토스 어댑터를 신규 작성하고, 코페이 gate·어댑터·수동 복구 seam은 제거하지 않고 판매 제한 상품 전용으로 대기시킨다. 연동 방식은 주문서형 v2 단일 채택 — API 개별연동(키인)은 별도 상점 계약·카드정보 취급 부담으로 배제.

## Consequences

- **판매 제한 상품이 도메인 개념이 된다.** `goods_sale_restriction` enum(`none`·`adult`)과 주문 단위 파생 규칙이 생기고, 성인인증(#209·#210) 도입 전까지 `adult` 굿즈는 전 스토어 표면 비노출·구매 차단이다. `random_box`는 이치방쿠지형 도입이 확정될 때 값 추가로 확장한다(미확정 값 선등록 금지). 19금 판매 오픈 자체는 별도 트랙이다(성인인증·노출 게이트·코페이 수동취소 콘솔·코페이 gate 재개방).
- **정합화가 자동이 된다.** 웹훅은 payload를 불신하고 조회 API 재검증으로만 반영하며, reconcile은 조회 기반 자동 정합화(굿즈 reconciliation seam 신설 포함)로 콜백 유실을 사람 손 없이 닫는다 — 코페이의 "전건 수동 검토" 고정과의 핵심 차이.
- **취소가 클레임 승인 한 동작으로 종결된다.** 어댑터 refund가 취소 API(전액만)를 발행하고 fresh 조회로 검증한 키만 환불 원장에 넘어간다. 코페이 결제는 여전히 수동 복구 seam이 정상 경로다.
- **심사 기간의 특수 상태가 생긴다.** production에 테스트 키(`test_gck_`/`test_gsk_`)가 물린 채 홈페이지·카드사 심사를 진행한다(약 3~4주). 라이브 전환은 키 교체 + gate env로만 이뤄진다 — `docs/runbooks/toss-production-rollout.md`.
- **유보:** 가상계좌는 에스크로(구매안전서비스) 법적 의무가 커플링되므로 토스 라이브 후 2단계에서 자체 무통장 대체 여부와 함께 결정한다. 쿠지(이치방쿠지형)의 도입 형태(기존 `prize_sale` 도메인 vs 굿즈 랜덤박스)와, 랜덤박스 판매 시 확률 고지 의무 vs "확률 어휘 사용자-facing 금지" 규율의 조정도 미결이다.
