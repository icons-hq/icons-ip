# 상품 유형은 대표 카테고리에서 파생한다

- Status: accepted (2026-11-12) — 사용자 결정(원장 재작업 묶음 11, 아래 인용). main 머지와 운영 배포는 별도 승인.
- 관련: [ADR-0036](./0036-goods-kc-self-declaration.md)(KC 자가 신고), [ADR-0038](./0038-system-product-number.md)(상품번호·상품 엑셀 v8), [운영 절차: KC 검토](../runbooks/goods-kc-review.md)

## 맥락

MD 시트(MD-0003, 10/26)는 "상품등록>상품 주요정보 > 상품 유형(필수) 카테고리 다양화 필요"와 "기타 없음"을 요청했다(SHEET-003). 그때 상품 유형은 카테고리 트리·상품속성과 별개인 고정 9종(피규어·인형·키링·아크릴·문구·쿠션·파우치·세트·기타, `goods_type_check`)이었고, 운영자가 상품마다 골랐다. 카테고리 경로로 유형을 추천하는 기능만 있었다.

상품 유형은 여러 판정의 기준이다.

- **KC 맥락**: `private.goods_kc_context`가 유형을 검토 맥락에 넣는다. 유형이 바뀌면 KC 검토가 미검토로 돌아가고(`goods_kc_guard`), 공개 중에는 바꿀 수 없다(`goods_kc_reassessment_required`, 화면의 '공개 중 잠금').
- **고시 템플릿 제안**: 등록 화면은 유형 이름으로 맞는 상품정보제공고시 템플릿을 제안한다.
- **고객 굿즈샵 필터 축**: 카테고리 전시·컬렉션의 유형 필터 칩은 공개 상품의 `goods.type`을 센다.

스마트스토어는 고정 '유형' 칸 없이 카테고리(와 그 카테고리의 상품속성)로 상품 종류를 나타낸다.

사용자 결정 원문:

- SHEET-003: "카테고리에서 파생" — 업계 권장안(스마트스토어). 상품 유형 입력을 없애고 대표 카테고리에서 파생. 스토어 필터 축·공개 중 잠금·KC 재검토·고시 제안 기준이 함께 바뀜. 크기 L, 법적 고지 위험 — 설계 시 KC·고시 판정이 약해지지 않게.

판단 위임 원칙(11/12)으로 오케스트레이터가 세부를 정했다: 카테고리마다 '상품 유형'(9종) 연결 칸을 두고 상품 유형 = 대표 카테고리(없으면 가까운 상위)의 연결값, 연결이 없으면 공개 불가, `goods.type`은 파생값 저장으로 유지, 공개 중 유형이 바뀌는 카테고리 변경은 막음, 엑셀은 내보내기에 유형을 보이고 반입에서 무시, 기존 상품의 유형은 migration이 바꾸지 않고 불일치는 목록으로 보고, 배포 직후 공개가 막히지 않게 연결 초기값을 기존 분포로 채움, 공개 중 상품은 연결값이 비거나 달라도 다른 칸 저장을 막지 않고 경고만.

## 결정

1. **카테고리에 상품 유형 연결 칸을 둔다.** `catalog_categories.good_type`(9종 또는 비움, `catalog_categories_good_type_check` — `goods_type_check`·`lib/goods-taxonomy.ts` GOOD_TYPES와 같은 목록). 카테고리 추가·수정 화면(`admin_upsert_category`의 `target_good_type`: null = 그대로, '' = 연결 해제, 9종 = 연결)에서 고른다. 비워 두면 상위 카테고리의 연결을 따른다.
2. **상품 유형 = 대표 카테고리(없으면 가까운 상위)의 연결값**(`private.goods_category_type`). 경로 어디에도 연결이 없거나 대표 카테고리가 없으면 ''이다. 화면은 같은 규칙(`categoryGoodTypeSource`)으로 '상품 유형: 피규어(카테고리에서)'를 읽기 전용으로 보이고 입력칸은 없다.
3. **`goods.type`은 파생값을 저장하는 자리로 남는다.** 고객 필터 칩·검색·주문 스냅샷·KC 맥락처럼 읽는 곳은 그대로다. 초안은 트리거(`goods_category_type_derive`, `goods_kc_guard`보다 먼저 돈다)가 쓰기 때마다 연결값으로 맞춘다. 연결이 없으면 들어온 값을 그대로 둔다 — 그 초안은 공개할 수 없으므로 판정이 약해지지 않고, 카테고리를 고르기 전에 KC 검토만 되돌리는 일을 막는다. 그룹 상품은 그룹 공통 저장(그 트랜잭션의 쓰기 허가)에서만 맞춘다.
4. **공개 전환은 연결값을 강제한다.** `private.set_good_published`가 필수 입력 확인 뒤 연결값이 없으면 `goods_type_category_required`, 저장된 유형과 다르면 `goods_type_category_changed`로 거절한다(운영자 공개 경로는 모두 이 함수를 지난다). 판매 준비는 초안에 연결값이 없으면 `type_missing`('카테고리에 상품 유형 연결 필요'), 저장된 유형과 다르면 `type_category_mismatch`를 막는 사유로 보인다.
5. **공개 중에는 저장된 유형을 유지한다.** 연결값이 비거나 달라도 다른 칸 저장은 막지 않고 판매 준비가 `type_category_mismatch`를 검토 사유(경고)로 보인다. 대표 카테고리를 바꿔 유형이 바뀌면(연결 없음 포함) 상품 저장의 카테고리 단계와 카테고리 화면의 대표 분류 적용이 `goods_type_category_locked`/`goods_type_category_required`로 막는다(지금 '유형' 잠금과 같다 — 초안 전환 후 수정). 유형을 바꾸는 직접 쓰기는 `goods_kc_guard`가 그대로 막는다.
6. **유형이 바뀌면 KC를 다시 검토한다.** `goods_kc_guard`의 열 목록에 `category_id`를 더해, 카테고리만 바꾸는 쓰기에서 유형이 바뀌어도 KC 검토가 미검토로 돌아간다. 상품 저장은 고시정보(상품 단계)와 카테고리 유형(카테고리 단계)을 다른 단계에서 바꾸므로 둘을 함께 바꾸면 무효화 이력이 두 번 남는다.
7. **카테고리 연결·상위가 바뀌면 그 아래 초안을 맞춘다.** `catalog_categories_good_type_refresh`가 그 카테고리(하위 포함)의 초안(보관·그룹 제외) 유형을 새 연결값으로 바꾸고(KC는 미검토로) 바뀐 상품을 감사 기록(`admin.catalog.category.good_type_changed`)에 남긴다. 새 연결값이 ''이면 초안의 유형을 지우지 않는다. 공개 중 상품은 바꾸지 않는다.
8. **저장 후 공개는 카테고리 변경 뒤에 공개한다.** 상품 저장의 카테고리 단계가 공개 요청을 그 단계 끝으로 미뤄(안쪽 저장 단계들과 같은 방식) 카테고리를 바꾸며 공개해도 공개 판정이 새 카테고리의 유형을 본다.
9. **연결 초기값은 기존 분포로 채운다.** migration이 카테고리마다 그 카테고리를 대표로 쓰는 상품(보관 제외·유형 있음) 가운데 가장 많은 유형을 연결한다(`private.goods_category_type_majority`). 동률·상품 없음은 비운다. 상품의 유형은 바꾸지 않는다. 비운 카테고리·연결값과 다른 상품·카테고리 없는 상품 목록은 `supabase/tests/goods_type_from_category.sql` 맨 위 읽기 쿼리로 본다.
10. **상품 엑셀(v8)은 저장된 유형을 내보내고 반입에서 유형 열을 무시한다.** 파일 값이 적용될 유형과 다르면 미리보기 경고로 알리고, 변경 여부·같은 상품 행 일치 비교에서도 뺀다. 연결이 없는 새 상품의 공개, 공개 중 상품의 유형이 바뀌는 카테고리 변경은 미리보기 오류다. 양식 버전·열 이름은 그대로다(구형 파일 호환).
11. **고시 템플릿 제안은 카테고리 유형을 기준으로 한다.** 고객 필터 칩은 지금처럼 공개 상품의 저장된 유형을 센다.

## 검토한 대안

- **MD 목록대로 유형 추가(원래 요청안).** 상수·CHECK·필터 RPC·고시 매핑을 한 migration에서 늘린다. 사용자가 업계 권장안을 골랐다.
- **관리 화면에서 유형을 늘리는 마스터 표.** KC·고시 기준이 운영값이 되어 법적 고지 위험이 커진다. 사용자가 고르지 않았다.
- **카테고리 연결값이 없으면 저장된 유형으로 공개 허용.** 카테고리 없는 상품이 운영자가 고른 유형으로 계속 공개될 수 있어 '카테고리에서 파생'이 아니다. 기각 — 연결이 없으면 공개 불가.
- **배포 때 기존 초안의 유형도 연결값으로 맞추기.** KC 검토가 한꺼번에 미검토로 돌아가고 운영값 정리(MD)를 건너뛴다. 기각 — 기존 상품은 바꾸지 않고 저장·공개 때 맞춘다(판매 준비가 미리 알린다).
- **공개 중 상품도 카테고리 연결 변경 때 유형을 맞추기.** 공개 중 KC 맥락이 바뀌어 고시가 실제 상품과 어긋날 수 있다. 기각 — 경고만 하고 초안 전환 때 맞춘다.
- **유형 강제를 쓰기 주체(운영자 JWT)로 나누기.** 시험·시드 같은 신뢰 경계 쓰기를 따로 다루려면 인증 상태에 기대야 한다. 대신 공개 판정은 운영자 공개 경로(`set_good_published`)에, 공개 중 카테고리 잠금은 저장 RPC에 두고, 초안 파생은 연결값이 있을 때만 하도록 했다.

## 결과

- 상품 등록·수정·그룹 공통정보에 유형 입력이 없다. 카테고리 관리에 연결 칸(이름 기준 추천 포함)과 트리 표시가 생기고, 분류 CSV에 '상품 유형 연결'·'적용 상품 유형' 열이 붙는다.
- 대표 카테고리가 없거나 연결이 없는 상품은 새로 공개할 수 없다. 이전에는 카테고리를 비워도 팔 수 있었다.
- 사람 게이트: 카테고리별 상품 유형 연결 운영값(MD), 연결값과 다른 기존 상품·카테고리 없는 상품 정리(MD). 배포 뒤 위 읽기 쿼리로 목록을 본다.
- 판매 준비에 `type_category_mismatch`가 새로 생겼다. 이전 앱 판은 모르는 사유를 '준비 상태 확인 필요'로 보이므로(fail-closed) 배포 중 잠깐 그렇게 보일 수 있다.
