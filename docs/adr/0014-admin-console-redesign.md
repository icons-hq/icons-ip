# 어드민 운영 콘솔 재설계 — 워크플로 표면 재설계와 White Catalog 편입

- Status: accepted (2026-09-07)
- 관련: [ADR-0011](./0011-lfs-storefront-redesign.md)(공개 표면 White Catalog), [ADR-0005](./0005-icons-allocated-inventory.md)(할당 재고), [ADR-0015](./0015-goods-variants.md), [ADR-0016](./0016-fulfillment-origins-and-shipments.md)

## 맥락

2026-09-07 운영 리뷰 회의에서 운영 총괄이 어드민을 직접 테스트한 결과를 놓고 "이 상태로 오픈은 언감생심"이라고 판정했다. 지적은 룩이 아니라 워크플로였다 — 저장 실패 시 입력값 전부 소실, 굿즈에 재고 입력·옵션·코드·출고지가 없음, 주문·고객을 따라가는 상세 화면 부재, 배송비·택배사·연락처가 코드에 박혀 있음. 코드 대조로 전부 사실임을 확인했다(입력값 소실은 `useActionState`가 오류만 돌려주고 비제어 입력이 리셋되는 구조, 신규 굿즈는 `stock_qty` 기본값 0으로 태어남, 배송비 상수는 TS 1곳+SQL 3곳).

ADR-0011 시점의 `AGENTS.md`·`DESIGN.md`는 어드민을 "개편 대상이 아니라 현재 어휘 유지"로 못 박았다. 이 결정은 그 규칙을 뒤집는다.

## 결정

1. **재작성하지 않는다.** 셸과 2단 IA(2026-08 재구축), audited RPC 83개, RLS, 결제·재고 원장, 테스트 119파일은 유지한다. 돈·재고·RNG 불변식을 다시 짜지 않는다.
2. **워크플로 표면을 다섯 패턴으로 재설계한다.** ① 모든 자원에 전용 상세 페이지와 `audit_log` 기반 타임라인 ② 모든 목록에 검색·필터·페이지·일괄 액션(판매 콘솔 8개가 이미 쓰는 프리미티브를 카탈로그로 확장) ③ 초안→공개→보관 **게시 상태**와 실패에 살아남는 폼 ④ 설정 섹션 — 배송 정책·택배사·사업자/CS 연락처·무통장 계좌 표시값을 코드 상수에서 감사되는 DB 설정으로 ⑤ 엑셀 가져오기·내보내기 양방향.
3. **룩은 White Catalog 토큰으로 편입한다.** editorial 라이트 콘솔과 `globals.css` 어드민부는 미전환 화면이 남는 동안 유지하고 전환 완료 시 퇴역한다. 전환은 **셸부터** 한다 — 사이드바·헤더·레이아웃을 첫 웨이브에 새 어드민 레이어로 바꾸고, 화면은 재설계 순서대로 하나씩 전환하며 미전환 화면은 새 셸 안에서 editorial 클래스로 남겨 두 스타일 공존을 허용한다. editorial 계열은 마지막 웨이브에서 퇴역한다.
4. **어드민 라벨은 운영팀 어휘를 쓴다** — 상품·상품코드·옵션. 코드·문서·공개 표면은 `CONTEXT.md`의 굿즈를 유지하고, 카드·카드팩·티켓은 어드민 안에서도 "상품"이라 부르지 않는다.
5. **합격 기준은 운영팀이 스테이징에서 직접 수행하는 시나리오 5개**이며 오픈 게이트다. S1 굿즈 30종을 옵션 포함 엑셀로 일괄 등록해 초안·검수·공개까지 30분 이내, 실패 행만 재업로드 / S2 IP 등록 중 이미지 업로드 실패에도 입력값 소실 0 / S3 주문 100건을 발주확인 일괄→출고지별 출고지시 내보내기→운송장 업로드→배송완료까지 클릭 10회 이내 / S4 문의 1건을 화면 이동 없이 주문·결제·배송·클레임 이력을 보며 답변 / S5 배송비·무료 기준·택배사·CS 연락처를 배포 없이 어드민에서 변경.
6. **선행 조건**: 토스 재전환 스택(PR #397~#405)이 굿즈·클레임·주문 테이블을 건드리므로, 스택 머지 뒤에 굿즈 폼·클레임 표면을 만진다. IP 폼·폼 상태 보존 인프라·주문 상세는 겹치지 않아 먼저 시작한다.

## 검토한 대안

- **전면 재작성** — 2만9천 줄·RPC 83개를 10월 말 안에 한 명이 끝낼 수 없고, 검증된 불변식을 재발명한다. 기각.
- **회의 지적 항목만 점 수정** — 다음 운영 리뷰에서 같은 지적을 형태만 바꿔 다시 받는다. 기각.
- **룩은 라이트 콘솔 유지, 워크플로만 재설계** — 권고안이었으나 제품 소유자가 공개 표면과 한 디자인 시스템으로 통일하는 쪽을 택했다.

## 결과

- `AGENTS.md`·`DESIGN.md`·`docs/PRD.md`의 "어드민은 개편 비대상" 문구를 개정했다. `app/editorial-design.test.ts`의 경계 계약은 전환 단계마다 함께 갱신한다.
- `lib/shipping.ts`의 "어드민 토글을 두지 않는다"(#174 D5) 결정은 철회된다. 배송 정책은 출고지 설정으로 이동하고 SQL 사본 3곳은 설정을 읽는 함수 하나로 수렴한다.
- 회의 일정 — 10월 말까지 파악된 문제 수정 완료, 오픈은 빨라야 11월 중순 — 이 실행 기한이다. 웨이브는 W1 9/8~9/20(셸 전환·폼 상태·IP 게시 상태·IP 허브·상품 목록·주문 상세·문의 배정·스테이징), W2 9/21~10/11(옵션·상품코드·상품 게시 상태·상품 폼·프리셋·일괄 등록·출고지·배송 정책·설정), W3 10/12~10/31(배송 건·발송 콘솔·고객 상세·FAQ·실시간 문의·editorial 퇴역·S1~S5 리허설), 11/1~11/14 버퍼다. 주 1회 운영 리뷰 미팅과 운영팀 스테이징(전용 Supabase 프리뷰 프로젝트·고정 도메인·시드·운영자 계정·토스 테스트 키)이 검증 루프다.
