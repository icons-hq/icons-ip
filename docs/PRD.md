## 1. 개요

**ICONS**는 서브컬처 팬덤을 위한 **슈퍼앱**이다. 공식 라이선스 굿즈 커머스를 척추로, 수집형 디지털 카드(무료 리워드), 팝업/티케팅, 팬 커뮤니티, IP 허브를 하나의 경험으로 묶는다. 공개 스토어프론트의 디자인 시스템은 "White Catalog"([ADR-0011](./adr/0011-lfs-storefront-redesign.md), 루트 `DESIGN.md`)이고, 초기 프로토타입의 "Holographic Midnight"은 어드민 콘솔의 잔존 어휘로만 남아 있다.

현재 리포(`/Users/sangwopark19/icons/icons-ip`)는 Claude Design 핸드오프를 옮긴 **시각적 프로토타입**에서 출발했다. App Router 화면에 Supabase 공개 카탈로그, 이메일/PW Auth, 온보딩, IP 팔로우, 커뮤니티, 검색, admin 경로가 연결되어 있다. 굿즈 실장바구니와 굿즈·티켓 provider-neutral checkout attempt, 본인 주문 내역·청약철회 요청, 관리자 주문·배송·환불·실재고·티켓 회차·회원 제재·카탈로그 아트워크 업로드·보관/복원·홈 큐레이션 콘솔, 공개 회차 선택·승인 뒤 QR 발급, 내 티켓·예매 취소/환불, staff 현장 검표까지 연결됐다. gate 기본값은 OFF이며 현재 Production에서 열려 있는 것은 폐쇄 대기 중인 코페이 굿즈 gate 하나뿐이다. 이후 스토어프론트 전면 개편(ADR-0011)으로 공개 표면이 White Catalog으로 이행되면서 위시리스트·재입고 알림, 쿠폰·회원 등급, 캠페인(`/events`)·코인, 상품 Q&A가 더해졌고 오프라인 팝업 예매는 `/offline-popups`로 옮겨졌다. 이 PRD는 프로토타입을 **실제 출시 제품**으로 전환하기 위한 요구사항을 정의한다.

결제 전환의 정본은 **신규 결제 기본 토스페이먼츠 주문서형 v2, 코페이는 판매 제한 상품 전용**이다([ADR-0013](./adr/0013-toss-default-pg-pivot.md), 에픽 [#384](https://github.com/icons-hq/icons-ip/issues/384)). 굿즈와 티켓 checkout은 공통 attempt/claim/finalizer 위에서 토스 위젯 prepare→경로 세그먼트 nonce callback→서버 승인으로 이동했고, 모호 결과는 조회 API 기반 reconcile로 자동 정합화한다. **판매 제한 상품**(성인(19금))이 하나라도 담긴 주문만 서버가 주문 단위로 코페이를 파생한다 — 관리자가 PG를 고르지 않는다. 토스 목적별 gate 둘과 canary 둘은 모두 닫혀 있고 개방은 심사 트랙([#394](https://github.com/icons-hq/icons-ip/issues/394)·[#395](https://github.com/icons-hq/icons-ip/issues/395))을 따른다. 2026-08-18 공개 ON으로 열어 둔 코페이 굿즈 gate 폐쇄([#385](https://github.com/icons-hq/icons-ip/issues/385))는 실행 대기다. 성인인증(#209·#210) 도입 전까지 판매 제한 상품은 스토어 전 표면 비노출·구매 차단이고, 19금 판매 오픈과 코페이 gate 재개방은 별도 트랙이다. 이 전환은 2026-08-21 법정 본문 활성화나 #208의 코페이 취소·모호 승인 운영을 해소하지 않는다.

### 1.1 제품 비전

> "흩어진 서브컬처 팬덤의 소비·수집·소통을 한 곳에서 — 공식 라이선스의 신뢰 위에서."

### 1.2 목표 (v1)

- 공식 라이선스 굿즈를 안전하게 **구매**할 수 있다 (장바구니 → provider 재검증 → 주문).
- IP별 **수집형 디지털 카드**를 무료 카드팩·참여형 게임으로 받고 **바인더**에 모은다.
- **팝업** 티켓을 예매하고 전자티켓(QR)으로 입장한다.
- 관심 IP를 **팔로우**하고 팬들과 **커뮤니티**에서 소통한다.

### 1.3 비목표 (v1에서 하지 않는 것)

- **C2C 마켓**(굿즈 중고 거래)·**트레이드**(카드 직거래·경매): UI는 유지하되 거래·정산·에스크로는 구현하지 않는다 → **v2**. 굿즈 클레임 유형인 **교환**(회수 후 재출고)과 다른 개념이다.
- **유료 멤버십/구독**(IP 팬덤 유료 티어) → v2. 굿즈를 회차별로 다시 구매하는 정기배송은 §4.5의 별도 커머스 범위다.
- 실시간 채팅/라이브 피드 → 검토 후 차기.
- 글로벌(다국어·해외결제) 본격 대응 → 차기.
- 범용 온라인 팝업 운영 레이어(popups 운영 단위·미션·등급·래플·브랜드 리포트)와 Expo webview 앱 호스트는 현 로드맵에서 만들지 않는다. 현재 웹 티케팅·참여형 게임은 이 비목표와 별개로 유지한다.

## 2. 대상 사용자

| 페르소나 | 설명 | 핵심 니즈 |
|---|---|---|
| **수집러** | 포토카드·홀로 카드 컬렉션에 진심인 팬 | 카드팩 개봉 경험, 보유 현황(바인더), 한정 드롭 알림 |
| **굿즈 구매자** | 공식 라이선스 굿즈를 정품으로 사고 싶은 팬 | 신뢰(정품)·재고·빠른 결제 |
| **이벤트 참여자** | 팝업에 가는 팬 | 회차/잔여 확인, 간편 예매, 전자티켓 |
| **커뮤니티 유저** | 인증샷·후기·트레이드글로 소통하는 팬 | 작성·반응·신고/차단 안전장치 |
| **운영자(내부)** | IP·상품·카드풀·이벤트·신고를 관리 | 백오피스(`/admin`)에서 카탈로그·확률 공시·모더레이션 |

브라우징은 **로그인 없이 공개**. 액션(구매·카드팩 개봉·게임 플레이·예매·작성·팔로우) 시점에 로그인을 요구한다.

## 4. 범위

### 4.1 v1 포함

1. 인증 & 온보딩
2. IP 허브 (브라우징 + 무료 팔로우)
3. 굿즈 커머스 (장바구니 · 결제 · 주문) — **척추**
4. 무료 카드 리워드(카드팩·참여형 게임) + 바인더
5. 오프라인 팝업/티케팅 (실제 예매 · 전자티켓)
6. 커뮤니티 (작성형)
7. 검색
8. 운영 백오피스(`/admin`)
9. 쿠폰·회원 등급, 캠페인(이벤트 허브)·코인, 상품 Q&A — 커머스 개편(ADR-0011)에서 더해진 v1 범위. 별도 적립금 원장과 거래확정 영업 검토 엑셀은 영업 피드백(#488·#489·#495)으로 확장한다.

### 4.2 v2 이후

- C2C 마켓 · 트레이드(카드 직거래·경매) — 에스크로·정산·분쟁·통신판매중개

### 4.3 별도 승인 트랙

- **19+ 꽝 없는 유한 실물 쿠지**는 기존 카드 리워드·참여형 게임·legacy 래플의 후속 기능이 아니다. 별도 `prize_sale` 원장과 서버 배정 계약은 [#212](https://github.com/icons-hq/icons-ip/issues/212), 공개 확률·last-one·결과 영수증·운영은 [#213](https://github.com/icons-hq/icons-ip/issues/213)이 추적한다.
- 이 트랙은 판매 제한 상품 전용 PG(코페이) 결제 재개방, NICE `adult_19` 증거([#209](https://github.com/icons-hq/icons-ip/issues/209)·[#210](https://github.com/icons-hq/icons-ip/issues/210)), 법률·IP·재고·환불 evidence가 모두 맞기 전에는 활성화하지 않는다. 현재 v1 코드가 이 기능을 제공한다고 해석하지 않는다.

### 4.4 영업팀 피드백 확장 설계 (2026-09-10)

현재 기능 표와 아래 기존 요구사항은 기존 요구 및 구현 상태의 기준선이다. [영업팀 확장 스펙 #460](https://github.com/icons-hq/icons-ip/issues/460)은 이미 구현한 기능을 재사용하고, 남은 요구 전체를 설계 범위로 다룬다. [원문 대비와 확정 답변](./superpowers/specs/2026-09-10-sales-admin-feedback-design.md), [게시 스펙 사본](./superpowers/specs/2026-09-10-sales-admin-feedback-spec.md)을 함께 보관한다. 구현한 계약은 아래에 명시하며 코드 구현·합성 검증과 실제 운영 수치 승인·판매 활성화·운영 인수는 구분한다.

- 자체 상품/옵션 코드와 ERP 코드·바코드를 분리한다. 고객용 계층 카테고리에는 외부 ERP 분류를 매핑한다.
- 공급가는 공급처에서 사오는 매입단가다. 안전재고는 옵션별 부족 경보 기준이며 판매 가능량에서 차감하지 않는다.
- KC는 실제 모델·사업자·대상 옵션·유형별 근거를 검토한 뒤 새 공개와 비공개 후 재공개를 허용한다. 도입 전에 이미 공개된 KC 미기록 상품은 게시상태를 보존하고 미기록으로 식별하며, 가격·할당 재고 조정을 유지한다. 상품·옵션의 모델 정체성을 바꾸거나 새 옵션을 활성화하려면 재검토한다. 신규 seed 상품에는 합성 인증을 넣지 않고 초안으로 둔다. [운영 절차](./runbooks/goods-kc-review.md)를 따른다. KC 대상이 아닌 상품은 상품 전체 해당 없음 확인(제품군·제도·사용 중인 옵션 전부 연결)만으로 검토를 완료한다(2026년 10월 7일 MD 회의).
- 일반재고 굿즈는 할인과 별도의 판매 시작·종료 기간을 설정할 수 있다. 기간 밖에도 공개 탐색은 유지하고 신규 구매를 차단한다. 예약판매 정책과는 함께 적용하지 않으며, 이미 승인 요청을 시작한 결제는 기존 주문 계약으로 확정한다. [판매기간 운영 절차](./runbooks/goods-sale-periods.md)를 따른다.
- 상품별 사은품 설명(100자·검증된 사진 최대 3장)과 이벤트 문구(40자)를 독립 저장해 공개 상세에 표시한다. 이벤트 템플릿은 문구를 복사하며 이후 템플릿 수정·보관으로 상품 문구를 바꾸지 않는다. 안내만으로 사은품 재고 배정·자동 지급·할인이 발생하지 않는다.
- 자주 쓰는 카테고리와 A/S 안내는 템플릿으로 재사용한다. 카테고리 템플릿은 상품 폼에 분류를 불러오며, A/S 전화번호·안내·판매자 특이사항은 법정 상품 고시와 별도 값으로 저장·해제하고 공개 상세에 표시한다. 템플릿 보관·수정으로 기존 상품의 분류나 복사된 안내를 바꾸지 않는다.
- 예약판매는 주문 시 선결제하고 안내한 예정일에 발송하는 방식으로 설계한다.
- 주문제작은 기본 꺼짐의 상품별 납기를 주문서에 표시하고 주문 당시 조건을 보존한다. 운영자가 실제 시작·완료를 기록하며 완료 전 출고를 막는다. 시작 후 취소도 검토 접수하고 자동 환불하지 않는다. 교환은 전체 회수 후 별도 재제작한다([주문제작 계약](research/smartstore-admin/made-to-order.md)).
- 상품별 배송 방식 선택과 배송정보 템플릿의 명시적 유지/복사, 선결제 설치비·직접배송·화물·퀵 비용, 배송없음 직접전달과 보호된 디지털 파일 다운로드를 제공한다. 구매 당시 방식·비용·파일을 보존하고 디지털 제공 후 취소는 검토 접수한다([상품 제공 계약](research/smartstore-admin/goods-fulfillment.md)).
- 쿠폰은 발급·사용 고객 자격과 할인 대상 굿즈를 분리한다. 대상 소계와 사용 조건은 주문 생성 시 다시 검증하고 보존하며, 첫구매 혜택 예약과 화면에서 확인한 쿠폰 선택의 견적 보존·재검증로 동시 주문·다른 탭의 선택 변경을 처리한다. [쿠폰 운영 절차](./runbooks/coupon-targeting.md)를 따른다.
- 주문 할인용 적립금은 쿠폰·코인·카드팩과 분리된 혜택 잔액으로 구현했다. 기간 할인가에 상품 쿠폰을 선택 순서대로 적용한 뒤 남은 굿즈 금액에 사용하고, 거래확정 적립·출처별 취소/환불 복원·원적립 회수를 같은 원장으로 추적한다. 초기 정책은 비활성이며 실제 수치·회수 방식·승인 근거를 설정해야 활성화할 수 있다. 현금 충전·출금·타인 양도는 제공하지 않는다. [적립금 운영 절차](./runbooks/store-credits.md)를 따른다.
- 교환·반품비는 비용 안내와 운영자가 확인한 금액을 기록한다. 자동 추가 결제나 환불액 차감은 이번 요구의 범위가 아니다.
- 해외 수령 고객도 원화로 결제하고 국내 배송대행지로 받는다. ICONS의 발송 범위는 국내 주소까지이며, 이후 배송대행은 고객이 진행한다. 국제 운송·다통화 판매로 확대하지 않는다.
- 거래확정 엑셀은 품목×배송 건 행과 주문 대조 시트로 영업·정산 검토를 지원한다. 주문 당시 ERP 정보·쿠폰 대상·금액과 실제 확정/결제 시각을 사용하고, 생성한 비공개 영수증을 재다운로드한다. 현재 카탈로그를 소급 대입하지 않으며 미기록은 공란과 사유로 남긴다. [엑셀 운영 절차](./runbooks/settled-export.md)를 따른다. 2026-09-11 확정한 상세 HTML 범위는 기본 문서 요소·안전 링크·검증 이미지이며, 지연 주문 안내 채널은 인앱 알림+주문 이메일이다. 내부 지연 메모와 고객 문구를 분리하고 채널별 결과·중복 방지·부분 실패 재시도를 제공한다. 실제 운영 수치·증빙과 고객 발송·배포 승인은 별개다.

### 4.5 선물·복수구매 할인·착불·정기배송 (2026-10-14)

사용자가 네 기능의 설계·구현을 포함하도록 확정했다. [ADR-0021](./adr/0021-goods-transaction-sources.md)의 공통 주문 계약을 사용하며, 로컬 구현·검증과 운영 판매 활성화를 구분한다.

- **복수구매 할인**: 같은 굿즈의 옵션·직접입력별 수량을 합산하고 수량 또는 정상가 합계 조건의 개당 정액/정률 할인을 적용한다. 기간 할인 후 복수구매 할인 → 정책에 맞는 대상 상품 쿠폰 → 배송비 쿠폰 → 적립금 순서이며 원 단위 배분과 당시 조건을 주문에 고정한다.
- **확장 배송비**: 수량 반복·2/3구간과 선불·착불·구매자 선택을 제공한다. 온라인 결제는 선불 운임만 포함하고, 착불은 수납 주체·방법·고객 안내가 준비된 출고지에서 별도 금액으로 동의받는다. 수납·환급·정정 증거는 온라인 결제/환불과 별도 기록한다.
- **선물**: 구매자가 굿즈와 메시지를 선택하고 링크를 전달한다. 로그인한 수령인이 수락·주소 입력을 마친 뒤 구매자가 최종 금액을 확인하고 결제한다. 구매자에게 수령인의 주소·연락처·운송장을 노출하지 않고 수령인에게 구매금액·결제수단을 노출하지 않는다. 수령인은 자신의 교환·반품 요청을 관리하며 환불은 구매자에게 처리한다. 선물은 선불 배송만 제공한다.
- **정기배송**: 고객이 카드와 회차별 금액·주기·배송지에 동의하면 첫 회차를 결제하고 이후 회차를 실행한다. 최초 선택한 쿠폰/적립금은 첫 회차에만 적용한다. 가격·착불·배송 조건 변경은 재동의하고, 오래 지연된 회차를 한꺼번에 청구하지 않는다. 일시정지·해지는 미래 회차를 중지하며 이미 발생한 주문의 취소·환불은 별도 처리한다. 실제 자동결제 계약과 키 준비 전 공개·청구 스위치는 닫는다.
- 네 흐름 모두 기존 **주문 전체·전액 취소/환불**을 유지한다. 부분취소·부분반품, 임의 추가청구, 실제 은행·운송사 수납 자동화는 이 변경에 포함하지 않는다.

[공통 계산·생성 계약](./research/smartstore-admin/goods-transaction-module-proposal.md), [선물 공개 범위](./research/smartstore-admin/gift-orders-transaction-proposal.md), [정기배송 운영](./runbooks/goods-subscription-billing.md)의 검증·운영 조건을 따른다.

## 5. 기능 요구사항

표기: **P0/P1/P2/P3**는 [§9 출시 단계](#9-출시-단계)의 빌드 순서. `M`=필수(MUST), `S`=권장(SHOULD).

### 5.1 인증 & 온보딩 (P0)

- `M` 이메일/비밀번호 가입·로그인.
- `M` 이메일 확인 메일 콜백과 재전송. 같은 브라우저에서 같은 이메일로 반복 가입을 시도하면 최신 확인 메일을 재발송하되, 과도한 반복은 10분 window로 제한한다.
- `M` 비밀번호 재설정: 계정 존재 여부를 노출하지 않는 메일 요청 → 전용 token-hash callback → 새 비밀번호 저장 → 전역 로그아웃. 같은 브라우저의 정규화 이메일별 요청은 총 3회/10분으로 제한하고 provider rate limit을 실제 상한으로 둔다.
- `M` 소셜 로그인: **Google · Apple · Kakao**. 세 버튼은 Supabase 관리형 OAuth에 연결됐고 production provider도 활성화됐다. Google은 production 공개, Apple은 웹 App ID·Services ID·키, Kakao는 비즈 앱·필수 `account_email` 동의 구성이 완료됐다. production 배포 뒤 신규·기존 사용자 controlled smoke가 남아 있다.
- `M` 소셜 로그인이어도 **온보딩에서 이메일·닉네임·생년월일(자가신고)·약관/마케팅 동의를 수집**하여 프로필을 완성한다.
- `M` 공개 페이지는 비로그인 접근 가능. 보호 액션은 로그인 게이트.
- `M` v1 가입 기준은 **만 14세 이상**이다. 다만 현재 `profiles.birth_date` 자가신고만으로는 이 기준을 충족했다고 간주하지 않는다. 서버 강제 지점·만 나이 경계·기존 계정 dry-run·법정 문서·`minimum_age_14` 증거 계약은 [#188](https://github.com/icons-hq/icons-ip/issues/188)의 승인과 구현 증거가 갖춰질 때까지 미완료다. 이 문서 변경만으로 production gate를 열지 않는다.
- `M` 19+ 상품 접근은 NICE 기반 `adult_19` 증거를 별도 purpose로 사용한다([#209](https://github.com/icons-hq/icons-ip/issues/209)·[#210](https://github.com/icons-hq/icons-ip/issues/210)). 자가신고 생년월일, `minimum_age_14` 증거, PG 결제 인증은 성인인증을 대체하지 않는다.
- `S` 로그아웃·계정 삭제·동의 철회.

### 5.2 IP 허브 (P0)

- `M` IP 목록/상세를 **비로그인 공개** 브라우징.
- `M` IP 상세: 배너·태그라인·시놉시스·지표(팬/굿즈/카드/이벤트), 탭(굿즈·카드·팝업·커뮤니티).
- `M` **무료 팔로우**(관심 IP 등록) → 홈/피드/알림 개인화.
- `S` 알림 설정(IP별 드롭·이벤트 알림 on/off).
- 버티컬: 캐릭터 IP · 게임 · 애니메이션 (버티컬별 액센트 유지).

### 5.3 굿즈 커머스 (P1) — 척추

- `M` 굿즈 목록(타입·IP·정렬·재고 상태), 굿즈 상세 — 갤러리·설명·**고시정보**(전자상거래 상품정보제공고시)·배송 안내를 포함한다.
- `M` 장바구니: 담기/수량/삭제, 비로그인 시 로컬 → 로그인 시 병합.
- `M` 체크아웃: 배송지 확인 → 결제수단 선택(카드·무통장) → `pending` 주문 생성·재고 선점 → **카드 결제**(기본 토스, 판매 제한 상품이 담긴 주문은 코페이로 파생) 또는 **무통장 입금** → 서버 확정.
- `M` 무통장 입금(굿즈 전용, [ADR-0007](./adr/0007-bank-transfer-payments.md)): 회사 법인계좌로 24시간 안에 입금하면 운영자가 대조·확인해 확정한다. 티켓에는 제공하지 않고, 굿즈별로 차단할 수 있다. 법인계좌 확정(#255) 전에는 결제수단 자체가 노출되지 않는다.
- `M` **배송비**는 주문 시점 값을 스냅샷으로 고정한다. 기본 정액·일정 금액 이상 무료와 §4.5의 수량/구간 배송비를 지원하며 선불·착불을 구분한다.
  - 출고지별 지역 추가료는 실제 물류사 회신의 지역·금액·무료/묶음 관계를 확인한 버전만 주소별로 적용한다. 최초 도입 전에는 기존 표시 배송비로 확정하고 사후 추가청구하지 않는다. 도입 후 미확정 주소·정책 만료·택배사 불일치는 결제를 차단하며, 적용 정책과 추가료는 주문·배송 건에 보존한다([운영 절차](./runbooks/shipping-regions.md), #493).
- `M` 재고는 `pending` 주문 생성 시 원자적으로 선점하고, 결제 실패·만료 시 복원한다(품절 동시성).
- `M` 운영자는 현재 실재고를 확인하고 사유·멱등키·예상 수량을 포함한 audited RPC로만 입고·보정한다. 수량 0은 공개 화면에서 자동 품절로 파생하되 수동 판매중지는 보존한다. 외부 창고를 함께 쓰는 경우 이 수량은 **할당 재고**를 가리킨다([ADR-0005](./adr/0005-icons-allocated-inventory.md)).
- `M` 주문 내역·상태(결제완료/배송중/완료/취소).
- `M` 발송 전 배송지 수정: 판매관리 담당자가 고객 합의 근거를 남기고 결제완료·발주확인 주문의 수령자·연락처·주소·메모를 주문 전체 단위로 변경한다. 출고지시/발송 이력·열린 클레임을 차단하고 배송 지역이 바뀌면 현재 배송 가능 여부와 출고지별 기존 배송비를 대조한다. 금액 변경은 허용하지 않으며 이전/이후 주소와 담당자 이력은 비공개로 보존한다([변경 계약](./research/smartstore-admin/order-address-changes.md)).
- `M` 고객 요청 철회: 취소·반품·교환의 접수/검토/수거 전 요청을 고객 직접 또는 판매관리 담당자가 합의 근거로 철회한다. 실제 반송·입고·금전 처리가 시작된 건은 차단하고, 주문·결제·재고를 유지하며 거절과 구분한 이력을 남긴다([철회 계약](./research/smartstore-admin/claim-withdrawal.md)).
- `M` 반품·교환 전환: 고객 합의 후 환급/재출고 착수 전의 요청 유형을 주문 전체 단위로 바꾼다. 원래 접수일·수거 근거·보류·금액은 보존하며 무통장 반품의 환불계좌, 변경 이력과 동시처리 충돌을 검증한다([전환 계약](./research/smartstore-admin/claim-type-conversion.md)).
- `M` 요청 보류·해제: 한 주문의 현재 요청 유형·버전을 확인해 처리한다. 다른 탭의 유형 전환·철회·금전 처리와 충돌하면 오래된 요청을 거절하고, 응답을 확인하지 못한 경우 같은 작업의 결과부터 조회한다. 원본의 같은 주문 내 상품주문 선택과 단계 통합 처리를 여러 주문 일괄 보류로 해석하지 않는다([보류 계약](./research/smartstore-admin/claim-hold-contract.md)).
- `M` 교환 사유 정정: 고객과 협의한 분류·설명을 재출고/환급 착수 전의 교환 요청에서 바로잡는다. 원래 접수일로 기한을 다시 확인하고 비용·보류·회수·금액을 보존한다. 내부 협의 근거와 고객 이력을 분리하며 실제 변경에만 앱 알림을 한 번 남긴다([사유 정정 계약](./research/smartstore-admin/exchange-reason-change-contract.md)).
- `S` 어드민 통계: 판매분석(일별 매출·객단가·굿즈 순위·결제수단별 비중·티켓), 클레임(유형·사유·환급 소요), 고객현황(가입·재구매·문의). KST 직접 기간·직전/전년 비교·조회 조건을 포함한 엑셀을 제공한다. 방문·유입은 별도 선택 동의 원장으로 집계한다.
- `S` 고객 구매 분석: 기존 고객현황 안에서 실제 승인·입금 시점과 결제 직전 180일 이력으로 신규/재구매를 나눈다. 마감된 주·월, 별도 비교 기간, 13주/13개월 추이와 전체 엑셀을 제공한다. 취소·반품 이후에도 결제 이력을 유지하고 고객 유형 중복·적립금 포함 여부·미확인 금액/시각을 명시한다([집계 계약](research/smartstore-admin/customer-purchase-analysis-plan.md)).
- `M` **운송장** 등록·조회 — 운영자가 택배사·운송장번호를 남기고 구매자가 배송을 추적한다.
- `M` **청약철회/환불**(전자상거래법) 처리 흐름 — 배송 전 취소와 **배송 후 청약철회**를 모두 포함한다.
- `M` 주문 상세의 **직접 신청**은 취소의 경우 발주확인 전, 반품·교환의 경우 주문한 굿즈가 모두 실제 배송 완료된 뒤에 제공한다. 혼합 출고지 주문과 주문 전체 처리는 유지하고, 부분 취소·부분 반품·부분 환불은 제공하지 않고 항상 주문 전체·전액으로 처리한다(2026-10-12 재확정). 반품·교환은 출고지별 회수 근거를 모아 전체 회수 확인 후 환급·재출고로 진행한다. 직접 신청이 닫힌 동안에도 1:1 문의·고객지원에서 청약철회 의사표시와 접수 시각을 보존해 검토하며, 앱 상태를 법정 권리의 소멸 조건으로 사용하지 않는다([ADR-0017](./adr/0017-order-claim-intake-and-origin-collections.md), [운영 절차](./runbooks/order-claim-intake.md)).
- `M` **주문 확인·배송 시작 이메일** — 계약내용에 관한 서면(전자문서) 교부 경로. [launch-readiness-plan §6](./launch-readiness-plan.md)의 "알림은 v1에서 인앱만" 가정에 대한 예외다.
- `M` 상품 사이즈 안내: 최대 10개 사이즈와 10개 측정 항목의 cm/mm 치수표를 기본 상품·옵션·고시와 별도로 저장한다. 템플릿을 복사해 상품마다 수정하고 공개 상세에서 표와 측정 안내를 확인한다. 템플릿 변경은 이미 저장한 상품표에 전파되지 않으며, 착용모델의 사진·신체정보는 포함하지 않는다([계약·검증](research/smartstore-admin/goods-size-chart-proposal.md)).
- `M` **리뷰** — 배송완료된 굿즈에 구매자가 남기는 별점(1~5)·글·사진 후기. 자격은 해당 굿즈의 **`delivered` 이상 주문 보유자**로 한정하고 **일반 리뷰는 주문×굿즈당 1회**, 작성 기한은 **배송완료 후 90일**이다. 한달사용 리뷰는 별도 1회이며 기본 꺼짐인 관리자 정책의 배송완료/구매확정 기준·시작/마감일·선택 주문 최대 기간을 따른다. 이미 작성한 리뷰의 수정 마감과 한달사용 보상 자격은 작성 당시 값으로 보존한다. 재구매는 작성 당시 최근 180일 안의 동일 상품 배송완료·유효 결제 이력으로 고정하고 과거 리뷰에는 소급 추정하지 않는다. 공개 일반·한달사용 리뷰 모두 평점에 포함한다([유형 계약](research/smartstore-admin/review-types-plan-20261016.md)). 굿즈 상세는 평점 요약(평균·분포·개수)과 리뷰 목록(최신/평점순·사진 필터)을 **비로그인에게도** 공개한다(공개 브라우징 원칙). 작성자 수정은 기한 내, 삭제는 상시이며 운영자 블라인드와 구분한다. 운영자 답글은 공개 표시되고 작성자에게 인앱 알림이 간다. 일반 리뷰 작성만으로 지급하는 기본 포인트는 없다. **리뷰이벤트**는 별도로 공지한 기간·대상·혜택에 따라 신규 유효 구매 리뷰가 자동 응모되고, 별점과 무관하게 수동 선정한 고객에게 기존 적립금을 지급한다. 고객당 이벤트 1회이며, 발표일 이후 운영자가 발표·전체 지급을 한 트랜잭션에서 확정한다. 삭제·비공개·원주문 취소/반품 완료 시 해당 혜택을 회수하고 혜택 제공 이력은 공개 리뷰에 표시한다. 조건·권한·불일치 처리의 정본은 [리뷰이벤트 계약](research/smartstore-admin/review-events-parity.md)이다. 운영자는 적용한 필터로 이벤트·응모 목록을 각각 최대 10,000행의 엑셀로 내려받으며 선정·지급·회수 상태와 조회 조건을 함께 확인한다. 베스트 리뷰의 별도 선정과 평점 추이 통계는 개별 범위를 따른다.
- `M` **위시리스트** — 로그인 사용자가 굿즈를 찜해 `/my/wishlist`에 모은다. 수량이 없는 토글이며 장바구니와 별개 도메인이다.
- `M` **재입고 알림** — 품절 굿즈에 신청하면 그 굿즈가 다시 "판매 가능"이 되는 시점에 알림함과 이메일로 알린다. 재신청은 새 행이 아니라 같은 신청을 되돌린다.
- `M` **쿠폰** — 발급형 주문 할인 혜택이다. 전체·첫구매·재구매 고객 자격과 전체·선택 굿즈·카테고리 대상을 구분한다. 일반 코드형은 코드 입력·등급 혜택·운영자 발급을 지원하고 고객지정형은 명시적 운영자 발급 후에만 사용할 수 있다. 발급 경로마다 현재 자격을 재검사한다. 장바구니에서는 **한 장만** 선택하며 대상 굿즈의 기간 할인·복수구매 할인 후 소계로 최소금액과 할인을 평가한다. 계산 버전 1의 기존 주문 계약은 유지한다. 새 일반 주문서는 선택한 쿠폰 배열·순서를 견적에 보존하고 주문 생성 시 조건을 재검증하며 당시 조건·대상 소계·실제 할인액을 보존한다. 주문이 취소되면 사용 원장을 남긴 채 쿠폰을 복구한다. 코인·뽑기권과 교차하지 않는다.
- `M` **적립금** — 쿠폰 적용 뒤 남은 굿즈 금액에 1원 단위로 사용하는 별도 혜택 잔액이다. 배송비 사용을 제외하고 최소 유상 결제액을 유지한다. 주문 생성 시 선점, 검증된 결제 확정 시 사용, 전액 취소·환불 시 원출처 기준 복원을 멱등 처리한다. 거래확정 시 주문 당시 정책으로 적립하며, 그 주문이 환불되면 원적립을 회수하고 이미 사용한 부분은 이후 적립·복원 금액에서 상계한다. 실제 지급률·상한·유효기간·회수 방식은 admin이 승인 근거와 함께 설정해야 하며 미설정 상태로 활성화할 수 없다. 고객의 현금 청구·환불액 차감·유상 충전·현금 출금·양도는 제공하지 않는다.
- `M` **상품 Q&A** — 굿즈 상세에 남기는 **공개** 구매 전 질문과 운영 답변이다. 비공개 1:1 **문의**와 분리한다. 목록은 비로그인에게도 공개하고(공개 브라우징 원칙), 작성·삭제는 작성자 본인, 블라인드는 운영자 권한으로 구분한다. 답변이 달리면 작성자에게 인앱 알림이 간다. 내 질문 내역은 `/my/questions`에서 본다.
- `S` 한정·신상·예약·품절 배지, 한정 수량 표시.

### 5.4 무료 카드 리워드 & 바인더 (P2)

> 유료 가챠·충전금 모델은 폐기됐다([ADR-0003](./adr/0003-free-reward-pivot.md), [ADR-0001](./adr/0001-paid-digital-gacha.md) superseded). 카드 리워드의 현재 계약은 [ADR-0004](./adr/0004-draw-ticket-card-packs.md)와 이 절이다.

> 운영 gate: 무료 리워드 모델 자체의 법무·운영 검토가 끝나기 전에는 DB 전역 gate를 OFF로 둔다. OFF 상태에서는 신규 주문 리워드 발급, 카드팩 개봉, 카드 보상형 게임 플레이, 수동 발급, 발급 정책·게임 활성화를 DB에서 차단하고 `/packs`·게임 공개 표면을 숨긴다. 기존 보유 카드 바인더 조회는 유지한다.

- `M` **카드팩**: 조건에 맞는 굿즈 주문 확정은 특정 카드풀에 묶인 `draw_tickets`를 멱등 발급한다. 카드 자체를 유상 판매하거나 충전금·지갑을 제공하지 않는다.
- `M` **개봉**: 사용자가 카드팩을 열 때 `open_draw_ticket`이 서버에서 카드를 결정·발급한다. 클라이언트 reveal은 결과를 바꾸지 못한다.
- `M` **참여형 게임**: 무료 플레이의 결과와 카드 발급은 `play_game`이 서버에서 결정한다. legacy `goods` variant는 운영 콘솔에서 읽기 전용이고, mock 연출은 실제 경품·구매권을 만들지 않으며 신규 실물 판매에 사용하지 않는다.
- `M` **바인더**: 보유/미보유 카드, 등급(N·R·SR·SSR·HOLO), 도감 진행률, IP/등급 필터를 제공한다.
- `M` 카드풀 확률·운영 기간·정책·발급·개봉·회수는 감사 가능한 서버 원장으로 관리한다.
- 법률·PG 적용 여부를 "무료"라는 명칭만으로 단정하지 않는다. 상품가·발급 조건·표현·실제 운영에 대한 최신 검토 증거를 활성화 조건으로 둔다.

### 5.5 오프라인 팝업/티케팅 (P3)

- `M` 오프라인 팝업 목록/상세(`/offline-popups`, 모드: 온/오프라인, 상태: 예매중/예정/진행중, 일시·장소). 기간 한정 캠페인 허브인 **이벤트**(§5.9)와 별개 도메인이다.

- `S` 1인 구매 한도, 예매 오픈 시각, 대기열(고동시성 회차).

### 5.8 운영 백오피스 `/admin` (각 도메인과 병행)

- `M` 판매자센터는 통합 매니저·계정 주매니저·계정 부매니저·인플루언서·대행사·물류출고관리의 여섯 역할에 따라 메뉴·조회·변경을 제한한다. 담당업무는 별도 표시이며 접근 권한을 바꾸지 않는다. 기존 운영자의 최초 전환에서는 통합 매니저와 전원의 역할 또는 회수를 명시한다.
- `M` 매니저 초대는 기존 이메일 경로를 사용하며 생성·발송·수락을 구분한다. 인증된 동일 이메일의 계정이 7일 안에 수락하고, 통합 매니저를 제외한 매니저·유효한 수락 대기는 합해 1,000명, 한 번의 초대는 10명까지다. 역할 변경·회수·통합 승계는 멱등 처리·감사를 거치며 권한 회수는 기존 로그인 세션에도 다음 요청부터 적용된다.
- `M` 카탈로그 관리: IP·굿즈·카드·카드풀 운영 기간·등급별 발급 확률·카드 풀 바인딩·이벤트·티켓 회차.
- `M` IP 식별자 관리: 내부 IP ID는 유지한 채 공개 슬러그를 수정할 수 있고, 기존 공개 URL은 재사용할 수 없는 별칭으로 보존한다. 미사용 초안은 기존 보관/복원 동선으로 정리하며, 변경은 권한 검증과 감사 로그를 거친다.
- `M` IP·굿즈·카드·이벤트는 hard delete하지 않고 참조 가드가 있는 audited RPC로 보관/복원한다. 공개 탐색과 신규 거래에서는 보관 항목을 제외하되 기존 주문·바인더·발급·팔로우·커뮤니티 이력의 FK와 조회 가능성은 유지한다.
- `M` 뽑기권 발급 정책: 구매 대상 IP와 선택 same-IP 굿즈, 독립 보상 카드풀, 최소 결제 금액, 발급 수량, 운영 기간·활성 상태를 관리한다. 한 주문에 조건이 맞는 정책은 모두 누적 적용한다.
- `M` 참여형 게임 운영: 카드 보상형 게임의 slug·제목·준비된 카드풀·같은 IP의 온라인 이벤트·KST 운영 기간·일일 한도를 audited RPC로 등록·수정하고 PII-free 플레이 집계를 확인한다. 신규 게임은 card variant·10개 구슬로 고정하고 등급 라인업은 카드풀 확률을 largest-remainder로 배분해 결정적으로 생성하되, 실제 결과는 `play_game`이 정한다. 게임 창 전체는 카드풀 창 안에 있어야 하며 연결된 카드풀·이벤트 변경도 이 계약을 깨뜨릴 수 없다. slug는 첫 플레이 전까지만 변경할 수 있고 플레이 후 type·카드풀·이벤트·config와 함께 잠긴다. 현재 시각이 운영 창에 포함되는 기존 카드 게임은 DB 현재 시각으로 종료하며 직접 DML은 허용하지 않는다. 기존 `goods` variant는 운영 콘솔에서 읽기 전용이며, 남은 mock 연출은 실제 경품·구매권을 만들지 않고 실물 쿠지에 재사용하지 않는다.
- `M` 주문/티켓/환불 조회 및 처리.
- `M` 전체 사용자·특정 IP 팔로워 대상 인앱 공지의 수신자 수 미리보기·즉시 발송·감사 이력. 이메일·푸시·예약 발송은 제외한다.
- `M` 스토어 전시 설정(`/admin/display/settings`): 공통 테마·헤더·홈 검색과 상품목록 비율·추가이미지·명시 색상칩·PC 설명·담기·BEST/NEW 태그를 각각 저장한다. 미리보기·동시 편집 충돌·멱등 저장을 제공하며 상품별 색상칩은 옵션·재고를 바꾸지 않는다. [전시 설정 계약](./research/smartstore-admin/store-presentation-implementation-qa.md)을 따른다.
- `M` 스토어 브랜드·SNS(`/admin/settings/store`): 표시 이름·PC/모바일 로고·소개·SNS와 별도 정사각형 대표 이미지를 관리한다. 대표 이미지는 최소160px 정사각형의 검증된 업로드이며 푸터에80px로 표시한다. 헤더 로고와 법정 사업자 정보는 별도로 유지한다([대표 이미지 계약](research/smartstore-admin/store-profile-parity.md)).
- `M` 상품상세 표시(`/admin/display/detail`): 상단 띠배너의 문구·스타일·대상·KST 기간과 공개 구매 리뷰 요약·자동 추천 4종을 각각 저장한다. 수동 연관상품 편성을 우선하며 자동 추천은 현재 공개 카탈로그와 검증된 구매·찜 근거만 사용한다. 최초에는 추가 영역이 모두 꺼져 있고 필수 상세정보·KC·리뷰·배송 안내는 유지한다([표시 계약](./research/smartstore-admin/product-detail-presentation-implementation-qa.md)).
- `M` 상품 동영상·숏클립: 상품별 각 1개와 1~20자 타이틀을 관리하고 이미지·동영상·숏클립 대표 순서와 별도 숏클립 영역을 설정한다. MP4(H.264/선택 AAC-LC)·50MB·60초·가로/세로 1920px까지 지원하며 재생 실패 시 대표 이미지로 전환한다. 네이버 원본의 1024MB·다중 컨테이너, 라이브 추출·GIF 자동 생성은 포함하지 않는다. [미디어 수용·검증 계약](./research/smartstore-admin/product-detail-media-parity.md)을 따른다.
- `S` 상세 구매·탐색 안내: 확정 구매자/재구매자 수, 직전 3일 판매수량 TOP10·7일 신상품, 현재 옵션/수량과 후보의 실제 기본배송비 절약 비교, 본인 재구매·장바구니·찜·최근 본 굿즈를 선택적으로 표시한다. 관심 모아보기는 동일 스위치의 `/interests`로 연결하며 최근 본 굿즈는 계정별 브라우저에만 최대30개 보관한다. 기본은 비노출이다([원본 대조와 계약](./research/smartstore-admin/product-detail-experiences-parity.md)).
- `M` 홈 큐레이션: 히어로·특집 IP·공지 배너의 제목·안전한 내부 링크·노출 순서·KST 기간·활성 상태를 관리한다. 공개 홈은 현재 활성인 큐레이션만 반영하며, 공지 배너 저장은 인앱 공지를 자동 발송하지 않는다. 홈 상품형 베스트리뷰는 이미 선정된 상품의 대표 후기에 현재 유효한 BEST 선정을 우선하고, 없으면 공개 후기의 평점·작성시각·ID순으로 표시한다. 상품 후보·순서·평균·개수는 유지하며 [홈 대표 후기 계약](research/smartstore-admin/home-review-best-priority-implementation-qa.md)을 따른다.
- `M` 상품공지(`/admin/catalog/announcements`): 분류·본문·게시기간·중요 표시 기간·PC/모바일과 전체 또는 선택 상품을 관리한다. 중요기간 밖에는 일반 공지로 표시한다. 별도로 선택한 공지 한 건을 지정 기간의 홈 팝업으로 표시하며 게시 조건도 함께 적용한다. 예약·종료 뒤 이전 팝업이 되살아나지 않고, 고객은 한국 자정까지 오늘 숨김을 선택한다. 공지와 팝업 선택은 동시 수정 충돌·고정 요청 재시도·감사를 거친다([기간·팝업 계약](research/smartstore-admin/goods-announcement-period-popup-proposal.md)).
- `M` 홈 자유상품은 리스트·풀이미지·8슬롯 모자이크를 합쳐 비노출 포함 최대 5개 구성으로 편성한다. 리스트·풀이미지는 후보 최대100개의 순서·표시 수·사진 비율을 고르고, 공개 적격 상품만 후보 순서로 채운다. 품절·무매출 상품은 유지하고 적격 상품이 없으면 영역을 숨긴다. 전체 홈 순서·숨김과 개별 기간을 함께 적용하며 [진열 계약](research/smartstore-admin/home-free-products-contract.md)을 따른다.
- 프로모션 배너는 비노출·예약·종료 포함 최대 10개다. 제목 40자·내용 150자/3줄은 선택이며, 이미지 대체텍스트와 이동 링크 없음을 각각 설정한다. 이미지 전용 배너·PC/모바일 이미지와 동시 수정 충돌의 계약은 [배너 보완](./research/smartstore-admin/home-promotion-banner-parity.md)을 따른다. 이미지 딤(없음·흰색·검정색)과 문구색(흰색·검정색)을 별도로 선택한다. 삭제는 이미지·문구를 보관하면서 공개 화면과 등록 한도에서 제외하고, 복구는 한도를 확인해 같은 ID의 비노출 상태로 되돌린다([표시·삭제·복구 계약](./research/smartstore-admin/home-banner-style-archive-parity.md)).
- `M` 쇼핑스토리(`/admin/display/stories`): 제목·안전한 본문·검증 이미지·선택 전시기간과 관련상품을 편성한다. 최대 10섹션·섹션별 200개·전체 300개 상품을 순서대로 관리하고, 공개 `/stories` 목록·상세와 홈 최신 3개에 연결한다. 등록일순은 고정이고 수정으로 순서가 바뀌지 않는다. 저장·선택 삭제는 버전 충돌·멱등 처리·감사를 거치며 삭제는 복원 기능 없이 이력을 보존한다. [운영 계약](./runbooks/shopping-stories.md)을 따른다.
- `M` 마케팅 링크(`/admin/marketing/links`): 스토어홈·상품·쇼핑스토리·카테고리에 고정된 주소를 발급·조회·복사한다. 각 대상 편집·목록에서 해당 업무 권한으로 발급하고 통합 조회는 통합·계정 주매니저에게 열린다. 같은 대상에는 같은 주소를 반환하며 비공개·보관·종료 상태는 방문 시 다시 검사한다. 별도 선택 동의가 있는 방문·결제 귀속은 방문 분석에서 확인한다.
- `M` 방문·유입·마케팅 링크 성과(`/admin/stats/traffic`, `/admin/stats/marketing`): 별도 선택 동의가 있는 브라우저의 열람·방문 세션·링크 유입과 본인 주문의 결제 전환을 기간·직전/전년 비교·일/주/월 추이·한글 검색·엑셀로 조회한다. `stats.read` 권한을 요구하며 카드 승인과 무통장 입금 확인의 공통 서버 확정 근거를 사용한다. 0원 주문·티켓은 제외하고 미측정 기간을 0으로 표시하지 않는다. 수집은 기본 비활성이며 [측정 계약](research/smartstore-admin/traffic-attribution-parity.md)과 [활성화 런북](runbooks/store-analytics-activation.md)을 따른다.
- 회원별 방문·상품 영상 세그먼트는 별도 선택 동의(`member-activity-v1`)를 받은 일반 회원만 대상으로 한다. 기본 수집은 꺼짐이며 원시 이력은 최근 90일 보존, 철회·탈퇴 요청 시 삭제한다. 방문·미방문·상품 조회·유사 분류 상품 조회·영상 재생 조건과 관측 가능 기간은 [회원 행동 계약](research/smartstore-admin/member-activity-segments.md)을 따른다. 익명 통계와 마케팅 수신 동의는 별개다.
- 고객 성별·연령 분석은 별도 선택 동의한 자가 입력 성별과 기존 생년월일로 집계한다. 10명 미만 셀은 서버·화면·엑셀에서 비공개이며 합계·비율·개인별 명단을 제공하지 않는다. 철회·탈퇴 신청 시 성별을 삭제하고, 동의 전 결제에 성별을 소급하지 않는다. [집계 계약](research/smartstore-admin/customer-demographics.md).
- `M` 타겟 세그먼트(`/admin/marketing/segments`): 현재 가입·장바구니·찜·쿠폰·IP 알림 구독·구매 근거로 9개 타겟 조건을 만들고 추정·저장·수정·복사·보관·개인별 즐겨찾기 최대 3개를 관리한다. 추정 회원수와 현재 마케팅 수신 동의 회원수를 구분하고, 실제 관찰이 없는 월은 미집계로 표시한다. 저장된 조건을 재사용할 때 현재 계정 상태·조건·동의를 다시 검사한다. 방문 데이터 수집은 별도 기능이며 [대응 계약](./research/smartstore-admin/target-segment-parity.md)을 따른다.
- `M` 마케팅 메시지(`/admin/marketing/messages`): 현재 마케팅 수신 동의·계정 자격·세그먼트 조건을 다시 확인한 고객에게 설명형·이미지형·상품목록형·상품카드형 인앱 알림을 즉시·일시 예약·주간 반복으로 등록한다. 발행 후 조건을 고정하고 회차별 등록·읽음·제외·취소·기한 지남을 구분한다. 외부 발송·클릭·구매 전환과 구분하며 [메시지 계약](./research/smartstore-admin/marketing-message-parity.md)을 따른다.
- `M` 커뮤니티 신고 처리. 신고 대상에는 굿즈 **리뷰**도 포함하며 같은 큐에서 다룬다.
- `M` 리뷰 관리(`/admin/cs/reviews`): 기간·평점·상태·사진 유무·답글 유무·검색(굿즈/작성자) 필터와 **저평점(1~2점) 고정 필터**, 운영자 답글 작성·수정(공개 표시), 사유와 감사 로그가 남는 블라인드/해제, 신고 건 모더레이션 연결. 블라인드는 작성자 삭제와 다르다 — 원문과 사유가 남아 언제든 해제할 수 있다. 공개 상품문의·리뷰의 단건 답변은 읽은 원본의 버전을 저장 시 다시 검사하며, 미확인 요청은 같은 입력으로 결과를 확인하고 복구한다. 같은 내용 재저장은 새 감사·알림을 만들지 않는다([단건 답변 계약](research/smartstore-admin/cs-single-reply-cas.md)).
- `M` 회원 운영: 목록 이메일은 마스킹하고 명시적 상세에서만 전체 이메일·현재 동의 상태·최소 운영 집계를 조회한다. 매니저 전환 후에는 통합·계정 주매니저가 정지·해제할 수 있으며 본인과 통합·계정 주매니저 대상은 제외한다. 대상이 통합·계정 주매니저라면 먼저 승계 또는 역할 변경을 처리한다. 전환 전 호환 모드의 기존 staff/admin 제재 범위는 보존한다. 정지 계정은 새 작성·댓글·주문·예매·카드팩 개봉·게임 플레이와 매니저 접근 권한을 잃되, 기존 주문·환불·삭제·신고 같은 회복 경로는 유지한다. 내부 사유는 상세 RPC에만 노출하고 감사 로그에는 남기지 않는다.
- `M` 쿠폰 운영(`/admin/sales/coupons`): 정액·정률과 상한, 대상 소계의 최소금액, 기간, 발급 한도, 등급 혜택, 발급/사용 고객 자격, 선택 굿즈, 보관/복원을 audited RPC로 관리한다. 조건 버전이 다르면 덮어쓰지 않으며 보관 중 비운 대상은 활성화 전에 검증한다. 발급·적용·사용·복구는 전부 서버 경로만 지난다.
- `M` 적립금 운영(`/admin/settings/store-credits`, 고객 상세의 적립금): 통합·계정 주매니저가 정책·지급·정정을 수행한다(전환 전 호환 모드는 기존 admin 전용). 금액·사유·유효기간·예상 잔액·멱등 요청 키를 검증하고 출처와 감사 기록을 보존한다. 고객은 `/my/store-credits`에서 본인 잔액과 전체 이력을 확인한다. 조회 실패와 미설정 값은 0원으로 표시하지 않는다.
- `M` 거래확정 검토(`/admin/sales/settled`): 현재 주문일(KST)·검색 조건의 전체 거래확정 주문에서 확정일·주문번호·운송장·ERP 품명·수량·판매금액·배송비·결제일을 내보낸다. 품목별 쿠폰·적립금은 원 단위로 배분하고 배송비는 배송 건 첫 행에 한 번만 기록한다. 주문·결제 원장과 대조하며 미기록은 현재 값으로 채우지 않는다. 생성자는 권한을 유지하는 동안 같은 비공개 영수증을 다시 받을 수 있다. ERP 자동 입력·정산 지급 기능은 아니다.
- `M` PG 정산 조회(`/admin/settlements`): 통합·계정 주매니저가 토스 정산 원본을 최대 31일·20,000건씩 수집하고 두 차례 대조를 마친 완료 자료의 일별·건별·수수료 및 결제·환불 연결을 조회한다. 미수집·확인된 0건·일부 수집·실패를 구분하며, 완료 자료와 수집 시점 대조 결과는 불변이다. 소수 금액은 원문 정밀도를 보존하고 승인·취소·통화별로 집계한다. 실제 PG 연결은 기본 OFF이며 은행 실입금, 코페이 원본, 세무 증빙과 지급보류·조정은 [추가 계약 확인 대상](./research/smartstore-admin/pg-settlement-followups.md)이다. [운영 절차](./runbooks/pg-settlement-reconciliation.md)를 따른다.
- `M` 캠페인 편성(`/admin/display/campaigns`): 유형(EVENT·DROP)·기간·게시 상태·허브 배너 순서와 랜딩 본문 블록을 관리한다. 슬러그는 오프라인 팝업 이벤트 id와 겹칠 수 없다.
- `M` BEST 리뷰 선정: 별점과 무관하게 리뷰를 선정·해제하고 사유를 기록한다. 상품별 유효한 선정 리뷰가 3개 이상일 때 무작위 3개를 상품 갤러리의 마지막 슬라이드에 표시한다. 원문·공개 상태·구매 자격이 바뀌면 재확인이 필요하다. 선택형 BEST 보상은 기본 꺼짐이며, 운영자가 금액·유효기간·회수 정책을 설정한 뒤 이후 선정부터 리뷰당 최초 1회 지급한다. 재선정은 중복 지급하지 않으며 실제 혜택 제공 사실을 공개 리뷰에 표시한다. 선정 전시의 [검증과 운영 경계](./research/smartstore-admin/product-detail-review-best-implementation-qa.md), [보상 계약](research/smartstore-admin/customer-rewards.md)을 따른다.
- 등급별 주문 적립은 기본 꺼짐이며 WELCOME·SILVER·GOLD·PLATINUM의 최종 적립률을 관리자가 설정한다. 활성 시 기본 정률·정액을 대체하고 기본 적립 상한·유효기간을 적용한다. 주문 생성 시 당시 등급·정책을 저장해 거래확정 때 지급한다. 금액·기간을 임의 기본값으로 활성화하지 않는다.
- 반품·교환의 회수 시작 전 전체 주소와 재출고 전 수령 주소를 정정할 수 있다. 지역 요금 차액·확인 불가 상태는 저장을 막고, 수거 방식·택배사·송장은 최초 접수와 구분한 이력으로 수정한다. 실제 수거 요청·입고 확인은 별개이며 주문 금액·배송비를 자동 변경하지 않는다. [계약·검증](research/smartstore-admin/claim-address-collection.md).
- 구매자는 배송완료 후 직접 구매확정할 수 있다. 자동 구매확정은 기본 꺼짐·기간 미설정이며 활성화 이후 첫 배송완료 시 당시 기간을 보존한다. 고객 1회 기간 연장, 관리자 인앱 요청·보류·해제와 이력을 제공하고, 확정 후에도 배송일·사유별 반품/교환 자격을 유지한다. [구매확정 계약·검증](research/smartstore-admin/purchase-confirmation.md).
- 반품·교환 배송비는 기본 꺼짐 정책과 고객별 합의에 따라 별도 청구한다. 고객 입금 알림, 실제 입금 확인, 청구 취소/면제, 실제 반환과 대기 목록을 제공한다. 요청 철회·거부·유형/사유 변경 시 미입금 청구는 취소하고 받은 비용은 반환 대기로 남긴다. 주문 전액 환불에서 차감하거나 미입금으로 클레임을 자동 차단하지 않는다([계약·검증](research/smartstore-admin/claim-fees.md)).
- 반품·교환은 실제 발송된 배송 중 주문부터 전체 수량을 접수한다. 출고지별 모든 실물의 회수/창고 보관 확인 전에는 환불·교환 재출고를 허용하지 않는다. 접수만으로 결제나 재고를 바꾸지 않으며 미출고 배송 건의 추가 발송을 막는다. [배송 중 접수 계약·검증](research/smartstore-admin/in-transit-claims.md).
- 일반 장바구니 주문에 관리자 설정형 쿠폰 중복 사용·배송비 쿠폰을 제공한다. 기본은 꺼짐이며 상품 쿠폰 최대 1~5장·배송비 쿠폰 1장을 선택한다. 설치비·착불은 배송비 할인 대상에서 제외하고, 발급 후 상품/배송비 할인 구분·중복 허용·발급 방식은 고정한다([계약·검증](research/smartstore-admin/coupon-combinations.md)). 선물·정기배송은 기존 단일 상품 쿠폰 계약을 유지한다.
- 쿠폰은 지정 고객 또는 저장한 세그먼트에 수동 발급할 수 있다. 최대 1,000명의 확인된 대상을 15분 이내에 현재 자격·기간·한도를 재검사해 전체 발급하며 기보유 고객은 건너뛴다. 쿠폰함 발급은 마케팅 알림 발송과 별개다([계약·검증](research/smartstore-admin/coupon-target-issuance.md)). 고객지정형 정의는 일반 코드 입력으로 신규 발급되지 않는다. 카테고리 대상은 현재 대표·추가 분류와 하위 분류를 적용하며 이후 등록 상품도 포함한다([카테고리 계약](research/smartstore-admin/coupon-category-targeting.md)).
- `M` 발송지연 안내 상태: 배송건의 최근 발송 요청과 앱·이메일 원장의 실제 결과를 발송 처리·일부 실패/제외·대기/처리 중·결과 확인 필요·미발송으로 조회한다. 검색·집계·페이지·전체 엑셀에 같은 조건을 적용하며 [기존 전송 정책과 구분](./research/smartstore-admin/shipment-delay-notice-filter.md)한다.
- `M` 상품 Q&A 답변(`/admin/cs/qna`): 미답변 큐에서 답변을 등록·수정하고 블라인드/해제를 수행한다. 답변은 작성자에게 인앱 알림으로 간다.
- `M` **감사 로그**(audit_log): 민감 작업 기록.

### 5.9 회원 등급 · 캠페인 · 코인 (커머스 개편 확장)

> 세 기능 모두 v1 범위이며 [ADR-0011](./adr/0011-lfs-storefront-redesign.md) 개편에서 더해졌다. 굿즈 주문은 기간 할인가에 **복수구매 할인·상품 쿠폰·배송비 쿠폰·적립금**(§4.5·§5.3)을 순서대로 적용한다. 등급은 혜택 쿠폰 발급 조건이며 별도 자동 할인을 만들지 않고, 코인은 주문 할인과 교차하지 않는 무료 참여 재화다.

- `M` **회원 등급** — 최근 **90일** 결제 확정 실적으로 오르는 무료 4단 등급(WELCOME·SILVER·GOLD·PLATINUM). 유료 **멤버십**(v2)이 아니다. 승급하면 통과한 등급의 혜택 쿠폰을 자동 발급하고 인앱 알림을 보내며, 강등은 이력만 남기고 이미 발급한 혜택은 회수하지 않는다. 등급은 마이페이지 프로필과 쿠폰함에 표시한다. 통합·계정 주매니저는 기존 등급명·90일 창·재산정 시점을 유지하면서 등급별 사용 여부와 금액 또는 상품 주문 항목 수 조건을 설정한다. 설정 저장만으로 기존 회원을 일괄 재산정하지 않는다. 혜택 쿠폰은 기존 등록·수정 화면에서 등급별로 연결하며 스토어 정책과 각 쿠폰의 중복 허용 조건을 따른다.
- `M` **캠페인(이벤트)** — 기간 한정 캠페인·프로모션의 허브(`/events`)와 상세 랜딩. 유형은 EVENT·DROP이고 허브는 배너 슬라이더·유형 탭·기간과 상태 뱃지를 제공한다. 랜딩 본문은 운영자가 고르는 블록(소개·이미지·텍스트·출석·교환·쿠폰·굿즈·공지)으로 조립하고, 준비 중(draft) 편성은 공개되지 않는다. **오프라인 팝업 예매는 이 도메인이 아니다** — `/offline-popups`로 분리돼 있고 저장된 옛 `/events/[id]` 링크는 그쪽으로 리다이렉트된다.
- `M` **코인** — 출석·캠페인 참여로 적립되는 무상 참여 재화. 소진처는 **카드팩(뽑기권) 교환**뿐이며 결제 수단이 아니고 폐기된 충전금과 무관하다. 출석은 KST 자정 경계로 하루 1회이고 적립·사용은 append-only 원장에 남는다. 교환은 기존 카드 리워드 발급 경로를 그대로 쓰므로 카드 리워드 전역 gate가 OFF면 함께 막힌다. 사용자-facing 표면에서 '가챠·뽑기·충전' 어휘를 쓰지 않는다.

## 6. 핵심 사용자 플로우

1. **첫 방문(비로그인)**: 홈 → IP 탐색 → 굿즈/카드 구경(공개). 액션 시 로그인 유도.
2. **온보딩**: 소셜/이메일 로그인 → 이메일·닉네임·생년월일·동의 입력 → 관심 IP 팔로우.
3. **비밀번호 재설정**: 로그인 → 재설정 메일 요청 → 요청한 브라우저에서 최신 링크 열기 → 새 비밀번호 저장 → 새 비밀번호로 로그인.
4. **굿즈 구매**: 굿즈 상세 → 장바구니(기간 할인가·상품 쿠폰 미리 선택) → 체크아웃(상품 쿠폰 순서·배송비 쿠폰·적립금·최종 금액 확인) → provider-neutral attempt/confirm(기본 토스, 판매 제한 상품 주문은 코페이 파생. 토스 gate는 심사 전까지 닫힘) → 주문완료 → 내역.
5. **카드 리워드**: 굿즈 주문·무료 참여형 게임·캠페인 코인 교환 → 카드팩 발급/서버 결과 확정 → 개봉 연출 → 바인더 적립.
6. **티켓**: 오프라인 팝업 상세 → 회차/수량 예약 → provider-neutral 토스 결제(현재 Production gate OFF) → 승인 finalizer의 전자티켓(QR) 발급 → 현장 검표.
7. **커뮤니티**: 피드 → 글 작성(이미지)·수정 → 반응/댓글 → (문제 시) 신고/차단.
8. **리뷰**: 배송완료 → 주문 상세 또는 내 리뷰에서 진입 → 별점·글·사진 등록 → 굿즈 상세 공개 → (필요 시) 운영자 답글·신고.
9. **캠페인 참여**: 이벤트 허브 → 캠페인 랜딩 → 출석 코인 적립 → 카드팩 교환 → 개봉.

## 7. 규제 · 법무 요구사항

선택한 기능(실물 굿즈·티켓 결제, 무료 카드 리워드, UGC)과 별도 승인 트랙은 다음 검토 표면을 동반한다. 적용 여부를 문서만으로 단정하지 않고 제품·법무·공급사 evidence를 출시 전에 맞춘다.

| 항목 | 적용 | 요구사항 |
|---|---|---|
| **전자상거래법** | 굿즈·티켓·실물 쿠지 | 사업자/판매자 정보·약관·상품 고지·청약철회·환불·표시광고 준수, **통신판매업 신고** |
| **게임산업·사행성 관련 검토** | 카드팩·참여형 게임·실물 쿠지 | 명칭이나 무상 주장만으로 적용 제외를 단정하지 않고 실제 대가성·게임성·운영 구조를 법률 검토와 일치시킨다 |
| **개인정보보호법(PIPA)** | 전체 | 수집 항목 최소화·동의·보관/파기. 14+ 가입 기준과 기존 계정 처리의 상세 계약은 #188에서 승인한다 |
| **청소년보호·성인 콘텐츠** | 19+ 상품 | NICE `adult_19` 증거 없이 상세·구매·결과 미디어에 접근시키지 않는다. PG 인증은 연령보증이 아니다 |
| **저작권/라이선스** | IP·굿즈·아트워크 | 공식 라이선스 범위 내 사용, 침해 신고 대응 |

## 8. 비기능 요구사항

- **무결성**: 카드 발급·티켓 재고·주문·실물 경품 배정은 동시성에서도 **원자적**이어야 한다(중복 발급·이중 차감·초과 판매 금지). → Postgres RPC + 행 잠금([아키텍처](./ARCHITECTURE.md) 참조).
- **결제 신뢰성**: callback body와 클라이언트 성공 신호는 입력일 뿐이다. 서버가 provider 결과를 재검증하고 멱등 DB finalizer가 성공한 경우에만 확정한다.
- **보안**: 사용자 데이터는 Supabase **RLS**로 소유자 범위 격리. 카탈로그는 공개 읽기. 관리자 작업은 역할+감사 로그.
- **성능**: 공개 카탈로그는 캐시 가능(SSR/정적). LCP 목표 양호 수준, 이미지 최적화.
- **가용성/관측성**: 결제·카드 발급·티켓 트랜잭션 로깅, 실패 알림.
- **접근성/반응형**: 모바일 우선(가로 탭 GNB·하단 탭 바·바텀시트), 데스크톱 3단 헤더. 한국어 기본.
- **디자인 일관성**: 공개 표면은 "White Catalog"(ADR-0011, 루트 `DESIGN.md`·`app/styles/wc-*.css`). 어드민은 2026-09 운영 콘솔 재설계([ADR-0014](./adr/0014-admin-console-redesign.md))로 White Catalog에 편입하며, 미전환 화면만 기존 콘솔 어휘(`app/styles/editorial-*`의 라이트 콘솔 + `app/globals.css`의 Holographic Midnight 유산 밑층)를 유지한다.

## 9. 출시 단계

범위는 v1로 동일하되, **위험도·의존성 순**으로 단계 출시한다.

| 단계 | 내용 | 트랜잭션 |
|---|---|---|
| **P0 — 기반** | Supabase Auth·DB·RLS, 카탈로그 브라우징(IP/굿즈/카드/이벤트), IP 팔로우, 커뮤니티(작성형), 검색, `/admin` 골격 | 비결제 |

## 11. 미해결 사항 / 가정

- **14+ 가입 기준**: 공통 `AgeAssurance` 계약, 기존 계정 dry-run과 법정 문서는 #188 acceptance evidence가 필요하다. 현재 자가신고는 완료 증거가 아니다.
- **19+ 성인인증**: NICE 계약·callback·최소 데이터는 #209, 실제 상품 gate는 #210에서 별도 추적한다.
- 카드의 **디지털 자산 성격**(소유 이전 가능 여부)은 v1에서 비이전(계정 귀속) 가정. 트레이드는 v2.
- provider-neutral 원장과 굿즈·티켓 checkout seam 위에 **토스 어댑터가 기본**으로 구현됐고, 코페이 어댑터는 판매 제한 상품 전용으로 남는다(ARCH §9, ADR-0013). 토스 gate 둘과 canary 둘은 닫혀 있어 실제 결제 경로는 심사 트랙(#394·#395) 전까지 열리지 않고, 2026-08-18 열어 둔 코페이 굿즈 gate 폐쇄(#385)가 실행 대기다. 라이브 첫날 테스트 키 시절의 `provider=toss` 원장 2건은 이력으로 보존한다. 이 상태는 2026-08-21 법정 본문 활성화나 #208의 코페이 취소·모호 승인 운영을 대신하지 않는다.
- **BM 확정(2026-07-03)**: 유료 가챠를 폐기하고 **무료 리워드 모델**로 피벗했다([`docs/adr/0003-free-reward-pivot.md`](./adr/0003-free-reward-pivot.md), 0001 superseded). §5.4의 유상 가챠·충전금·확률 공시·전자금융 항목은 이 결정으로 대체된다.
- 관련 산출물: 도메인 용어는 `CONTEXT.md`, 무료 카드 리워드는 [ADR-0003](./adr/0003-free-reward-pivot.md)·[ADR-0004](./adr/0004-draw-ticket-card-packs.md), 19+ 유한 실물 쿠지는 #212·#213이 각각 정본이다. [ADR-0002](./adr/0002-cross-platform-popup-game-miniapps.md)는 superseded 이력이며 현 로드맵의 구현 근거가 아니다.

- 여러 주문 합포장(2026-10-16): [합포장 계약](research/smartstore-admin/combined-packing.md)에 따라 동일 구매자·수취 주체·주소·출고지·포장/수금 조건의 발송 대기 배송 건을 묶는다. 원 주문/품목·결제/환불·선결제/착불 배송비를 유지하고, 출고 전 검증·전체 송장/도착 처리·창고 별도 안내를 적용한다.
