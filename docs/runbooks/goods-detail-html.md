# 굿즈 상세 HTML 운영

2026-09-11 승인된 Q12의 기본 문서 HTML 범위다. 기존 일반 텍스트는 `plain`으로 읽으며 태그처럼 생긴 문장도 글자로 유지한다.

## 입력과 확인

1. 상품 편집 → 이미지와 상세 설명 → 상세 설명 형식에서 `HTML 문서`를 선택한다. 형식을 바꾸어도 원문을 자동 변환하거나 지우지 않는다. `plain`으로 바꾸면 HTML 코드가 글자로 보인다.
2. 제목·문단·목록·표 버튼으로 코드를 넣거나 직접 입력한다. 제목(`h1`은 `h2`로 정리), `h2`~`h6`, 문단·줄바꿈·구분선, 강조·밑줄·취소선, 목록, 인용, 표·표 제목·표 머리글, 링크, 이미지·그림 설명을 지원한다. `colspan`·`rowspan`은 1~100이다. CSS·class·id·스크립트·이벤트·iframe·SVG·MathML·form은 지원하지 않는다.
3. 이미지는 **HTML 이미지 업로드**에서 JPEG·PNG·WebP를 검증 업로드한다. 대체 설명을 적고 **업로드한 이미지를 설명에 넣기**를 누른다. 본문에는 서로 다른 이미지 최대 20장을 넣는다. 외부 URL·data/blob URL·검증 경로가 없는 이미지는 표시되지 않는다. 원본 파일을 업로드해 다시 넣는다.
4. 제거 안내와 **공개 화면 미리보기**를 확인한다. 저장 서버와 공개 상세는 같은 문서 허용목록과 렌더러를 쓰므로 미리보기의 정리된 결과가 저장·공개된다. 표는 자체 가로 스크롤, 이미지와 긴 문장은 본문 폭을 따른다.
5. 초안으로 저장하고 다시 열어 확인한 뒤 기존 공개 절차를 진행한다. 일반 텍스트 상한은 2,000자, HTML은 입력과 정리된 코드 모두 30,000자다. 저장 실패 시 정리 전 원문·형식·업로드 경로·대체 설명을 복구한다. 브라우저의 미저장 입력 복구에도 같은 값이 포함된다. 파일 자체는 복구되지 않는다.

## 저장·검증 계약

- `goods.description_format`은 `plain|html`, `description`은 일반 텍스트 또는 정리된 HTML, `description_image_paths`는 HTML에 사용된 검증 이미지 경로다. HTML 이미지 `src`는 환경 독립적인 `public-media/catalog/good/<uuid>.jpg|png|webp` 형식으로 저장한다. 렌더 시 현재 프로젝트의 공개 Storage URL로 바꾼다.
- 서버 저장·엑셀 검증·미리보기·공개 렌더는 [`sanitize-html`](https://github.com/apostrophecms/apostrophe/tree/main/packages/sanitize-html)의 동일한 허용목록을 사용한다. 커스텀 HTML 파서를 만들지 않는다. 링크는 HTTP(S), `mailto`, `tel`, 사이트 내부 `/경로`만 허용하고 제어문자·인증정보·프로토콜 생략 주소는 제거한다.
- DB는 staff 재검사·형식·길이·이미지 목록·감사를 강제한다. 새 이미지 경로는 현재 운영자의 유효한 검증 upload claim을 같은 트랜잭션에서 소비한다. 해당 상품에 이미 붙은 경로는 다시 소비하지 않고 대표·갤러리·HTML 사이에 옮길 수 있다. 다른 상품의 경로를 임의로 재사용할 수 없다.
- 같은 저장에서 이전 이미지 칸을 비우며 HTML로 옮겨도, 잠근 상품의 저장 시작 시점 경로를 최종 HTML 쓰기까지 트랜잭션 한정으로 유지한다. 이 권한은 현재 상품·운영자에만 결속하고 HTML 쓰기 직후 삭제하며, 실패하면 앞선 메타데이터 수정과 함께 롤백한다. 상품 복사·카테고리 지정과 동일하게 카테고리 트리 → 상품 순서로 잠근다.
- DB RPC를 직접 호출해 원시 HTML을 넣어도 공개 렌더가 다시 정제한다. `description_image_paths` 밖의 이미지는 공개되지 않는다. DB가 HTML을 파싱한다는 계약은 없다.
- 상품 복사는 HTML·형식·검증 이미지 경로를 복사한다. 기존의 잠긴 원본과 트랜잭션 한정 이미지 복사 허가를 사용하며 별도 정체성·초안·재고 0·KC 미검토 계약을 보존한다. 원본 설명·이미지·주문은 바뀌지 않는다.
- 일반 텍스트의 2,000자 제한은 기존 편집기 규칙이다. 과거 DB에 더 길게 저장된 일반 텍스트에는 새 길이 제약을 소급하지 않으며 상품 복사도 원문을 보존한다.
- `admin.good.description_saved` 감사 기록에 원문·형식·이미지 경로의 전후가 남는다. 공개/초안 전환과 관련된 기존 권한·KC·게시 검증은 유지된다.

## 엑셀

상품 파일은 **v3**다. 마지막 `상세 설명 형식` 열은 `plain` 또는 `html`이고 `상품 설명` 열은 그 형식의 원문이다. 새 양식을 내려받으며 기존 옵션·고시·식별자 열 순서는 유지한다. 무수정 파일은 변경 없음이고, 다른 항목만 수정해도 HTML 형식과 코드·이미지 경로를 보존한다. HTML은 30,000자 상한으로 Excel 셀 32,767자 한도를 넘지 않는다.

HTML·일반 텍스트의 줄바꿈은 XLSX를 거치며 CRLF에서 LF로 바뀔 수 있다. 가져오기 비교는 줄바꿈 표기만 같은 것으로 보고 DB 원문을 다시 쓰지 않는다. 공란·문자 `0`·공백·문구·키워드·이미지 경로의 실제 변경은 계속 수정으로 구분한다.

HTML 안의 외부 이미지 URL과 ZIP 파일명은 자동으로 가져오지 않는다. 상품을 초안으로 만들고 편집기에서 검증 업로드한 뒤 다시 내보낸다. 대표·갤러리·기존 상세 이미지의 URL/ZIP 가져오기는 기존 경로를 사용한다. HTML 이미지가 다른 상품에 필요하면 상품 복사 기능을 사용한다.

## 검증 경계

- `app/admin/actions.test.ts`: 정제된 서버 payload, 길이 증가 검증, 실패 후 원문 복구.
- `components/screens/GoodDetail.test.tsx`: 허용 문서·이미지, 실행 요소·유해 URL 제거, 미리보기와 공개 동일성, 일반 텍스트 호환.
- `components/admin/sections/GoodSection.test.tsx`: 입력·형식·업로드 복구와 제거 사유/미리보기.
- `lib/admin/goods-workbook*.test.ts`: 실제 XLSX 및 무수정/수정 왕복.
- `supabase/tests/goods_detail_html.sql`: 같은 트랜잭션의 저장·검증 claim·상품 복사·권한·감사·롤백. 운영 DB에서 실행하지 않는다.
- `supabase/tests/goods_detail_html_concurrency.sh`: 명시한 격리 컨테이너/DB에서 실제 HTML 저장과 상품 복사·카테고리 지정의 동시 실행을 검증한다. 앞선 트리 잠금에 후속 저장이 대기한 것을 확인한 뒤 진행하며, 두 작업의 결과와 임시 이미지 권한 정리를 확인한다. 합성 fixture만 만들고 정리하며 운영 DB에서 실행하지 않는다.

브라우저 인수에서는 320/390/1440px에서 긴 표·긴 링크·세로 이미지의 폭과 실제 이미지 로드를 확인하고, 형식 전환·저장 실패 복구·초안 재열기·공개 상세를 직접 비교한다.
