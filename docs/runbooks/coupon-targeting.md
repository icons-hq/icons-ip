# 쿠폰 고객·상품 대상 운영

쿠폰 콘솔에서 **발급·사용 대상 고객**과 **할인 대상 상품**을 따로 설정한다. 고객은 전체·첫구매·재구매 또는 고객지정을 고르고, 상품은 전체·선택한 상품·선택한 카테고리로 지정한다. 선택 상품은 상품명·상품코드로 검색하고 페이지를 이동하면서 최대 1,000개까지 담는다. 수정 화면은 저장된 선택을 복원하고 이미 보관된 상품도 식별해 보여준다. 기존 선택에 없는 보관 상품을 새 대상으로 추가하지 않는다.

선택 상품 목록이 비어 있어도 보관 상태로 저장할 수 있다. 활성화할 때는 유효한 대상을 먼저 검증하고 대상과 상태를 같은 트랜잭션에서 바꾼다. 현재 쿠폰 DB 상태는 활성·보관이며, 폼의 초안은 오류 발생 시 입력을 복구하는 값이다. 별도 활성 쿠폰을 만들지 않고도 빈 선택을 입력 상태에 보존할 수 있다.

고객지정 쿠폰은 저장 후 고객·세그먼트를 선택하고 발급 확인을 확정해야 쿠폰함에 들어간다. 코드 입력으로 새로 발급하지 않으며, 이미 발급받은 고객의 코드 재조회는 기존 쿠폰을 반환한다. 한 장이라도 발급한 뒤에는 코드형/고객지정 발급 방식을 바꿀 수 없고 고객지정은 등급 자동 발급과 함께 설정하지 않는다. 일반 코드형 쿠폰도 운영자가 직접 지정 발급할 수 있다.

카테고리는 최대 100개를 선택하며 대표·추가 분류와 하위 분류의 현재 상품을 포함한다. 혜택 등록 뒤 새로 등록하거나 해당 분류로 이동한 상품도 적용되고, 보관한 분류 또는 보관한 상위 분류의 상품은 제외한다. 다른 분류로 이동하면 대상에서 벗어난다. 카테고리 변경과 주문 확정이 겹치면 재견적을 요구하며 완료 주문의 할인 근거는 보존한다.

발급 자격과 할인 가능 여부는 다르다. 일반 코드형 쿠폰은 자격이 있는 고객이 장바구니에 대상 상품이 없어도 코드를 등록할 수 있다. 실제 장바구니·주문서에서는 대상 상품이 없거나 최소금액에 미달하면 이유를 표시하고 할인을 적용하지 않는다. 최소금액과 할인 기준은 **선택 대상 상품의 기간·복수구매 할인 후, 쿠폰 할인 전 소계**다. 대상 밖 상품과 배송비는 그 소계에 포함하지 않는다.

첫구매는 유효한 굿즈 결제 이력이 없는 고객, 재구매는 그 이력이 있는 고객이다. 유효한 이력은 결제 완료 이후의 유효 주문에 해당 주문 금액과 일치하는 `paid` 결제 원장이 있는 상태다. 미입금 주문·결제 시도만 있는 주문·티켓 주문은 굿즈 구매 이력으로 보지 않는다. 모든 기존 굿즈 결제가 전액 취소·환불 완료되어 유효한 결제가 없어지면 첫구매 자격이 회복된다. 쿠폰의 유효기간·발급 한도·기존 보유 여부는 별도로 적용된다.

첫구매 쿠폰으로 주문을 만들 때 다른 미결제 주문이 있으면 먼저 완료하거나 취소하도록 안내한다. 첫구매 혜택이 포함된 주문이 진행 중이면 다른 신규 유상 주문도 대기시킨다. 고객별 잠금과 예약 원장으로 동시에 두 첫구매 주문을 만드는 일을 막는다. 결제 완료 시 예약을 소비하고 주문이 취소·만료로 `canceled`에 도달하면 해제한다. 결과가 모호하거나 재시도 가능한 결제 실패만으로는 예약을 풀지 않는다. 재시도는 기존 주문의 쿠폰·금액을 유지한다.

코드 등록, 운영자 발급, 등급 쿠폰 발급, 장바구니 견적, 주문 생성은 같은 고객 자격을 다시 확인한다. 등급 쿠폰도 대상 고객 조건을 충족해야 발급된다. 일반 주문서의 중복 사용은 **스토어 정책과 선택 쿠폰 모두의 중복 허용**을 요구한다. 기본은 꺼짐이며 상품 쿠폰 최대 1~5장·배송비 쿠폰 1장을 설정한다. 발급 후 상품/배송비 할인 구분·중복 허용·발급 방식은 바꿀 수 없다. 상품 할인 → 선택한 상품 쿠폰 순서 → 배송비 쿠폰 → 남은 상품금액의 적립금 순서로 계산한다. 배송비 쿠폰은 대상 상품이 포함된 이행 묶음의 선결제 운송비에만 적용하고 설치비·착불은 제외한다. 기존 최소 유상 결제금액도 보존한다.

주문을 만들면 당시 쿠폰 조건과 대상 상품·대상 소계·실제 할인액을 사용 원장에 보존한다. 운영자가 쿠폰을 나중에 수정해도 이미 만들어진 주문과 거래확정 엑셀의 과거 할인 근거를 바꾸지 않는다. 쿠폰 수정은 조건 버전을 비교하므로 다른 운영자가 먼저 바꾸면 최신 목록을 다시 확인한 뒤 저장한다. 정의 변경과 주문 생성은 같은 쿠폰 행 잠금에 직렬화된다.

새 일반 주문서는 화면에서 선택한 쿠폰 배열과 순서를 별도 견적에 보존한다. 이전 단일 쿠폰 주문서는 카트 선택을 비교해 다른 탭에서 바꾸거나 해제하면 재확인을 요구한다. 새 견적도 쿠폰 조건과 스토어 정책이 바뀌면 주문·재고·적립금 사용 전에 재확인을 요구한다. 같은 주문 요청을 재시도할 때는 이미 비워진 장바구니 대신 최초 주문의 쿠폰 기록과 비교한다. 쿠폰을 사용하지 않은 주문의 `null`도 명시적인 선택으로 보존한다.

대상 설정 저장과 변경 전후 값은 감사 로그에 남는다. 비운영자는 대상 상품 검색·쿠폰 설정 변경을 사용할 수 없고, 고객별 첫구매 예약 원장은 공개되지 않는다. 쿠폰 폼의 오류가 발생하면 입력한 고객·상품 대상도 함께 복구된다. 쿠폰은 별도 운영 항목이므로 상품 엑셀·상품 등록 초안에 쿠폰 조건을 추가하지 않는다. 결제 완료·취소 원장의 이전 기록을 현재 고객 등급이나 카탈로그 값으로 수정하지 않는다.

검증은 `supabase/tests/coupon_targeting.sql`과 `coupon_targeting_concurrency.sh`에서 자격·대상·전액 환불 후 회복·동시 최초 주문·조건 변경 시 과거 보존·권한을 확인한다. `coupon_targeting_restore.sql`은 빈 선택 보관 후 활성 복원을, `checkout_coupon_expectation.sql`은 다른 탭의 선택 변경·해제와 최초 주문 기준 재시도를 검증한다. 동시성 스크립트는 작업 소유의 폐기 가능한 DB를 명시해야 실행되며 기존 fixture 식별자가 있으면 덮어쓰지 않는다. 적립금의 지급·사용·복원은 [적립금 운영 절차](./store-credits.md), 품목별 할인 배분과 미기록 처리는 [거래확정 엑셀](./settled-export.md)을 따른다.

중복·배송비 할인 및 실제 SQL/HTTP 경합 검증은 [쿠폰 조합 계약](../research/smartstore-admin/coupon-combinations.md)을 따른다. 선물·정기배송의 기존 단일 상품 쿠폰 계약은 유지한다.

카테고리·고객지정 등록 흐름, 주문/환불·잠금 경합과 실제 화면 근거는 [카테고리 쿠폰 계약](../research/smartstore-admin/coupon-category-targeting.md)을 따른다.
