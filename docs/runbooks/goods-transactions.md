# 굿즈 할인·배송 금액과 착불 기록

2026-10-14 구현 기준. 공통 거래 계산·견적·주문과 착불 기록은 격리 로컬 DB에서 검증했다. 실제 PG·운송사 계약, 운영 환경 활성화와 배포는 별도 승인 범위다. 로컬 합성 주문의 성공을 실거래 수납 증거로 사용하지 않는다.

## 주문 금액

상품별 기간할인 단가에 수량을 곱한 합계를 S, 복수구매 할인을 V, 선결제 배송비를 H, 쿠폰을 C, 적립금을 R, 착불 별도 지급을 D로 구분한다. 온라인 결제금액은 `T = S − V + H − C − R`이며 D를 포함하지 않는다. 고객이 부담할 합계는 T + D다.

- 복수구매 할인은 같은 상품의 옵션·직접입력 행을 합쳐 조건을 판정한다. 다른 상품과 추가상품은 각각 판정한다. 금액 조건은 옵션 정상가 합계이며, 할인액은 기간할인 단가에 적용한다.
- 쿠폰과 적립금은 복수구매 할인 후 상품금액을 기준으로 한다. 착불은 쿠폰·적립금 적용 대상이나 온라인 결제액에 포함하지 않는다.
- 무료배송 기준은 기간할인 후·복수구매 할인 전인 S를 사용한다. 복수구매 할인을 받았다는 이유로 기존 무료배송 기준을 잃지 않는다.
- 수량별 배송비는 같은 상품의 옵션·직접입력 수량을 합쳐 계산한다. 같은 상품을 여러 행으로 나눠도 운임은 달라지지 않는다.
- 주소가 없거나 추가료 적용 여부를 확정할 수 없으면 최종 결제금액을 0원 배송비로 확정하지 않는다. 공개 상세의 주소 없는 금액은 기본 운임 안내이며 주문 주소의 최종 견적이 아니다.

견적은 주문 선택·주소·운임 선택·쿠폰·적립금·정책 버전에 결속한다. 만료되거나 조건이 달라지면 새 견적을 확인해야 한다. 결제 최소금액보다 낮아지는 할인은 임의 축소하지 않고 결제를 차단한다. 성공한 주문의 같은 요청 재확인은 견적 만료 후에도 원래 주문을 돌려준다.

새 거래 모드의 장바구니에서는 현재 가격·재고·구매한도·공통 결제수단을 확인한 뒤 주문서로 이동한다. 확인에 실패하면 `가격·구매 조건 다시 확인`으로 재조회한다. 이 단계의 상품금액은 복수구매 할인 전 금액이며 배송비·쿠폰·최종 결제액은 주문서에서 확인한다. 배송비 묶음그룹에 배정된 상품도 같은 흐름을 사용하고, 장바구니 조회만으로 주문이나 재고 예약을 만들지 않는다. 카드 주문은 결제가 확정될 때까지 장바구니를 그대로 남기고(무통장은 접수 시 뺀다), 같은 장바구니로 다시 주문하거나 장바구니·주문서로 돌아오면 결제를 마치지 않은 이전 주문을 자동으로 닫는다([ADR-0026](../adr/0026-cart-retained-until-payment.md)).

배송비 묶음그룹은 같은 주문·출고지의 원상품을 명시적으로 배정해 사용한다. 최소 또는 최대 운임 중 선택한 방식으로 계산하며 유효한 무료배송 조건을 우선한다. 지역 추가료는 출고지 정책을 상속하거나 그룹에 지정한 주소 구간표로 한 번 계산한다. 기본 그룹을 바꿔도 기존 상품은 자동으로 이동하지 않는다. 그룹상품의 별도 상품은 원상품의 배정을 따르며, 변경은 원상품에서 수행한다. 이미 확정한 주문의 배송비는 이후 그룹 변경으로 바뀌지 않는다.

## 배송정보 템플릿으로 정책 복사

배송정보 템플릿의 확장 배송 정책은 **기존 정책 유지**가 기본이다. 기존 템플릿도 같은 의미로 읽는다. **템플릿 정책 복사**를 선택하면 반복 수량·2/3구간 요금과 선결제·착불·구매자 선택을 저장하고, 적용할 상품마다 기존 정책 저장기로 새 버전을 만든다. 비활성 정책을 복사하면 적용 후에도 해당 정책은 비활성이다. 템플릿 수정만으로 이미 적용한 상품이 바뀌지는 않는다.

적용 전 상품별 기본 설정과 실제 적용될 확장 배송 정책을 모두 확인한다. 무료배송 기본값을 선택해도 기존 활성 수량 정책을 유지하면 그 정책이 계산에 사용된다. 그룹상품의 별도 상품은 원상품 링크로 이동해 변경하며, 원상품에서는 정책을 공유하는 합산 상품 수를 함께 확인한다. 원상품을 선택해도 선택하지 않은 가족의 기본 설정을 일괄 변경하지 않는다.

최대 100개 상품의 템플릿·상품·정책·출고지·수납 계약 버전과 합산 구성이 미리보기 때와 같아야 적용된다. 한 상품이라도 충돌하거나 착불 수납 계약이 준비되지 않으면 전체 미적용이다. 활성 정책을 새로 적용하는 경우 기존 거래 런타임 활성화 조건도 충족해야 한다. 화면에서 실패 원인을 해결하고 미리보기를 다시 확인한다. 템플릿 적용으로 런타임이나 수납 계약을 켜지 않는다.

저장·적용 응답이 끊기면 같은 요청 결과부터 확인한다. 원래 입력이 화면에 남아 있으면 같은 요청과 입력으로 재시도하며, 새로고침 후 원문이 없으면 요청 결과 조회와 종료를 거쳐 새 요청을 시작한다. 미확정 결과만 보고 새 번호로 반복하지 않는다. 계정·로그인 세션이 달라지면 이전 요청을 이어서 처리할 수 없다.

복수구매 할인, 과거 배송 정책 버전, 기존 주문의 품목·금액·주소는 바뀌지 않는다. 2026-10-14 템플릿 연결은 소유 격리 clone 검증과 승인된 로컬 named DB 적용을 마쳤다. 실제 브라우저 검증과 운영 배포 여부는 [대응표](../research/smartstore-admin/shipping-template-parity.md)를 따른다.

## 착불 활성화와 증빙

출고지의 실제 수납 주체·수납 방식·반환 연락처·고객 안내·계약 근거·출고 인계 방식이 있어야 착불 조건을 활성화한다. 예시값이나 테스트 값을 운영 계약으로 대신하지 않는다. 같은 물리 배송 건의 기본 운임과 지역 추가료를 상품별로 배분한 뒤 선결제/착불로 나누며, 나눴다는 이유로 운임을 중복 부과하지 않는다.

관리자의 주문 상세에서 착불 기록을 확인한다. 금액·실제 발생 시각·수납/반환 주체·외부 증빙 참조를 확인하고 다음 상태를 기록한다.

- **예정**: 주문에 보존된 D다. 실제 수납 완료를 뜻하지 않는다.
- **수납 완료**: D 전액의 수납 증빙이 확인됐다.
- **수납 취소**: 수납 전 의무를 취소했다.
- **반환 확인 필요**: 취소·반품 후 외부 수납/반환 여부를 확인해야 한다.
- **반환 완료**: D 전액의 외부 반환 증빙이 확인됐다.
- **금액 불일치**: 증빙 금액이 예정 금액과 다르다. 온라인 결제금액을 임의 변경하지 않는다.

배송완료·거래확정이나 카드 환불만으로 착불을 수납/반환 완료로 표시하지 않는다. 기록을 잘못 입력했다면 마지막 기록에 대한 정정과 근거를 추가한다. 과거 증빙을 삭제하거나 덮어쓰지 않는다. 이미 취소된 주문은 정정 후에도 필요한 외부 반환 검토를 유지한다.

저장 응답이 끊기면 같은 요청의 기록을 먼저 조회한다. 화면을 새로 열어 원래 입력을 잃었다면 먼저 기존 요청의 결과를 확인하거나 종료한 뒤 최신 상태를 확인하고 새 기록을 작성한다. 결과가 불명확한 요청을 새 번호로 반복하지 않는다.

## 취소·환급·내보내기

전체 취소·반품의 PG 환급액은 온라인 결제금액 T다. 쿠폰·적립금 복구와 재고 처리는 기존 멱등 원장에 따르며, D의 반환은 착불 증빙에서 별도로 처리한다. 안내용 반품 배송비를 PG 환급액에서 자동 차감하지 않는다. 부분취소·부분반품은 이번 범위에 포함하지 않는다.

주문·거래확정 파일은 복수구매 할인, 선결제 배송비, 착불 별도 지급과 수납 상태를 구별한다. [거래확정 엑셀](settled-export.md)은 주문 시점의 품목별 배분을 보존하며 과거 정책으로 다시 계산하지 않는다. 상품 순위 금액은 기간·복수구매 할인 후, 쿠폰·적립금·배송비 전이다. 실제 결제 매출과 PG 정산에는 D를 더하지 않는다. [PG 정산 조회](pg-settlement-reconciliation.md)는 정기결제와 일반 결제의 저장된 계정을 구별한다.

## 계정 탈퇴와 기록 보존

진행 중인 선물·정기배송·카드 해지·착불 확인은 탈퇴 화면에서 별도 사유와 이동 경로를 표시한다. 탈퇴 요청의 쓰기 차단이 확정된 뒤 별도 처리에서 미확정 견적·종료된 정기배송의 주소와 직접입력 데이터를 정리한다. 카드 해지를 실제 완료하기 전에 성공으로 간주하지 않는다.

주문 금액·할인 배분·착불 상태의 비개인 증거와 정기배송의 수락한 계약 버전·주기·금액·최초/재동의 이력은 기존 보존 원장에 남긴다. 정기배송 결제·환급의 불변 연동 정보도 유지해 원본 주소나 카드 암호문 없이 과거 거래를 조회·환급할 수 있다. 현재 단계는 탈퇴 요청 차단과 보존·개인정보 정리이며 Auth 계정의 물리 삭제 완료를 의미하지 않는다.

## 검증 경계

공통 계산·1,001개 직접입력 행·2 MiB 차단·견적 만료·동일 요청 경합·계정 정지 경합·기존 쿠폰/적립금/예약 주문 회귀는 `supabase/tests/goods_transaction_isolated.sh`의 매번 새 disposable clone에서 검증한다. 원본 로컬 DB는 dump와 readback만 수행하고 reset하지 않는다. 착불 금액·기록 재시도·정정, 실제 정기배송 결제 후 계약 보존과 개인정보 정리, 일반/정기 PG 계정 분리도 같은 방식으로 확인한다. 실제 PG나 운송사 수납 API를 호출하는 시험은 포함하지 않는다.
