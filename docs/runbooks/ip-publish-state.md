# IP 게시 상태 운영 절차

정본: [#410](https://github.com/icons-hq/icons-ip/issues/410), [#437](https://github.com/icons-hq/icons-ip/issues/437), [ADR-0014](../adr/0014-admin-console-redesign.md).

## 저장과 전환

- 신규 IP는 이름·공개 URL·버티컬을 입력해 초안으로 저장한다. 내부 ID는 `admin_create_ip`가 공개 URL로 발급하고(겹치면 `-2`·`-3`) 이후 바꾸지 않는다. 등록 화면은 저장 뒤 그 IP 상세로 옮겨 발급된 내부 ID를 알린다([ADR-0039](../adr/0039-ip-internal-id-and-draft-delete.md)). 초안에도 상품·카드·카드풀·이벤트를 연결할 수 있다.
- 검증·저장 실패는 제출 문자열과 업로드한 `imagePath`를 반환한다. 실패 회차나 저장 필드가 바뀔 때 폼을 다시 구성하며, 공개·보관 시각만 바뀌면 미저장 입력을 유지한다.
- 공개 IP의 일반 저장은 게시 상태를 유지한다. 초안 전환은 영향 확인 체크 후 실행하며 액션도 체크 값을 검사한다.
- 초안 IP와 하위 카탈로그는 공개 목록·검색에서 제외된다. 이미 담긴 상품은 장바구니에 판매 종료로 남으며, 미리 열어둔 주문·예매 화면에서도 새 주문을 만들 수 없다. 연결된 이벤트 상세는 404다. 기존 주문·보유 카드·팔로우·커뮤니티 이력의 읽기는 유지한다.
- `place_order`와 `reserve_tickets`는 신규 생성 시 상품·이벤트의 부모 IP를 공유 잠금하고 공개·미보관 상태를 검사한다. 초안 전환과 경합하면 먼저 잠근 거래가 끝날 때까지 다른 쪽이 기다린다. 생성된 주문·예매의 동일 키 재시도와 기존 결제 시도의 준비·확정·정합화·환불은 계속 처리하며, IP 상태로 주문 스냅샷이나 재고 선점 이력을 다시 쓰지 않는다.
- 공개 검색은 IP 게시·보관 조건과 상품 판매 제한 조건을 함께 적용한다. 공개 IP에 속하더라도 판매 제한 상품은 검색 결과에서 제외된다.
- 보관은 기존 자식·운영·큐레이션 참조 가드를 그대로 검사하며 공개 시각을 비운다. 복원은 항상 초안이고, 재노출에는 별도의 공개 전환이 필요하다. 전환은 행 잠금 안에서 감사되며 같은 상태로의 재호출은 추가 감사를 만들지 않는다.

## 미사용 초안 삭제

- 대상은 지금 초안이고, 공개된 적이 없고(`private.ip_public_history`), 연결된 항목이 0건인 IP뿐이다. 연결은 IP를 가리키는 모든 FK와 쿠폰 대상 IP·주문 품목 IP 스냅샷·IP 페이지로 가는 홈 전시 링크를 센다. 게시 상태 seam(2026-09-09) 전에 만든 IP는 저장 즉시 공개됐으므로 공개 이력이 있는 것으로 본다.
- IP 상세 기본정보 탭의 초안에 '미사용 초안 삭제' 패널이 근거(공개 이력·연결 종류별 건수)를 보인다. 막히면 이유를, 지울 수 있으면 확인창에 같은 근거를 다시 보인다. 버튼은 legacy admin·`platform.manage`만 누를 수 있고 DB가 다시 판정한다.
- 삭제는 행 스냅샷·이전 URL·판단 근거를 `catalog.ip.deleted`로 감사하고 내부 ID를 퇴역시킨다. 같은 공개 URL로 다시 등록하면 내부 ID에 `-2`가 붙는다. 보관된 초안은 복원해 초안으로 돌린 뒤 지운다.

## 검증

`supabase/tests/ip_publish_state.sql`은 백필·권한·초안 검색 제외·공개/초안 감사·보관/복원 초안 계약을 검증한다. `ip_draft_delete.sql`은 내부 ID 발급(퇴역 ID 건너뛰기·이름 공간 충돌 거절), 공개 이력 기록, 삭제 권한·근거·감사·멱등과 막히는 경우(연결 상품·홈 전시 링크·쿠폰·팔로우·공개했던 초안·공개·보관)를 검증한다. `catalog_archiving.sql`은 공개 상태의 IP·상품·카드가 보관 전에 검색되는 양성 대조 후 보관 제외를 검사한다. `search_catalog_visibility.sql`은 공개 IP의 제한 상품과 초안 IP의 일반 상품이 모두 검색에서 제외되는지 확인한다.

`ip_purchase_publish_guard.sql`은 오래 열린 화면의 신규 주문·예매 차단, 실패 시 재고·장바구니 원복, 플랫폼 이벤트 예매, 기존 주문 재시도·결제 시도 보존을 검증한다. `ip_purchase_publish_concurrency.sh`는 상품·티켓 각각에서 초안 전환 선행과 구매 선행 두 순서의 실제 잠금 대기·커밋 결과를 확인한다. CI는 기존 Supabase 컨테이너를 사용하며, 격리 로컬 DB는 `PSQL_BIN`과 `PGHOST`·`PGPORT`·`PGUSER`·`PGPASSWORD`로 명시한다.

폼 키·입력 복구·확인 UI·서버 액션·공개 카탈로그·캠페인 상품·게임 보상 IP·온보딩 추천 검증은 해당 Vitest 테스트로 확인한다. S2 이미지 업로드 실패와 운영팀 스테이징 리허설은 별도의 실제 브라우저 수행 기록이 필요하다.

## 현재 읽기 경계와 후속 RLS 이슈

이 변경은 공개 앱 로더와 `search_public_content`에서 초안을 제외한다. `ips_read`의 `using (true)`와 기존 공개 카탈로그 SELECT 정책을 유지하므로 **anon REST 직접 조회는 초안 IP 및 하위 카탈로그를 읽을 수 있다**. 초안은 공개 시점 준비 상태이며 비밀자료 보관 수단이 아니다. 앱 필터 통과를 DB 접근 통제 완료로 기록하지 않는다.

후속 이슈: [#451 — 초안·보관 카탈로그의 Data API 읽기를 제한하고 보유 이력 읽기를 분리한다](https://github.com/icons-hq/icons-ip/issues/451).

- anon과 일반 authenticated의 직접 `ips`·하위 카탈로그 SELECT는 공개 상태만 허용한다. staff는 현재 어드민 읽기를 유지한다.
- 주문·바인더·카드팩·팔로우·커뮤니티 이력이 비공개 카탈로그에도 의존하는 호출처를 먼저 조사하고, 소유자 범위의 전용 RPC/뷰 또는 기존 스냅샷으로 옮긴다.
- 공개 검색·캠페인·게임·홈·상품 상세와 직접 REST 조회를 모두 검증하고, 소유자 이력 열람과 운영자 초안 편집을 회귀 검증한다.
- 익명·일반 회원·소유자·staff·service role의 allow/deny, 함수 EXECUTE 봉인, 동시 게시 전환을 SQL 스모크에서 확인한다.
- RLS 강화는 #437 범위 밖이므로 이 슬라이스에서 기존 공개 SELECT 정책을 변경하지 않는다. #451 발행은 #410 리뷰 ⑥의 추적 요구를 충족하며, DB 읽기 통제 구현 완료를 뜻하지 않는다.

공식 참조: [Supabase RLS의 grants와 policies](https://supabase.com/docs/guides/database/postgres/row-level-security), [함수 권한과 보안 경계](https://supabase.com/docs/guides/database/functions).
