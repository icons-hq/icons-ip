# IP 게시 상태 운영 절차

정본: [#410](https://github.com/icons-hq/icons-ip/issues/410), [#437](https://github.com/icons-hq/icons-ip/issues/437), [ADR-0014](../adr/0014-admin-console-redesign.md).

## 저장과 전환

- 신규 IP는 이름·공개 URL·버티컬을 입력해 초안으로 저장한다. 내부 ID는 `admin_create_ip`가 공개 URL로 발급하고 이후 바꾸지 않는다. 다른 IP의 공개 URL·이전 URL·내부 ID와 같은 공개 URL은 등록할 수 없고, 지운 IP의 내부 ID(퇴역 ID)와 같은 주소면 내부 ID에 `-2`·`-3`이 붙는다. 등록 화면은 저장 뒤 그 IP 상세로 옮겨 발급된 내부 ID를 알린다([ADR-0039](../adr/0039-ip-internal-id-and-draft-delete.md)). 초안에도 상품·카드·카드풀·이벤트를 연결할 수 있다.
- 검증·저장 실패는 제출 문자열과 업로드한 `imagePath`를 반환한다. 실패 회차나 저장 필드가 바뀔 때 폼을 다시 구성하며, 공개·보관 시각만 바뀌면 미저장 입력을 유지한다.
- 공개 IP의 일반 저장은 게시 상태를 유지한다. 초안 전환은 영향 확인 체크 후 실행하며 액션도 체크 값을 검사한다.
- 초안 IP와 하위 카탈로그는 공개 목록·검색에서 제외된다. 이미 담긴 상품은 장바구니에 판매 종료로 남으며, 미리 열어둔 주문·예매 화면에서도 새 주문을 만들 수 없다. 연결된 이벤트 상세는 404다. 기존 주문·보유 카드·팔로우·커뮤니티 이력의 읽기는 유지한다.
- `place_order`와 `reserve_tickets`는 신규 생성 시 상품·이벤트의 부모 IP를 공유 잠금하고 공개·미보관 상태를 검사한다. 초안 전환과 경합하면 먼저 잠근 거래가 끝날 때까지 다른 쪽이 기다린다. 생성된 주문·예매의 동일 키 재시도와 기존 결제 시도의 준비·확정·정합화·환불은 계속 처리하며, IP 상태로 주문 스냅샷이나 재고 선점 이력을 다시 쓰지 않는다.
- 공개 검색은 IP 게시·보관 조건과 상품 판매 제한 조건을 함께 적용한다. 공개 IP에 속하더라도 판매 제한 상품은 검색 결과에서 제외된다.
- 보관은 기존 자식·운영·큐레이션 참조 가드를 그대로 검사하며 공개 시각을 비운다. 복원은 항상 초안이고, 재노출에는 별도의 공개 전환이 필요하다. 전환은 행 잠금 안에서 감사되며 같은 상태로의 재호출은 추가 감사를 만들지 않는다.

## 미사용 초안 삭제

- 대상은 지금 초안이고, 공개된 적이 없고(`private.ip_public_history`), 연결된 항목이 0건인 IP뿐이다. 누를 수 있는 사람은 통합 매니저·계정 주매니저(권한 전환 전에는 기존 관리자)다. 연결은 IP를 가리키는 모든 FK와 쿠폰 대상 IP·주문 품목 IP 스냅샷·IP 페이지로 가는 홈 전시 링크를 센다. 게시 상태 seam(2026-09-09) 전에 만든 IP는 저장 즉시 공개됐으므로 공개 이력이 있는 것으로 본다.
- IP 상세 기본정보 탭의 초안에 '미사용 초안 삭제' 패널이 근거(공개 이력·연결 종류별 건수)를 보인다. 막히면 이유를, 지울 수 있으면 확인창에 같은 근거를 다시 보인다. 버튼은 legacy admin·`platform.manage`만 누를 수 있고 DB가 다시 판정한다.
- 삭제는 행 스냅샷·이전 URL·판단 근거를 `catalog.ip.deleted`로 감사하고 내부 ID를 퇴역시킨다. 같은 공개 URL로 다시 등록하면 내부 ID에 `-2`가 붙는다. 보관된 초안은 복원해 초안으로 돌린 뒤 지운다.

## 검증

`supabase/tests/ip_publish_state.sql`은 백필·권한·초안 검색 제외·공개/초안 감사·보관/복원 초안 계약을 검증한다. `ip_draft_delete.sql`은 내부 ID 발급(퇴역 ID 건너뛰기·이름 공간 충돌 거절), 공개 이력 기록, 삭제 권한·근거·감사·멱등과 막히는 경우(연결 상품·홈 전시 링크·쿠폰·팔로우·공개했던 초안·공개·보관)를 검증한다. `catalog_archiving.sql`은 공개 상태의 IP·상품·카드가 보관 전에 검색되는 양성 대조 후 보관 제외를 검사한다. `search_catalog_visibility.sql`은 공개 IP의 제한 상품과 초안 IP의 일반 상품이 모두 검색에서 제외되는지 확인한다.

`ip_purchase_publish_guard.sql`은 오래 열린 화면의 신규 주문·예매 차단, 실패 시 재고·장바구니 원복, 플랫폼 이벤트 예매, 기존 주문 재시도·결제 시도 보존을 검증한다. `ip_purchase_publish_concurrency.sh`는 상품·티켓 각각에서 초안 전환 선행과 구매 선행 두 순서의 실제 잠금 대기·커밋 결과를 확인한다. CI는 기존 Supabase 컨테이너를 사용하며, 격리 로컬 DB는 `PSQL_BIN`과 `PGHOST`·`PGPORT`·`PGUSER`·`PGPASSWORD`로 명시한다.

폼 키·입력 복구·확인 UI·서버 액션·공개 카탈로그·캠페인 상품·게임 보상 IP·온보딩 추천 검증은 해당 Vitest 테스트로 확인한다. S2 이미지 업로드 실패와 운영팀 스테이징 리허설은 별도의 실제 브라우저 수행 기록이 필요하다.

## 현재 읽기 경계와 후속 RLS 이슈

공개 앱 로더와 `search_public_content`는 초안을 제외한다. DB 읽기 경계는 표마다 다르다.

- **굿즈·옵션(20261118160000):** 익명·회원의 `goods` 직접 SELECT는 게시·미보관·부모 IP 게시·미보관·판매 제한 판정 통과(19금은 유효한 성인 인증 본인) 행만 연다(`goods_public_read`). `goods_variants` 공개 읽기는 그 부모가 보이는 행만이다(정책 안의 goods 조회가 goods RLS를 그대로 거친다). `catalog.read` 운영자는 초안·보관·19금까지 읽는다(`goods_operator_read`) — `catalog.read`가 없는 물류 역할은 고객과 같다. anon REST로 초안·보관·19금 굿즈를 직접 읽을 수 없다.
- 공개가 아닌 굿즈를 읽어야 하는 고객 화면은 RLS를 우회하는 좁은 읽기로 옮겼다: 본인 주문 품목 줄의 썸네일·IP·19금 가림(`my_order_line_goods`, 본인 주문에 담긴 굿즈만), 인증 전 방문자의 19금 가림 카드(`get_masked_adult_goods`, 이름·이미지 없음), 선물 품목의 랜덤 판매 옵션 가림(`get_random_option_good_ids`, 로그인 회원 전용 — 넘긴 id 중 공개 상품이거나 본인이 보내거나 받은 선물·연 선물 초대 세션의 품목인 랜덤 판매 상품만 답한다). 주문·장바구니·찜·리뷰·선물·정기구매·클레임·알림·영수증 RPC는 security definer라 영향이 없다. 내 상품 문의 목록은 지금 볼 수 없는 굿즈(초안·보관, 성인 인증이 만료된 회원의 19금)의 이름을 '지금 볼 수 없는 굿즈'로 보인다(문의 행은 회원이 직접 쓸 수 있어 비공개 이름을 여는 근거로 쓰지 않는다).
- 같은 경계를 우회하던 공개 읽기도 닫았다: 계산 열 `goods_random_option`은 위조한 goods 행으로 RPC를 직접 불러도 게시되지 않은 상품에는 값을 주지 않는다(goods·옵션 행을 받는 다른 공개 계산 열은 이미 공개 판정 또는 `catalog.read`가 있다). `reward_policies`는 익명·회원에게 IP 단위 정책과 대상 상품이 그 세션에 보이는 정책만 열고(`reward_policies_public_read`), `catalog.read` 운영자는 전부 읽는다. 고객 화면은 이 표를 읽지 않는다.
- **아직 열린 것:** `ips`·`cards`·`events`의 `using (true)` 공개 SELECT는 그대로라 **anon REST는 초안 IP·카드·이벤트를 읽을 수 있다**. `reviews`·`product_questions` 공개 읽기(visible)도 부모 굿즈 공개와 묶지 않았다 — 묶음 상품 리뷰가 보관된 구성 상품의 리뷰 사진을 열람자 세션으로 서명하므로 별도 설계가 필요하다. `public-media` 버킷은 공개 버킷이라 경로를 아는 이미지는 직접 열린다. 초안은 공개 시점 준비 상태이며 비밀자료 보관 수단이 아니다.

후속 이슈: [#451 — 초안·보관 카탈로그의 Data API 읽기를 제한하고 보유 이력 읽기를 분리한다](https://github.com/icons-hq/icons-ip/issues/451). 굿즈 부분은 위 migration으로 닫았고 남은 범위는 IP·카드·이벤트다.

- anon과 일반 authenticated의 직접 `ips`·카드·이벤트 SELECT는 공개 상태만 허용한다. staff는 현재 어드민 읽기를 유지한다.
- 주문·바인더·카드팩·팔로우·커뮤니티 이력이 비공개 카탈로그에도 의존하는 호출처를 먼저 조사하고, 소유자 범위의 전용 RPC/뷰 또는 기존 스냅샷으로 옮긴다.
- 공개 검색·캠페인·게임·홈·상품 상세와 직접 REST 조회를 모두 검증하고, 소유자 이력 열람과 운영자 초안 편집을 회귀 검증한다.
- 익명·일반 회원·소유자·staff·service role의 allow/deny, 함수 EXECUTE 봉인, 동시 게시 전환을 SQL 스모크에서 확인한다. 굿즈 쪽은 `supabase/tests/goods_public_read_visibility.sql`이 익명·회원·인증 성인·물류 운영자·카탈로그 운영자의 직접 읽기, 세 읽기 RPC의 권한·범위, 위조 행으로 부른 계산 열, 뽑기권 발급 정책의 대상 노출을 확인한다.
