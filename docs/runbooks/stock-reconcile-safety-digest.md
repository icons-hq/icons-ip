# 재고 파일 대조·안전재고 요약 메일 운영

ERP·창고 재고와 사이트 할당 재고를 맞추는 수동 반입 경로(1007-009·1007-011)와, 안전재고 기준 이하 옵션을 하루 한 번 메일로 알리는 경로(QNA-014)다. ERP·WMS API 자동 연동은 하지 않는다 — 비용·계약이 정해지면 별도 ADR로 결정한다([ADR-0005](../adr/0005-icons-allocated-inventory.md) 2026-11-12 보완).

## 재고 파일 대조

`배송관리 → 재고 대조`(`/admin/catalog/stock-reconcile`, 권한 `catalog.manage` — 재고 조정과 같다).

### 파일이 뜻하는 수량

파일 수량은 **그 시각 창고에 있던 ICONS 판매용(할당) 실물**이다. 창고 전체 재고나 다른 채널 몫을 넣지 않는다(ADR-0005). 서원(남양주)은 이카운트의 ICONS 몫, 김포는 EMP의 ICONS 몫 재고를 내려받는다(내려받는 방법은 아래 사람 게이트).

사이트 재고수량은 주문을 받을 때 줄고 취소·환불·교환 재출고 때 돌아오지만, 창고 실물은 출고할 때 줄고 회수할 때 돌아온다. 그래서 그대로 넣지 않고 다음처럼 맞춘다.

```
지금 창고 실물   = 파일 수량 − 기준 시각 뒤 출고 + 기준 시각 뒤 회수
맞춘 뒤 재고수량 = max(지금 창고 실물 − 출고 대기 − 회수 뒤 미반영, 0)
차이            = 파일 수량 − (재고수량 + 출고 대기 + 회수 뒤 미반영 + 기준 시각 뒤 출고 − 기준 시각 뒤 회수)
```

- **출고 대기**: 재고를 이미 뺐지만 아직 창고를 떠나지 않았고 취소·환불로 복원되지 않은 주문 품목 수량. 결제 대기·결제 완료·발주확인 주문의 준비 상태 배송 건(배송 건이 아직 없는 선물 수락 전 주문 포함)이다. 취소 주문, 취소 배송 건, 디지털 파일, 실물을 배정하지 않은 예약 품목은 세지 않는다.
- **기준 시각 뒤 출고**: 파일의 재고 기준 시각 뒤에 배송중·배송완료가 된 수량과 그 뒤의 교환 재출고 수량(그룹상품 교환 재출고 포함, 출고지마다 재출고하면 그 출고지의 재출고 시각). 나중에 반품돼도 출고는 출고로 센다. 파일에는 아직 들어 있기 때문이다.
- **기준 시각 뒤 회수**: 기준 시각 뒤에 창고로 돌아온 수량. 출고지별로 회수하는 클레임은 출고지(배송 건)마다 그 입고 확인 시각으로, 그 밖의 클레임은 클레임의 회수 시각으로 센다. 회수 생략한 출고지의 상품은 창고로 돌아오지 않으므로 세지 않는다. 또 회수 기록 없이 환불·취소로 재고가 복원된 출고분은 복원 시각에 돌아온 것으로 본다. 파일에는 아직 없기 때문이다.
- **회수 뒤 미반영**: 회수했지만 아직 환불·교환 재출고(출고지별 교환은 그 출고지의 재출고) 전이라 재고수량에 돌아오지 않은 수량. 창고에는 있지만 팔 수 없다.
- **그룹상품 전환**(ADR-0022)으로 재고가 승계 옵션으로 옮겨 간 경우, 전환 전 옵션을 가리키는 주문·회수는 지금 재고를 가진 승계 옵션에 센다(취소·환불 복원과 같은 귀속).
- 주문 접수·취소·출고·회수·환불 복원·교환 재출고·예약 배정은 이 항들을 함께 움직여 **차이를 바꾸지 않는다**. 하지만 출고 대기 등이 바뀌면 **맞춘 뒤 재고수량은 바뀐다**(예: 미리보기 '10 → 7' 뒤 주문 1개 → 지금은 '9 → 6'). 그래서 반영 때는 차이와 맞춘 뒤 재고수량이 모두 미리보기와 같은지 다시 본다(아래 충돌·재시도, 2026-11-12 QA1 결정).
- 출고 대기와 회수 뒤 미반영이 지금 창고 실물보다 많으면 **부족**이다. 반영하면 재고수량을 0으로 두고 더 팔지 않는다. 이미 받은 주문은 창고가 보낼 수 없으므로 실재고를 확인해 고객 안내·취소(ADR-0018)를 검토한다.
- **재고 기준 시각은 7일 안**만 받는다. 기록으로 가를 수 없는 변경(아래 수동 조정)이 쌓이지 않게 최근 파일로 대조한다.

### 절차

1. ERP·창고에서 ICONS 몫 재고를 내려받고 그 시각을 적어 둔다.
2. 재고 대조 화면에서 창고(출고지)와 **파일의 재고 기준 시각**(한국 시간)을 고른다. 창고 한 곳의 파일이면 출고지를 고른다 — 다른 출고지 상품의 행은 반영하지 않는다.
3. 표를 머리글 행까지 붙여넣거나 XLSX·CSV(900KB 이하, 2,000행 이하)를 올린다. 열마다 가져올 항목을 확인한다: 관리코드·ERP 코드(품번)·바코드·판매자상품코드 중 하나 이상과 재고 수량.
4. 미리보기에서 늘림·줄임·부족과 반영하지 않는 행의 사유를 확인한다. "기준 시각 뒤 직접 변경"이 붙은 옵션은 아래 알려진 한계를 보고 판단한다.
5. 반영 사유를 넣고 확인창 뒤 반영한다. 미리보기에서 본 맞춘 뒤 재고수량 그대로 바뀌는 옵션 전부가 한 번에 반영되고 옵션마다 감사 기록(`admin.good.stock_reconciled`)이, 실행마다 `admin.stock_reconcile.applied`가 남는다. 결과 표와 옵션별 감사의 반영 전 재고수량·출고 대기·기준 시각 뒤 출고·회수는 **반영할 때 다시 잰 값**이다(감사에는 미리보기 값도 `previewStockQty`·`previewPendingQty`로 남는다).

### 짝짓기와 반영하지 않는 행

옵션은 관리코드 → ERP 코드 → 바코드 → 판매자상품코드(사용 옵션이 하나뿐인 상품) 순으로 찾는다. ERP 코드·바코드는 상품 옵션 상세의 외부 식별값이다(비어 있으면 그 키로는 못 찾는다). 다음 행은 반영하지 않고 사유를 보인다.

| 사유 | 조치 |
|---|---|
| 사이트에서 찾지 못함 | 옵션의 관리코드·ERP 코드·바코드 등록을 확인한다 |
| 같은 옵션을 가리키는 행이 둘 이상 | 창고 위치(로케이션)별 행이면 품목별 합계로 만든 뒤 올린다 |
| 코드끼리 다른 옵션·상품을 가리킴 | 파일의 코드 열을 확인한다 |
| 옵션이 여럿인 상품 | 판매자상품코드만으로는 옵션을 정할 수 없다. 관리코드·ERP 코드·바코드 열을 함께 올린다 |
| 고른 출고지의 상품이 아님 | 출고지를 바꾸거나 해당 행을 뺀다 |
| 보관한 상품·사용 중지한 옵션 | 재고 조정 대상이 아니다 |

음수·빈 수량 행은 화면에서 미리 걸러 대조하지 않는다(ERP 음수 재고는 ERP에서 먼저 정리한다).

### 충돌·재시도

- 반영은 바뀌는 옵션을 상품 → 옵션 순으로 잠근 뒤 미리보기한 옵션 전부를 다시 잰다. 다음 옵션이 하나라도 있으면 **아무것도 바꾸지 않고** 그 옵션의 미리보기 값·지금 값(재고수량·출고 대기·맞춘 뒤 재고수량)과 이유를 돌려준다(2026-11-12 QA1 결정 a안 — 운영자가 확인한 숫자 그대로만 바꾼다).
  - **출고 대기 변동**: 미리보기 뒤 주문·취소·출고·회수로 맞춘 뒤 재고수량이 달라진 바뀌는 옵션.
  - **재고 변동**: 미리보기 뒤 재고 조정·다른 대조로 재고수량을 직접 바꿔 차이가 달라진 옵션(같은 옵션 포함).
  - 바뀌지 않던 옵션(같음)이 지금은 바뀌어야 하는 경우. 주문으로 재고수량과 맞춘 뒤 재고수량이 함께 움직인 같은 옵션은 막지 않는다.
  - 상품을 보관했거나 옵션을 사용 중지한 바뀌는 옵션.
- 화면의 **다시 미리보기**는 같은 파일·기준 시각으로 지금 값을 다시 계산한다(입력한 반영 사유는 남는다). 최근 대조 기록에서 연 미리보기는 파일이 화면에 없으니 같은 파일을 다시 올려 미리보기 한다. 주문이 계속 들어오는 옵션이면 미리보기 뒤 바로 반영한다.
- 미리보기는 24시간 안에만 반영할 수 있다. 반영 응답이 끊겨 같은 사유로 다시 누르면 처음 결과를 돌려준다. 다른 사유로 다시 반영하려 하면 거절한다.
- 미리보기만 해도 기록이 남는다(최근 대조 기록, `admin.stock_reconcile.previewed`). 출고 전 경고는 옵션마다 가장 최근 파일(기준 시각 순)을 쓴다.

### 알려진 한계

- 기준 시각 **뒤의 수동 재고 조정·다른 대조 반영**은 파일 뒤 입고인지 실사 보정인지 기록으로 가를 수 없어 계산에 넣지 않는다. 미리보기가 그 옵션에 "기준 시각 뒤 직접 변경 N건(합계)"을 표시한다. 파일 뒤 입고였다면 반영할 때 그 수량이 사라지니, 그 뒤에 받은 파일로 다시 대조하거나 반영 뒤 재고 조정으로 다시 더한다.
- 발송처리(운송장 등록)를 실제 출고보다 늦게 하면 그 사이 대조는 사이트를 적게 맞춘다(덜 파는 쪽). 회수 처리를 실제 입고보다 늦게 해도 같다. 실제 출고·입고보다 먼저 처리하지 않는다.
- 회수를 거절·철회한 클레임은 회수로 세지 않는다(실물이 다시 고객에게 갔다고 본다).

## 출고지시 전 재고 경고

`admin_stock_dispatch_warnings(출고지, 최소 차이)`(권한 `sales.read`)와 부품 `StockDispatchWarning`이 출고를 기다리는 옵션마다 가장 최근 재고 파일 기준으로 **부족**(출고 대기 > 창고 예상 = 파일 수량 − 기준 시각 뒤 출고 + 기준 시각 뒤 회수 − 회수 뒤 미반영)과 **차이**를 보인다. 그룹상품 전환 전 옵션의 주문은 승계 옵션으로 묶어 센다. 대조 기록이 없는 출고 대기 옵션도 센다. 경고만 하고 출고를 막지 않는다. 발주확인/발송관리 화면 연결 위치는 출고 화면 작업에서 정한다.

## 안전재고 하루 1회 요약 메일

`재고 대조 → 안전재고 요약 메일`(권한 `platform.manage`, 계정 주매니저 이상)과 `배송관리 → 배송정보 관리 → 출고지 탭 → 안전재고 요약 메일 담당자`.

- 매일 설정 시각(한국 시간)이 지나면 **그날 한 번** 실행을 만든다. 기본 **09:00** — 국내 업무 시작이라 담당자가 그날 실재고를 확인하고, 자동 발주확인·출고 마감 기본 16:30(ADR-0025) 전에 보충·품절 처리를 할 수 있다. 전날 저녁 주문까지 반영된다.
- 대상: 사용 중 옵션 중 `재고수량 ≤ 안전재고 기준`. 보관 상품·판매 중지 상품·사용 중지 옵션·기준을 비운 옵션은 뺀다.
- 운영자 주소(10개까지)는 전체 목록, 출고지 담당자 주소(출고지마다 5개까지)는 그 출고지 상품만 받는다. 같은 주소는 하루 한 통이다 — 운영자 목록이 이기고, 한 주소가 여러 출고지 담당이면 그 출고지들 상품을 한 통에 담는다(제목·인사말에 출고지 이름, 표에 출고지 열). 대상 옵션이나 받는 주소가 없으면 보내지 않고 실행만 남긴다.
- 메일에는 상품명·옵션명·판매자상품코드·관리코드·ERP 코드·바코드·재고수량·기준을 싣는다(한 통 300개까지, 넘치면 "외 N개"). 창고 담당자 메일에는 어드민 링크를 넣지 않는다.
- 오늘 시각이 이미 지났고 오늘 실행이 없으면 **켠 직후** 오늘 요약을 보낸다. 같은 날 시각을 바꿔도 다시 보내지 않는다.
- 공급사 일시 오류·발송 설정 대기는 10분 뒤 다시 시도한다. 결과 불명은 dispatcher의 24시간 검토 경계를 따른다. 실행 뒤 20시간이 지난 대기 요약은 보내지 않는다(다음 날 요약이 대신한다). 꺼지면 새로 선점하지 않는다.
- 기록: 화면의 최근 발송 기록(7일), `private.stock_safety_digest_runs`·`_deliveries`, 시스템 감사 `system.stock_safety_digest.prepared`, 설정 감사 `admin.stock_safety_digest.settings`·`.origin`.

### 켜는 순서(사람 게이트)

1. 서원·김포와 받는 사람·알림 방식을 합의한다(재고 정보를 외부로 보낸다 — 영업 정보).
2. 알림 받을 옵션마다 안전재고 기준을 넣는다(상품 수정의 옵션 상세).
3. 운영 env 확인: `CRON_SECRET`, `EMAIL_DISPATCH_HMAC_SECRET`(32자 이상), Resend 설정(`RESEND_*` 또는 legacy `EMAIL_PROVIDER_API_KEY`·`EMAIL_FROM`), `SITE_URL`. 값은 문서·로그에 남기지 않는다. 없으면 실행은 만들어지고 발송은 `메일 발송 설정 전`으로 재시도된다.
4. 출고지 탭에 담당자 주소, 재고 대조 화면에 운영자 주소·시각을 넣고 **사용**을 켠다. 이 설정의 사용 여부가 dispatcher의 전용 gate다(#191 Auth 메일 gate와 별개, 주문 지연 안내와 같은 방식).
5. 첫 발송은 운영자 주소 하나로만 켜서 수신·본문을 확인한 뒤 담당자 주소를 넣는다.

끄면 다음 틱부터 새로 선점하지 않는다. 이미 공급사가 받은 메일은 되돌릴 수 없다.

## 자동 연동(사람 게이트)

- ERP(사내 AX·이카운트)·김포 EMP·사방넷 API 연동은 비용·계약 뒤 별도 결정이다(10/7 "추가 비용", 10/27 사방넷 견적).
