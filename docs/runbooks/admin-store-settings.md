# 운영 설정 (#426)

`/admin/settings/operations`는 실제 운영값의 입력 시작점이다. 사업자·CS·계좌, 출고지·반품 주소, 지역 추가료, 택배사·배송 안내, 상품 ERP·매입단가·KC, 카테고리·혜택의 기존 입력 화면으로 연결한다. 상품별 정보는 상품 선택 후 입력한다. 적립금 정책 링크는 admin에게만 표시한다.

운영 총괄과 출고지별 담당자 이름·업무 연락처·운영 자료 위치·인수 기록 위치를 같은 페이지에서 저장한다. 자료 위치는 사내 문서 주소 또는 폴더 경로를 기록하는 텍스트이며 파일 업로드나 외부 공유 권한을 부여하지 않는다. 각 항목은 미확정 상태로 비워둘 수 있고 입력 수는 실제 인수·계약·판매 승인 상태가 아니다. 비활성 출고지도 담당자 기록을 관리할 수 있다.

담당자 정보는 `private.operations_contacts`에 보관하고 staff 조회·활성 admin 저장 RPC만 허용한다. 일반 고객·anon·service_role 및 앱의 직접 테이블 접근은 봉인한다. 담당자별 버전 비교와 잠금으로 동시 덮어쓰기를 막으며 입력 실패 시 폼을 보존한다. `admin.operations_contact.updated` 감사 기록은 변경자·대상·시각·변경 필드 이름과 버전만 남겨 연락처·문서 경로 원문을 복제하지 않는다. 화면에는 최근 30건을 표시한다. 담당자 저장은 공개 카탈로그·기존 주문·판매 및 발송 gate를 변경하지 않는다.

`/admin/settings/store`에서 사업자·CS 연락처, 무통장 계좌 표시값, 스토어 브랜드·SNS와 공개 메뉴를, `/admin/settings/carriers`에서 택배사를 관리한다. staff는 조회 전용이며 정지되지 않은 admin만 저장한다. 직접 테이블 쓰기는 봉인되어 있고 저장 RPC가 감사 이력을 남긴다.

- 기존 사업자·CS 정보는 자동 변경하지 않는다. DB에 설정하지 않은 키는 기존 공개값을 사용한다. 관리자가 빈 문자열을 저장한 키는 공개 행에서 생략한다. 실제 연락처 값은 이 문서에 복사하지 않는다.
- 저장하면 공개 캐시와 법정 문서 경로를 갱신한다. 다음 조회에서 푸터·법정 문서가 같은 설정을 읽는지 확인한다. 이미 열려 있는 브라우저는 새로고침한다.
- 무통장 계좌는 `store_settings.bank_transfer`가 진실원이다. 이전 `BANK_TRANSFER_*` env는 읽지 않는다. 최초 전환 전에 승인된 법인계좌를 설정 화면에서 입력하고 별도로 대조한다. 미설정·일부 누락·DB 조회 실패는 새 무통장 결제수단을 숨긴다.
- 계좌 표시값을 바꾸기 전에 기존 입금 대기 주문과 이미 고객에게 안내된 계좌를 확인한다. 설정 변경은 과거 안내·실제 입금·결제 원장을 수정하지 않는다. 신규 주문을 중단하려면 계좌 세 항목을 모두 비운다. 기존 주문의 안내·입금 처리는 별도로 마무리한다.
- 택배사 코드는 등록 후 편집하지 않는다. HTTPS URL에 `{trackingNumber}`를 넣고 실제 계약 택배사의 조회를 확인한다. 비활성화는 신규 발송 선택을 막고 기존 배송조회 링크를 유지한다.
- 동시 편집은 `updated_at` 비교로 충돌을 알린다. 입력값을 복사하고 최신 설정을 다시 읽어 의도한 항목만 저장한다. 이력은 최근 50건을 표시하며 삭제하지 않는다.

`/admin/settings/origins`에서 출고지별 배송 정책을 관리한다. ‘출고지 정책 따름’ 상품이 있으면 가격이 0원이어도 기본 배송비를 묶음당 한 번 부과한다. 무료 배송 기준을 비우면 금액에 따른 면제가 없고, `0`으로 저장하면 정책 배송비가 항상 무료다. ‘무료배송’ 상품은 정책 소계에서 제외하며 ‘개별 배송비’는 해당 상품당 한 번 별도로 합산한다.

배송 정책 변경 이전 주문의 청구 배송비는 주문에 고정된 값을 따른다. 0원 상품·혼합 묶음·무료 기준 경계와 주문 스냅샷 보존은 `supabase/tests/fulfillment_zero_price_policy.sql`로 검증한다. 이 문서는 계좌·PG·생산 환경 변경 승인을 대신하지 않는다.

출고지시 양식은 표준 12열, 김포 WMS 21열, 서원 우체국 7열 중 선택한다. 실제 양식의 매핑, 빈칸과 창고 확인 항목, 송장 회신 절차는 [출고지시와 운송장 회신](warehouse-export.md)을 따른다.

## 문의 자동 안내

`/admin/settings/store?section=inquiry_auto_replies`에서 다섯 문의 유형의 안내를 한 번에 저장한다. 기본은 모두 꺼짐이며 기존 문의를 변경하지 않는다. 활성 admin만 저장하고 staff는 읽기만 한다. 문구는 앞뒤 공백을 정리한 2,000자 이내이며 켠 안내는 비어 있을 수 없다. HTTPS FAQ 주소는 텍스트 안에서 링크로 표시하고 HTML을 실행하지 않는다. 변경 전후는 기존 `admin.store_settings.updated` 감사 이력에 남는다.

새 문의 생성 RPC는 사용자 메시지 뒤에 `author=system`, `author_id=null`인 안내를 같은 트랜잭션에서 추가한다. 자동 안내 기록 실패 시 문의 생성도 롤백된다. 추가 질문에는 다시 넣지 않으며, 담당자·사람의 답변·첫 답변 기한·미답변 통계·인앱 알림·메일 발송은 기존 흐름을 유지한다. Realtime에서는 메시지를 다시 읽어 자동 안내로 표시하되 새 사람 답글 수에 포함하지 않는다. 운영 적용은 별도 승인 후 기본 꺼짐 상태로 배포한다. 실제 안내 문구의 활성화는 관리자 업무다.

## 스토어 브랜드·SNS

`/admin/settings/store?section=branding`에서 표시 이름(1~30자), 텍스트/이미지 로고, PC·모바일 로고, 소개(최대 50자)와 노출 여부, 네이버 블로그·페이스북·인스타그램 주소와 각각의 노출 여부를 한 번에 저장한다. 기본은 ICONS 텍스트이며 소개·SNS는 모두 꺼져 있다. 저장한 표시는 공개 헤더·푸터에 반영하며 법정 사업자명·문서·페이지 메타데이터를 바꾸지 않는다. 표시 이름 30자 상한과 업로드 규격은 ICONS 운영 계약이다.

이미지 모드에서는 PC 로고가 필수이고 모바일 로고를 비우면 PC 로고를 함께 쓴다. 기존 이미지 업로드의 JPEG·PNG·WebP, 5MB, 각 축 8192px·총 4천만 픽셀 이하 검증을 사용한다. 저장 RPC는 해당 관리자가 검증받은 유효한 업로드만 새 로고로 연결하며 같은 파일을 양쪽에 쓰면 한 번만 소비한다. 저장된 이미지는 다음 저장에서 유지하거나 PC·모바일 슬롯 사이에 재사용할 수 있다. 제거한 이미지를 다시 쓰려면 다시 업로드한다.

SNS 주소는 해당 서비스의 HTTPS 주소만 허용하며 계정 로그인·인증·OAuth 연결을 수행하지 않는다. 켜진 링크는 푸터에서 새 창으로 연다. 꺼진 소개·SNS 주소와 텍스트 모드의 이미지 경로는 익명 조회 응답에서도 제외한다. 동시 수정 충돌 시 입력값을 보관하고 최신 설정을 다시 확인한다. 응답을 받지 못해 같은 내용을 재시도하면 작업 ID로 이전 성공 결과를 돌려주며 감사 이력을 중복 생성하지 않는다. 저장 후 공개 캐시를 만료하고 새 조회에서 반영한다.

## 공개 메뉴

`/admin/settings/store?section=navigation`에서 NEW·BEST·카테고리·온라인 팝업·카드팩·이벤트·커뮤니티의 이름(앞뒤 공백을 정리한 1~20자), 순서와 노출을 함께 저장한다. 카테고리는 항상 노출하며 연결 경로는 기존 페이지로 고정한다. 기본 메뉴 복원과 PC·모바일 미리보기는 저장 전 편집이다. 실제 반영은 ‘공개 메뉴 저장’ 후 이루어진다.

공개 PC 상단·모바일 탭·모바일 전체 메뉴의 스토어 항목은 같은 설정을 읽는다. 카테고리 하위 메뉴에서는 해당 항목의 숨김과 이름을 반영하고 기존 분류 그룹을 유지한다. 계정·주문·법정 안내와 하단 바로가기는 이 설정의 대상이 아니다. 카드 리워드 중지와 커뮤니티 비공개 게이트는 노출 설정보다 우선한다. 긴 이름은 PC에서 줄임표와 전체 이름 툴팁으로, 모바일 전체 메뉴에서는 줄바꿈으로 표시한다.

저장은 활성 admin 전용 RPC에서 행 잠금·설정 전체의 `updated_at` 충돌·작업 ID 멱등성·감사를 적용한다. 충돌이나 응답 실패 시 입력값을 보존한다. 동일 요청 재시도는 기존 성공 결과를 돌려주며, 설정을 다시 편집하면 새 작업 ID를 사용한다. 익명 조회에는 보이도록 설정한 메뉴 ID·이름·순서만 포함한다. 저장 후 공개 캐시를 만료하고 새 조회에서 반영한다. 기존 설정을 불러오지 못하면 기본 메뉴를 사용하되 기능 게이트는 계속 적용한다.

## 자유상품 모자이크

`/admin/display/curations`에서 자유상품 모자이크를 추가한다. 영역 제목은 15자, 모자이크 공통 제목은 10자, 부제목은 20자까지다. 정확히 8개 위치에 상품과 대표이미지를 각각 등록하며, 앞으로/뒤로 이동은 상품과 이미지를 함께 이동한다. 상품이나 이미지를 비운 초안도 저장할 수 있다. 비노출 구성을 포함해 최대 5개이며 서버가 동시 등록에서도 한도를 보장한다.

대표이미지는 620×620px를 권장한다. JPEG·PNG·WebP를 지원하며 원본과 검증 후 저장 이미지가 각각 900KB 이하여야 한다. 새 이미지는 현재 관리자의 검증된 업로드만 연결하고 같은 구성 안에 이미 저장된 이미지는 위치를 옮길 수 있다. 제거 후 다시 사용하거나 다른 구성에 사용하려면 새로 업로드한다.

공개 홈과 미리보기는 1·6번을 크게 둔 7열2행을 사용하고 모바일에서는 가로로 넘겨 본다. 상품·이미지가 빠졌거나 상품이 공개되지 않았으면 그 위치를 빈칸으로 유지한다. 공개 가능한 품절 상품은 품절 표시와 상세 링크를 유지하며, 유효 상품이 하나도 없으면 영역 전체를 숨긴다. 이 배치와 빈칸 정책은 ICONS의 계약이다. 원본에서 확인한 8개 위치·제목/부제/이미지 조건과 구분한다.

‘이 구성 적용하기’로 개별 내용을 저장한 뒤 ‘영역 순서·노출’에서 전체 홈 배치를 바꾼다. 개별 구성의 노출 기간·노출 여부도 함께 적용된다. 잘못된 입력이나 전송 실패에서는 입력을 보존한다. 전체 순서의 오래된 버전은 HTTP 409로 거절하므로 최신 상태를 확인하고 의도한 변경을 다시 적용한다.
