# 예약판매와 실재고 할당

예약판매는 주문 시 결제하고 저장한 발송 예정일을 안내하는 판매 방식이다. 옵션의 실제 재고와 승인받은 예약 물량은 별도 장부이며, 예약 설정이나 주문이 실제 재고를 늘리지 않는다. 운영 수치나 근거가 비어 있는 정책은 초안으로 보존하고 활성화하지 않는다.

## 등록과 공개

상품 편집의 예약판매 패널에서 옵션별 승인 물량, 예약 시작·종료 시각, 발송 예정일, 승인 근거를 입력한다. 활성화는 admin만 할 수 있고, staff는 초안·열람·중지·입고 재고 할당을 처리한다. 활성화한 정책의 물량·기간·원 예정일은 수정하지 않는다. 변경된 판매 조건은 이전 정책을 중지한 후 새 버전으로 등록한다.

예약 접수는 서버 시각의 시작 이상·종료 미만에서만 열린다. 예약 중지나 종료 뒤에는 일반 재고 판매로 자동 전환하지 않는다. 이 옵션을 다시 일반 판매로 돌리려면 admin이 정책을 중지하고, 해당 옵션의 미할당 예약 건이 없음을 확인한 뒤 일반 재고 사용을 명시적으로 선택한다. 미할당 예약은 지금 선택된 정책만이 아니라 그 옵션의 모든 정책(이전 회차의 중지된 정책 포함)에서 센다(`admin_use_stock_supply`의 `preorder_allocations_pending`). 패널은 같은 기준으로 전환 버튼을 막고 옵션별 남은 수량을 보여 준다.

활성 예약 옵션은 공개 화면·추가상품 선택·장바구니·주문에서 같은 남은 예약 물량과 기간을 사용한다. 주문 시점의 정책 버전과 발송 예정일을 품목에 보존한다. 판매 중지·KC·게시 상태·결제수단·구매 한도·쿠폰·적립금 검증도 함께 적용한다. 예약 정책이 있다는 이유로 다른 판매 조건을 우회하지 않는다.

## 랜덤 판매 상품의 예약

랜덤 판매 상품([ADR-0027](../adr/0027-random-option-sale-goods.md) '랜덤 예약판매와 같은 옵션 배정 상한')은 옵션 하나씩이 아니라 판매 중인 모든 옵션을 함께 예약한다. 옵션마다 일정이 다르면 고객 주문의 발송 예정일로 배정 옵션이 드러나기 때문이다.

- 판매 중인 옵션은 모두 예약(선택된 정책)이거나 모두 일반 재고여야 한다. 예약이면 접수 시작·종료와 발송 예정일이 모든 옵션에서 같고 승인 예약 물량만 옵션별이다. 어긋나는 저장은 커밋에서 `random_option_preorder_mismatch`로 거절된다.
- 예약판매 패널의 '랜덤 판매 예약 (모든 옵션)'에서 접수 기간·발송 예정일·승인 근거를 한 번 입력하고 옵션별 승인 예약 물량을 표에 적는다. 저장 방식으로 초안 저장 또는 모든 옵션 예약 활성화를 고른다. 옵션마다 가장 최근 초안을 이어 쓴다.
- 중지와 일반 재고 전환은 '모든 옵션 한 번에 처리'의 버튼으로 모든 옵션을 한 트랜잭션에서 바꾼다(`admin_save_random_goods_preorders`). 옵션 하나만 일반 재고로 바꾸면 커밋에서 거절된다. 옵션 하나의 접수 중지는 허용되고 그 옵션은 배정에서 빠진다.
- 권한은 옵션 단위 예약과 같다. 초안·중지는 staff, 활성화와 일반 재고 전환은 admin만 할 수 있다. 일반 재고 전환은 모든 옵션에서 이전 회차를 포함한 미할당 예약이 0이어야 한다.
- 주문할 때 옵션별 남은 예약 물량에 비례해 옵션이 배정되고, 배정 행마다 그 옵션 정책의 스냅샷과 예약 기록이 남는다. 고객에게는 공통 일정과 남은 물량 합계만 보이고, 관리자 예약 주문 목록에는 배정된 옵션별로 보인다.

운영 규칙:

- 같은 옵션 배정 상한(구매 제한의 '모든 옵션' 한 줄)은 옵션별 승인 물량이 상한보다 충분히 클 때만 쓴다. 남은 물량이 상한 근처인 희소 옵션이 있으면 주문 가능 여부로 결제 대기 주문의 배정을 짐작할 수 있다. 상한을 정한 뒤 옵션을 더하면 새 옵션에도 같은 상한이 채워진다.
- 발송 예정일 변경은 특정 옵션이 든 주문만 하지 않고 그 상품의 예약 주문 전체에 같은 날짜로 한다.
- 입고 할당도 상품 단위로 맞춘다. 일부 옵션만 먼저 들어왔다고 그 옵션 주문만 할당하면 결제한 고객이 배송 건 준비 상태로 배정을 짐작할 수 있다.
- 예약 활성화 전에 옵션 구성을 확정한다. 예약 중인 랜덤 상품에 옵션을 더하려면 판매 방식을 옵션 선택 판매로 바꾼 뒤 추가한다. 새 옵션은 예약 선택이 없어 랜덤 조건이 깨지기 때문이다. 옵션 선택 판매인 동안에는 고객이 옵션을 골라 주문할 수 있다. 다시 랜덤 판매로 바꾸려면 새 옵션에도 같은 접수 기간·발송 예정일의 예약 조건을 활성화해 두거나, 모든 옵션을 일반 재고로 전환해야 한다.

## 실제 입고와 출고

1. 실제 물품이 입고되면 기존 재고 조정 기능에서 해당 옵션의 입고 수량과 근거를 기록한다.
2. 예약판매 패널의 주문 품목 목록에서 결제가 확인된 예약 품목을 선택한다. 옵션별 선택 합계가 실제 재고 이하여야 한다.
3. 입고 근거를 입력해 할당한다. 서버는 주문·옵션·예약 장부를 잠그고 실제 재고를 차감한 뒤 해당 품목을 할당 완료로 옮긴다. 같은 품목을 다시 처리해도 실제 재고를 재차 차감하지 않는다.
4. 출고지의 예약 품목이 모두 할당되어야 출고 파일 생성·발주 전달·발송을 진행할 수 있다. 다른 출고지의 일반 상품은 독립적으로 출고할 수 있다.

발송 예정일은 고객에게 안내한 예상 일정이다. 출고를 특정 날짜까지 강제로 금지하는 창고 예약 시각으로 사용하지 않는다. 실제 재고 할당과 기존 결제·클레임 검증이 출고 조건이다.

## 혼합 주문과 일정 변경

같은 출고지의 예약·일반 품목은 기존 계약대로 배송 건 하나에 묶는다. 그 배송 건의 원 발송 예정일은 예약 품목 중 가장 늦은 예정일이다. 다른 출고지는 별도 배송 건으로 유지한다.

관리자 주문 상세의 예약 발송 일정에서 준비 중인 배송 건의 새 예정일과 변경 사유를 기록한다. 주문 당시 예정일은 바뀌지 않으며 현재 일정, 이전/새 날짜, 담당자, 기록 시각이 남는다. 이 변경은 주문 화면에 반영된다. 고객 일괄 메시지 채널을 활성화하거나 메시지를 자동 발송하는 동작은 포함하지 않는다.

## 취소와 환불

- 실재고를 아직 할당하지 않은 예약 품목의 전액 취소·환불이 확정되면 승인 예약 물량만 회복한다. 실제 재고는 늘리지 않는다.
- 실재고를 할당한 품목은 기존 회수 확인과 결제 증거를 만족한 전액 환불 때 실제 재고를 복원한다. 이미 이행한 예약 물량을 새로운 판매 가능 물량으로 다시 열지는 않는다.
- 결제 응답이 불명확하거나 결제 시도만 실패한 경우에는 예약을 임의 해제하지 않는다. 기존 주문 취소 종결이 공급 장부 해제의 경계다.
- 주문 금액·할인·배송비는 주문 당시 값을 유지한다. 부분 환불이나 새 요금 청구는 제공하지 않는다.

## 확인

`goods_preorders.sql`은 정책 권한, 미설정 활성화 차단, 주문 공급원 보존, 할당·환불 회복, 혼합 배송과 일정 변경을 확인한다. `random_option_preorder.sql`은 랜덤 판매 상품의 공통 일정 강제, 일괄 저장, 예약 물량 비례 배정, 같은 옵션 배정 상한을 확인한다. `goods_preorders_concurrency.sh`는 작업 전용 DB에서 서로 다른 회원의 마지막 물량 경쟁과 취소·실재고 할당 경쟁을 검증하는 스크립트다. 스크립트 존재나 로컬 검증은 실제 운영 물량 승인·입고 확인을 대신하지 않는다.
