# 예약판매와 실재고 할당

예약판매는 주문 시 결제하고 저장한 발송 예정일을 안내하는 판매 방식이다. 옵션의 실제 재고와 승인받은 예약 물량은 별도 장부이며, 예약 설정이나 주문이 실제 재고를 늘리지 않는다. 운영 수치나 근거가 비어 있는 정책은 초안으로 보존하고 활성화하지 않는다.

## 등록과 공개

상품 편집의 예약판매 패널에서 옵션별 승인 물량, 예약 시작·종료 시각, 발송 예정일, 승인 근거를 입력한다. 활성화는 admin만 할 수 있고, staff는 초안·열람·중지·입고 재고 할당을 처리한다. 활성화한 정책의 물량·기간·원 예정일은 수정하지 않는다. 변경된 판매 조건은 이전 정책을 중지한 후 새 버전으로 등록한다.

예약 접수는 서버 시각의 시작 이상·종료 미만에서만 열린다. 예약 중지나 종료 뒤에는 일반 재고 판매로 자동 전환하지 않는다. 이 옵션을 다시 일반 판매로 돌리려면 admin이 정책을 중지하고, 해당 옵션의 미할당 예약 건이 없음을 확인한 뒤 일반 재고 사용을 명시적으로 선택한다.

활성 예약 옵션은 공개 화면·추가상품 선택·장바구니·주문에서 같은 남은 예약 물량과 기간을 사용한다. 주문 시점의 정책 버전과 발송 예정일을 품목에 보존한다. 판매 중지·KC·게시 상태·결제수단·구매 한도·쿠폰·적립금 검증도 함께 적용한다. 예약 정책이 있다는 이유로 다른 판매 조건을 우회하지 않는다.

## 실제 입고와 출고

1. 실제 물품이 입고되면 기존 재고 조정 기능에서 해당 옵션의 입고 수량과 근거를 기록한다.
2. 예약판매 패널의 주문 품목 목록에서 결제가 확인된 예약 품목을 선택한다. 옵션별 선택 합계가 실제 재고 이하여야 한다.
3. 입고 근거를 입력해 할당한다. 서버는 주문·옵션·예약 장부를 잠그고 실제 재고를 차감한 뒤 해당 품목을 할당 완료로 옮긴다. 같은 품목을 다시 처리해도 실제 재고를 재차 차감하지 않는다.
4. 출고지의 예약 품목이 모두 할당되어야 출고 파일 생성·발주 전달·발송을 진행할 수 있다. 다른 출고지의 일반 상품은 독립적으로 출고할 수 있다.

발송 예정일은 고객에게 안내한 예상 일정이다. 출고를 특정 날짜까지 강제로 금지하는 창고 예약 시각으로 사용하지 않는다. 실제 재고 할당과 기존 결제·클레임 검증이 출고 조건이다.

## 혼합 주문과 일정 변경

같은 출고지의 예약·일반 품목은 기존 계약대로 배송 건 하나에 묶는다. 그 배송 건의 원 발송 예정일은 예약 품목 중 가장 늦은 예정일이다. 다른 출고지는 별도 배송 건으로 유지한다.

관리자 주문 상세의 예약 발송 일정에서 준비 중인 배송 건의 새 예정일과 변경 사유를 기록한다. 주문 당시 예정일은 바뀌지 않으며 현재 일정, 이전/새 날짜, 담당자, 기록 시각이 남는다. 이 변경은 주문 화면에 반영된다. 고객 일괄 메시지 채널을 활성화하거나 메시지를 자동 발송하는 동작은 포함하지 않는다.

## 취소와 환불

- 실재고를 아직 할당하지 않은 예약 품목의 전액 취소·환불이 확정되면 승인 예약 물량만 회복한다. 실제 재고는 늘리지 않는다.
- 실재고를 할당한 품목은 기존 회수 확인과 결제 증거를 만족한 전액 환불 때 실제 재고를 복원한다. 이미 이행한 예약 물량을 새로운 판매 가능 물량으로 다시 열지는 않는다.
- 결제 응답이 불명확하거나 결제 시도만 실패한 경우에는 예약을 임의 해제하지 않는다. 기존 주문 취소 종결이 공급 장부 해제의 경계다.
- 주문 금액·할인·배송비는 주문 당시 값을 유지한다. 부분 환불이나 새 요금 청구는 제공하지 않는다.

## 확인

`goods_preorders.sql`은 정책 권한, 미설정 활성화 차단, 주문 공급원 보존, 할당·환불 회복, 혼합 배송과 일정 변경을 확인한다. `goods_preorders_concurrency.sh`는 작업 전용 DB에서 서로 다른 회원의 마지막 물량 경쟁과 취소·실재고 할당 경쟁을 검증하는 스크립트다. 스크립트 존재나 로컬 검증은 실제 운영 물량 승인·입고 확인을 대신하지 않는다.
