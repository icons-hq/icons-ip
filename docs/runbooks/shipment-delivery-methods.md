# 퀵·방문수령 운영

퀵·방문수령은 이미 결제된 주문의 배송 방식을 고객 요청으로 바꾸는 운영 흐름이다. 주문 당시 상품 금액·쿠폰·적립금·기본 배송비·지역 추가 배송비를 유지한다. 새로운 요금 청구, 자동 환불, 착불이나 주문서에서의 신규 방식 선택은 포함하지 않는다.

## 출고지 운영 조건 등록

`설정 → 출고지·배송 정책 → 퀵·방문수령 운영 조건`에서 방식을 선택하고 실제 담당자·연락처, 인계 장소와 방법, 예약·방문 시간 안내, 대리수령 허용 여부, 수령 확인 근거·절차, 취소 가능 시점·고객 응대 안내, 승인 근거를 기록한다.

필요한 값이 없는 상태는 초안으로 저장할 수 있다. admin만 정책 저장·활성화·새 선택 중지를 처리한다. staff는 등록된 정책을 조회하고 주문별 방식 변경과 인계·수령 기록을 처리한다. 초기 활성 정책은 제공하지 않는다.

활성 정책의 조건은 수정하지 않는다. 조건이 달라지면 기존 정책의 새 선택을 중지하고 새 버전을 등록한다. 이미 선택한 주문은 그 당시 안내와 기준으로 계속 처리하며, 최신 설정으로 이력을 덮어쓰지 않는다.

## 주문별 배송 방식 선택

1. 관리자 주문 상세에서 해당 출고지의 `배송 방식·인계 확인`을 연다.
2. 결제가 확인된 주문의 배송 준비 상태이며 출고지시를 아직 전달하지 않은 건인지 확인한다. 진행 중인 취소·클레임이 있으면 먼저 검토한다.
3. 실제 고객의 방식 변경 요청과 **기존 배송비 유지 동의** 근거를 입력한다. 퀵·방문수령은 해당 출고지의 활성 운영 조건을 선택한다.
4. 저장 후 주문 화면에 반영된 방식·인계 안내와 기존 배송비를 확인한다. 인계 전 같은 조건 안에서 다시 택배로 돌릴 때도 고객 요청·동의를 기록한다.

방식이 바뀌어도 고객 직접 취소 범위를 넓히지 않는다. 기존 발주확인 이후에는 인계 전이어도 CS/클레임 검토를 따르며, 출고·수령 상태와 회수 증거를 우회해 주문을 취소하지 않는다.

## 실제 인계와 수령 완료

퀵은 실제 업체와 연락처, 인계 담당자, 실제 인계 시각, 인계 참조·근거를 기록하면 배송 중으로 바뀐다. 수령 완료 때는 실제 수령 확인 담당자와 시각, 수령인 구분, 수령 근거, 주문자가 제시한 일회 수령 확인값을 함께 입력한다.

방문수령은 준비 상태에서 실제 인계 담당자·시각·수령인 구분·수령 근거와 일회 수령 확인값을 확인해 완료한다. 대리수령은 저장된 정책에서 허용한 경우에만 선택할 수 있다. 불필요한 신분증 사본 수집을 추가하지 않는다.

예약 품목이 있으면 실제 입고와 예약 물량 할당이 먼저다. 예정일은 고객과의 안내 일정이며 특정 날짜 전 인계를 강제로 금지하는 시각으로 사용하지 않는다. [예약판매 운영 절차](./goods-preorders.md)를 따른다.

퀵·방문수령에는 택배사나 가짜 운송장을 입력하지 않는다. 배송 콘솔은 해당 행을 주문 상세의 인계 확인으로 연결하고 택배용 발주 파일·운송장 등록·일괄 배송완료 대상에서 제외한다. 택배·퀵·방문수령이 섞여도 모든 배송 건이 완료되어야 주문이 배송 완료가 된다. 품목 수량과 기존 주문 전체 클레임·출고지별 회수 기준을 유지한다.

## 일회 수령 확인값

주문자는 자신의 주문 화면에서 확인값을 발급한다. 방문수령은 발주확인이 끝난 준비 상태에서, 퀵은 실제 배송 중일 때 발급할 수 있다. 운영자나 다른 고객은 주문자의 값을 조회하거나 대신 발급할 수 없다.

확인값은 12자리 난수이며 10분 동안 한 번 사용할 수 있다. 5회 틀리면 새 값을 발급해야 한다. 새 값의 발급·배송 방식 재선택은 이전 값의 사용을 막는다. 화면을 새로고침해 값을 잃어버렸다면 다시 발급한다. DB에는 해시·유효기간·시도 수만 저장하며 원문을 이력·운영 조회·로그에 남기지 않는다.

운영자는 고객이 물품을 확인한 뒤 제시한 값을 입력한다. 수령 확인값을 일반 운영 메모나 수령 근거 칸에 복사하지 않는다. 동일한 제출을 재시도하면 이미 처리한 기록을 확인하고 완료 시각·인계 근거를 중복 기록하지 않는다. 연결 오류 후 내용을 바꾸기 전에는 배송 건을 새로고침해 실제 저장 상태를 확인한다.

## 고객 안내와 확인 범위

선택 당시 연락처·장소·인계·예약·대리수령·수령·취소 안내는 주문 화면에서 볼 수 있다. 퀵 배송 중에는 기록된 실제 업체명도 표시한다. 확인값 자동 메시지나 비택배용 외부 알림은 추가하지 않는다. 기존 택배 배송 이메일 큐는 택배 건만 처리한다.

SQL 검증은 `shipment_delivery_methods.sql`의 합성 혼합 주문으로 정책 권한·활성화 차단, 저장 조건 보존, 실재고 할당, 확인값 소유권·재발급·만료·5회 제한, 중복 처리, 금액·지역 요금 스냅샷, 주문 집계와 택배 메일 회귀를 확인한다. 기술 검증은 실제 출고지 연락처·인계 절차 승인이나 실제 고객의 동의·수령 증거를 대신하지 않는다.
