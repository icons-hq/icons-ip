# 방문 통계 활성화와 보존 점검

정본 구현은 `20261013104526_store_analytics_collection.sql`, 측정 정의는 [방문·유입·마케팅 링크 성과 계약](../research/smartstore-admin/traffic-attribution-parity.md)이다.

## 발행 전 상태

- 마이그레이션은 수집을 **비활성**으로 설치한다. 웹 방문만으로 동의나 세션을 만들지 않는다.
- 기존 개인정보처리방침 `2026-08-22`의 내용·버전·해시를 바꾸지 않는다. `lib/store-analytics-notice.ts`의 `analytics-v1`은 별도 선택 안내다. 운영 활성화 전, 주문번호 연결·보관기간·처리 목적을 반영한 신규 정책 발행과 운영 승인 범위를 확인한다. 기존 발행 버전 내용을 같은 버전으로 덮어쓰지 않는다.
- 앱은 기존 서버 Supabase 설정과 `CRON_SECRET`을 사용하며 신규 환경변수나 외부 분석서비스를 요구하지 않는다. 운영 DB 변경/활성화는 이 구현 완료와 별개다.

## 활성화와 중단

1. Preview 또는 승인된 격리 로컬 DB에서 마이그레이션과 해당 앱 버전을 함께 준비한다. 운영 자격증명/데이터를 복사하지 않는다.
2. 승인된 서버 경계에서 service role로 `set_store_analytics_collection(true, 'analytics-v1')`을 호출한다. 고객·운영자 브라우저에 service role이나 세션 토큰을 제공하지 않는다. 최초 활성화 시각은 서버가 기록한다.
3. `/api/cron/store-analytics`를 기존 `CRON_SECRET`의 Bearer 인증으로 **매분** 실행한다. 이 호출은 분 단위 관측 점검과 보존 정리를 함께 수행한다. 점검 기록이 빠진 과거 날짜는 정상 0으로 보고하지 않는다.
4. 비로그인 공개 화면에서 안내→거부, 다시 설정→동의, 마케팅 링크 목적지→다른 공개 화면, 고객 본인 주문 생성→서버 결제 확정→운영자 보고서 조회를 확인한다. 통계 선택과 마케팅 수신 동의는 별개다.
5. 중단은 같은 RPC에 `false`를 전달한다. 기존 선택이 있어도 새 사건·주문 연결은 멈추고 중단 구간을 남긴다. 보존 정리 cron은 계속 실행한다.

## 수집과 철회

- 브라우저에 180일 선택 쿠키를 보존한다. 동의 때만 임의 32바이트 세션을 만들고 HttpOnly·SameSite=Lax 쿠키에 보관한다. 서버는 SHA-256 해시만 DB에 저장한다. 갱신 세션은 기존 동의의 만료를 연장하지 않는다.
- 세션은 30분 비활동·24시간 상한·한국 날짜 경계에서 끝난다. 새로고침은 별도 열람이고 같은 사건 ID 재시도는 중복되지 않는다. 프리패치, 관리자·회원·주문·결제·검색 화면은 수집하지 않는다. 로그인 운영자와 이용 정지 고객도 수집에서 제외한다.
- 전체 URL·referrer 경로/쿼리·이름·이메일·IP 주소·User-Agent·회원 ID를 통계 원장에 저장하지 않는다. 알려진 source/medium의 유한 분류만 전송한다. 원본 UTM campaign/term/content는 통계로 전송하지 않는다.
- 철회는 추가 수집과 주문 연결을 바로 멈추고 현재 세션 사건과 주문 연결을 삭제한다. 삭제 실패 시 선택은 거부로 유지하고 화면에 미완료를 표시한다. 후속 방문에서 삭제를 재시도한다. 브라우저의 다른 탭도 거부 선택을 적용한다.

## 보고서와 장애 구분

`/admin/stats/traffic`와 `/admin/stats/marketing`은 `stats.read`가 있어야 읽거나 내보낼 수 있다. 선택한 기간·차원·검색 조건을 엑셀에 함께 기록하며 10,000개를 초과하면 조건을 좁히도록 안내한다.

수집 전/중단/관측 공백/보존 만료는 `미측정` 또는 `일부 관측`이다. 오늘은 진행 중이므로 완료된 하루로 표현하지 않는다. 운영자 화면의 최근 점검이 3분 이상 지났으면 cron/서버 오류를 점검한다. 정상 관측 여부는 동의한 방문의 실제 사람 여부를 보증하지 않는다.

전환은 생성 시점에 연결된 본인 주문과 서버의 실제 승인 근거가 일치할 때만 계산한다. 카드는 PG 승인, 무통장은 해당 주문·결제 시도의 운영자 입금 확인과 공통 결제 확정 원장이 함께 있어야 한다. 입금 확인만 있고 결제 시도가 확인 필요(needs_review)로 남은 경우는 전환이 아니다. 결제금액 0원 주문과 티켓은 이 보고서 범위에서 제외한다. 결제 성공 URL이나 클라이언트 이벤트로 만들지 않는다. 주문 생성/구매 결과는 선택 통계의 실패로 중단하거나 재실행하지 않는다. 금액·재고를 다루는 기존 finalizer는 변경하지 않는다.

## 보존

- 세션·사건·주문 연결은 오늘을 포함한 한국 날짜 기준 최근 90일, 세션·주문 식별자를 제거한 일별 합계는 13개월이다.
- 매 실행에서 오래된 날짜 최대 7일을 집계하고 원자료를 지운다. 원자료가 많은 경우 `retentionBacklog`를 확인한다. cron 장애 기간에는 삭제가 지연될 수 있으므로 복구 후 backlog가 0이 될 때까지 점검한다.
- 일별 합계의 `observedUntil`은 최종 관측 시각이다. 원자료 삭제 이후의 늦은 환불은 이 합계에 갱신되지 않는다. 보존 합계를 최신 정산금액으로 쓰지 않는다.
- 애플리케이션·인프라 접근 로그의 기존 정책과 이 전용 통계 원장은 서로 다른 범위다. 이 기능은 인프라 로그를 분석 데이터로 가져오지 않는다.
