# 카카오 알림톡 주문 안내 런북

구매 안내가 이메일로만 가던 문제(10/14 회의 1014-010의 카카오톡 수단)를 풀기 위해, 결제 확인과 발송 시작 때 주문한
회원의 카카오톡으로 알림톡을 한 번 더 보낸다. 발송사는 카카오 공식 딜러사인 NHN Cloud(KakaoTalk Bizmessage)이고, 발신
채널은 회사 카카오톡 채널 **엑스 스퀘어**(검색용 아이디 `xsquare`, `pf.kakao.com/_CVlrn`)다. 키·시크릿·발신 키 값은
이 문서·이슈·PR·로그에 남기지 않는다.

## 1. 지금 상태

| 항목 | 상태 |
| --- | --- |

**왜 NHN Cloud(딜러사)가 필요한가.** 카카오는 알림톡 발송 API를 가맹점에 직접 열지 않고 공식 딜러사를 통해서만 제공한다
(카카오비즈니스 알림톡 안내의 공식 딜러사 목록 — NHN Cloud·다우기술·인포뱅크 등). 카카오비즈니스 파트너센터의 '메시지'
메뉴는 채널 친구에게 사람이 직접 쓰는 광고성 메시지(브랜드 메시지)라, 주문마다 서버가 자동으로 보내는 정보성 안내에는 쓸 수
없다(2026-11-18 파트너센터 메뉴 확인: 메시지 보내기·내 메시지·메시지 활용예시·웰컴메시지·친구 그룹·고객 파일·비즈니스폼+).

스위치가 꺼져 있으면 아무것도 읽지 않고 아무것도 보내지 않는다(결제·출고·메일 흐름은 그대로다).

## 2. 동작

| 안내 | 언제 | 받는 사람 | 담는 것 |
| --- | --- | --- | --- |
| 주문 접수(`order_confirmation`) | 결제 확정 직후 — 카드·간편결제 승인(토스·나이스페이), 정기구매 승인, 어드민 무통장 입금 확인. 주문 확인 메일과 같은 자리 | 주문한 회원(선물 주문이면 선물한 분) | 주문번호, 굿즈 요약('첫 굿즈 외 N건'), 결제금액, 주문 상세 링크 |
| 발송 시작(`order_shipped`) | 배송 건이 발송되면 — 출고 메일 작업(`processOrderShipmentEmails`)과 어드민 단건 '배송중' 변경 | 주문한 회원. **선물 주문은 보내지 않는다** — 송장번호로 받는 분 주소를 조회할 수 있어 선물한 분 메일도 운송장을 가린다 | 주문번호, 그 배송 건의 굿즈 요약, 택배사, 송장번호, 배송 조회·주문 상세 버튼 |

- **받는 번호는 DB가 정한다.** `service_claim_kakao_alimtalk_delivery`가 주문의 회원을 찾아 인증 휴대폰
  (`private.member_phone_numbers`)을 읽는다. 정지·탈퇴 봉인 계정, 인증 번호가 없는 회원(휴대폰 인증 도입 전에 가입하고 아직
  등록하지 않은 회원), 국내 휴대폰(010·011·016~019)이 아닌 번호에는 보내지 않는다. 그 회원은 이메일만 받는다. 배송지의
  수령인 연락처는 쓰지 않는다(받는 분이 다른 사람일 수 있다).
- **사실성 게이트.** 메일과 같은 주문 상태 집합이다 — 접수 안내는 `paid·confirmed·shipping·delivered·done`, 발송 안내는
  `shipping·delivered·done`이고 배송 건이 `shipping·delivered`이며 택배사·송장번호가 있어야 한다.
- **한 번만 보내기.** 결제 확정 훅은 웹훅 재전송·재확정 복구로 여러 번 불린다. (안내, 주문, 배송 건)마다 장부
  `private.kakao_alimtalk_deliveries` 한 행을 클레임한 호출자만 보낸다.

  | 장부 상태 | 뜻 | 다음 호출 |
  | --- | --- | --- |
  | `pending` | 클레임해 보내는 중 | 15분 안이면 건너뜀, 넘으면 `unknown`(`claim_expired`)으로 닫음 |
  | `sent` | NHN이 받았다(HTTP 200, 수신자 결과 코드 0). `provider_request_id`에 NHN 요청 id | 다시 보내지 않음 |
  | `failed` | NHN이 확실히 받지 않았다(4xx, 결과 코드 실패) | 다시 클레임해 보냄(최대 5번) |
  | `unknown` | 받았을 수도 있다(시간 초과·네트워크·5xx·읽을 수 없는 응답) | **자동으로 다시 보내지 않음** — NHN 콘솔 발송 조회로 확인 |

  `sent`는 NHN 접수까지다. 카카오톡 도달 여부(카톡 미사용·차단 등)는 NHN 콘솔 발송 조회에서 본다. 장부에는 번호·본문을
  남기지 않는다(회원 id·주문·배송 건·상태·요청 id·오류 코드만).
- **기다리는 시간.** 결제 승인 응답 경로에서는 주문 확인 메일과 동시에 보내고, NHN 응답은 3초까지 기다린다(넘으면 `unknown`).
- **절대 throw하지 않는다.** 실패는 `[alimtalk] <안내> failed (order:<id>): <코드>` 또는 `not sent … <사유>` 로그로만
  남고, 결제 확정·출고 작업·메일 결과에 영향을 주지 않는다. 정상 건너뜀(꺼짐·이미 보냄·인증 번호 없음·국내 번호 아님·선물
  주문)은 로그를 남기지 않는다. 발송기 로그는 `[alimtalk:nhn] … status=<HTTP> code=<NHN 결과 코드>`뿐이다.

## 3. 템플릿 초안(심사 제출용)

정본은 `lib/kakao/alimtalk/templates.ts`이고 아래 글과 같아야 한다(`templates.test.ts`가 대조한다). 승인된 본문과 다르면
발송이 템플릿 불일치로 거절된다. 본문을 바꾸면 재심사를 받고 두 곳을 함께 고친다.

공통 설정: 메시지 유형 **기본형**, 강조 유형 **선택 안 함**, 보안 템플릿 아님. 카테고리는 콘솔 목록에서 '구매' 계열의 가장
가까운 항목(주문 접수 → 구매 완료, 굿즈 발송 → 배송 상태). 링크 도메인은 `xsquare.kr`로 고정한다 — 도메인 전환 전에는
`xsquare.kr`가 경로를 유지한 채 `iconsip.com`으로 넘어가고(307), 전환 뒤에는 정규 주소다. 그래서 전환 때 재심사가 필요 없다.

### 3-1. 주문 접수 안내 — 코드 제안 `XSQ_ORDER_PAID`

```text
[X SQUARE] 주문 접수 안내

주문이 접수됐어요.
결제가 확인되어 배송 준비를 시작합니다.

■ 주문번호: #{주문번호}
■ 주문 굿즈: #{굿즈명}
■ 결제금액: #{결제금액}원

굿즈가 발송되면 다시 알려 드릴게요.
```

| 버튼 | 유형 | 링크(모바일·PC) |
| --- | --- | --- |
| 주문 상세 보기 | 웹링크(WL) | `https://xsquare.kr/orders/#{주문ID}` |

### 3-2. 굿즈 발송 안내 — 코드 제안 `XSQ_ORDER_SHIPPED`

```text
[X SQUARE] 굿즈 발송 안내

주문하신 굿즈가 발송됐어요.

■ 주문번호: #{주문번호}
■ 발송 굿즈: #{굿즈명}
■ 택배사: #{택배사}
■ 송장번호: #{송장번호}

아래 [배송 조회] 버튼으로 배송 현황을 확인할 수 있어요.
```

| 버튼 | 유형 | 링크(모바일·PC) |
| --- | --- | --- |
| 배송 조회 | 배송 조회(DS) | (카카오가 본문의 택배사·송장번호로 연결) |
| 주문 상세 보기 | 웹링크(WL) | `https://xsquare.kr/orders/#{주문ID}` |

심사 메모: 두 템플릿 모두 주문한 회원 본인에게 그 주문의 접수·발송 사실만 알리는 정보성 메시지다. 쿠폰·이벤트·추천 문구가
없고, 이름·주소·연락처를 담지 않는다. 변수 예시 값: 주문번호 `2026111816050001`, 굿즈명 `메이플스토리 아크릴 키링 외 2건`,
결제금액 `32,000`, 택배사 `한진택배`, 송장번호 `512345678901`, 주문ID `5f0c…`(UUID).

## 4. 사람이 할 일(순서대로)

1. ~~채널 고객센터 연락처 고치기~~ — 2026-11-18 `https://xsquare.kr`로 바꿨다.
2. **NHN Cloud 가입.** 사업자 회원((주)아이콘스)으로 가입 → 결제 수단 등록 → 조직·프로젝트 생성 → Notification >
   KakaoTalk Bizmessage 서비스 활성화. 콘솔의 **URL & Appkey**에서 앱 키와 시크릿 키를 확인한다.
3. **발신 프로필 등록.** KakaoTalk Bizmessage → 발신 프로필 관리 → 등록: 검색용 아이디 `@xsquare`, 관리자 휴대폰 번호(채널
   관리자 카카오 계정에 등록된 번호), 카테고리. 인증 토큰이 그 관리자 카카오톡으로 오면 입력한다. 등록되면 **발신 키**
   (40자)가 생긴다. 옛 Cafe24 몰이 이 채널을 다른 딜러사에 발신 프로필로 등록했더라도 NHN 등록은 따로 된다(추정 — 막히면 NHN에 문의).
4. **템플릿 등록·심사.** §3의 두 템플릿을 그대로 등록하고 검수를 요청한다. 승인되면 템플릿 코드를 기록한다.
5. ~~처리방침 개정 날짜~~ — 2026-11-19 공지·2026-11-26 시행으로 배포했다(§6). 시행일 0시(KST)부터 방침 본문이 바뀌고
   운영 게이트가 같은 날 열린다. `/legal/*`은 300초 ISR이라 시행일 0시 직후 방침 화면을 한 번 열어 재생성한다.
6. **env**(§5)를 Vercel Production·Preview에 넣고 마지막에 스위치를 켠 뒤 재배포한다.
7. **확인.** 직원 테스트 계정(인증 휴대폰 등록)으로 실제 결제 → 주문 접수 알림톡 1통, 같은 결제 웹훅이 다시 와도 1통 →
   발송 처리 → 발송 알림톡 1통(배송 조회 버튼이 택배사 화면으로 가는지). 장부 확인은 §7.

## 5. env(서버 전용)

| 이름 | 값 |
| --- | --- |
| `NHN_ALIMTALK_APP_KEY` | NHN 콘솔 KakaoTalk Bizmessage 앱 키 |
| `NHN_ALIMTALK_SECRET_KEY` | NHN 콘솔 시크릿 키(`X-Secret-Key`) |
| `NHN_ALIMTALK_SENDER_KEY` | 엑스 스퀘어 발신 프로필의 발신 키(40자) |
| `NHN_ALIMTALK_TEMPLATE_ORDER_CONFIRMATION` | 승인된 주문 접수 템플릿 코드(비우면 이 안내만 보내지 않는다) |
| `NHN_ALIMTALK_TEMPLATE_ORDER_SHIPPED` | 승인된 발송 템플릿 코드(비우면 이 안내만 보내지 않는다) |
| `ICONS_KAKAO_ALIMTALK_ENABLED` | 마지막에 `true` |

키 모양이 어긋나거나(앱 키 영숫자 8~64자, 시크릿 키 영숫자 6~128자, 발신 키 영숫자 40자, 템플릿 코드 20자 이하)
템플릿 코드가 하나도 없으면 전체가 꺼진다(fail closed). Preview는 처리방침 게이트 없이 env만으로 열리므로, 실제 회원에게
가지 않게 Preview에는 스위치를 켜지 않거나 테스트 번호만 인증된 계정으로 시험한다.

## 6. 처리방침 개정(코드에 있음, 법무 확인 전)

2026-11-18 시행본 제2조는 "휴대폰 번호 인증으로 확인한 번호는 … 문자 메시지를 통한 알림·거래 안내·마케팅 정보 발송에는
이용하지 않습니다"라고 고지하고, 거래 안내 수단은 "알림함·이메일"뿐이다. 알림톡은 그 번호로 주문 안내를 보내고 번호를 발송
대행사·카카오에 넘기므로 아래 개정이 시행돼야 운영에서 켤 수 있다. 본문 변환은 `lib/legal/documents.ts`의
`reviseAlimtalkPrivacyArticles`, 일정은 `lib/legal/alimtalk-privacy-revision.json`이다.

- **제2조(처리 목적)**: '알림함·이메일을 통한 거래 진행 안내와 서비스 공지' → '알림함·이메일·카카오톡 알림톡을 통한 거래 진행
  안내와 서비스 공지'. 마무리 문장을 '휴대폰 번호 인증으로 확인한 번호는 위 목적과, 주문한 회원 본인에게 주문 접수·굿즈 발송
  사실을 알리는 카카오톡 알림톡 발송에만 이용합니다. 문자 메시지를 통한 알림·거래 안내와 마케팅 정보 발송에는 이용하지
  않습니다.'로 바꾼다.
- **제5조(처리위탁) 표**: 'Resend' 행 다음에 '엔에이치엔클라우드 주식회사 — 카카오톡 알림톡(주문 접수·굿즈 발송 안내) 발송 대행',
  '주식회사 카카오 — 카카오톡 알림톡 전달'(둘 다 위탁계약 종료 시까지)을 더한다. 마무리 문장에 '알림톡 수탁자에는 인증한 휴대폰
  번호와 안내 내용(주문번호, 주문 굿즈 이름, 결제금액, 택배사와 운송장번호, 주문 상세 주소)만 전달됩니다'를 더한다.
- 두 수탁자 모두 국내 처리라 제6조(국외 이전)는 바꾸지 않는다. 카카오를 수탁자로 적을지(알림톡 전달 사업자로서의 지위)는
  법무와 정한다(추정 — 공식 문서로 확인하지 못함).
- **일정**: 공지일은 실제 운영 배포일(KST), 시행일은 공지일 + 7일 이상(방침 제13조). production 빌드 가드
  (`scripts/check-vercel-build-env.mjs`)가 형식과 7일 간격을 검사한다. 공지 기간에는 방침 화면에 개정 예정 안내가 붙고,
  시행일부터 본문이 바뀌며 직전 본문은 이전 판으로 남는다. `KAKAO_ALIMTALK_PRIVACY_EFFECTIVE_DATE`가 같은 시행일을 읽는다.

## 7. 운영 확인

장부(운영 DB, 읽기 전용 질의):

```sql
select template, order_id, shipment_id, status, attempt_count, error_code, provider_request_id, claimed_at, completed_at
from private.kakao_alimtalk_deliveries
order by claimed_at desc
limit 50;
```

- `unknown`이 쌓이면 NHN 콘솔 발송 조회에서 요청 시각으로 실제 발송 여부를 본다. 다시 보내는 화면은 아직 없다.
- `failed`의 `provider_http_401`·`provider_http_403`은 키, `provider_result_*`는 요청 거절(발신 키·템플릿 코드),
  `recipient_result_*`는 수신자 단위 거절(템플릿 변수 불일치 등)이다. 설정을 고치면 다음 훅 호출이 다시 보낸다.

## 8. 아직 하지 않은 것

- 선물 받는 분에게 보내는 알림톡(이메일만 간다)과 선물 주문의 발송 안내.
- 알림톡 실패 시 문자 대체 발송(NHN SMS 발신번호 등록과 방침 개정이 필요하다). 지금은 요청마다 `resendParameter.isResend=false`로
  대체 발송을 끈다 — NHN 콘솔에서 대체 발송을 켜 두면 이 값이 없는 요청에도 적용되기 때문이다. 알림톡이 실패한 회원은 이메일만 받는다.
- 해외 휴대폰 번호, 인증 번호가 없는 회원.
- 어드민 발송 이력 화면·재발송 버튼(메일의 발송 이력 화면 같은 것).
- 발송 되돌리기(ADR-0045) 뒤 같은 배송 건을 다시 발송해도 발송 알림톡은 다시 가지 않는다 — 장부가 (안내, 주문, 배송 건)마다
  한 번이라 발송 메일 원장과 같다. 잘못된 운송장이 담긴 알림톡은 회수할 수 없으니 되돌리기 결과 문구대로 고객에게 직접 안내한다.
