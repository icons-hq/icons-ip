# X SQUARE 스토어 개편 — 배포 뒤 운영 입력

2026-11-17 · [ADR-0043](../adr/0043-xsquare-figma-storefront.md) · 신사업팀 Figma(2026-11-12) · 디자인 정본 `DESIGN.md` §14

코드는 새 홈·목록·POP-UP·EVENT의 **틀과 기본 순서**만 만든다. 어느 IP·어느 배너·어느 문구를 보일지는 운영 데이터이므로 배포 뒤 사람이 어드민에서 입력해야 Figma와 같은 화면이 된다. 아래 8가지가 빠지면 화면이 비거나 옛 데이터로 새 틀에 그려진다(배포 직후 운영 홈은 지금 데이터로 그려지고, 히어로는 1장이면 넘어가지 않는다). 카테고리 분류는 [storefront-categories](storefront-categories.md)를 따른다.

권장 이미지 크기는 **화면 크기의 2배**이며 JPEG·PNG·WebP를 올린다. 문구는 가능하면 이미지에 넣지 말고 입력 칸에 적는다(이미지가 늦거나 실패해도 읽힌다). Figma에서 내보낸 배너 이미지는 문구가 그림에 들어 있을 수 있다 — 그런 이미지를 올릴 때는 제목·내용 칸(컬렉션 배너는 배너 문구·부제)을 비우고, 그림 속 문구를 이미지 대체텍스트에 적는다. 둘 다 있으면 같은 글자가 조금 어긋나 겹쳐 보인다. 컬렉션 배너는 배너 문구를 비우면 대체텍스트가 필수이고 부제를 쓸 수 없다(20261125100000).

| # | 입력 | 어디서 | 권장 이미지 |
|---|---|---|---|
| 1 | 프로모션 배너(히어로) 2장 이상 | `/admin/display/curations` → 구성 추가 → 프로모션 배너 | PC 2544×1080, 모바일 1000×1200 |
| 2 | IP 바로가기 4개 | 같은 화면 → 추천 콘텐츠 | 530×360 |
| 3 | 홈 스트립 배너 1개 | 같은 화면 → 홈 스트립 배너 | 2544×340 |
| 4 | 상품 모음 '그리드형(5열)' 2개 | 같은 화면 → 상품 모음 | (선택한 상품의 대표이미지) |
| 5 | ICONS PICK 카드 3개 | 같은 화면 → 기획전 배너 | 816×520 |
| 6 | 홈 영역 순서·노출 | 같은 화면 → 영역 순서·노출 | — |
| 7 | 텍스트 공지 바(롤링) 문구 1개 이상 | 같은 화면 → 텍스트 공지 바 | (이미지 없음) |
| 8 | 메뉴·사업자 정보·SNS 확인 | `/admin/settings/store` | — |

모든 구성은 저장 뒤 **이 구성 적용하기**로 적용하고, 홈 영역 순서는 별도로 저장한다. 노출 기간·노출 여부도 함께 적용된다.

## 1. 프로모션 배너(히어로) — 2장 이상

자동 슬라이드(5초)가 보이려면 **2장 이상** 등록한다. 1장이면 넘어갈 게 없어 진행 막대와 이전·다음·일시정지가 그려지지 않는다. 최대 10장(비노출·예약·종료 포함).

- 이미지: PC 2544×1080(화면 1272×540, 모서리 둥근 박스), 모바일 1000×1200(5:6). 모바일 이미지가 없으면 PC 이미지를 쓴다.
- 문구(선택): **내용**은 왼쪽 아래 작은 윗줄(21px), **제목**은 그 아래 큰 줄(36px)이다. 글자색은 흰색 또는 검정을 고르고, 글이 읽히도록 이미지 딤(적용안함·흰색·검정)을 정한다. 딤을 정하지 않은 기존 배너는 문구가 있을 때 아래쪽에 어두운 그라데이션이 깔린다.
- 손으로 장을 옮겨도 자동 넘김은 꺼지지 않는다. 멈추려면 일시정지 버튼을 누르거나 마우스를 올리거나 포커스를 둔다(움직임 줄이기 설정에서는 자동으로 넘어가지 않는다).

## 2. IP 바로가기 4개

홈 배너 바로 아래 줄이다. 추천 콘텐츠 구성 4개를 만든다: 이미지 **530×360**(화면 265×180), **배지 문구 = IP 이름**(작은 회색 줄), **제목 = 문구**(아래 줄), 이동할 화면 = 그 IP관. 4개면 가운데 정렬로 한 줄에 놓이고 모바일은 2열이다. 설명은 새 화면에 보이지 않는다. 4개보다 적게 두면 그만큼만 보인다.

## 3. 홈 스트립 배너 1개

본문 가운데 가로로 긴 이미지다. 구성 추가 → **홈 스트립 배너**(옛 공지 배너 종류)에서 이미지(**2544×340**, 화면 1272×170)와 이동할 화면을 정한다. **이미지와 이동할 화면이 둘 다 필수**다. 모바일에서는 같은 이미지가 줄어들어 보인다(모바일 이미지는 따로 없다). 제목은 화면에 보이지 않고 이미지의 대체 텍스트가 되니 이미지 안의 문구를 적는다. 노출 중인 배너가 여러 개면 순서가 앞선 하나만 보인다.

## 4. 상품 모음 '그리드형(5열)' 2개

홍실퀘스트·메이플스토리처럼 IP별 상품 줄이다. 상품 모음 구성에서 레이아웃을 **그리드형(5열)**, 제목(15자 이내, 예: "홍실퀘스트"), 노출 개수 **5개 또는 10개**를 고르고 상품을 직접 고른다. 사진 비율은 정사각으로 고정된다. 고른 상품이 **모두 한 IP**면 제목 옆 '전체보기'가 그 IP관으로 이어지고, 여러 IP를 섞으면 '전체보기'가 나오지 않는다. 자유상품·모자이크와 합쳐 최대 5개(비노출 포함)까지 만들 수 있다.

## 5. ICONS PICK 카드 3개

기획전 배너 구성 3개: 배너 이미지 **816×520**(화면 408×260), 제목, 이동할 화면, 상품 **2개 이상**(앞 2개가 카드 아래에 나온다). 설명은 보이지 않는다. 홈 영역 순서에서 **연달아** 놓인 기획전은 한 줄(3열)로 묶이고, 사이에 다른 영역이 끼면 각각 따로 보인다 — 6번에서 세 개를 붙여 둔다.

## 6. 홈 영역 순서

영역 순서·노출에서 Figma와 같은 순서로 맞춘다:

1. 프로모션 배너 → 2. IP 바로가기 → 3. NEW ARRIVAL(최신 상품 자동 — 최신 등록 10개, 전체보기 → `/shop/new`) → 4. 홈 스트립 배너 → 5. 홍실퀘스트 모음 → 6. 기획전 3개(연달아 = ICONS PICK) → 7. 메이플스토리 모음.

그 밖의 영역(카테고리 BEST·인기템·혜택·쇼핑스토리·판매 BEST·리뷰 BEST·모자이크 등)은 **노출을 끈다**. Figma에 없는 섹션이라 켜 두면 새 틀 아래에 옛 섹션이 이어진다. 저장된 레이아웃이 있으면 배포 migration이 NEW ARRIVAL·홈 스트립 배너를 IP 바로가기 바로 뒤에 켜진 상태로 끼워 두므로(운영자가 숨긴 키는 건드리지 않는다) 순서만 확인·조정한다. 전체 순서의 오래된 버전은 409로 거절되니 충돌하면 최신 상태를 다시 읽고 의도한 변경을 다시 적용한다.

## 7. 롤링 텍스트 공지 바

스토어 맨 위 빨간 띠다. 텍스트 공지 바 구성에서 문구(60자, 줄바꿈 없음)와 선택 링크(이동할 화면을 고르면 버튼 문구 12자)를 입력하고 공지를 보일 화면(홈·상품 목록·상품 상세·쇼핑스토리/이벤트·그 밖)을 정한다. **1개 이상** 있어야 띠가 보인다. 문구는 띠 안에서 흘러가고 여러 개를 두면 스토어를 새로 열 때마다 하나가 **무작위**로 보인다(같은 화면 유형 안에서). 고객이 닫으면 같은 브라우저 탭 동안 그 화면 유형의 공지가 모두 닫힌다. 마우스를 올리거나 포커스를 두면 멈추고, 움직임 줄이기 설정에서는 흐르지 않는다.

## 8. 메뉴·사업자 정보·SNS 확인

`/admin/settings/store`에서 확인한다.

- **공개 메뉴**(`?section=navigation`): NEW·BEST·카테고리·**POP-UP·EVENT**가 노출이고 **쇼핑스토리·온라인 팝업·카드팩·커뮤니티는 숨김**(MD-0035)인지. 배포 migration이 옮겼지만 운영자가 먼저 손댄 설정은 쇼핑스토리만 숨기고 나머지를 보존하므로 이름·순서를 눈으로 확인한다.
- **사업자·CS 연락처**: 푸터에 보이는 대표 이메일. Figma 시안은 `xsquare@…` 주소를 쓰는데 현재 기본값은 다르므로 바꿀지 결정해 입력한다(코드가 정하지 않는다). 상호·사업자등록번호·통신판매업·전화·호스팅도 법정 표기라 틀리지 않게 확인한다.
- **브랜드·SNS**(`?section=branding`): 푸터 인스타그램 아이콘은 여기서 주소를 입력하고 노출을 켠 경우에만 보인다. 블로그·페이스북은 글자 링크다. X(구 트위터)는 설정 항목이 없어 푸터에 그리지 않는다(후속). 로고는 업로드 로고가 없고 표시 이름이 ICONS일 때 기본 X SQUARE 로고가 쓰인다.

## 목록·POP-UP·EVENT 입력(참고)

| 대상 | 어디서 | 권장 이미지 |
|---|---|---|
| NEW·BEST·굿즈샵 전체 상단 배너 | `/admin/display/curations` → 컬렉션 배너(슬롯 선택). Figma 배너처럼 문구가 그림에 든 이미지는 배너 문구를 비우고 대체텍스트에 그 문구를 적는다 | PC 2544×680(화면 1272×340), 모바일 750×350(없으면 PC 이미지를 같은 비율로 줄인다) |
| 카테고리 전시 배너 | `/admin/display/categories` → 구성 → 배너 | PC 2544×680, 모바일 750×350 |
| EVENT 맨 위 배너 | `/admin/display/campaigns` → '이벤트 목록 배너 이미지 경로' + '배너 순서'(비우면 배너에 안 나온다). 이미지만 보이며 링크 이름은 캠페인 제목 | 2544×680 |
| EVENT·POP-UP 카드 | 캠페인의 '목록 카드 이미지 경로'(없으면 배너 → 상세 상단 이미지 순) | 816×520(화면 408×260) |

어드민의 컬렉션 배너 안내 문구에 이전 치수(굿즈샵 전체 2880×1160, BEST·NEW 2360×520)가 남아 있으면 이 표를 따른다 — 새 틀에서는 세 슬롯 모두 같은 1272×340이다.

### POP-UP·EVENT에 무엇을 싣나

`/admin/display/campaigns`에서 저장된 캠페인을 열면 캠페인 폼 아래에 **노출 설정** 패널이 있다(`promotion.manage`). 저장은 캠페인 저장과 별개다.

- **POP-UP에 싣기**: `싣지 않음 — EVENT에 보입니다`(기본) / 온라인 / 오프라인 / 온·오프라인. 고르면 그 캠페인은 EVENT에서 빠지고 `/popups`에 실린다(게시되고 진행 중이거나 오픈 예정일 때). 장소(120자, 선택)는 카드 메타 줄과 상세 머리에 보인다.
- **카드·배너 바로가기**(300자, 선택): 사이트 안 경로(`/`로 시작)만. 비우면 캠페인 페이지로 가고, 상품·IP관·카테고리 주소를 넣으면 EVENT 카드와 배너(POP-UP이면 POP-UP 카드)가 그곳으로 바로 간다. 'Figma Event의 마케팅 중인 제품·IP' 요청이 이 칸이다.
- **오프라인 팝업**(`/admin/catalog/events`의 예매 도메인)은 모드 '오프라인'이고 상태가 진행중·예매중·예정이며 종료 시각이 지나지 않은 것이 자동으로 `/popups`에 실린다. 온라인 모드 `events`는 싣지 않는다 — 온라인은 POP-UP 캠페인으로 등록한다. 예매가 있는 팝업을 캠페인으로도 소개하려면 캠페인 랜딩의 이동 버튼 블록에 `/offline-popups/<id>`를 건다.
- 진행 중인 POP-UP이 없으면 `/popups`는 빈 상태("진행 중인 POP-UP이 없어요")를 보인다. 메뉴는 항상 보인다.
- EVENT는 POP-UP이 아닌 게시 캠페인 중 진행 중·오픈 예정만 보이고 종료된 캠페인은 빠진다. 이미 EVENT로 공유된 POP-UP 캠페인 링크(`/events/<id>`)는 `/popups/<id>`로 영구 이동한다.

## 확인 체크리스트

1. 홈 — 맨 위 빨간 띠(흐름), 히어로 자동 넘김과 진행 막대, IP 바로가기 4개, NEW ARRIVAL 5×2, 스트립 배너, 그리드형 두 줄, ICONS PICK 3열, 푸터.
2. 헤더 — X SQUARE 로고, NEW·BEST·카테고리·POP-UP·EVENT, 검색을 연 채로 장바구니·마이 이동.
3. `/shop/new`·`/shop/best`·`/shop` — 스트립 배너, 제목·탭, 정렬, 5열(NEW는 셀렉트 없음).
4. `/popups`·`/events` — 카드 3열, 오픈 예정 배지, 빈 상태.
5. 모바일 375px에서 위를 다시 본다.
6. BEST의 첫 줄이 판매 랭킹으로 보이는지 — 시뮬레이션 가주문이 결제 승인 상태로 남아 있으면 순위가 왜곡되므로 먼저 정리 여부를 확인한다.
