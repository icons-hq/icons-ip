# 지역 추가 배송비 운영

대상: [#493](https://github.com/icons-hq/icons-ip/issues/493), [#177 H6](https://github.com/icons-hq/icons-ip/issues/177)의 실제 출고지·물류사 회신. 설정 화면은 `/admin/settings/shipping-regions`다. staff는 조회하고, 활성 admin만 초안 저장·활성화·중단할 수 있다. 각 변경과 확인한 원본 참조를 감사 로그에 남긴다.

## 현재 확보한 사실과 도입 경계

실제 지역표·추가료·무료/묶음 적용 기준을 초기 데이터로 넣지 않았다. 2026-09-10 확인한 #177에는 필요한 H6 확정 회신이 없다. 코드와 자동 검증용 가상 우편번호·금액은 실제 물류 계약을 대신하지 않는다. 다른 #177 인수 항목의 완료를 이 기능의 선행 조건으로 확대하지 않는다.

지역 정책을 도입하지 않은 출고지는 기존 출고지 기본료·무료 기준·상품별 무료/개별 배송비로 주문을 확정한다. 내부 값은 `legacy_base_only`, `regionalContractFee: null`, `regionalFee: 0`이다. 실제 계약 추가료를 0원으로 확인했다는 의미가 아니며, 고객에게는 “표시된 배송비로 주문이 확정됩니다.”라고 안내한다. 확정 주문에 사후 지역료를 추가하지 않는다.

최초 활성 정책의 적용 시작부터 해당 출고지는 지역 정책이 필수다. 이를 `private.shipping_region_adoptions.managed_from`에 보존한다. 정책 만료·중단·택배사 불일치가 발생해도 이전 방식으로 자동 복귀하지 않으며 신규 주문을 차단한다. 미래에 시작하는 최초 정책은 시작 전까지 기존 배송비를 유지한다. 활성화했다가 시작 전에 중단해도 예정된 도입 시각은 남으므로, 그 시각부터 적용할 대체 정책을 준비해야 한다.

## 원본 수령 후 등록

1. 출고지와 실제 계약 택배사를 선택한다. 활성화 시 출고지의 현재 기본 택배사, 계약 택배사, 택배사의 활성 상태가 일치해야 한다.
2. 원본 회신·계약을 찾을 수 있는 사내 문서번호 또는 접근 제한 문서 주소를 입력한다. 이 값은 고객 견적·주문 배송 안내에 공개하지 않는다.
3. 한국 시각 기준 적용 시작·종료 일시를 입력하거나 무기한을 명시한다. 시작은 포함하고 종료는 포함하지 않는다. 같은 출고지·택배사의 활성 기간은 겹칠 수 없다.
4. 실제 표를 스프레드시트에서 6열 TSV로 붙여넣는다. 우편번호를 텍스트로 다루어 선행 0을 보존한다. 최대 1,000행이다.
5. 표에 없는 지역이 ‘추가료 없음’인지 ‘개별 확인 필요’인지 선택하고, 부과 단위와 아래 무료/묶음 관계를 모두 확인한다.
6. 초안을 저장하고 지역표 미리보기를 검토한다. 필수 값과 원본 확인 체크가 갖춰진 저장본만 활성화할 수 있다. 공란·미확정 값은 초안으로 저장할 수 있다.

지역표 열은 다음과 같다.

| 열 | 입력 계약 |
| --- | --- |
| 우편번호 시작·끝 | 각각 5자리. 구간 양 끝을 포함한다. |
| 주소 시작문구 | 선택값. 공백을 정리한 기본주소와 시작 단어 경계가 정확히 일치해야 한다. |
| 지역명 | 결제 전 안내와 주문 당시 배송 기록에 표시되는 명칭. |
| 처리 | 추가료 없음 / 추가료 부과 / 배송 불가 / 개별 확인 필요. |
| 추가료 | 추가료 부과 행만 0~1,000,000원의 정수. 명시적 0원과 공란은 다르다. 나머지 처리 행은 비운다. |

우편번호 구간이 겹치면서 주소 조건도 함께 적용될 수 있는 행은 활성화할 수 없다. 같은 우편번호에 서로 다른 구체적 주소 시작문구를 쓰는 것은 가능하다. 다만 그 우편번호에 해당하면서 어느 주소 시작문구에도 일치하지 않는 주소는 ‘개별 확인 필요’가 된다. 표 외 지역을 ‘추가료 없음’으로 선택했어도 이 모호한 주소는 통과하지 않는다. 주소 검색·지오코딩 서비스를 대신하는 판정은 아니며, 입력한 기본주소의 정확한 조건만 사용한다.

표가 비어 있으면 실제 회신에 예외 지역이 없음을 별도로 확인해야 한다. 빈 표를 시스템이 임의로 무료 정책으로 해석하지 않는다.

## 무료·묶음·개별 배송 관계

다섯 가지 항목 모두 실제 계약 근거에 따라 선택해야 활성화된다. 미확인을 임의의 기본값으로 채우지 않는다.

| 항목 | 의미 |
| --- | --- |
| 부과 단위 | 출고지 배송 건당 1회 또는 대상 상품당 1회. 상품당일 때 옵션 수·수량을 곱하지 않는다. |
| 정책 배송비 상품 부과 | 출고지 정책을 따르는 상품에 지역료를 부과할지 결정한다. |
| 무료 기준 도달 시 면제 | 정책 상품의 할인 전 합계가 출고지 무료 기준을 채웠을 때만 해당 정책 상품을 지역료 대상에서 뺀다. 기본 배송비 자체가 0원인 것은 별도 면제 근거가 아니다. |
| 무료배송 상품 부과 | 상품이 무료배송이어도 지역료를 부과할지 결정한다. |
| 개별 배송비 상품 부과 | 상품당 개별 배송비 외에 지역료를 더할지 결정한다. |

배송 건당 부과는 적용 대상 상품이 하나라도 있으면 한 번 부과한다. 상품당 부과는 대상 상품의 서로 다른 상품 ID 수를 센다. 무료 기준을 채운 정책 상품과 지역료 대상 개별 상품이 섞이면 개별 상품에 대한 지역료는 남는다. 배송 불가·개별 확인 필요 판정은 무료배송 상품도 차단한다.

## 변경과 조회

활성 정책의 내용을 수정하지 않는다. 기존 정책으로 새 버전 초안을 만들고 적용 기간과 실제 원본을 다시 확인한다. 종료 일시가 있는 기존 버전의 종료와 새 버전의 시작을 맞추면 이어서 적용된다. 무기한 정책을 즉시 교체하려면 대체 초안을 먼저 저장한 뒤 기존 버전을 중단하고 새 버전을 활성화한다. 두 상태 변경 사이에는 신규 주문이 차단될 수 있으며, 이를 조용히 기존 배송료로 통과시키지 않는다.

주소 없는 장바구니는 기존 기본료를 참고 견적으로 보여줄 수 있다. 지역 정책을 도입한 출고지가 포함되면 `checkoutAllowed: false`, `finalTotalFee: null`이며 배송지 입력 후 확정한다. 견적의 `nextChangeAt`은 다음 정책 시작·종료 시각을 포함한다. 쿠폰의 최소 결제액 제한과 적립금 사용 가능액도 최종 지역 배송비를 포함해 계산한다.

서버 주문 계산은 저장한 주문 주소와 주문 품목의 출고지·배송 유형 스냅샷을 읽는다. 출고지 ID 순서의 공유 잠금은 지역 정책 활성화·중단의 출고지 갱신 잠금과 맞물린다. 지역 정책·금액·적용 단위·대상 상품 수·우편번호·일치한 주소 시작문구를 `orders.shipping_fee_breakdown`과 배송 건의 `shipping_fee_snapshot`에 고정한다. 전체 기본주소는 이미 주문 주소에 있으므로 지역 스냅샷에 중복 저장하지 않는다.

고객 주문 상세는 확정 배송비와 포함된 지역 추가료·지역명을 표시한다. 운영 주문 상세는 정책 버전·계약 추가료·부과 건수까지 표시한다. 이전 주문에 지역 스냅샷이 없으면 현재 정책을 추정해 채우지 않는다. 이후 정책·기본 택배사·금액 변경은 과거 주문에 영향을 주지 않는다.

상품 엑셀, 상품 복제, 기존 상품 입력 복구는 이 설정의 저장 경로가 아니다. 지역표는 출고지·택배사 계약에 속하므로 별도 설정과 TSV 붙여넣기로 관리하며, 개별 상품의 기존 배송 유형은 그대로 소비한다. 화면의 저장 실패는 현재 입력을 보존하고 저장된 초안은 다시 조회할 수 있다. 원본 참조를 브라우저 영구 저장소에 복제하지 않는다.

## 검증

`lib/shipping-regions.test.ts`, `lib/admin/shipping-regions.test.ts`와 action/화면 검증은 미확인 금액, 합계 변조, 주소 시작 경계, 활성화 필수값, TSV 선행 0·공란 보존을 다룬다. `supabase/tests/shipping_regions.sql`은 우편번호 경계, 주소 조건 불일치, 서로 다른 출고지, 옵션·수량 합산, 무료/개별 관계, 쿠폰·적립금, 실제 주문·배송 스냅샷, 정책 교체·만료·택배사 변경, 권한·감사를 확인하고 모든 합성 행을 롤백한다. 이 검증의 통과는 실제 H6 회신의 확보를 뜻하지 않는다.
