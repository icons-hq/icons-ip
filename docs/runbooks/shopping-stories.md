# 쇼핑스토리 운영

쇼핑스토리는 카드팩·이벤트 캠페인과 별도인 콘텐츠 원장이다. 운영 경로는 `/admin/display/stories`, 공개 경로는 `/stories`와 `/stories/[UUID]`다. `store.manage` 권한이 목록·수정·삭제·관련상품 검색을 함께 통제한다. 원본 비교 근거는 [마케팅 링크·쇼핑스토리 계약](../research/smartstore-admin/marketing-story-parity.md)이다.

## 등록과 공개

제목은 Unicode 문자 기준 1~50자, 본문은 정리 후 최대 30,000자이고 텍스트 또는 업로드한 이미지가 있어야 한다. 글쓰기 도구에서 제목·문단·강조·목록·인용·표·구분선을 넣을 수 있다. HTML 가져오기는 같은 허용 목록으로 정리한 뒤 본문에 넣는다. 외부 링크, 운영/API 경로, 외부 이미지, 스크립트·스타일·임베디드 콘텐츠는 제거된다. 내부 공개 링크만 허용한다.

정렬(왼쪽·가운데·오른쪽)과 글자 크기(12·14·16·20·24·32·40px)는 현재 문단이나 선택한 문단에 적용한다. 굵게·기울임·밑줄·취소선은 선택한 글에 적용하며 해제 토글은 아니다. 인용 5종·구분선 8종은 상품 상세설명과 같은 서식 값을 사용한다. 전체 서식 작업의 브라우저 기본 실행 취소 이력은 보장하지 않는다.

**개인 본문 템플릿**은 현재 운영자만 사용하는 글·서식 원장이다. 상품 편집기와 함께 사용하며 이미지·문서 제목·관련상품·기간은 저장하지 않는다. 보관함을 포함해 50개, 이름 50자, 텍스트가 있는 본문 30,000자까지다. 선택 위치에 넣거나 확인 후 본문 전체를 바꾸며, 적용 후 본문이 바뀌지 않았을 때만 직전 적용을 되돌린다. 템플릿 저장과 스토리 저장은 별도다. 상품의 외부 링크는 스토리에 적용할 때 제거한다. 계정·세션·본문이 바뀌면 이전 창의 적용을 거부하며 불명확한 저장은 같은 요청으로 확인한다. 자세한 경계와 실제 결과는 [공통 서식·개인 템플릿 검증](../research/smartstore-admin/body-format-templates-implementation-qa.md)을 따른다.

본문 이미지에는 기존 `curation` 업로드 검증·일회용 claim을 사용한다. 새 이미지 저장은 현재 매니저가 업로드한 미만료·검증 완료 claim을 소비하며, 이미 해당 스토리에 저장된 이미지 경로는 수정 시 유지할 수 있다. 본문 이미지는 실제 등장 횟수 최대 20장이다. 공개 렌더링은 저장된 첨부 경로에 포함된 이미지만 허용한다. 삭제된 스토리도 이미지 참조와 감사 이력을 보존한다.

목록 대표이미지는 정리된 본문에서 첫 번째로 남은 이미지, 설명은 정리된 본문의 첫 160자다. 이미지가 없으면 텍스트 카드로 노출하고 임의 이미지를 만들지 않는다. 이미지뿐인 본문은 설명을 생략한다. PC·모바일 미리보기는 공개 화면과 동일한 본문 정리·렌더러를 사용한다. 관련상품의 최종 판매가·재고·공개 상태는 공개 요청 시 다시 계산한다.

## 전시기간과 정렬

- 입력·표시 시간대는 한국 시각이다. 저장은 절대 시각으로 처리한다.
- 시작 시각을 포함하고 종료 시각은 포함하지 않는다. 시작 전은 **전시대기**, 시작 후·종료 전은 **전시중**, 종료 시각부터는 **전시중지**다.
- 시작을 비우면 즉시, 종료를 비우면 무기한 공개한다. 별도 비노출 스위치는 없으며 종료 시각을 지정해 내린다.
- 공개 목록은 등록일 내림차순, 같은 등록 시각은 UUID 내림차순이다. 수정해도 공개 순서가 바뀌지 않는다.
- 홈에는 현재 공개 중인 최신 3개를 보여준다. 공개 목록·상세·홈은 요청마다 기간을 확인하고 열려 있는 화면도 다음 시작/종료 경계에서 갱신한다.
- 홈 영역 편집기에서 쇼핑스토리 영역 전체 순서와 표시 여부를 바꿀 수 있다. 개별 스토리의 최신순은 바뀌지 않는다.

목록 기본 검색기간은 최근 3개월, 기본 표시 수는 100개다. 제목·전시상태·등록기간·정렬·페이지로 범위를 좁힐 수 있다. 기간 필터는 한국 시각의 시작일 00:00부터 종료일 다음 날 00:00 직전까지다.

## 관련상품

섹션은 최대 10개, 제목은 1~13자, 섹션마다 상품 1~200개, 스토리 전체는 최대 300개다. 같은 상품은 스토리 전체에서 한 번만 선택한다. 섹션과 상품을 위·아래 버튼으로 순서 변경하고 정사각형/세로 직사각형 상품 이미지를 선택한다. 관련상품이 필요 없다면 섹션을 만들지 않는다.

상품 검색은 상품명·상품코드·내부 식별자를 대상으로 하며 20개씩 표시한다. 저장은 새로 보관된 상품/IP를 추가하지 못하게 한다. 비공개 상품은 미리 선택해 둘 수 있다. 기존에 연결된 상품이 이후 보관되면 참조는 유지할 수 있지만 공개 화면에서는 제외한다. 공개에는 상품과 IP가 모두 공개·미보관이고 판매 제한이 없는 상품만 표시한다. 품절 상품은 품절 표시와 함께 남긴다. 공개 전 상품의 내부 식별자·URL이 변경되면 FK가 새 식별자로 따라가며, 상품이 영구 삭제되면 해당 연결을 제거한다.

상품 선택기는 검색 항목, 카테고리(하위·추가 배정 포함), 공개 상태, 판매 가능 여부, 일반/예약 판매, 가격 범위, 할인, 무료배송, 리뷰 유무와 최소 평점을 조합한다. 검색과 페이지를 바꾸어도 선택한 상품은 유지되며 현재 페이지 일괄 선택과 선택 상품 일괄 추가를 제공한다. 섹션·전체 잔여 한도와 기존 선택 상품의 중복을 함께 검사한다.

- 가격 필터·정렬은 옵션별 기간가격을 반영한 현재 최저 판매가를 쓴다. 할인 필터는 현재 할인 중인 옵션 또는 기본 판매가보다 높은 비교가격이 있는 상품이다.
- 판매 가능 여부는 옵션별 일반 재고·예약판매 공급의 현재 판매 가능 수량으로 계산한다. 예약판매 옵션이 하나라도 연결되어 있으면 예약 판매에 포함한다.
- 무료배송은 최저 판매가 옵션 1개의 기본배송비가 0원인 상품이다. 기존 출고지 배송 계산을 사용하며 무료배송 임계금액도 현재 옵션가로 판단한다. 지역 추가배송비와 주문 전체 배송비는 주문 시 별도로 다시 계산한다.
- 인기순은 찜 수, 최근 30일 판매순은 결제 승인 증거 또는 계좌이체 확인이 있는 판매 수량이다. 완료된 취소·반품 주문은 제외한다. 두 정렬은 서로의 지표를 동률 보조 기준으로 쓴다.
- 리뷰 수·평점은 공개 리뷰만 집계한다. 최소 평점은 반올림 전 평균으로 검사하며 표시만 소수 둘째 자리로 반올림한다. 리뷰 많은순은 평점, 평점 높은순은 리뷰 수를 보조 기준으로 쓴다.
- 등록일 최신순·인기순·판매순·리뷰 많은순·평점 높은순·가격순·상품명순을 제공하며 마지막 동률은 등록일 내림차순과 내부 ID 오름차순으로 정한다.

원본의 렌탈 구분에 대응하는 ICONS 상품 계약은 없으므로 일반 판매·예약 판매 옵션 포함으로 표시한다. 공개 가격과 수량도 같은 옵션별 기간가격·예약판매 공급 계산을 반영한다.

## 저장 충돌·삭제·마케팅 링크

저장은 스토리 revision과 operation UUID로 동시 변경·중복 요청을 구분한다. 저장 성공 후 원장을 다시 읽어 화면에 반영한다. 다른 매니저가 먼저 저장하면 입력은 유지되고 최신 저장 내용을 별도 창에서 확인할 수 있다. 최신 버전 기준으로 현재 입력을 유지한 후 다시 저장할 수 있으며, 그 사이 또 수정되면 다시 충돌한다.

연결 오류로 저장 여부가 불명확하면 입력을 잠그고 동일 operation과 동일 payload로 결과를 다시 확인한다. 이미 저장된 뒤 readback만 실패한 경우에는 해당 스토리 편집 경로로 이동하여 확인한다. 불명확한 요청을 새 UUID로 자동 반복하지 않는다.

삭제는 최대 100개를 revision 검증 후 하나의 트랜잭션으로 처리한다. 하나라도 변경되었으면 전체 삭제를 취소한다. 성공하면 운영·공개 목록에서 제외하고 공개 상세는 404가 된다. 원장 tombstone과 감사 기록은 남지만 운영 복원 기능은 제공하지 않는다. 선택 항목의 마케팅 링크 생성/복사는 목록 툴바에서 수행하며 발급·라우팅 계약은 별도의 마케팅 링크 원장을 따른다.

DB 검증은 `supabase/tests/shopping_stories.sql`과 `supabase/tests/shopping_story_goods_picker.sql`을 KC 테스트 helper와 함께 격리 로컬 DB에서 실행한다. 공유 개발 DB reset이나 운영 적용으로 대신하지 않는다. 이미 매니저 설정이 활성화된 DB의 합성 검증 계정에는 명시적인 매니저 membership이 있어야 한다.
