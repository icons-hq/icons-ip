# 거래확정 영업 검토 엑셀

`/admin/sales/settled`에서 주문일과 검색어를 적용한 뒤 **현재 조건의 거래확정 엑셀 만들기**를 누른다. 생성이 끝나면 **거래확정 엑셀 다운로드**로 XLSX를 받는다. 현재 페이지에 한정하지 않고 같은 조건의 모든 거래확정(`done`) 주문을 담는다. 최대 주문 1,000건·품목 10,000행이며, 상한을 넘으면 기간을 줄여 다시 생성한다. 일부 행을 잘라 성공한 파일처럼 내보내지 않는다.

조회 기간은 화면과 동일한 **주문일, 한국 시간(KST)** 기준이다. 시작일 00:00 이상부터 종료일 다음 날 00:00 미만까지 포함한다. 확정일이나 결제일로 조회하는 기능은 아니다. 검색은 주문번호·닉네임·이메일·수취인·운송장에 동일하게 적용되며 `%`와 `_`는 일반 문자로 찾는다.

생성 시점의 주문·품목·배송·쿠폰·결제 증거를 한 DB 문장으로 읽어 비공개 영수증에 보존한다. 생성 이후의 ERP·운송장·쿠폰 변경은 이미 생성한 영수증에 반영되지 않는다. 같은 다운로드 링크는 보존된 내용을 다시 제공한다. 최신 상황이 필요하면 생성 버튼으로 새 영수증을 만든다. 영수증 생성자와 조회 조건·행 수는 감사 로그에 남고, 다운로드는 로그인한 생성자에게만 허용된다. 권한이 회수된 계정은 이전 링크도 사용할 수 없다.

## 시트와 금액

- **거래확정 품목**: 주문 품목과 배정된 배송 건당 한 행이다. 첫 8개 열은 확정일·주문번호·운송장·ERP 품명·수량·판매금액·배송비·결제일이다. 할인 전 정가·상품 할인·쿠폰 적용 전 금액·쿠폰·적립금, 주문 당시 ERP 코드·바코드·상품명·옵션명, 원장 식별자와 미기록 사유를 함께 담는다.
- **주문 대조**: 주문별로 품목·배송비 합계와 주문 결제금액, 결제 원장금액을 비교한다. 차이 0원은 금액이 같다는 뜻이다. ERP·시각의 미기록 여부와 환불 기록은 별도 사유 열에서 확인한다.

판매금액은 `수량 × 주문 당시 실제 단가 − 쿠폰 배분 − 적립금 배분`이다. 상품 할인은 별도 정가 스냅샷과 실제 단가의 차이로 보여준다. 쿠폰은 주문에 보존된 대상 품목의 실제 단가금액 비율로만 나누며, 적립금은 쿠폰을 뺀 뒤의 상품금액 비율로 나눈다. 배송비에는 쿠폰·적립금을 배분하지 않는다. 소수 원은 먼저 버린 뒤 나머지가 큰 품목부터 1원씩 배분하며, 동률이면 주문 품목 UUID 오름차순을 쓴다. 계산은 정수로 수행해 쿠폰·적립금 원장 합계를 보존한다.

배송비는 배송 건에 보존된 실제 금액을 해당 배송 건의 첫 품목 행에 한 번만 기록하고 나머지 행에는 0원을 쓴다. 배송 건 정렬과 최초 행은 배송 건 UUID·주문 품목 UUID 순서로 고정한다. 품목 배정이 없거나 배송비 합계가 주문 원장과 다르면 사유와 차이를 표시한다. 현재 출고지 정책으로 과거 배송비를 계산하지 않는다.

## 기록과 미기록

ERP 코드·품명·바코드는 비공개 주문 품목 스냅샷을 사용한다. 카탈로그의 현재 ERP 값이나 상품명을 ERP 품명에 소급 대입하지 않는다. 주문 당시 실제 상품명과 옵션명은 별도 열로 구분한다. 스냅샷 도입 전 ERP·정가와 쿠폰 대상이 없으면 공란과 사유를 남긴다. 쿠폰 대상 기록이 없어 품목별 판매금액을 계산할 수 없는 경우에도 주문 대조 시트는 기록된 주문·쿠폰·적립금·배송비 금액을 그대로 보여준다.

확정일은 `orders.done_at`이다. 발주확인·주문 생성 시각을 대신 넣지 않는다. 결제일은 해당 결제 원장에 연결된 결제사의 승인 시각 또는 무통장 입금확인 기록이다. 결제 원장 생성 시각이나 주문 생성 시각으로 대체하지 않는다. 연결된 결제 원장이 없거나 중복이면 금액·시각 대조 불가 사유를 남긴다. 환불 상태의 결제 원장은 원결제금액과 환불 상태를 구별해 보여준다.

공란은 0원이 아니다. 품목 금액이 한 행이라도 미기록인 열은 그 열의 전체 합계도 공란으로 두어 불완전한 합계를 정상 합계로 오인하지 않게 한다. XLSX의 합계 수식은 저장된 숫자 셀을 합산한다. 코드·바코드·운송장은 텍스트 자료형으로 보존하고 `=`로 시작하는 이름도 수식으로 실행하지 않는다. 날짜 셀은 KST 시각으로 표시되는 Excel 날짜형이다.

이 파일은 영업 검토와 원장 대조용이다. ERP 자동 입력 매핑이나 정산 지급 파일을 생성하지 않는다. 상품 등록 초안·공개 카탈로그·상품 엑셀은 이 다운로드에서 수정하지 않으며, ERP 저장·주문 시점 보존은 기존 상품 옵션의 ERP 관리 경로를 따른다.

## 검증

- `supabase/tests/settled_export.sql`: 실제 복수 품목·배송·쿠폰·적립금 주문과 무통장 입금확인에서 거래확정 영수증까지 검증한다. KST 기간 경계, 재요청 고정, 현재 정보 변경, 미기록·역할·감사를 포함한다. 합성 데이터는 롤백하고 KC fixture helper를 같은 연결에 먼저 불러온다.
- `lib/admin/settled-export.test.ts`: 1원 배분·대상 제한·입력 순서 독립성·합계·미기록·중복 및 큰 정수 연산을 검증한다.
- `lib/admin/settled-workbook.server.test.ts`: 실제 XLSX를 재개방해 필수 열·합계 수식·텍스트 식별자·수식 주입·날짜형·미기록 공란을 확인한다.
- 생성 Server Action과 다운로드 Route 테스트는 권한 검사가 조회보다 먼저 수행되고 다운로드가 보존된 영수증만 읽는지 확인한다.
