# 홍실 퀘스트 — 성인 트랙 설계

원작은 성인 BL이다. 게임을 원작 수위에 가깝게 가져가려면 **전연령 본편과 분리된 별도 트랙**이 필요하다.

**현재 상태: 프로토타입에 구현 완료.** 사내 검토용으로 플레이 가능하다.
`?track=adult` 로 들어가거나 화면 하단 `TRACK` 알약으로 전환한다.

| | 상태 |
|---|---|
| 트랙 분기·게이팅 아키텍처 | ✅ 구현 |
| 확장 씬 3라운드(R5·R6·R7) | ✅ 작성 |
| 정사 장면 본문 | ⬜ **집필 슬롯 3곳** — 원작자 집필분 (§0) |
| 연령 게이트 UI | ✅ 구현 (자가 확인 · 실제 인증 아님) |
| 본인인증(PASS) | ⬜ 도입 예정 |
| 게임물 등급분류 | ⬜ 미확정 |
| 서버 게이팅·RLS | ⬜ 실서비스 전환 시 |

---

## 0. 집필 범위 경계

확장 씬의 본문은 **성인 수위의 긴장·접촉·입맞춤까지** 작성돼 있고, 정사 구간은 `gap` 비트로 남겨 뒀다. 화면에는 점선 박스 안에 `집필 슬롯 · 원작자 검수분`으로 그대로 드러난다 — 본문인 척하지 않는다.

**성적으로 노골적인 본문은 이 저장소의 에이전트 작업 범위 밖이다.** 계약·등급·일정과 무관하게 유지되는 경계다.

라이선스 관점에서도 이쪽이 맞다. 원작의 성인 장면은 숲이랑 작가의 저작물이고, 프로토타입 PR #167 본문도 이미 `"개별 장면·대사·결말 문장은 새로 쓴 것이지 원작 본문이 아니다. 작가 검수가 필요하다"`고 적고 있다. 성인 구간은 특히 그렇다.

집필 슬롯 3곳은 `components/prototype/hong-sil-vn/story-adult.ts`의 `kind: 'gap'` 비트다. `note`에 장면 경계와 전후 감정이 적혀 있어, 그 자리에 본문만 넣으면 된다.

| 항목 | 담당 | 상태 |
|---|---|---|
| 트랙 분기 구조, 씬 경계, 감정 비트, 연출 지시 | 사내 기획 | ✅ |
| 연령 게이팅 아키텍처, 데이터 모델 | 사내 개발 | ✅ 프로토타입 |
| RLS·서버 게이팅 | 사내 개발 | ⬜ 실서비스 |
| 등급분류·본인인증·약관 | 사내 법무/운영 | ⬜ |
| **성인 장면 본문과 원화** | **원작자 검수 또는 계약 작가** | ⬜ 슬롯 3곳 |

## 1. 왜 별도 트랙인가

전연령 본편에 수위를 섞는 방식은 세 가지 이유로 성립하지 않는다.

1. **등급이 콘텐츠 전체에 걸린다.** 성인 씬이 한 장면이라도 본편 경로에 있으면 게임 전체가 성인 등급이 된다. 카드 리워드·팝업 연동·커뮤니티 노출이 전부 연령 게이트 뒤로 들어간다
2. **원작의 강제성 프레임을 그대로 옮길 수 없다.** 원작 시즌1의 성인 장면들은 저주가 행위를 *명령*하는 구조 위에 있고, 거부 대사가 장면 안에 섞여 있으며, 9화는 만취 상태에서 벌어진다. 게임은 플레이어가 이연을 *조작*하므로 같은 프레임을 옮기면 강제 상황을 플레이어에게 수행시키는 인터랙션이 된다. **원작에서 그대로 이식할 수 없는 유일한 요소다**
3. **시즌2가 더 나은 재료를 준다.** 전생 아크(37~49화)의 친밀 장면들은 강제 프레임 밖에 있고, 두 사람이 서로를 선택한 뒤의 것이다. 성인 트랙을 만든다면 여기가 출발점이다

---

## 2. 실서비스 선행 조건 — 셋 다 해결돼야 출시한다

프로토타입 검토는 이것들과 무관하게 지금 할 수 있다. 아래는 **실제 출시**의 조건이다.

### 2.1 게임물 등급분류 *(프로토타입 검토와 병행)*

[docs/PRD.md](../../PRD.md) §7이 이미 게임물 등급분류를 **출시 블로커 가능성**으로 표시하고, §11 미해결 항목에 `"분류 필요 여부·연령등급 결과가 P2 출시와 §5.1 본인인증 수준을 좌우. 법무 확인 필요"`로 남겨 뒀다.

성인 트랙은 이 불확실성을 제거하는 게 아니라 **확정적으로 트리거한다.**

- [ ] 게임물관리위원회 분류 대상 여부 확인
- [ ] 청소년이용불가 등급 신청 필요 여부와 절차·기간
- [ ] 웹 서비스 내 게임 콘텐츠의 자체등급분류사업자 경로 검토

### 2.2 본인인증

PRD §5.1이 본인확인을 `"자가신고 + 결제 시 결제사(토스페이먼츠) 위임"`으로 두고, `"게임물 등급에서 연령제한 요구 시 v1.x에 PASS 추가"`로 유보했다. 성인 트랙은 이 유보를 끝낸다.

- [ ] PASS 등 본인인증 연동 (자가신고로는 부족)
- [ ] 인증 결과 저장 범위와 보존 기간 (개인정보 최소수집)
- [ ] 미인증·미성년 계정의 트랙 접근 차단을 **RLS 레벨에서** 강제

### 2.3 라이선스 범위

- [ ] 계약서상 각색 권한에 성인 장면이 포함되는가
- [ ] 원작 장면의 재현/각색 중 어느 쪽이 허용되는가
- [ ] 원화 발주 시 성인 표현의 승인 절차
- [ ] 앱스토어 배포 계획이 있다면 Apple/Google 정책 충돌 (ADR-0002가 앱 심사 리스크를 이미 기록)

## 3. 트랙 구조 (구현됨)

### 3.1 분기 방식 — 비트 치환

본편의 씬 배열을 그대로 두고, **성인 트랙에서만 특정 라운드의 beats를 확장판으로 갈아 끼운다.** 별도 게임도, 별도 씬 객체도 만들지 않는다.

```ts
// story.ts — 순수 모듈. 성인 비트는 여기 없다.
export type AdultBeats = Readonly<Record<string, readonly Beat[]>>;
export const NEVER_ADULT = ['r3', 'r4'];          // 아역 등장 라운드. 등록 시점에 막는다
export function registerAdultTrack(beats: AdultBeats): void;
export const sceneBeats = (scene, flags, track = 'all-ages'): Beat[];
```

- **축·플래그·선택지·엔딩 판정은 공유한다.** 성인 트랙 전용 엔딩이 없어서 같은 21종에 도달하고, 6,561경로 열거도 그대로 성립한다. 회귀 테스트로 못 박아 뒀다
- 성인 비트는 `story-adult.ts`라는 **별도 청크**다. 게이트를 통과한 세션만 `await import('./story-adult')` 로 받는다. 전연령 플레이는 그 청크를 요청하지 않는다
- ⚠ 실서비스에서는 이 전달을 **서버가** 맡아야 한다. 지금은 클라이언트가 청크를 부르므로, 번들을 뜯으면 보인다

### 3.2 치환 대상

| 라운드 | 전연령 | 성인 트랙 |
|---|---|---|
| R3 이름을 지은 보름 | 그대로 | **치환 금지** (아역 등장 — `NEVER_ADULT`) |
| R4 첫 매듭 | 그대로 | **치환 금지** (아역 등장 — `NEVER_ADULT`) |
| R5 잠긴 문 | 12비트 | **36비트** — 혼례 사흘 전 밤 확장 (원작 49화 대응) |
| R6 나를 알아차려 줄래? | 15비트 | **26비트** — 접촉이 기억을 부르는 밤 |
| R7 검은 돌 | 19비트 | **28비트** — 포장마차 이후 |

확장본은 **원래 씬과 같은 마지막 비트로 끝난다.** 이어지는 prompt와 선택지 3개가 그대로 성립해야 하기 때문이고, 이것도 테스트가 검사한다.

### 3.3 검토자가 보는 것

- 하단 `TRACK` 알약으로 **플레이 중에도** 전연령 ↔ 성인을 즉시 전환할 수 있다. 같은 라운드에서 두 판본을 나란히 비교하는 게 검토의 핵심이다
- 성인 트랙은 첫 진입 시 게이트를 한 번 띄우고, 이후에는 알약만으로 오간다
- 게이트 화면이 **미배선 항목 4가지를 그대로 노출**한다 — 검토자가 "이걸로 출시 가능"이라고 오해하지 않도록

> **절대 규칙**: 전생 아역 구간(R3·R4)과 중고등학생 시절 회상은 **어떤 트랙에서도 성적으로 다루지 않는다.** 원작에 해당 시기의 묘사가 있더라도 각색물에서는 배경 서사로만 처리한다.

이건 규율이 아니라 **코드로 강제**돼 있다. `NEVER_ADULT`에 든 라운드를 확장하려 하면 `registerAdultTrack`이 던지고, 테스트가 그 동작을 검사한다.

### 3.4 강제성 프레임 처리

원작 시즌1의 퀘스트 강제 구조는 성인 트랙에서도 그대로 쓰지 않는다. 대신:

- 퀘스트는 **계기**이지 명령이 아니게 재구성한다 (원작 27화 이연의 재해석 — 퀘스트는 장난이 아니라 신호였다 — 이 정확히 이 방향이다)
- 모든 성인 씬 진입 전에 **이연 측의 명시적 선택지**를 둔다. 플레이어가 고르지 않으면 진입하지 않는다
- 씬 내 회피·중단 선택지를 유지한다
- 만취 상태 관련 원작 비트(7~9화)는 **이식하지 않는다**

## 4. 게이팅 아키텍처

```
[진입]
  → 로그인 필수
  → profiles.age_verified = true 확인 (PASS 등 인증 결과)
  → 트랙 선택 UI (기본값 = 전연령)
  → 성인 트랙 선택 시 명시적 동의 1회 (세션 아님, 계정 단위 저장)
  → 서버가 성인 씬 청크를 세션에 바인딩해 전달
```

**신뢰 경계** — [docs/ARCHITECTURE.md](../../ARCHITECTURE.md) §7·§15와 ADR-0002의 규율을 그대로 따른다.

- 연령 판정은 **서버**가 한다. 클라이언트 상태·쿼리 파라미터로 트랙을 바꿀 수 없어야 한다
- 성인 씬 데이터에 **RLS**를 건다. `age_verified` 미충족 계정은 행 자체를 못 읽는다
- 게임 번들은 첫파티 오리진 허용리스트에서만 로드한다 (ADR-0002)
- 정지된 계정은 트랙 접근을 잃는다 (기존 정지 규칙과 동일)

**노출 정책**
- 성인 트랙 엔딩 카드는 **바인더에서 마스킹**한다. 카드 자체는 공유 21종이므로 이미지 변형만 다르게 간다
- 커뮤니티·팝업·홈 큐레이션에 성인 트랙 이미지를 노출하지 않는다
- 검색·OG 메타데이터에서 제외 (`robots: noindex`)

## 5. 남은 일

**검토 단계 (지금)**
1. 사내 검토자가 두 트랙을 같은 라운드에서 비교한다. `TRACK` 알약으로 전환
2. 확장 씬의 **톤**이 원작에 맞는지, 집필 슬롯의 **경계 위치**가 맞는지를 본다 — 이 둘이 이번 검토의 질문이다
3. 슬롯 3곳의 `note`를 작가님께 전달해 본문 집필 범위를 확정한다

**실서비스 전환 전 (§2)**
- 게임물 등급분류 결과
- PASS 본인인증 연동 — 자가 확인 버튼을 대체한다
- 서버 게이팅·RLS — 클라이언트 동적 import를 서버 바인딩으로 옮긴다
- 계정 단위 동의 저장 — 지금은 메모리라 새로고침하면 사라진다

> 전연령 개정판만으로 팬 평가가 얼마나 회복되는지도 함께 보면, 성인 트랙이 등급분류·본인인증 비용을 감수할 만한지 판단할 근거가 생긴다.
