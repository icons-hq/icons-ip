# ICONS 온라인 팝업 — 제품 요구사항 정의서 (PRD)

> 작성일 2026-06-30 · 문서 2/4 · 짝 문서: [01-report.md](./01-report.md) · [04-dev-spec.md](./04-dev-spec.md)
> 전제: **무료 리워드 모델**(실물만 유료결제 / 디지털 카드는 실물구매 후 무료 / 충전금·유료가챠 배제). 근거·리스크는 보고서 §1·§5 참조. **확정: [ADR-0003](../adr/0003-free-reward-pivot.md)** (0001 supersede).
> 도메인 용어는 [CONTEXT.md](../../CONTEXT.md)를 따른다. 단 "가챠/충전금"은 본 모델에서 **뽑기권(카드팩) 개봉 기반 무료 카드 발급**으로 대체된다([ADR-0004](../adr/0004-draw-ticket-card-packs.md), 충돌 해소는 보고서 §1.3).
> 주문 연동 무작위 카드팩과 참여형 게임 보상의 게임물·간접 유상성·확률 표시의무는 미확정이다. 법무·관계 기관 확인 전 공개하지 않으며, 표시가 필요하면 `pool_odds`를 진실원으로 사용한다.
> **상태·범위:** 2026-08-12 #115를 current product scope에서 제거해 이 문서는 historical candidate다. 아래 P0~P3, `M`, MVP/V1/V2/V3는 active roadmap·backlog·루트 [`PRD.md`](../PRD.md)의 요구사항이 아니다. 실제 partner/pilot 신호가 생기면 이 문서를 그대로 구현하지 않고 작은 tracer RFC로 재검증한다.

## 1. 제품 목적

**좋아하는 IP의 한정 굿즈를 사는 경험을, 끝나도 남는 수집·커뮤니티로 잇는 온라인 팝업.**

- 2주마다 IP/브랜드가 바뀌는 온라인 팝업에서 라이선스 실물 굿즈를 판매한다.
- 실물을 사면 **무료 디지털 수집카드**를 리워드로 주고, 카드는 **바인더**에 영구 적재된다.
- 팝업이 끝나도 **커뮤니티·카드·바인더·마이페이지·아카이브**가 남아 재방문을 만든다.
- 성공의 정의: 매출(상품 마진)과 **재방문율·수집률·미션 완료율**의 동반 상승.

### 비목적 (이 제품이 하지 않는 것)
- 유료 가챠·포인트/사이버머니 충전·유료 랜덤 카드팩 (배제 — 법률·PG 이유, 보고서 §5·§6).
- 카드의 현금화·환전·C2C 거래소 (리셀·사행성 차단).
- B2B 마켓플레이스·입점·제작대행·데이터 판매 (정체성 분산 방지, v3 이후 검토).
- 해외 직배송 (IP territory 확인 전까지 보류, 보고서 §5.3).

## 2. 사용자 유형

| 페르소나 | 설명 | 핵심 니즈 |
|---|---|---|
| **수집러** | 좋아하는 IP의 카드·굿즈를 모으는 팬(10·20대 다수) | 한정성, 바인더 도감 진행, 카드 자랑 |
| **굿즈 구매자** | 정품 라이선스 굿즈를 사려는 팬 | 신뢰(정품), 재고, 빠른 결제, 한정 드롭 |
| **이벤트 참여자** | 미션·래플·룰렛 참여형 유저 | 참여 재미, 당첨, 등급·랭킹 |
| **커뮤니티 유저** | 후기·인증·소통하는 팬 | 작성·반응·신고/차단 안전장치 |
| **운영자(내부)** | 팝업·상품·카드·미션·CS 관리 | 백오피스에서 팝업 생성·발급정책·통계 |
| **브랜드/IP사(B2B 리포트 수신)** | 제휴 IP사 | 팝업 성과 리포트(재계약 근거) |

브라우징은 **로그인 없이 공개**. 보호 액션(구매·미션·작성·팔로우·래플 응모) 시점에 로그인을 요구한다(기존 ICONS 공개 브라우징 정책 유지).

## 3. 핵심 사용자 플로우

1. **첫 방문(비로그인)**: 진행 중 팝업 랜딩(티저·카운트다운) → 굿즈·카드 구경 → 보호 액션 시 로그인.
2. **온보딩**: 소셜/이메일 로그인 → 닉네임·생년월일(자가신고)·약관/마케팅 **분리 동의** → 관심 IP 팔로우.
3. **구매·개봉**: 굿즈 상세 → 장바구니 → 체크아웃(배송지) → **토스페이먼츠 결제** → 주문 확정(웹훅) → 조건에 맞는 **카드팩(`draw_ticket`) 발급** → 사용자가 카드팩 개봉 → 서버가 카드 결정·`card_grants` 기록 → 바인더 적재.
4. **수집·자랑**: 바인더에서 도감 진행률 확인 → 카드 전시 → 좋아요·랭킹 → 공유.
5. **미션·참여**: 미션(구매·출석·공유) 클리어 → 포인트/도장 → 등급·한정 카드 보상.
6. **래플(한정 드롭)**: 응모(무과금) → 추첨(공정·검증가능) → 당첨자만 정가 결제.
7. **커뮤니티**: 피드 → 작성(이미지) → 댓글·좋아요 → (문제 시) 신고/차단.
8. **팝업 종료 후**: 종료 IP는 아카이브로, 카드·바인더·미션 이력·커뮤니티는 잔존.

## 4. 기능 요구사항

표기: `M`=해당 online-popup 단계 안의 필수, `S`=해당 단계 안의 권장. P0~P3는 [03-roadmap.md](./03-roadmap.md)·[04-dev-spec.md](./04-dev-spec.md)의 #115 post-launch 내부 순서이며 루트 v1 우선순위가 아니다.

### 4.1 인증 & 온보딩 (P0) — 기존 ICONS 자산 재사용
- `M` 이메일/PW 가입·로그인, 확인 메일 콜백·재전송과 소셜 Google·Apple·Kakao 코드·provider 설정이 구현됐다. Production 신규·기존 사용자 controlled smoke만 잔여다.
- `M` 온보딩에서 닉네임·생년월일(자가신고)·약관 동의 + **마케팅 분리 동의**(서비스/마케팅/광고수신/야간 각각).
- `현행 정본 참조` #188의 2026-08-12 내부 결정은 Asia/Seoul 기준 만 14세 이상 전용, 법정대리인 동의 예외 없음, 자가신고와 분리된 `verified_14_plus`, 신규 거절 계정 durable 파기다. 이 historical online-popup 문서의 P0 요구가 아니며 실제 시행은 [현행 PRD §5.1](../PRD.md)과 연령·탈퇴 구현 gate를 따른다. 만 14세 이상 미성년자의 개별 소비자 계약 의무는 별도 거래 법률 gate다.

### 4.2 팝업/IP 허브 (P0)
- `M` **팝업(Popup)** = 한 IP의 기간 한정 운영 단위(상태: 예정·진행중·종료, 시작/종료일, 테마·배너·랜딩).
- `M` 진행 중 팝업 랜딩: 티저·**카운트다운**·스토리형 랜딩(MVP는 2D 연출, 3D/AR은 후속).
- `M` IP 목록/상세 공개 브라우징, **무료 팔로우**(개인화).
- `S` 알림 신청(오픈 알림·재입고 알림), 사전예약.

### 4.3 굿즈 커머스 (P1) — 척추
- `M` 굿즈 목록/상세(타입·재고·한정수량·기간한정 배지).
- `M` 장바구니(비로그인 로컬→로그인 병합), 체크아웃, **토스페이먼츠 결제**, 주문 내역·상태.
- `M` **재고 선점은 `place_order`의 pending 주문 생성 시점에 원자 차감**하고, 결제 확정은 해당 주문을 `paid`로 전이한다. 미결제 만료·취소는 재고를 복원한다. 한정수량·1인 구매 한도를 DB에서 검증한다.
- `M` **청약철회/환불**(실물 7일 보장), 반품·재배송, CS.
- `S` 묶음배송 무료 임계치(객단가 상향), 선착순/타임 세일.

### 4.4 무료 카드 & 바인더 (P1, 커머스와 결합) ★핵심 차별
- `M` **실물 주문 확정의 부수효과는 뽑기권(카드팩) 발급**([ADR-0004](../adr/0004-draw-ticket-card-packs.md)). 카드팩 자체 가격·별도 결제 RPC는 없으며, 구매 금액·상품에 따른 발급 정책을 둔다. 주문 연동의 법적 분류는 별도 human gate다.
- `M` **뽑기권 개봉**(리워드형): 사용자가 개봉하는 시점에 카드풀에서 무작위 1장 발급. 풀 바인딩·무기한·천장 없음. 카드팩 자체의 충전금·별도 결제는 없다.
- `M` 카드 등급(N·R·SR·SSR·HOLO 등 — 기존 CONTEXT 유지)은 결제 금액과 무관한 수집 분류다.
- `M` **바인더**: 보유/미보유, 도감 진행률, IP/등급 필터, 카드 상세 연출(포일).
- `M` 카드 **자랑/전시·좋아요·랭킹**(콜리식 소셜 루프).
- `S` 동일가치 실물 랜덤상품("균등가치 기획세트")은 **별도 P3 후속**(법률·PG 단계 분리, 보고서 §5.2·§6).
- 제품·법무 경계([04-dev-spec.md](./04-dev-spec.md) §RLS·§리워드): 카드 자체 직접 판매 RPC 금지, 상품가는 카드팩 유무와 무관하게 고정, 유료 가챠·충전 상품으로 오인시키는 문구 금지. 게임물·간접 유상성·확률 표시는 별도 human gate다.

### 4.5 미션·등급·참여 (P2)
- `M` 미션(구매·출석·공유·팔로우 등) 정의·진행·보상(카드·도장·포인트성 비현금 보상).
- `M` **룰렛/도장깨기** 등 참여형(무과금). 미션 클리어 이력.
- `S` 등급(활동 기반), 친구 초대, 랭킹.
- ⚠️ 포인트는 **비현금·비환금**(굿즈 결제 할인 등 한정). 충전·현금화 불가(사이버머니화 금지).

### 4.6 래플/한정 드롭 (P2)
- `M` 래플: **응모(무과금) → 마감 → 추첨(공정·검증가능) → 당첨자만 정가 결제**.
- `M` 봇·중복 응모 방지(1인 1회, Turnstile, 서버 멱등).
- `S` 선착순 드롭(대기열은 트래픽 규모에 따라).

### 4.7 커뮤니티 (P0) — 기존 ICONS 자산 재사용
- `M` 포스트 작성(텍스트+이미지·태그·IP 연결), 댓글, 좋아요, **신고·숨김·차단**, admin 모더레이션.
- `S` IP/팝업별 피드, 트렌딩 태그, 리뷰.

### 4.8 검색 (P0) — 재사용
- `M` IP·굿즈·카드·포스트·태그 통합 검색(Postgres pg_trgm).

### 4.9 관리자 백오피스 (병행) — §8

### 4.10 게임 미니앱 & 크로스플랫폼(웹+앱) (V1 웹 · V2 네이티브 앱)
> 결정 근거: [ADR-0002](../adr/0002-cross-platform-popup-game-miniapps.md) · 상세 스펙: [05-game-miniapp-spec.md](./05-game-miniapp-spec.md)

- `M` **마블 룰렛**(대표 게임): **참여형 게임**과 **래플 추첨 시각화** 두 역할을 겸한다. 참여형은 추가 결제 없이 `grant_cards`로 카드 보상을 발급하고, 래플 연출은 `draw_raffle`의 **commit-reveal 검증 결과**를 마블로 표시한다. **결과는 서버 RPC가 결정하고 게임은 렌더러**다.
- `M` **공정성 층위 분리**: 참여형 게임 = **코스메틱 연출**(서버가 결과, 물리는 장식, commit-reveal 불필요), 래플 선정 = **commit-reveal**(검증가능·정원 제한·당첨자 정가 결제). 선정과 연출은 다른 층이다.
- `M` **게임 = 자기완결 웹 번들, 호스트가 띄운다**(첫파티 미니앱). 웹은 게임을 라우트로 직접 렌더한다. 웹 host는 앱 바이너리 재빌드 없이 배포할 수 있지만 Expo에 노출되는 신규·변경 미니게임은 ADR-0002의 App Store 심사·소프트웨어 색인·원격 변경 절차를 생략하지 않는다.
- `M` 호스트↔게임 **얇은 브리지**: 허용된 서버 작업 + 네이티브 편의(햅틱·공유·닫기)만 노출한다. #66 Expo는 refresh token·범용 Supabase session을 WebView에 주입하지 않고, native 인증 subject/session과 정확한 capability·resource에 묶인 짧은 TTL·single-use token을 first-party BFF가 한 번만 소비해 작업을 대행하는 방식을 기본으로 한다. BFF는 client user ID나 임의 service-role RPC를 신뢰하지 않으며 cross-user token swap을 거부한다. 짧은 access JWT 직접 주입은 명시 승인된 예외뿐이다.
- `S` **(V2+) 네이티브 앱(Expo)**: 같은 원격 URL을 `react-native-webview`로 로드 → 웹·앱 **동일 경험을 구조로** 보장. 원격 URL은 **첫파티 오리진 허용리스트**만, Apple App Store 4.7(2025.11 강화) 대응.
- 참여형 룰렛/도장깨기(§4.5)·래플(§4.6)은 이 미니앱 프레임 위에서 구현한다.

> 현재 `lib/games/host.ts`의 `getSession(): { accessToken, userId }`는 같은 오리진 웹 호스트용 현행 인터페이스이며 #66 Expo bridge 계약으로 승인된 것이 아니다. #66 구현에서는 [ADR-0002](../adr/0002-cross-platform-popup-game-miniapps.md)와 [05-game-miniapp-spec.md §2](./05-game-miniapp-spec.md)의 BFF 경계로 교체한다.

## 5. 비기능 요구사항

- **무결성**: 재고·주문·카드 발급·래플 추첨은 동시성에서도 **원자적**(이중 차감·초과판매·중복 발급 금지). Postgres RPC + 행 잠금.
- **결제 신뢰성**: 결제 확정은 **토스 웹훅 + 멱등**. 클라이언트 콜백만으로 확정 금지.
- **트래픽**: 오픈런 순간 부하는 카탈로그 ISR 정적화로 엣지 흡수, 결제/재고만 DB. 봇은 Turnstile + Rate Limiting.
- **보안**: RLS 소유자 격리, 카탈로그 공개 읽기, 관리자 역할+감사 로그. service role은 서버 경계 안에서만.
- **컴플라이언스 by design**: 카드 자체 결제 RPC 부재, 상품가 고정, 청약철회 표시·로그, 마케팅 분리 동의, 야간 푸시 gate, 미성년 보호. 법적 분류·표시·약관 승인은 별도 human gate다.
- **성능/접근성**: 모바일 우선, 한국어 기본, 이미지 최적화, LCP 양호.
- **디자인**: "Holographic Midnight" 시스템 유지(기존 자산).

## 8. 관리자 기능 (백오피스 `/admin`)

- **팝업 생성/관리**: IP·기간·테마·배너·랜딩·상태(예정/진행/종료) 전환, 종료 시 아카이브화.
- **상품 등록·재고 관리**: 굿즈 CRUD, 한정수량·기간한정·1인 한도·배지.
- **주문 관리**: 상태·배송·취소·환불(청약철회 처리), CS 메모.
- **카드/카드풀·발급 정책**: 카드풀·등급별 확률, **리워드 정책**(구매 조건→발급 카드팩 수·풀), 카드팩·카드 발급 이력 조회.
- **미션 관리**: 미션 정의·조건·보상·기간.
- **래플 관리**: 응모 조건·정원·추첨 실행(commit-reveal)·당첨자·결제 권한 부여.
- **커뮤니티 관리**: 신고 처리·게시물 숨김·차단(기존 모더레이션 재사용).
- **배너/랜딩 관리**: 팝업별 랜딩·티저·카운트다운·티저 페이지.
- **통계 대시보드**: 매출·방문·가입률·구매전환·재방문·객단가·수집률·미션완료율·공유율·유입채널·퍼널·품절/이탈.
- **CS/환불 관리**: 환불·반품·재배송·미성년 취소 처리 워크플로.
- **아카이브 관리**: 종료 팝업·IP별 아카이브.
- **브랜드 리포트**: IP사 제공용 성과 리포트 생성(§9).
- 모든 민감 작업은 `audit_log` 기록.

## 9. 데이터/KPI & 브랜드 리포트

- **서비스 KPI**: 매출, 방문자, 회원가입률, 구매전환율, 재방문율, 객단가, 카드 수집률, 미션 완료율, 공유율, 브랜드 재계약률.
- **브랜드/IP사 리포트**: 인기 상품, 팬 연령대, 구매 전환, 지역, 미션 참여율, 재방문율, 카드 선호도, 팝업별 매출, 유입 채널별 성과, 구매 퍼널, 품절/이탈 구간, 커뮤니티 반응.
- **데이터 수집 구조**: 개인정보 **최소 수집 + 분리 동의 + 목적 명시**(PIPA). 행동 데이터는 **가명·집계 기준**으로 브랜드 리포트화(개인 식별 정보 직접 제공 금지). 마케팅 동의 이력 로깅(2년 재확인).

## 10. 범위: MVP / V1 / V2 / V3

아래 단계명은 모두 **#115 post-launch online-popup 로드맵의 로컬 단계명**이다. 특히 "MVP 출시 최소"와 "V1"은 ICONS 루트 v1 출시 판정과 무관하다.

### MVP (출시 최소) — "실물 커머스 + 무료 카드 + 회원 + 단일 팝업"
인증·온보딩(재사용) · 1개 팝업 랜딩(2D·카운트다운) · 굿즈 커머스(장바구니·토스결제·주문·재고·환불) · **주문 확정 시 추가 결제 없는 뽑기권(카드팩) 발급→사용자 개봉→카드 획득** · 바인더(보유·도감) · 커뮤니티·검색(재사용) · admin(팝업/상품/재고/주문/발급정책/통계 기본).

### V1 — "팝업 운영 본격화"
- 2주 IP 교체 운영 루프·아카이브, 미션·등급·룰렛/도장깨기(**마블 룰렛** 포함), 카드 자랑·랭킹, 래플(응모 무과금→당첨 결제), 알림신청·사전예약, 기존 소셜 로그인 controlled smoke, 브랜드 리포트.
- 게임은 **미니앱 계약(§4.10) 뒤에서 웹 우선 구현** → 이후 앱 임베딩 시 재작성 불요.

### V2 — "참여·확장"
- 동일가치 실물 랜덤상품("균등가치 기획세트", 법률·PG 단계 분리 후), 선착순 대기열(트래픽 규모 시 Cloudflare Waiting Room), 3D 전시관/AR 전시, 카드 교환(C2C, 기존 `/exchange` 플레이스홀더 발전), 친구 초대·고도화 랭킹.
- **네이티브 앱(Expo webview 미니앱, #66·[ADR-0002](../adr/0002-cross-platform-popup-game-miniapps.md))** — online-popup V1의 웹 게임 번들을 그대로 앱에 임베드해 웹·앱 동일 경험. 인증은 refresh token/범용 session 주입이 아닌 승인된 BFF single-use bridge 계약을 사용한다.

### V3 — "플랫폼화(검토)"
- 다IP 동시 팝업 대규모 운영, 해외 판매(IP territory 확보 후), 브랜드 입점/마켓플레이스·제작 협업(정체성·범위 재검토 후).

> MVP→V1→V2→V3는 [03-roadmap.md](./03-roadmap.md)의 타임라인과 정합한다. 각 단계는 독립 출시 가능하도록 설계한다.
