# 영업팀 어드민 피드백 — 기존 구현 대조와 설계 질문

작성일: 2026-09-10. 상태: 분석 완료 / Q1~Q10 반영 / 종합 스펙 게시.

정본 스펙은 [GitHub #460](https://github.com/icons-hq/icons-ip/issues/460)이며 [게시 본문 사본](./2026-09-10-sales-admin-feedback-spec.md)을 함께 보관한다. 사용자의 to-spec 요청에 따라 추가 인터뷰 없이 합성해 ready-for-agent·ops-feedback 라벨로 게시했다. 이 문서는 원문 대비와 판단 근거를 보존한다.

## 결론과 범위

영업팀 원문은 2026-09-07 작성이며, 기존 관리자 콘솔 통합 배포는 그 이후인 2026-09-09에 이뤄졌다. 따라서 원문의 “없음”을 현재 결함으로 그대로 옮기지 않는다. 현재 코드와 완료 기록을 대조하면 **원문 36행 중 6행은 기존 구현을 재사용하고, 16행은 일부 기능만 추가하며, 14행은 신규 설계·정책 해석 또는 오류 재현이 필요하다.** 한 행에 여러 기능이 묶여 있으므로 이 숫자는 기능 수나 개발 난이도가 아니다.

사용자는 2026-09-10 첫 질문에서 **“이미 구현된 부분을 제외한 모든 요구를 이번 설계 범위에 포함”**을 선택했다. 예약판매·계층 카테고리·안전재고·구매한도·적립금·해외판매 등도 설계 대상이다. 이전 v1 비목표는 변경 영향을 확인할 기준이며, 이번 설계에서 해당 요구를 누락시키는 근거가 아니다. 아직 구체적인 정책과 구현 순서는 합의하지 않았다.

## 판단에서 특히 구분할 것

1. **식별자**: 내부 참조 ID, 공개 URL, 사람이 쓰는 상품코드, ERP 코드, 바코드는 용도가 다르다. 같은 문자열 한 칸에 전부 넣으면 조회·복사·URL 수정·기존 주문 스냅샷이 함께 흔들린다.
2. **가격**: 기본 가격은 옵션 편집 기준가이며 고객이 결제하는 값은 선택 옵션 판매가다. 소비자가는 비교 표시용이고 공급가는 의미가 아직 정해지지 않았다. 기존 물류 파일에 공급단가라는 열이 있다고 원가 데이터가 있는 것은 아니다.
3. **재고**: 옵션별 할당 재고와 안전재고는 다르다. 경보 기준인지 판매에서 제외할 완충 물량인지 결정하지 않고 주문 재고를 차감해서는 안 된다.
4. **예약**: 돈을 받는 예약판매, 무결제 신청, 발표용 예약 체험은 별개다. 원문은 기간·발송일만 요청했으므로 결제 시점과 취소·재고 계약을 추정하지 않는다.
5. **물류**: 배송 정책 템플릿, 창고 출고지시 파일, 고객에게 보여주는 배송 안내, 실제 배송 방법은 각각 다른 데이터/행동이다.
6. **할인·리워드**: 회원 쿠폰은 이미 있다. 적립금이 주문 할인에 쓰는 잔액이라면 무료 코인을 재활용하는 것이 아니라 적립·사용·취소·만료·정산 계약을 새로 설계해야 한다.
7. **거래확정**: 현재 확정일은 자동 거래확정 시각이다. 고객이 구매확정 버튼을 누른 날짜를 보유한 것처럼 이름을 바꾸지 않는다.
8. **KC**: 한 개의 인증 있음/없음 체크로 모든 굿즈에 같은 의무를 강제하지 않는다. 공식 제품안전 체계는 제품군과 안전인증·안전확인·공급자적합성확인 등을 구분한다. 유형별 데이터/검증 설계가 필요하다는 결론은 이 체계에서 도출한 제안이다. 개별 상품의 적합성은 이번 조사에서 판정하지 않았다. [Safety Korea 대상품목](https://www.safetykorea.kr/policy/targetsSafetyCert2), [공급자적합성확인](https://www.safetykorea.kr/policy/targetsSafetyQuality).

| 3. 판매·혜택 정책 | 안전재고·옵션 사용·구매한도·예약판매·할인 기간·상품별 수단·적립금/쿠폰 타겟팅·추가구성 | 서버 가격/재고/한도/혜택 계약, 동시 주문·취소·기간 경계 검증. 화면 설정만 추가해서 완료 처리하지 않음 |
| 4. 배송·고객 응대 | 배송 템플릿·퀵/방문수령·도서산간·교환반품 비용 기록·국내 배송대행지 안내·일괄 지연 안내 | 실제 물류 규칙·비용·수령 증거·채널 결정. 원화/국내 배송 유지, 기존 배송 건/클레임/알림 처리 재사용 |

여러 묶음에 걸리는 G13/G19는 한 티켓에 넣지 않는다. 단일 원문 행에서 파생한 하위 기능의 완료 상태를 연결해 전체 누락 여부를 확인한다. 이미 구현된 옵션·엑셀·배송·주문 상세를 다시 만들지 않는다.

## 기존 정책·문서에 미치는 영향

- 계층 분류는 고정 유형이라는 기존 결정을 바꾸므로 PRD·ARCHITECTURE·유형 소비자와 이관 계획을 맞춘다.
- 옵션 재고·가격은 ADR-0015, 출고지·배송 건은 ADR-0016, 주문 전체 클레임은 ADR-0017에 연결된다. 안전재고 차감, 예약판매, 새로운 배송 방식·회수비 자동 처리는 이 계약에 대한 영향을 먼저 확정한다.
- 결제 수단의 허용 여부와 ADR-0013의 PG 파생은 구분한다. 관리자 PG 선택을 필드 하나로 추가하는 방식으로 처리하지 않는다.
- Q7에서 별도 적립금을 채택했으므로 기존 쿠폰 단독 할인 원칙은 새 설계에서 개정된다. 현재 결제 코드는 여전히 쿠폰만 처리하며, 적립/사용/복원의 구체 계약은 아직 확정되지 않았다. Q9는 국내 배송대행지 수취·원화 결제로 정했으므로 국제 운송·다통화 기능은 이 요청의 의미가 아니다.
- 확정된 새 용어만 CONTEXT.md에 추가한다. 설계 메모나 DB 필드를 용어집에 넣지 않는다. Q2~Q9에서 확정된 식별자·계층 분류·매입단가·안전재고 기준·예약판매·적립금·국내 배송대행지 구분을 기록했다. ADR은 되돌리기 어렵고 대안 간 선택 이유가 필요한 결정에만 작성하며, 현재는 새 ADR을 작성하지 않았다.
- #451 직접 Data API 읽기 제한과 #453의 잔여 물류 인수/단일 교환 운송장 한계는 별도 미해결이다. 새 티켓으로 복제하지 않고 같은 이슈에 연결할 범위를 정한다.
- 운영 가이드의 “이번 주 바뀐 것”은 현재 셸 변경만 안내한다. 이번 기능 안내를 정리할 때 이미 배포된 상품·배송·CS 개선도 사용자가 찾을 수 있도록 보완한다. 미구현 기능을 완료형으로 게시하지 않는다.
