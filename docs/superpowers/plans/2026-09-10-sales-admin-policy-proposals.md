# 영업팀 어드민 피드백 — 채택한 정책 구조와 운영 입력

작성: 2026-09-10. 상태: **운영 규칙의 권장 구조 채택. 실제 수치·증빙 미설정 기능은 활성화 차단.**

구현 작업에서 제품 소유자가 “권장 구조로 구현하고, 실제 수치·증빙 미설정 기능은 활성화 차단”을 선택했다. 아래 ERP·카테고리·매입단가·판매/예약·쿠폰/적립금·배송/엑셀의 권장 구조를 구현 기준으로 채택한다. 표의 대안은 선택되지 않았으며, 실제 요금표·인증자료·금액·기한을 채우지 않은 상태를 0원·무제한·검토 완료로 해석하지 않는다. 2026-09-11 사용자가 “권장안으로 진행해”라고 답해 Q11(인앱 알림+주문 이메일)과 Q12(기본 문서 HTML)도 확정했다. 두 기능의 구현·검증을 진행하며 실제 고객 발송 승인은 별개다.

대상은 #460의 정책 의존성이 있는 27개 티켓(#462, #467, #471~#495)이다. Q1~Q12의 결정을 유지하고, 미정 금액·기한·물류 사실은 승인된 기본값으로 바꾸지 않는다. 이 문서 채택은 실제 고객 발송·배포·운영 데이터 변경 승인이 아니다.

## 판단 요약

**#462·#467·#480·#481의 4개는 기존 기능 안에서 구현자가 정할 수 있는 화면·조회 결정이다.** 새 경제 정책이나 외부 사실이 필요하지 않으므로 자율 구현 범위에서 선택안을 명시하고 실제 동선으로 검증할 수 있다. 다만 과거 인터뷰에서 사용자가 이 값을 골랐다고 기록하지 않는다. 원 티켓의 정책 항목은 실제 구현 결정과 근거로 해소해야 한다.

**나머지 23개는 제품·운영 결정 또는 사실 확인이 남는다.** #471에서도 이미 지원하는 무통장·19금 컨트롤을 폼에 연결하는 부분은 독립적으로 진행할 수 있지만, 새로운 결제수단 조합까지 확정된 것은 아니다. P12 하나를 일괄 해제하면 안 된다. 검색·진열(#480·#481), 구매 구성(#482), KC(#477)는 서로 다른 결정이다.

금액·기한이 없는 정책을 `0`, 무제한, 영구 유효, 모든 직원 허용으로 해석하지 않는다. 명시적인 미설정 상태와 실제로 설정된 0을 구별한다. 주문 전체 취소·반품·교환 계약을 유지하며 부분 환불 원장을 이 범위에 추가하지 않는다.

## 유지하는 Q1~Q10

1. 원문 미반영 요구 전체를 추적하고 기존 구현을 재사용한다.
2. 자동 상품/옵션 코드·ERP 코드·바코드를 분리한다.
3. 고객 계층 카테고리에 ERP 분류를 연결하며 IP/버티컬과 구별한다.
4. 공급가는 공급처에서 사오는 매입단가다.
5. 안전재고는 옵션별 경보 기준이며 판매 물량을 차감하지 않는다.
6. 예약판매는 주문 시 결제하고 약속한 예정일에 발송한다.
7. 적립금은 주문 할인용 별도 잔액이며 무료 코인·카드팩·쿠폰과 분리한다.
8. 교환·반품비는 안내와 운영 확인액 기록에 한정하며 자동 청구·환불 차감을 하지 않는다.
9. 해외 고객도 원화 결제와 국내 배송대행지 수취를 사용한다.
10. 거래확정 엑셀은 요청한 8개 정보를 담는 영업·정산 검토 자료다.

### 돈·수량에 관한 최소 합의 항목

- **공통 원장**: 기간 할인 후 옵션 단가·품목 수량·대상 쿠폰 할인·사용 적립금·배송비·최종 청구액을 각각 보존한다. `최종 청구액 = 품목 금액 합계 - 쿠폰 할인 - 사용 적립금 + 배송비`가 주문과 엑셀에서 같아야 한다. 0원 결제나 부분 환불을 신규로 지원한다고 가정하지 않는다.
- **할인 배분**: 품목별 할인 후 금액을 엑셀에 넣으려면 주문 생성 시 정한 원 단위 배분 결과가 필요하다. 비례 배분 뒤 나머지를 안정적인 품목 순서로 배정하는 방식을 제안한다. 내보낼 때 현재 상품 가격으로 다시 배분하거나 배송비를 모든 품목에 반복 합산하지 않는다.
- **과거 할인 기록**: 품목별 할인 배분을 기록하지 않은 과거 주문은 할인 후 품목금액을 당시 기록처럼 만들어내지 않는다. 품목 원금액과 주문 단위 실제 할인액을 구별해 보여주고, 새 배분 계약의 적용 시점과 미기록 상태를 명시한다.
- **결제 시각**: PG는 검증된 승인 증거 시각, 무통장은 실제로 기록한 입금확인 시각을 사용하는 안이다. 서로 다른 사건이면 `결제시각 기준`을 같이 내보낸다. 실제 입금 시각을 수집하지 않았다면 운영 확인시각을 실제 이체시각으로 표시하지 않는다.
- **적립금 환불**: 사용한 적립금의 복원과 해당 구매로 새로 적립한 적립금의 취소는 다른 사건이다. 원적립분이 이미 사용된 경우, 만료된 사용분을 복원하는 경우의 정책을 확정해야 한다. 임의의 현금 청구·환불액 차감·환불 접수 거절로 해결하지 않는다.
- **운영 수치**: 적립률/정액, 상한, 만료, 사용 하한/상한, 복원 유예기간, 예약 물량/예정일, 구매 한도/기간, 물류 금액은 별도 결정표에 실제 값을 기록한다. 이 문서의 설계안을 채택해도 빈 수치가 자동 확정되지는 않는다.

## 확인한 근거와 한계

- 제공된 [부모 스펙 #460](https://github.com/icons-hq/icons-ip/issues/460)와 대상 27개 티켓의 본문·수용 조건·정책 의존성을 대조했다. 특히 #460의 최초 게시본은 Q11/Q12 미답변, 숫자·범위 임의 확정 금지, 기존 인수 증거와 개발 검증의 구별을 명시했다. Q11/Q12는 위 후속 사용자 답변으로 해소했다.
- 현재 `CONTEXT.md`, `docs/PRD.md`, `docs/ARCHITECTURE.md`의 카탈로그·주문·혜택·배송·인증·권한 관련 계약을 확인했다. 구현 판단의 근거로 `app/login/actions.ts`의 local sign-out/홈 이동, `lib/shop-catalog.ts`의 추천/최신/가격 정렬과 BEST 큐레이션, 기존 `/admin/sales/orders/[orderId]` 경로를 추가 확인했다.
- [#177 물류 사양](https://github.com/icons-hq/icons-ip/issues/177)은 2026-09-10 read-only 조회 시 OPEN이며, 확인한 본문·댓글에는 H6의 실제 배송 가능 지역·요금 회신이 없다. 다른 곳에 회신이 존재하지 않는다고 단정한 것은 아니다. 기존 담당 회신을 찾으면 그 증거를 재사용하고 H1~H7 전체 재확정을 요구하지 않는다.
- Safety Korea는 생활용품의 안전인증·안전확인·공급자적합성확인·안전기준준수를 구별한다. 안전인증과 공급자적합성확인의 확인 절차도 다르다. 따라서 KC UI를 모든 굿즈의 공통 인증번호 한 칸으로 확정하지 않는 것이 타당하다. 2026-09-10 확인: [생활용품 안전인증](https://www.safetykorea.kr/policy/targetsSafetyCert2), [생활용품 공급자적합성확인](https://www.safetykorea.kr/policy/targetsSafetyQuality). 이 확인으로 개별 판매 굿즈의 법적 분류나 적합성을 판정하지 않았다.
- 검증은 정책·의존성·문서 일관성 검토다. 이 제안서 작성에서 앱·DB·엑셀·브라우저 기능 테스트, 운영팀 인수, production 변경, 실제 고객 메시지 발송을 수행하지 않았다.
