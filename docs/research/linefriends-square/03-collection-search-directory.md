## 1. 컬렉션 페이지

### 1.1 URL 체계

- 상설 카테고리: `/collections/category-{toy|keyring|closet|interior|living|electronics|office|travel|beauty-acc|apparel|pouch|sticon}` — GNB "카테고리" 메가메뉴에서 진입
- 브랜드 컬렉션: `/collections/{brand-handle}` (`bt21`, `joguman`, `truz`, `i-dle`…) — 소문자 kebab 핸들
- 특수 컬렉션: `/collections/new`(신제품), `/collections/sale`, `/collections/shop`(카테고리 허브·히어로 캐러셀 있음, `17-category-shop-*` 참조), 기획전 핸들 다수
- 필터/정렬 적용 시 쿼리 직렬화: `?filter.p.vendor=BT21&filter.v.price.gte=0&filter.v.price.lte=218000&sort_by=manual`
  - 브랜드 필터: `filter.p.vendor` (다중 값 반복 가능)
  - 상품타입 필터: `filter.p.m.lfs.product-badge` (메타필드; 값 `NEW`/`EXCLUSIVE`/`SALE`)
  - 가격: `filter.v.price.gte`/`.lte`

### 1.2 페이지 헤더

- **상설 카테고리 페이지에는 컬렉션 타이틀·설명·배너가 없다.** 헤더(GNB) 바로 아래에서 필터+그리드가 시작된다.
- 그리드 상단 좌측 카운트 행(h2 `.product-count__text`, 그리드 좌측 정렬 x406.5):
  - `전체 › {N}개 제품` — "전체" 14px regular + 구분 글리프 + 카운트 **700 14px** `#111`
  - 필터 적용 시 `전체 {선택}/{전체}개 제품` 형태로 즉시 갱신 (예: `전체 209/690개 제품`, 0건이면 `전체 0/690개 제품`)
  - 일부 컬렉션(`/collections/sale`)은 "전체" 프리픽스 없이 `{N}개 제품`만 노출
- 카운트 행 우측 끝에 정렬 컨트롤(1.4)

### 1.3 필터 사이드바 (데스크톱, 200px)

그룹 전수(상설 카테고리 기준, 위→아래). 모두 `<details open>` 디스클로저 — 기본 전부 펼침, 제목 클릭으로 접기 가능.

| 그룹 | 제목 표기 | 컨트롤 |
|---|---|---|
| 브랜드 | `브랜드 (n)` — n은 **선택된 필터 수** (기본 0) | 체크박스 리스트. category-toy 기준 70개 브랜드, 각 항목 `{브랜드명} ({상품수})` |
| 상품타입 | `상품타입 (n)` | 체크박스 3종: `NEW` / `EXCLUSIVE` / `SALE` |
| 가격 | `가격` | 듀얼 핸들 레인지 슬라이더 + 최소/최대 라벨 |

- 그룹 제목: **800 18px** Pretendard `#111`, 그룹 간 세로 리듬 ~167–400px(항목 수에 따라)
- 체크박스: 네이티브 input 숨김 + 커스텀 SVG 20×20 두 장 겹침
  - 미체크: 흰 배경, `#DCDEE0` 1px 스트로크, radius 1.5
  - 체크: 검정 채움 + 흰 체크마크
- 항목 라벨: 14px/25.2, `#111`, 행 높이 34px, 텍스트는 체크박스에서 32px 들여쓰기
- 가격 슬라이더: 트랙 195×6px, 듀얼 `input[type=range]` 겹침. 아래에 보더 박스로 `₩ 0 ~ ₩ {max}` 라벨(700 14px). **max는 컬렉션별 동적**: category-toy 218,000 / bt21 134,900 / shop 290,000
- 최하단 `전체 초기화` 버튼: 200×40, 흰 배경 + 1px 보더, 14px, 리프레시 아이콘 동반
- **적용된 필터 칩(chip) 행이 없다.** 피드백은 3곳: 그룹 제목의 `(n)`, 카운트 행 `{선택}/{전체}`, 체크된 박스. 해제는 체크 재클릭 또는 전체 초기화
- 적용 방식: 체크 즉시 AJAX로 그리드 교체(페이지 리로드 없음) + URL 쿼리 replaceState. 결과는 20개부터 다시 로드

### 1.4 정렬 드롭다운

- 구현: **네이티브 `<select name="sort_by">`** + 커스텀 caret SVG(10×6). 별도 커스텀 패널 없음(OS 기본 옵션 리스트). 라벨 "정렬 기준:"은 시각적으로 숨김
- 표시 텍스트 12px(.caption), 우측 정렬(x1123.5~1302.5 영역)
- 옵션 9종 전체(값 → 라벨):

| value | 라벨 |
|---|---|
| `manual` | 추천순 |
| `most-relevant` | 가장 관련성 높음 |
| `best-selling` | 베스트셀러 |
| `title-ascending` | 브랜드명, A-Z |
| `title-descending` | 브랜드명, Z-A |
| `price-ascending` | 가격(낮은 가격부터) |
| `price-descending` | 가격(높은 가격부터) |
| `created-ascending` | 출시순(오래된 날짜부터) |
| `created-descending` | 출시순(최신 날짜부터) |

- 기본값은 컬렉션별로 다름: category-toy·sale·bt21 = `추천순`, 신제품(`02-collection-desktop.png`) = `출시순(최신 날짜부터)`

## 2. 검색

### 2.1 진입 (헤더 검색 아이콘)

- 헤더 아이콘은 `<a href="/search">`지만 JS가 가로채 **페이지 이동 없이 인라인 오버레이 레이어**를 연다
- 데스크톱: 헤더 밑으로 패널 확장(스티키 헤더 섹션이 늘어남). 검색 인풋 **1180×60**, 배경 `#F6F8FA`, 보더 없음, placeholder `어떤 상품을 찾으시나요?` 16px(Arial 폴백). 인풋 우측에 돋보기 아이콘. 패널 아래 화면 전체 딤 `.searchBackdrop` rgba(0,0,0,0.1). 닫기 버튼 없음(바깥 클릭/ESC)
- 모바일: 같은 레이어의 모바일 배치 — 인풋 좌측에 뒤로가기 화살표, 우측 돋보기 (`detail/03r-search-overlay-mobile.png`)
- **추천 검색어**: 라벨 `추천`(700 17px) + 운영자 큐레이션 칩 10개 — `.ipxSearchTerm` 필 칩, 14px, 핑크 `#F83BAA` 텍스트 / rgba(248,59,170,0.1) 배경 / radius 17 / h32. 각 칩은 `/search?q={term}&options[prefix]=last&type=product` 링크
- **최근 검색어 UI 없음. 타이핑 중 자동완성(프리딕티브) 패널도 없음** — 제출해야 결과 페이지로 이동

### 2.2 결과 페이지 레이아웃 (`/search?type=product&q={q}&options[prefix]=last`)

- 상단 밴드: 좌측 H1 `'{q}'에 대한 {N}개의 결과` — 24px/26.4, 기본 `#111`에 **질의어·건수만 핑크**(`.ipx-text-pink`) / 우측 인라인 검색 인풋 433.5×50 (돋보기 프리픽스, 질의어 유지, 배경 `#F6F8FA`)
- 그 아래는 컬렉션과 동일 골격(사이드바 200 + 그리드 896). 카운트 행 `전체 › 1067개 결과` ("~개 결과" 표기)
- **결과 타입 탭 없음** — 상품 단일 타입(`type=product` 고정). 콘텐츠/페이지 검색 구분 UI 부재

### 2.3 검색 전용 사이드바

컬렉션과 달리 **최상단에 `카테고리` 링크 트리가 추가**된다(체크박스 아님, 내비게이션):

- 제목 `카테고리` 800 18px (`.category-title`)
- `ul.category-list`: 5개 `<details>` 그룹 — `토이` `리빙` `전자소품` `문구` `패션`, 각 행에 chevron(11×7 `#111`)
- 펼치면 서브카테고리 링크 목록, 첫 항목은 항상 `전체`. 실측 예:
  - 토이 → 전체 `/collections/toy` · 피규어 `/collections/figurine` · 인형 `/collections/plush` · 쿠션 `/collections/cushion` · 키링 `/collections/keyring`
  - 리빙 → 전체 `/collections/living` · 아웃도어 `/collections/outdoors` · 인테리어 `/collections/household` · 욕실/바디케어 `/collections/bath-body`
- **주의: GNB 카테고리(`/collections/category-*`)와 다른 핸들 체계**(예: 토이 전체가 `category-toy`가 아니라 `toy`) — 카테고리 컬렉션이 이중으로 존재
- 그 아래 브랜드/상품타입/가격 facet은 컬렉션과 동일 UI이되, **값은 검색 결과 기준으로 축약**(예: q=bt21 → 브랜드 BT21(1064)·COLLER(3), 상품타입 NEW(112))

### 2.4 정렬·페이지네이션 (컬렉션과 다름)

- 정렬 옵션 **3종만**: `관련성`(기본) / `가격(낮은 가격부터)` / `가격(높은 가격부터)`
- 페이지당 **40개**
- **숫자 페이지네이션** (`nav.ipx-custom-pagination`), 그리드 하단 중앙:
  - 번호 셀 36×36, 16px `#333`; 현재 페이지 700 `#111` (aria-current)
  - 표시 번호 데스크톱 최대 10개 + 말줄임, 모바일 5개
  - 양끝 화살표 4종: 맨처음(더블 chevron)·이전·다음·맨끝 — 1페이지에선 이전/맨처음 숨김
  - 동작: `location.href`로 `&page={n}` **풀 페이지 이동**(AJAX 아님) — 컬렉션의 VIEW MORE와 완전히 다른 모델
- 결과 카드 마크업은 컬렉션 카드와 동일(§1.5). 검색 페이지에서는 `#product-grid`가 wrapper div이고 내부 `ul.product-grid` + `.loading-overlay` + 페이지네이션 wrapper 구조

### 2.5 결과 없음 상태

- H1: `'{q}'에 대한 0개의 결과`, 인라인 검색 인풋 유지
- 본문 중앙: `"{q}"에 대한 검색 결과가 없습니다. 철자를 확인하거나 다른 단어/문구를 사용해 보십시오.` — 16px/22 `#111`
- **사이드바(카테고리·facet) 전체 미노출**, 추천 칩 재노출 없음 — 회복 수단이 문구뿐인 빈약한 상태 (리디자인 시 개선 포인트)

### 2.6 모바일 검색 결과

- **H1(결과 헤딩)·인라인 검색 인풋·카테고리 트리 모두 숨김** — 모바일 컬렉션과 사실상 동일한 화면(필터 및 정렬 트리거 + 카운트 행 + 2열 그리드)
- 정렬 select 컨트롤도 미노출(관련성 고정 노출) — 정렬 변경은 바텀시트 경유 불가, 사실상 데스크톱 전용
- 페이지네이션은 숫자 5개 + 화살표, 중앙 정렬

## 3. 브랜드 디렉토리 (`/pages/brand`)

### 3.1 데스크톱 구성 (위→아래)

1. **피처드 브랜드 타일 5개**: 212×212 정사각, gap 30, 각 브랜드관 링크(bt21/joguman/truz/zonfriends/i-dle). 타일 비주얼 이미지 + 좌하단 브랜드명 오버레이(`.ipx-title` 700 14px 흰색)
2. **A–Z 인덱스 바**: 상하 보더 행(h40.5, w848), 28개 항목 = `ALL` + A–Z + `ETC`
   - 15px; 비활성 `#C8CACC`, 활성 700 `#111` + 밑줄. 기본 `ALL`
   - 우측 끝에 `총 44 개` (14px, 44 굵게)
   - 레터 클릭 = **클라이언트사이드 필터** (URL 변화 없음, 리스트·카운트 즉시 갱신. 예: B → 2개)
3. **브랜드 리스트**: 4열 × 11행 그리드 (열 폭 256, 열 간격 52, 행 간격 0)
   - 행(타일) anatomy: 256×89, 하단 `1px solid #EBEDEE` 디바이더
   - 좌측 **로고/비주얼 썸네일 56×56 정사각**(radius 0) + 76px 지점부터 브랜드명 700 14px `#111` (수직 중앙)
   - 링크는 각 브랜드관 `/collections/{handle}`
   - 텍스트 온리 아님·로고 온리 아님: 항상 이미지+텍스트 병기

### 3.2 모바일 구성

1. 피처드: **1장씩 보이는 스와이프 캐러셀**(Swiper) — 슬라이드 332×332, gap 8, 하단 도트 페이지네이션 6개(활성 검정). 슬라이드 좌하단 브랜드명 700 28px 흰색
2. A–Z 바: 한 줄 가로 스크롤(항목 14px), `총 44 개`는 바 아래 우측 정렬로 분리
3. 브랜드 리스트: **2열 큰 타일** — 타일 159.5 폭, 썸네일 159.5×159.5 정사각 + 아래 브랜드명 700 16px, 열 간격 9, 타일 높이 219 (데스크톱의 가로형 행과 완전히 다른 카드형)

### 3.3 개별 브랜드관과의 관계

- 디렉토리의 모든 링크는 §1.9의 브랜드 컬렉션으로 연결. 브랜드관 = 일반 컬렉션 + 브랜드 배너(비주얼·좋아요·설명·해시태그) + 축약 facet
- 브랜드 "팔로우"에 해당하는 좋아요는 브랜드관 배너에서만 가능(디렉토리 타일에는 없음)

## 4. 재현·리디자인 시 참고 노트

1. **페이지네이션 모델이 3원화**되어 있다: 컬렉션 = VIEW MORE(AJAX 20개), 검색 = 숫자 페이지(풀 리로드 40개), 브랜드 디렉토리 = 전량 렌더 + 클라이언트 필터. 리디자인 시 통일 여부가 UX 결정 포인트
2. **카테고리 체계 이중화**: GNB용 `/collections/category-*` 와 검색 사이드바용 서브카테고리 핸들(`/collections/toy` 등)이 병존한다. 정보구조 재설계 시 통합 대상
3. **적용 필터 칩이 없다**: 데스크톱은 즉시 적용 + 카운트 피드백, 모바일은 바텀시트 + 적용 버튼(지연 적용)으로 패턴이 갈린다
4. 가격 슬라이더 max, facet 값 목록, 정렬 기본값이 모두 **컬렉션 컨텍스트에 따라 동적**
5. 배지(NEW/EXCLUSIVE/SALE)는 상품 메타필드(`lfs.product-badge`) 기반 — 배지가 곧 필터 축
6. 원 사이트 결함(재현하지 말 것): (a) 컬렉션/검색 페이지에서 로드 수십 초 후 첫 상품 상세로 강제 이동하는 스크립트 내비게이션이 주기 실행됨(자동화 환경에서 재현 확인, speculation-rules prerender와 결합해 발생), (b) 빈 결과 페이지에 no-JS용 `<button…>` 마크업이 이스케이프된 텍스트로 노출, (c) VIEW MORE 버튼·검색 인풋이 Pretendard가 아닌 Arial로 렌더
7. 검색 빈 결과에서 사이드바·추천 칩이 사라져 회복 동선이 없음 — 리디자인 개선 후보
8. 모바일 검색 결과에서 정렬 변경 수단이 없음 — 개선 후보
