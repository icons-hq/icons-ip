## 1. 요약

1. **골격은 그대로다.** 전역 크롬·홈 밴드·컬렉션·PDP·카트·마이 셸·이벤트 허브의 구조와 주요 수치(헤더 68/81, GNB 54, 히어로 1440×770, 컬렉션 200+84+896, PDP 649/531/446, 로그인 448, 이벤트 1180×260)는 8/26 스펙과 ICONS 구현 모두 일치한다.
2. **라이브에서 가장 크게 보이는 차이는 데이터와 게이트다.** ICONS 홈은 7개 밴드 중 3개만 그려진다. 카테고리 BEST·인기템·추가 배너+리스트는 큐레이션이 비어 있고, 혜택 밴드는 카드 리워드 게이트(OFF)가 통째로 비운다(`lib/home-catalog.ts:84-89`). GNB 두 번째 항목 `/shop/best`는 빈 화면이고, 노출 굿즈 대부분이 시연 데이터다(§8.8).
3. **코드 차이의 P0는 상품 상세에 몰려 있다.** 모바일 구매 바텀시트 부재(다옵션 굿즈는 하단 바가 비활성으로 남는다), 담기 결과 모달 부재, 데스크톱 미니 구매바가 짧은 상세에서 첫 화면부터 본문 CTA와 겹치고 문의 런처를 가리는 결함, 모바일 갤러리 풀블리드 이탈(§8.4).
4. **로그인 표면을 처음 실측했다.** 마이페이지 대시보드 블록 4종, 모바일 바로가기, 회원 등급 안내 페이지, 독립 배송지 관리(주소록), 리뷰 보상 배너가 새로 확인됐다(§5). ICONS에는 대시보드·주소록·등급 안내가 없다(§8.6).
5. **8/26 스펙 자체의 오기·누락이 20건 확인됐다.** LFS의 JS 자산은 모두 8/26 이전 날짜라 동작 차이 대부분은 레퍼런스 변화가 아니라 기록 오류다(모바일 헤더 축약 방향, 하단 탭바 스크롤 숨김, 검색 배경 흐림, 바로구매 목적지 등). 수치를 맞추기 전에 스펙부터 정정한다(§4).
6. **LFS의 실제 변화(LFS-Δ)는 적다.** 닫기 가능한 텍스트 공지 바(10/19 생성), 모바일 PDP 구매 시트, 데스크톱 레일 안 플로팅 박스(추정), '추가정보' 아코디언, PRE-ORDER 필터 값, 푸터 링크·배지, 사은품·구매제한 설정 개정(§3).

## 10. 확인 못 한 것

- **ICONS 다옵션 PDP·담긴 카트·캠페인 데이터 상태**: 운영에 다옵션 굿즈 0건, 담기 금지, 캠페인 0건이라 코드로 판정했다. 구현 단계의 격리 스택 QA에서 시드 후 확인한다.
- **LFS 주문 행·로그인 쿠폰 적용·재입고 등록 응답·브랜드 좋아요 동작**: 계정에 주문이 없고 상태 변경을 하지 않았다.
- **LFS 메가메뉴 열린 화면**: hover를 재현할 수 없어 DOM 구조로 판정했다.
- **LFS 모바일 구매 시트 애니메이션·시트 안 담기 후 UX**: 클래스 토글로 띄운 정지 화면만 봤다.
- **8/26 비교 자료가 없는 것**: BEST 배너, 모바일 브랜드관, 모바일 상단 고정, 데스크톱 플로팅 박스의 합계 행 — 변화 여부 판정 보류(동작 수치는 실측값이 정본).
- **`?v=` 날짜 해석**: 추정이다.
- **운영 DB 값**: 게이트·스토어 설정·큐레이션은 코드·기본값과 라이브 화면으로 판정했다.
