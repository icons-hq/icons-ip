## CUSTOMERS (고객·혜택)

담당 범위: 고객·회원 목록과 상세(정지·등급 보정·탈퇴 처리·카카오 연결 해제 대기), 타겟 세그먼트·회원 방문·영상 분석 설정, 신규/재구매 분석·혜택 리포트, 쿠폰(등록·발급·회수·중복 정책·대상·기간), 적립금(정책·단건 조정·일괄 지급·엑셀), 등급(고객등급 관리·등급·리뷰 보상), 판매방해 고객 구매제한(단건·복수·선택 해제), 할인 프로모션, 상품 혜택·이벤트 템플릿 액션, 카드팩 발급 정책.

### 이번에 맞춘 공통 문형
- **결과를 모르는 실패(불명확·불확실·“같은 요청으로 다시 확인”)**: “○○됐는지 확인하지 못했습니다” + 화면에 실제로 있는 버튼 이름(‘같은 요청으로 저장 결과 확인’, ‘등록 결과 재조회’, ‘같은 요청 결과 조회’, ‘처리 결과 조회’, ‘현재 작업 결과 조회’, ‘현재 저장본 다시 불러오기’, ‘현재 상태 조회’ 등) + “두 번 처리되지 않습니다”. 두 번 처리되지 않는다는 말은 각 화면이 같은 작업 번호(operationId·batch id)를 다시 보내는지, DB 함수가 같은 번호를 다시 받으면 저장된 결과를 돌려주는지 코드로 확인한 곳에만 넣었다(쿠폰 회수처럼 새 번호로 다시 보내는 곳은 ‘이미 회수된 쿠폰은 두 번 처리되지 않음’으로 근거를 바꿔 씀).
- **처리 안 된 실패**: “○○하지 않았습니다” + 어느 칸·체크를 고치면 되는지 + 어느 버튼을 다시 누르는지.
- **다른 사람이 먼저 바꿈(PT409 등)**: “다른 관리자(작업)가 먼저 바꿔 저장하지 않았습니다” + 최신 내용을 보는 버튼 이름.
- **로그인 바뀜(세션)**: “로그인 계정이 바뀌었습니다(다른 계정·로그아웃)” + “화면을 새로고침”.
- **회원 ID·고객 ID** → 고객 상세에 이미 쓰는 이름 **회원번호**, **작업 ID** → **작업 번호**, 혜택 리포트의 **혜택 ID·쿠폰 ID**(실제 값은 쿠폰 코드) → **쿠폰 코드**, 발급·사용 UUID → **발급 번호·사용 번호**.
- 돈·탈퇴·정지 확인창·안내에는 되돌릴 수 있는지(정지 해제 가능, 탈퇴 처리·쿠폰 회수는 되돌릴 수 없음 — 기존 문구 유지)와 조건(15분, 최대 인원·글자 수)을 빠뜨리지 않았다.
- 버튼 이름을 문장에 넣을 때는 ‘ ’(굽은 따옴표)를 썼다. 곧은 따옴표는 렌더 HTML에서 `&#x27;`로 바뀌어 테스트·검색에 걸리기 때문이다.
