# 어드민 문구 전수 정리 (2026-11-19)

어드민(`/admin/**`) 화면과 어드민 가이드의 운영자용 문구를 전부 훑어, 개발 용어·추상적인 문장·행동 안내가 빠진 안내·고칠 방법이 없는 오류를 쉬운 말로 바꾼 기록이다. 원칙은 **정보는 빼지 않고 말만 쉽게**다. 규칙과 용어 대체표는 [어드민 문구 작성 규칙](../../admin-copy-guide.md), 코드 칸 이름과 잠금은 [ADR-0048](../../adr/0048-auto-generated-code-labels.md)이다.

## 계기

2026-11-19 MD가 상품 49개를 등록하면서 받은 엑셀의 '코드'(ERP 코드)를 옛 '관리코드' 칸에, 바코드를 옛 '판매자상품코드' 칸에 넣었다. 옵션 상세 정보 안내는 "ERP 품명을 입력해 반입된 ERP 품목을 고르면 … 선행 0을 유지합니다. 비워 두면 미설정입니다."처럼 개발 용어로만 쓰여 있었고, 어느 칸이 거래확정 엑셀에 찍히는지는 말하지 않았다.

사용자 지시: "그거 알려주긴 해야 되잖아. 근데 말을 어렵게 써 놓고 이해 안 되게 해서 문제인 거잖아"

## 방법

- 대상: 어드민 소스(`components/admin`·`app/admin`·`lib/admin`, kit 제외) 1,175개 파일에서 문구가 있는 915개 파일, 한글 문구 약 1만 7천 개. 안내문·칸 이름·입력칸 예시 글·도움말·오류·성공 메시지·확인창·빈 화면 문구·엑셀 안내 시트·aria-label·어드민 가이드.
- 영역 8개(상품 편집·카탈로그·주문·클레임·고객·상담·전시/설정·가이드)로 나눠 같은 지시서로 조사·수정하고, 메인이 합치며 영역 사이 이름·표기를 맞췄다.
- 바꾸지 않은 것: 동작·DB·저장값·식별자, 올릴 때 읽는 엑셀 머리글, 외부 양식(창고·스마트스토어·사방넷)의 열 이름, DB 함수가 직접 돌려주는 오류(`raise exception`), 지난 업데이트 내역.
- 사실 확인: 다시 쓴 문장은 코드·migration으로 확인했다(어느 엑셀에 찍히는지, 다시 눌러도 한 번만 처리되는지, 누가 할 수 있는지 등). 확인하지 못한 것은 원래 정보 수준을 유지하고 '남긴 후보'에 적었다.

## 이름이 바뀐 주요 화면 문구

화면 이름이 바뀐 곳은 가이드·런북도 같이 맞췄다. 전체 목록은 각 영역 기록의 '이름 변경' 절에 있다.

- 상품 코드: 판매자상품코드 → **상품 자동코드**, 관리코드 → **옵션 자동코드**(기본 잠금, ADR-0048, 별도 PR)
- ERP 품목: 품목 반입 → 품목 올리기, 반입된 품목 → 올린 품목, 최근 반입 → 최근 올린 날
- 카테고리 관리: 활성화 상태 → 고객 화면·ERP 사용 설정, 활성화 상태 저장 → 사용 설정 저장, 미설정만 → ERP 값 없는 것만
- 기간 할인·복수구매 할인: 이 정리에서 '초안'을 '대기'로 바꿨으나, 같은 날 예약판매 PR #701이 상태 선택(초안) 자체를 없애 '사용·사용 안 함'만 남았다(#701 문구를 따름)
- 상담 작성 중 보관: 초안 복구·초안 버리기 → 작성하던 내용 복구·버리기
- 적립금 정책: 상한·하한 → 최대·최소, 비활성 → 꺼짐, 미설정 → 선택 안 함
- 회원·고객 ID → 회원번호, 작업 ID → 작업 번호, 혜택 ID·쿠폰 ID → 쿠폰 코드
- 주문: 큐에서 내리기 → 목록에서 내리기, 착불 수납 원장 → 착불 수납 기록, 이전 요청 봉인 후 다시 입력 → 이전 요청 무효 처리 후 다시 입력, 출고지시 컬럼과 헤더 설정 → 열과 머리글 설정, 공급자 접수 → 발송 서비스 접수
- 클레임: 환불 완료를 원장에 기록 → 환불 완료 기록만 남기기, 회신 미리보기 매칭 → 확정 대상, 저장 작업의 요청번호 → 처리 번호
- 시스템 상태: 결제사·원장 불일치 → 결제사·주문 불일치, 2단계 인증 '이 로그인 세션' → '지금 로그인'
- 표기 통일: 감사 로그·운영 기록(감사 뜻) → 감사 기록, 시각은 KST(`lib/admin/copy-contract.test.ts` #25)

## 다시 생기지 않게

- 규칙: [어드민 문구 작성 규칙](../../admin-copy-guide.md). DESIGN.md §어드민 콘솔과 AGENTS.md가 가리킨다.
- 테스트: `lib/admin/copy-contract.test.ts`에 #40(선행 0·반입·스냅샷·멱등·페이로드·감사 로그 금지), #41('미설정'만 쓰지 않기), #42(옛 코드 이름 금지)를 더했다. 주석은 보지 않는다.

## 2차: 미룬 영역과 같은 날 새로 들어온 문구

1차가 머지된 뒤(2026-11-19 #703·#704) 같은 기준으로 이어서 정리했다.

| 영역 | 고친 문구 | 기록 |
|---|---|---|
| 예약판매·상세 이미지·상품 목록(1차에서 다른 작업과 겹쳐 미룬 파일) | 129 | [deferred.md](deferred.md) |
| 같은 날 다른 PR(#693·#694·#696~#700·#689)이 새로 넣은 문구(창고 출고 중단 회신, 부분 반품, 운영 알림 메일, 탈퇴 처리 등) | 81 | [new-2026-11-19.md](new-2026-11-19.md) |

- 예약판매의 '할당'은 '입고 확인'으로 바꿨다. 화면 버튼·칸이 이미 '입고 확인'을 쓰고 있었고, '배정'은 랜덤 판매의 옵션 무작위 배정이라는 다른 뜻이다. 버튼은 [선택한 예약 주문 입고 확인], 상태는 '입고 확인 전·입고 확인 완료'. 이 버튼을 가리키던 다른 화면(발송·배송 처리, 출고 관리, 자동 발주확인, 주문 상세 이력, 강제 배송완료)과 가이드·런북도 같은 이름으로 맞췄다.
- 상품 재고를 뜻하던 '할당 재고'는 1차와 같이 '재고수량'이다.
- copy-contract #41('미설정')의 예외 목록을 지웠고, #25(KST)는 '(한국)' 표기도 잡게 했다.

## 남긴 후보

문구만으로는 못 고치거나 여러 화면을 한 번에 바꿔야 해서 남겼다. 자세한 내용은 각 영역 기록의 '남긴 후보'.

- **결과 확인 버튼 이름이 화면마다 다르다**('같은 요청 결과 확인'·'같은 요청으로 결과 확인'·'저장 결과 확인' 등). 문구는 각 화면의 버튼 이름을 정확히 부르게 했다. 이름 통일은 전 화면·가이드를 함께 바꾸는 별도 작업이다.
- **동작 변경이 필요한 것**: 구매 제한의 근거 주문번호 칸이 내부 주문 ID만 받는다(화면의 주문번호는 20자리 번호). 등급·리뷰 보상 정책은 저장 오류 뒤 입력이 잠기고 '현재 저장본 다시 불러오기'가 입력을 덮어쓴다. 리뷰 일괄 답글 결과에 리뷰 내부 ID만 보인다.
- **외부·내려받기 파일 이름**: 거래확정 엑셀의 '원장' 머리글(회계·ERP가 열 이름으로 찾을 수 있음), 리뷰·이벤트·응모 엑셀의 'ID' 머리글(개인정보 접속기록 검색 칸과 함께 바꿔야 함), 엑셀 '고시 프리셋'(올릴 때 읽음), 적립금 대상 CSV의 '고객 ID 또는 이메일'(파서에 '회원번호' 별칭을 더하는 동작 변경 필요).
- **기능·상태 이름**: 'ERP 분류 매핑', 지역 정책·배송 안내 템플릿의 '초안·활성' 상태, '같은 옵션 배정 상한', IP '내부 ID', 시스템 상태의 'DB 자동 작업'·'DB 오류'·'응답 코드'(개발팀에 넘기는 구분값), 통계의 '방문 세션'(분석 지표 이름).
- **어드민 밖 공용·고객 문구**: `lib/claim-contact/contracts.ts`, `lib/orders/claim-*.ts`, `components/orders/ClaimWithdrawal.tsx`·`ClaimRefundAccount.tsx`('불확실'·'입력 고정'·'브라우저 저장소'), `lib/store-credits.ts`(옛 칸 이름 '사용 하한·상한'), 고객 화면 `components/account/AccountDeletionPanel.tsx`('결제 정합화').
- **다른 영역 테스트가 원문을 고정해 남긴 문구**: `bounded-zip.server`·`workbook-safety`의 '상한을 초과', `remote-image-fetch`의 시간 초과 문구, `catalog.ts`의 '명시적으로 선택'.
- **같은 일반 오류가 화면마다 다르게 남은 곳**: 한 화면에서 고친 일반 문구('정책을 불러오지 못했습니다.' 등)가 다른 영역 파일에는 옛 문장으로 남은 곳이 72곳 있다. 동작 문제는 아니고 표기 차이다.
- **2차에서 남긴 것**: 상품 편집의 KC 형식 오류 2종과 '저장 요청을 확인하지 못했습니다…'는 같은 문장이 다른 파일(`goods-kc.ts`·`goods-kc-actions.ts`·`goods-base-revision.ts`·`app/admin/actions.ts`)에도 있어 한쪽만 바꾸면 갈린다(뒤 문장은 요청 형식이 거절된 경우인데 결과를 모르는 것처럼 읽힌다). 운영 스위치의 켜기 전 확인 목록에 남은 '계산 버전 1'·'amount_mismatch'·'런북 게이트'는 개발팀 확인용이고 스위치가 이미 켜져 있어 두었다.
- **DB 오류 문구**: `raise exception`으로 DB가 직접 돌려주는 문구는 migration을 바꿔야 해서 손대지 않았다. 앱 쪽 매핑이 있는 곳은 매핑을 고쳤다.
