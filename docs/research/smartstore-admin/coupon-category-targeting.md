# 카테고리 쿠폰과 고객 지정 등록

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-16 구현·격리 검증. 혜택 등록의 고객/상품 범위를 먼저 정하고 할인·발급 조건을 입력하는 두 단계 흐름에 카테고리 선택과 고객지정을 연결했다. 운영 DB·실제 고객·외부 결제는 변경하지 않았다.

## 원본 근거와 자체 계약

[스마트스토어 혜택상품 지정 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=4379)는 전체·카테고리·개별 상품 지정과 혜택 등록 후 해당 카테고리에 신규 등록된 상품의 자동 적용을 설명한다. [타겟팅 그룹 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=4398)와 보관한 등록 화면도 고객 지정 경로의 근거다. 두 도움말의 대상별 허용 범위가 완전히 같지는 않으므로 네이버 계정별 제한을 ICONS의 새 정책으로 추정하지 않는다.

- 카테고리는 자체 상품분류 UUID 최대 100개다. 대표·추가 분류와 하위 분류의 현재 상품에 적용하며 새 등록·분류 이동을 반영한다. 보관한 분류/상위 분류는 제외한다. 네이버의 분류 사전이나 상품 선택 상한을 복제한 계약은 아니다.
- 고객지정은 저장 후 기존 지정 고객·세그먼트 발급 화면으로 이동한다. 대상을 확인한 뒤 명시적으로 발급해야 쿠폰함에 들어간다. 일반 코드 입력으로 새로 받을 수 없으며 이미 보유한 같은 코드는 재발급 없이 반환한다.
- 일반 코드형의 기존 코드 입력·운영자 지정 발급은 유지한다. 발급 후 방식 변경을 막고 고객지정형에 등급 자동 발급을 함께 설정하지 않는다. 다운로드형 마케팅 쿠폰 후보와 기존 메시지의 받기 가용성에서도 고객지정형을 제외한다.
- 현재 자격과 사용기간은 그대로 재검사한다. 대상 카테고리 변경은 조건 revision에 포함하며, 완료 주문의 할인·배분·사용 기록을 현재 분류로 다시 쓰지 않는다. 발급 시 모든 상품분류를 동결하는 계약은 아니다.
- 목록·혜택 리포트·발급 상세·엑셀에서 지정 고객 필터를 공유한다. 목록은 지정 고객을 전체 고객으로 표시하지 않는다.

## 계산과 잠금

`private.coupon_good_matches`가 쿠폰 평가, 단일 상품 쿠폰 배분, 순차 조합의 상품 배분과 배송 묶음 범위에 같은 판정을 적용한다. 기존 전체·상품 ID 대상의 의미는 유지한다. 배송비 쿠폰은 해당 분류 상품이 포함된 묶음의 선결제 운송비만 차감하며 설치비·착불은 제외한다.

결제는 상품 행을 먼저 잠글 수 있으므로 카테고리 트리 공유 잠금은 기다리지 않고 시도한다. 분류 변경이 트리 잠금을 가진 채 상품을 기다리면 결제는 `coupon_category_changed`로 종료하여 교착을 해소한다. 견적 이후 대상 여부가 달라지면 주문 확정 시 재견적을 요구한다. 브라우저의 전체 장바구니 할인 계산기는 카테고리 쿠폰을 임의 계산하지 않는다.

새 공개 읽기 RPC는 `marketing.manage`를 검사한다. 내부 함수와 새 공개 함수의 기본 execute를 네 역할에서 봉인한 뒤 필요한 authenticated 읽기만 허용하고 operator 계약 레지스트리에 등록했다. 적용 파일은 `20261016093000`·`20261016093100`이며 세 작업 전용 로컬 DB에 적용한 뒤 보존했다.

## 검증

- `coupon_category_targeting.sql`: 빈/없는 분류, 신규 상품 자동 포함, 추가 분류, 보관 상위 분류 제외, 직접 코드 발급 거절, 지정 발급·기보유 재조회, 발급 방식 고정, 메시지 가용성, 목록/리포트 필터, 상품·배송비의 정확한 차감, 견적 후 분류 변경 거절, 주문 취소 복원과 권한을 통과했다.
- 대상 상품 20,000원·비대상 5,000원, 대상 운송비 5,000원·비대상 2,000원·설치비 2,400원에서 상품 10%와 대상 운송비 전액 쿠폰을 적용하면 27,400원이다. 불변 주문·배송·사용 원장을 검산했다.
- `coupon_category_targeting_concurrency.py`: 상품/트리 잠금 역전은 0.011초에 재견적 오류로 종료했고 대기 교착 0건, 분류 변경 중 동시 판정 12개 모두 차단, 잠금 해제 후 정상 적용을 확인했다.
- 실제 브라우저: PC/390px 선택·저장→지정 발급 진입, 미발급 상태의 코드 등록 차단, 실제 1장 발급·새로고침·쿠폰함 표시를 확인했다. 쿠폰 저장 뒤 만든 대상 상품 10,000원과 비대상 20,000원에 실제 주문서가 1,000원만 할인하여 29,000원을 표시했다. 이 UI 검증은 결제 제출 없이 종료했다.
- 기존 쿠폰 콘솔·검색·발급/사용·타겟팅·기간·복원·카트 기대값 SQL도 통과했다. 구 회귀는 전용 빈 DB의 테스트 운영자 fixture wrapper를 사용하고 종료 후 제거했다. 신규 권한 검증에는 해당 fixture를 쓰지 않았다.
- 관련 앱·가이드 11개 파일 82개 검사와 격리 전체 어드민 SQL 19개 파일을 통과했다. 최종 공통 검사 결과는 [전체 작업 기록](full-admin-implementation-20261016.md)을 따른다.
