# 고객 요청 철회

migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-13 기준. 고객이 요청을 취소한 사실을 판매자의 거절과 구분하고, 주문·결제·재고를 유지한다. 전체 주문·전액 취소/반품 계약은 바꾸지 않는다.

## 원본 관찰과 적용 범위

로그인한 스마트스토어 반품관리의 `반품거부(철회)처리` 새 창에서 대상 상품 선택, 500자 사유, 구매자와 사전 협의 안내, 처리 버튼을 읽었다. 실제 원본 요청은 제출하지 않았다. `교환으로변경` 확인창도 표시만 확인하고 취소했다. 원본은 수거완료 목록에서도 진입할 수 있으나, 이 관찰만으로 실물 반환과 금전 정산을 안전하게 해제할 수 있다고 판단하지 않는다.

ICONS는 고객이 직접 철회하거나 `sales.manage` 담당자가 고객 합의와 반송 중인 굿즈가 없다는 확인을 남긴다. 실효 단계가 접수·검토중·수거중인 요청만 대상이며, 보류는 `held_from`으로 판정한다. 실제 입고/재출고, 고객 직접 반송 근거, 출고지 입고 증거, 결제 취소 실행, 환불 원장, 주문 취소가 있으면 차단한다. 실제 수거·환급 이후의 절차 변경과 반품↔교환 전환은 이 단위에 포함하지 않는다.

## 저장 계약

- `withdrawn`을 별도 종결 단계로 추가하고 기존 `status=rejected` 투영을 유지한다. 목록·필터·집계·통계·엑셀은 `stage`로 철회를 구분한다.
- 모든 요청 행 변경은 `claim_revision`을 증가시킨다. actor와 구매자 권한 경계 → operation → 주문 → 정렬 배송건 → 요청 → 정렬 회수건 잠금 뒤 예상 버전과 자격을 재검증한다.
- `private.order_claim_withdrawals`는 operation, 원 요청, 실제 actor/customer 또는 operator, 이전 단계, 사유와 처리 시각을 보존한다. 같은 operation은 actor·모드·요청·버전·사유가 모두 같을 때만 재생한다.
- 고객 재조회와 운영자 재조회 RPC를 분리한다. 운영자는 현재 `sales.manage`를 다시 통과해야 하며 다른 actor의 receipt는 반환하지 않는다.
- 철회는 요청 단계·비공개 근거·감사·알림만 변경한다. 주문 상태/금액, 결제/환불/재고 원장은 바꾸지 않는다. 감사에는 자유 입력 사유를 넣지 않는다. 남은 환불계좌 원문은 기존 종결 후 30일 파기 정책을 따른다.
- 철회된 요청은 재개할 수 없다. 다시 신청하면 별도의 새 요청으로 당시 주문 상태·기한을 검증한다.
- 클라이언트는 첫 전송 본문을 고정한다. 응답 유실 뒤 결과가 없거나 후속 재시도가 확정 오류여도 고정을 풀지 않는다. 동일 요청만 조회·재시도하며 다른 receipt를 성공으로 표시하지 않는다. 확정된 버전 충돌은 사유를 보존하고 최신 상태 확인과 새 동의를 요구한다.

## 검증

`20261020085251_order_claim_withdrawal.sql`을 OWN/FRESH 격리 DB에 적용했다. `order_claim_withdrawal.sql`의 권한·공개/비공개 경계·요청 멱등·버전 충돌·물류/금전 차단·종결 불변·재신청·계좌 파기·철회 집계/통계와 운영 권한 커버리지가 통과했다.

별도 복제 DB의 12개 실제 잠금 경합(동일 요청, 두 actor, 다른 본문, 저장 중 재조회, 검토/승인/수거와 양방향 경합, 금전 처리, 권한 회수)을 검증했다. 성공 7건의 receipt/audit만 남고 주문 상태·금액·재고는 그대로였다. 서버/API/클라이언트와 관련 도메인 테스트 94개가 통과했다.

Chrome에서 합성 고객 PC 반품 철회, 390px 교환 철회, 관리자 대리 반품 철회를 실제 저장했다. 고객/관리자 이력 재조회와 390px 가로 넘침 없음도 확인했다. 세 건 모두 receipt/audit가 각각 1개이고 주문 배송완료 상태·13,000원 금액·3,000원 배송비·재고가 유지되며 환불/취소 실행 원장은 0건이다. 검증 기록 (`output/smartstore-reference-20261013/verification-claim-withdrawal/manifest.json`)과 DB readback에 저장했다. 임시 호스트/127 주소는 Next 개발 서버의 localhost 정규화 때문에 same-origin 차단됐으며 실제 POST는 localhost에서 확인했다. 출처 검사는 완화하지 않았다. 운영 배포·운영 DB 변경·실제 거래는 수행하지 않았다.
