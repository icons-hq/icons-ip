# 판매·정산 후속 범위 분류

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-15 현재 작업 트리 기준. [판매·정산 대조표](sales-parity.md)의 미구현 항목을 현재 운영 업무의 확장, 신규 정책/거래 구조, 제공자 전용 기능으로 나눴다. 완료한 단위는 개별 검증 문서로 연결하고 아직 남은 정책·연동 경계를 구분한다. 2026-10-14 사용자가 선물 주문·복수구매 할인·착불/수량별 배송비·정기배송을 모두 포함해 설계·구현을 계속하도록 명시했다. 아래 네 단위는 공통 거래 모델과 로컬 SQL·실제 고객/관리자 화면 검증을 마쳤으며 합성 검증 자료와 전용 런타임을 정상 정리했다. 운영 배포·실제 결제 실행까지 승인된 것은 아니다.

2026-10-15 사용자는 남양주·김포 담당자가 어드민에서 엑셀을 내려받아 각 창고의 WMS에 직접 넣는 운영 방식을 확정했다. ICONS의 작업 범위는 창고 양식에 맞춘 엑셀 출력이며, 운송장 발급·회수 접수·배송추적 API 자동화는 제외한다. 공급자 API·계정·요금 확인을 이 작업의 대기 조건으로 두지 않는다. 기존 출고 파일 생성과 운송장 회신 등록, 실제 창고의 WMS 수용 확인은 [출고지시·회신 런북](../../runbooks/warehouse-export.md)의 서로 다른 검증 단계다.

## 이미 구현되어 미구현 목록에서 빼야 하는 항목

주문/상품주문 보기·검색·열 설정·엑셀, 발송 전 고객 합의 기반 주소 변경, 기존 허용 단계의 관리자 취소/반품/교환 접수, 고객/관리자 요청 철회, 반품↔교환 전환, 개별 보류/해제, 구매제한 복수등록/선택해제, 현재 운임 체계의 배송정보 템플릿, 고객 적립금 원장·지급·엑셀이 구현되어 있다.

발송지연 **안내여부 필터**도 실제 채널 결과·페이지·전체 건수·엑셀까지 연결됐다. 토스 정산의 독립 수집 원장·2회 대조·일별/건별/수수료·수집 시점 결제/환불 대조·전체 엑셀도 구현됐으며 합성 로컬 검증을 마쳤다. 실제 PG 수집 활성화와 은행 입금 대사는 별도다. [안내여부 필터](shipment-delay-notice-filter.md), [PG 정산 구현](pg-settlement-parity.md).

## 기존 계약으로 가능한 작은 일반 보완

상품·스토어를 함께 읽은 [현재 모델 재대조](remaining-general-work-reclassification.md)에서 판매상품 TOP20 밖의 전체 결과·페이지·엑셀을 별도 조회 단위로 확인했고, 이후 [구현과 로컬 검증](sales-goods-ranking-parity.md)을 완료했다. 전체 일별표와 원본 미확인인 개별 상품 펼침을 합쳐 새 필수 기능으로 세지 않는다. 판매 처리의 새 쓰기·환불 정책 후보와는 구분한다.

조회·검색·열·엑셀에서 확인한 구체적 누락은 위 후속으로 구현했다. [클레임 처리 현황 요약](claim-progress-summary.md)도 기존 단일 상세 응답으로 구현하고 실제 PC/390px·상태 근거·키보드 이동을 확인했다. 처리 단계, 보류 전 단계/사유, 회수, 환불 또는 교환 배송 기록을 각각 읽고 기존 영역으로 이동한다. [현재 처리 패널](../../../components/admin/screens/ClaimActionPanel.tsx)의 개별 확인·회수/환불 증거·전체 주문/전액 가드를 유지하며 연쇄 확정이나 복수 주문 일괄 환불은 추가하지 않는다.

## 제공자 전용 제외 및 기존 확정 경계

- 네이버 ID/상품주문번호와 Npay 원장·구매확정·기한 경과 자동 발주해제/자동환불, 굿스플로/N배송의 고유 계약은 그대로 복사하지 않는다. 일반 회원 조회·배송 추적·클레임 업무까지 제외하는 뜻은 아니다.
- 네이버 빠른정산의 선지급 금융상품·자격심사, 비즈월렛의 유료 충전/광고 요금 지갑, 반품안심케어의 보험 가입/보상, 네이버 세무 발급 서비스 연계는 고유 서비스 범위다. PG의 일반 정산·세무 증빙 필요성은 위 적용 가능한 후속에 남긴다.
- ICONS는 유료 충전금을 폐기했다. 외부 PG의 별도 선지급·판매자 지급대행 계약도 현재 수집/대사 기능의 필수 구현으로 간주하지 않는다.
- **부분취소·부분반품은 사용자 결정으로 제외**했다. 주문 전체·전액 계약을 유지하며 일반 미구현 목록에 다시 넣지 않는다. [확정 계약](partial-claims-contract.md).
- **운송장 발급·회수 접수·배송추적 API 자동화와 운송사 이벤트 기반 배송완료 자동 동기화는 2026-10-15 사용자 결정으로 제외**했다. 창고 담당자가 양식 엑셀을 내려받아 자체 WMS에서 처리한다. 기존 운송장 회신 등록·수동 배송완료·실물 증거 확인 계약은 유지한다.

## 확인 한계

원본 빈 선물/미결제 목록의 후속 상태, 암호화 파일 실제 결과, 일부 합포장/주소/구매확정 입력 폼, 실제 환불·보류 해제·운송사 결과, 세무 파일·인쇄·환급 자격 결과는 미확인이다. ICONS의 실제 PG 계약 권한·원격 LIVE 자료·은행 입금·세무 원문도 조회하지 않았다. 이 한계는 일반 기능의 미구현 여부와 별도로 유지한다.

이번 문서는 현재 코드·기존 검증 문서·2026-10-14 추가 공식 원문 조사와 2026-10-15 사용자의 물류 운영 결정에 근거한 분류다. 개별 구현의 로컬 검증, 실제 WMS 인수와 운영 배포는 구분하며, 이번 작업에서 운영 DB와 배포는 변경하지 않았다.
