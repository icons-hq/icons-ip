# 고객 구매 분석의 구현·검증

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14 원본 UI와 공식 고객센터를 추가로 읽고 별도 구매 분석 탭을 구현했다. OWN/FRESH 격리 DB와 실제 Chrome의 월간·주간 조회, 모바일, 엑셀 다운로드·재열기를 검증했다. 기존 고객현황의 집계 의미는 유지한다.

## 원본에서 확인한 정의

로그인된 [고객 리포트](https://sell.smartstore.naver.com/#/insight/store-analytics/customer)의 신규/재구매 비중·13개월 추이·지표 선택·비교기간·데이터 표를 확인했다. 이후 실제 주간 전환·마감 주 선택·조회까지 실행해 **주간은 13주 추이**임을 확인했다. 기본 주간은 10월5~11일, 비교는 9월28일~10월4일로 월요일~일요일 단위였다. 공식 [고객 분석 도움말](https://help.sell.smartstore.naver.com/faq/list.help?categoryId=11208)의 다음 네 항목을 직접 열었다.

- **분석 기준 설명**(문서 17820): 각 고객의 최근 180일 결제 이력 유무로 신규/재구매를 구분하며 취소된 결제도 이력에 포함한다. 성·연령은 고객 정보와 별도 제공 기준을 사용한다.
- **고객 유형별 비중의 합**(17824): 조회 중 유형이 바뀌면 두 유형에 함께 포함될 수 있어 고객 수 비중 합계가 100%를 넘는다. 이 문서의 예시 날짜는 조회 기간과 구매 날짜가 어긋나 있으므로 날짜 예시 자체를 구현 근거로 삼지 않는다.
- **지표 설명**(17819): 결제 시점의 고객·판매금액은 이후 취소·반품을 포함한다. 판매금액은 배송비·쿠폰 할인액을 제외하고, 객단가는 주문 수 대신 결제 고객 수로 나눈다. 방문 고객은 상품 상세 방문으로 집계하며 로그인하지 않은 방문도 포함한다.
- **조회·비교 기간**(17822): 마감된 주간·월간만 제공한다. ICONS의 기존 임의 기간 조회와는 다른 계약이다.

기존 [고객현황 도움말](https://help.sell.smartstore.naver.com/faq/content.help?faqId=4513)의 730일 신규 기준은 이 180일 리포트에 적용하지 않는다. 최초 iframe 조작에서는 도움말 표시를 확인하지 못했지만 실제 화면 위치를 기준으로 다시 눌러 기간 도움말을 열고 마감 주·월 규칙을 재확인했다. 실제 원본 엑셀 생성·저장은 수행하지 않았다.

## ICONS 구현 경계

현재 `admin_customer_report`는 주문 생성일과 매출 인정 상태를 사용하고, **기간 내 두 번 이상 구매한 고객**을 센다. 이 기존 계약은 유지한다. 후속 구매 분석은 실제 결제 승인·입금 확인 근거와 180일 이력을 사용하는 별도 집계로 추가한다. 하나의 기간에서 신규와 재구매 고객 수는 중복될 수 있지만 개별 결제 건과 금액은 한 유형에만 속하도록 정의한다.

기간·KST 경계·동일 승인 시각의 순서·취소 이력·180일 경계·13주/13개월 추이·비교 기간·엑셀 일치를 검증한다. 방문 분석은 현재 익명 동의 세션이므로 이를 회원 고유 방문 고객이나 신규/재구매 방문 고객으로 치환하지 않는다. 성별·추가 관찰값·네이버 바우처도 추정하지 않는다.

## 추가 집계의 구체적 계약

- 기존 고객현황 안의 `신규/재구매 분석` 탭이며 별도 `admin_customer_purchase_report` RPC와 동일 집계를 이용하는 엑셀을 사용한다. 현재 `stats.read` 권한을 다시 확인한다. 새 결제·개인정보 원장을 만들지 않는다.
- 조회·비교는 KST의 마감된 월요일~일요일 또는 월 첫날~말일이고 각 기간 최대 366일이다. 2010년 이후라는 시작 상한은 ICONS 입력 계약이며 원본 상한으로 주장하지 않는다. 비교는 직전 같은 주/월 개수 또는 운영자가 직접 고른 마감 기간이다.
- 각 상품 주문의 실제 승인·입금 시각에 직전 4,320시간(180일) 경계까지의 이전 결제가 있으면 재구매다. 같은 승인 시각에는 주문번호 오름차순으로 선후를 정한다. 이 동률 규칙은 ICONS의 명시적 결정이며 네이버 내부 계산식으로 주장하지 않는다.
- 상품금액 합계는 `order_items.unit_price × qty`의 주문 당시 값이다. 상품 판매금액은 이 합계에서 `orders.discount_total`을 차감하며 `store_credit_total`을 포함한다. 상품 실결제액은 여기서 적립금을 빼고 배송비는 포함하지 않는다. 객단가는 상품 판매금액을 해당 고객 유형의 고유 결제고객수로 나눈다.
- 품목 누락·쿠폰/적립금 초과·주문 총액 불일치가 있는 주문은 고객수·주문수에는 남기되 해당 기간·유형의 모든 금액과 객단가를 미확인으로 표시한다. 금액을 0으로 보정하지 않으며 `monetaryIssueOrderCount`로 확인 건수를 표시한다.
- 실제 승인·입금 시각이 없는 주문을 결제 기간에 임의 귀속하지 않는다. 각 기간에 **생성된** 결제 완료 이력 주문 중 시각 미확인 건수를 별도로 표시하며 미결제 취소는 제외한다.
- 추이는 선택한 종료일을 포함한 마감 주/월까지 13개 기간이다. 주간은 최근 13주, 월간은 최근 13개월이며 조회 종료일을 넘는 사건을 포함하지 않는다. 신규/재구매 막대를 분리해 중복 고객을 누적 합계로 오해하지 않도록 한다.
- 엑셀은 조회·비교 요약, 13개 기간 전체 39행, 조회 기준을 별도 시트로 제공한다. 화면 페이지에 보이는 20행만 내보내지 않는다. 원본 엑셀의 열과 바이트를 검증한 결과는 아니다.

원본의 월간 카드·13개월 추이 화면은 `output/customer-purchase-analysis-qa-20261014/source-monthly-trend.png`에 보존했다. 최초 주간·달력 클릭은 선택 변경을 확인하지 못했으며, 후속 실제 화면 좌표 기반 조작에서 주간 선택·달력·조회 결과와 기간 도움말 표시를 확인했다(`source-week-calendar.png`, `source-week-report.png`, `source-period-help.png`). 리포트의 모든 성/연령 조합이나 원본 엑셀을 확인한 것은 아니다.

## 격리 검증 결과

- DB: `20261013170608` 집계와 `20261013173410` 읽기 전용 권한 검사 보완의 원문 SHA가 OWN/FRESH 원장과 일치한다. 기존 결제일 도우미와 결과를 대조했고 KST·180일 경계·동률·취소 이력·금액 불일치·권한을 검증했다. 읽기 전용 트랜잭션에서도 동작한다. 집계 migration 검증 (`output/smartstore-reference-20261014/customer-purchase-report/migration-verification.json`), 권한 검사 보완 검증 (`output/smartstore-reference-20261014/customer-purchase-report/read-guard-migration-verification.json`).
- 월간: 2019년 8월의 전체 2명·3건·상품 판매금액 11,900원·실결제액 9,700원·객단가 5,950원, 신규 1명(50%)·재구매 2명(100%)을 독립 기대값과 대조했다. 13개월의 상세 39행을 20/19행 두 페이지로 조회했다.
- 미확인 근거: 9월의 금액 불일치 1건은 전체·신규 금액을 비워 두고 재구매 9,000원을 유지했다. 승인·입금 시각 미확인 2건을 별도로 표시하고 미결제 취소는 제외했다.
- 주간: 8월19~25일 1명·1건·판매금액 1,900원·실결제액 1,700원과 5월27일~8월25일의 13주를 확인했다. 직전 비교는 8월12~18일이다. 지표 네 종류, 신규/재구매 선택, 비교 해제, 0건·객단가 없음 표시를 확인했다.
- 날짜 입력: 날짜를 바꾼 직후 비교하기를 껐다 켜거나 직전 동일 기간을 눌렀을 때 이전 값으로 되돌아가던 문제를 수정했다. 실제 Chrome 재현 순서와 native input 이벤트 회귀 검사를 통과했다.
- 모바일: 390px에서 문서·본문 폭 380px로 바깥 넘침이 없었다. 차트는 내부 폭298/전체920px, 데이터 표는274/1,141px이며 키보드 오른쪽 이동 후 실제 `scrollLeft` 40/80px를 확인했다. 데이터 두 번째 페이지와 0건 표기도 직접 보았다.
- 엑셀: 실제 브라우저에서 내려받은 월간·근거 미확인·주간 3개 파일의 조회/비교6행과 전체추이39행, 총 **2,025개 셀**을 독립 기대값과 대조해 불일치0을 확인했다. 다른 엔진으로 재열고 3개 시트의 표시를 렌더링했다. 긴 기준 설명의 잘림과 숫자 형식을 보완한 최종 파일로 다시 다운로드·대조했다. 전체 재열기 결과 (`output/customer-purchase-analysis-qa-20261014/all-workbook-readback.json`).
- 앱: 관련 6파일 36테스트와 추가 날짜/엑셀 2파일 4테스트, 수정 파일 ESLint가 통과했다. CI에 집계 SQL 회귀를 추가했다. 전체 최종 통합 검사는 별도 통합 기록을 따른다.

최종 화면·파일 SHA는 검증 manifest (`output/customer-purchase-analysis-qa-20261014/ui-manifest.json`)에 기록한다. 원본 성/연령 조합·원본 엑셀 재현·네이티브 Excel 앱 검증은 이 완료 범위에 포함하지 않는다. 권한 거부는 SQL·로더·라우트 검사로 검증했으며 별도 거부 역할의 실제 UI 검수는 이 단위에서 수행하지 않았다. 합성 결제 증거 20건은 격리 DB의 불변 원장 계약에 따라 보존하며 강제 삭제나 trigger 해제를 하지 않았다. 실제 PG 호출·운영 DB 변경·배포는 없다.
