# 다른 상품 옵션 불러오기

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

확인일: 2026-10-14. 로컬 합성 데이터로 검증했으며 운영 배포·운영 데이터 변경은 하지 않았다.

## 원본에서 확인한 범위

원본 옵션 도구 (`output/smartstore-reference-20261012/product-form-11-option-copy.jpg`), 선택창 (`output/smartstore-reference-20261012/product-form-12-option-copy-dialog.jpg`), 검색창 (`output/smartstore-reference-20261012/product-form-13-option-copy-search.jpg`)에서 다른 상품의 옵션 불러오기, 상품 검색·분류·목록, 옵션 가격 선택을 확인했다. 원본에 적용·저장하지 않았으므로 원본의 재고·옵션 ID·주문 연결·가격 산정 계약까지 같다고 주장하지 않는다. 아래는 ICONS에 맞춰 구현하고 검증한 계약이다.

## 사용 흐름과 저장 계약

새 상품 또는 보관되지 않은 비공개 상품의 재고수량·옵션에서 **다른 상품 옵션 불러오기**를 연다. 상품명·상품코드/옵션코드·상품번호와 카테고리로 검색하고 20개씩 이동한다. 보관 상품은 검색 결과에서 제외한다. 원본 하나를 고르면 기존 유지·신규·사용 중지·옵션가 변경 수와 적용 전후 값을 비교한다. **현재 초안에 적용**은 작성 폼만 바꾸며, 기존 상품 저장 또는 신규 상품의 개인 서버 임시저장으로 확정한다.

- 같은 조합은 속성의 키와 값을 **정확한 문자열**로 비교한다. 키 순서는 무관하지만 공백·Unicode 정규화 차이를 합치지 않는다. 기존 이름·ID·관리코드·ERP 품명/코드·바코드·재고·재고 기준값·안전재고·사용 상태를 유지한다.
- 새 조합에는 원본 이름·속성·순서만 가져온다. 새 ID/관리코드는 기존 저장기가 생성하며 재고는 0, ERP·바코드는 비어 있다. 작성 직후의 손대지 않은 기본 옵션 빈 행만 대체한다.
- 원본에 없는 현재 옵션은 ID·재고·주문 기록을 보존한 채 사용 중지한다. 중지 행을 포함해 최대 100행이며 선택형 축은 최대 3개다. 동일한 축 구성이 없는 원본, 중복 조합, 허용되지 않는 금액은 거절한다.
- **옵션가도 불러오기**는 기본 해제다. 해제 시 같은 조합의 현재 옵션가를 유지하고 새 옵션가는 0이다. 선택 시 `원본 goods.price`와 `원본 goods_variants.price`의 차액을 현재 상품의 기준 금액에 더한다. 실시간 기간 할인가·정가 투영값은 사용하지 않는다. 현재 상품의 판매가·즉시할인·판매기간은 바꾸지 않는다.
- 원본 재고·옵션 ID·관리코드·ERP·바코드·KC·직접입력형 정의·예약판매 정책을 가져오지 않는다. 옵션 구성이 바뀐 저장은 기존 KC 무효화·재검토 규칙을 따른다.

읽기 서버 액션은 `catalog.manage`와 계정을 검사한다. 비교와 적용 직전에 원본 및 대상 저장값을 다시 읽고, 저장값·계정·현재 작성값이 바뀌면 다시 비교하게 한다. 대상 버전은 가격·공개/보관·모든 옵션의 식별/재고 정보와 별도 ERP 읽기 결과를 포함한다. 원본 조회는 일반 저장 가격·옵션 구성에 필요한 필드만 사용한다. 모달은 `body` portal로 상품 폼 바깥에 두어 검색 입력/Enter가 상품 폼의 native 자동보관과 제출에 섞이지 않는다. 초기 요청·검색·비교·적용 재조회는 하나의 순번으로 오래된 응답을 폐기하고, 재조회 중 취소/닫기도 허용한다.

옵션 적용은 React commit 뒤 축·행 전체를 자동보관한다. 상품속성의 비동기 초기화(`productAttributes`, `productAttributeDraft`)만 보류 중 복구 후보를 덮지 않도록 했다. 사진 보관함 선택·순서 변경처럼 hidden 값만 바뀌는 사용자 편집, 다른 hidden 값과 섞인 배치, native input/change는 기존 보관 동작을 유지한다. 단순 클릭은 편집으로 취급하지 않는다.

## 경계와 남은 제약

적용 전 재확인은 DB 트랜잭션의 전체 편집 CAS를 새로 만드는 기능이 아니다. 적용 뒤 저장까지의 동시 변경은 기존 상품 writer와 재고 충돌·보관·KC 잠금 규칙을 따른다. 예를 들어 적용 후 동시 공개되고 옵션 구성은 같으며 가격만 달라지는 경우까지 importer 전용 비공개 쓰기 조건을 추가하지 않았다. 이는 현재 가격 편집 계약을 유지한 범위다.

뷰포트 변경 직후의 문서 390/393px 중간 측정은 안정된 레이아웃의 결함으로 세지 않는다. 이후 별도 단계에서 기록한 비교 모달 문서는 390/390px, 모달을 닫고 3행을 적용한 상품 폼과 신규 초안은 각각 380/380px였다.

검증용 상품·개인 서버 초안·주문/사용자·IP는 정확한 전용 식별자로 제거했고, 전용 브라우저 탭과 4348 임시 앱을 종료했다. 공용 4320 앱과 다른 작업자의 합성 데이터는 건드리지 않았다.
