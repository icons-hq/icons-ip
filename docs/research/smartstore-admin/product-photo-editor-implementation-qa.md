## 원본 근거와 적용 범위

원본 도구 관찰 (`output/smartstore-reference-20261012/product-photo-tools.json`)의 자르기/회전, 원본·자유·7개 고정 비율, 보정, 재설정, 취소·완료를 근거로 한다. 원본 9개 도구 캡처를 직접 확인해 색온도 조절, 사각·원 모자이크, 일반 텍스트의 존재도 확인했다. 조절 범위와 적용 픽셀은 확인되지 않았으므로 효과 계산과 한도는 아래 ICONS 계약을 따른다. 이 기본 구현 시점에는 원본 필터의 고유 효과, 자동 수평/레벨, 선명도·블러·비네팅, 액자·서명·자동 모자이크 인식·아트 타이포·스티커·마스크를 포함하지 않았다. 이후 일반 기능의 구현·검증은 위 후속 문서에 구분한다. 네이버 전용 API와 고유 에셋·폰트는 이식하지 않는다. 원본 사진 보관함은 0장이어서 보관함에서 편집기로 이어지는 실제 저장 경로는 미확인이다.

ICONS에서는 저장되거나 업로드 검증을 마친 대표/추가 이미지의 **사진 편집**으로 연다. 사진 보관함의 원본을 직접 덮어쓰지 않는다. 선택 사진에 포인터로 범위를 그리거나 픽셀 좌표를 입력하며 방향키 1px·Shift+방향키 10px 이동을 지원한다. 원본 보기, 편집 결과 보기, 편집 시작 상태 재설정으로 비교한다. 공유 대화상자·기존 녹색/회색 관리자 토큰을 사용하고 390px에서는 도구를 세로로 배치한다.

## 파일·저장 계약

- 편집 입력은 JPEG/PNG/WebP, **5MiB 이하·400만 픽셀 이하·가로/세로4096px 이하**다. 일반 업로드 한도와 별도다. MIME·바이트 헤더·실제 크기·JPEG 방향을 확인하고 애니메이션·다중 프레임과 과도한 데이터는 거절한다. CORS 읽기, 자격증명 미전송, 리다이렉트 거절과 스트림 바이트 상한을 적용한다.
- 브라우저의 한 세션에서 원본 bitmap 하나를 디코딩한다. 회전·반전·자르기와 RGB 보정은 결정론적 연산이며 알파는 보존한다. 미리보기는 최대1280px, 실제 결과는 선택한 픽셀 크기다. PNG/WebP는 PNG, JPEG는 품질0.92 JPEG로 내보낸다. 결과가5MiB를 넘으면 실패를 알리고 원본을 유지한다. 자동 품질 저하나 크기 축소는 하지 않는다.
- **완료 → 새 파일 검증 업로드 → 기본 상품 저장** 순서다. 완료만 누른 상태에서는 DB 상품 경로가 바뀌지 않는다. 무변경 완료는 파일을 만들지 않는다. 취소와 업로드 중 취소는 이전 타일을 복구한다. 취소 전에 서버에 도착한 미연결 업로드는 기존 만료 정리 계약을 따른다.
- 작업은 계정·로그인 세션·상품 폼·타일 키·원본경로에 결속한다. 서버 prepare/verify는 편집 업로드의 예상 actor와 현재 actor를 비교한다. 계정 변경·폼 교체·타일 교체·취소 후 늦게 도착한 결과는 적용하지 않는다. 일반 업로드의 기존 호출 계약은 유지한다.
- 새로운 DB migration은 없다. 상품·공유 사진·업로드 claim은 기존 검사와 저장 절차를 사용한다. 운영 환경·네이버 계정에는 쓰지 않았다.

## 색온도·모자이크·텍스트 확장 계약

- 색온도는 -100~100의 상대 보정값이며 Kelvin 값이 아니다. 기존 밝기·대비·채도를 계산한 뒤 빨강에 `temperature × 0.4`, 파랑에 그 반대 값을 더해 8bit 범위로 제한한다. 0은 무변경이며 alpha를 바꾸지 않는다. 색온도·모자이크·텍스트를 모두 초기화하면 기존 무변경 완료 계약으로 돌아간다.
- 모자이크는 사각형 또는 원을 수동으로 추가한다. 최대8개, 블록 크기2~128px이며 영역의 좌상단이 블록 격자의 시작점이다. 원은 원본 기준 너비·높이가 같은 원이다. 각 블록은 영역 안 픽셀만 alpha 가중 평균하고 각 픽셀의 alpha를 유지한다. 완전 투명 픽셀의 숨은 RGB는 평균에 넣지 않는다. 영역 밖 RGBA는 픽셀 연산에서 바꾸지 않는다. 겹치면 나중 영역이 앞선 결과를 읽는다.
- 텍스트는 최대8개, 레이어별300자·8줄, 크기8~512px, 6자리 RGB 색을 지원한다. 줄 높이는 글자 크기의1.3배이며 왼쪽·위쪽을 기준으로 그린다. 빈 문구는 그리지 않는다. 모든 모자이크 위에 추가 순서대로 텍스트를 합성하므로 사진 보정값이 문구 색을 바꾸지 않는다. 글자가 사진 밖으로 나가면 잘린다.
- 위치·크기는 **EXIF 표시 방향을 반영한 원본 이미지의 픽셀**로 저장한다. 편집기 회전·반전은 사진과 레이어를 함께 변환한다. 자르기는 합성 결과를 가리고 영역 자체를 삭제하거나 다시 평균내지 않는다. 숫자 좌표 입력은 회전 전 원본 기준이며 방향키와 드래그는 화면 방향으로 이동한다. 방향키1px·Shift10px 이동, 선택·삭제·전체 재설정을 제공한다.
- 처리 순서는 **원본 해상도에서 밝기·대비·채도·색온도 → 모자이크 → 텍스트 → 전체 회전·반전·자르기 → 미리보기만1280px 이하 축소**다. 미리보기와 저장이 동일한 합성 경로를 사용하므로 확대 비율이나 crop이 모자이크 강도·블록 위상·텍스트 크기·보정 제한값을 바꾸지 않는다. PNG의 동일 브라우저 픽셀 대조와 JPEG 재압축 차이는 구분한다. 브라우저의 alpha premultiplication·텍스트 안티앨리어싱까지 서로 다른 브라우저/OS에서 동일하다고 보장하지 않는다.
- 폰트는 사이트가 이미 불러오는 Pretendard400을 사용한다. 실제 문구로 `document.fonts.load()`를 호출하고 반환한 face가 존재하며 모두 loaded 상태인지 확인한 뒤 그린다. 실패 또는8초 초과 시 완료를 막고 오류를 표시한다. 텍스트를 지우면 같은 세션에서 복구할 수 있다. 취소는 폰트 대기와 렌더 큐를 해제하며 늦은 폰트/인코딩 응답은 적용하지 않는다. 폰트 파일 복제나 새 패키지는 없다.
- 원본 bitmap 하나와 직렬 렌더 큐를 유지한다. RGB는65,536픽셀, 모자이크는 약32,768회 읽기·쓰기 단위로 취소 여부를 확인하고 작업 시간이8ms를 넘으면 이벤트 루프에 제어를 돌려준다. 네이티브 decode·getImageData·encode 자체를 중간 정지할 수 있다는 의미는 아니다. 캔버스는 완료·실패·취소 시 크기를0으로 해제한다.

확장 코드의 단위 회귀는7파일150테스트, scoped ESLint와 관련10개 TS/테스트 파일의 타입검사를 통과했다. 범위는 색온도 극값·무변경·alpha, 사각/원 외부 픽셀, 투명 픽셀 가중 평균, 겹침 순서, 원본 좌표 왕복, 여러 레이어 CRUD·한도·키보드 이동, 폰트 성공·실패·지연·취소, 원본 해상도 처리 후 preview 축소, 4MP 연산 중 취소를 포함한다. Canvas mock 단위 검사와 실제 브라우저 결과는 구분한다.
