# 상품 엑셀의 카테고리 코드 찾기

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14 구현·격리 로컬 Chrome 검증 완료. 원본 카테고리 찾기 (`output/smartstore-reference-20261012/catalog-cs/64-bulkadd-category-finder.jpg`)의 이름 검색·단계 선택·템플릿·전체코드 다운로드를 기존 ICONS 카테고리와 상품 엑셀 계약에 연결했다.

상품 일괄등록의 **카테고리 찾기**에서 이름·경로·코드를 검색하고 20개씩 조회한다. 네 단계 분류를 직접 선택하거나 저장한 카테고리 템플릿으로 고른 뒤 코드를 복사한다. 자동 복사가 거절되면 선택 가능한 읽기 전용 입력칸을 제공한다. 복사한 값은 ICONS 양식의 고객 카테고리 코드·추가 카테고리 코드 열에 붙여넣는다. 이 창은 상품이나 분류를 수정하지 않으며 사방넷·네이버 고유 코드를 만들어 내지 않는다.

새로 연결할 수 있는 활성 말단만 선택한다. 보관 분류·보관된 상위 경로·불완전한 경로는 검색 결과에서 제외하며 상위 분류까지만 고르면 복사를 막는다. **최신 카테고리 다시 조회**는 선택을 초기화하고 서버 자료를 읽는다. 실패 시 기존 선택을 사용할 수 없으며 재조회한다. 창이 닫힌 후 늦은 응답은 반영하지 않는다. 이후 실제 엑셀 검증·적용에서도 현재 분류의 존재·보관·말단 상태를 기존 서버 계약으로 다시 확인한다.

목록 읽기 서버 액션은 현재 `catalog.manage`를 검사하고 기존 카테고리 RLS로 조회한다. 전체코드 CSV는 기존 `/api/admin/categories/export`를 재사용한다. CSV에는 상위·보관 분류와 상태도 포함하며 ERP 열은 기존 `platform.manage` 권한에 따른다. 기존 양식 v5·파일 적용·감사·코드 해석 계약과 DB 스키마는 바꾸지 않았다. 원본의 실제 코드 복사·다운로드 결과는 실행하지 않았으므로 파일 형식과 아래 검증 결과는 ICONS 구현 계약이다.

검증 결과:

- 관련 4파일 16개 테스트, 전체 TypeScript와 변경 파일 ESLint 통과. 활성 말단·보관 상위·누락 부모·순환·깊이 초과, 현재 권한, 빈 결과와 조회 오류를 구분한다.
- 실제 Chrome에서 합성 말단 21개를 20/1 페이지로 검색하고 마지막 코드를 복사했다. 단계 선택의 부모 복사 차단과 말단 코드, 기존 템플릿 코드가 각각 일치했다.
- 브라우저가 내려받은 CSV를 다시 열었다. 28개 전체 행 중 이번 합성 분류 25개와 보관 상태 1개가 DB와 같았다.
- 390×844에서 문서 폭 390px·모달 폭 370px, 모달 내부 스크롤·긴 표의 가로 스크롤·입력칸 선택·포커스 복귀를 확인했다. 탭 오프라인에서 재조회 실패를 확인하고 온라인 복원 후 다시 조회했다.
- 검증 manifest (`output/category-code-finder-qa-20261014/manifest.json`)에 직접 검토한 최종 화면 6장, CSV·소스 SHA-256, 실제 실행 코드 일치를 기록했다. 초기 과도한 창 너비의 화면 1장은 중간 결과로 제외했다. 합성 분류·템플릿은 정리하고 감사 1건은 보존했으며 네트워크·화면 크기를 복원했다.

원산지 사전·도해형 사이즈·상품 엑셀에 없는 택배사 코드 반입은 이번 완료 범위에 포함하지 않는다. 운영 변경·원본 저장·실제 상품 반입·배포는 수행하지 않았다.
