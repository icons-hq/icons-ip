# 공개 상품문의·리뷰 답변과 CS 템플릿 초안 복구

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14 구현·격리 로컬 검증 기준이다. 공개 상품문의 답변·리뷰 답글과 세 종류의 답변 템플릿 편집에 새로고침·화면 이동 후 명시적인 **초안 복구**를 제공한다. 일반 고객문의 답변·내부 메모의 기존 복구는 [상세 이동 계약](inquiry-navigation-drafts.md)을 유지한다. 원본에서 새로고침 복구 동작은 확인하지 않았으며, 아래 보존 기간과 충돌 대응은 ICONS의 계약이다.

## 보관과 인증 경계

`sessionStorage`에 계정·로그인 세션·표면·답변 대상별로 분리한다. 템플릿은 표면별로 편집 중인 여러 항목과 선택 항목을 보관하므로 검색·20개 페이지·다른 문의·창 닫기·새로고침으로 문구를 잃지 않는다. 저장하지 않은 새 템플릿과 현재 검색에 없는 편집 항목도 초안 목록에서 다시 연다. 복구 후보가 있으면 복구하거나 버리기 전까지 편집·저장을 잠근다.

일반 작성 초안은 마지막 편집부터 24시간 미만만 복구한다. 단건 공개 답변의 미확정 저장 요청은 결과 확인까지 보존하며, 같은 탭의 다른 편집기가 저장소를 정리해도 만료시키지 않는다. 손상·미래 시각·다른 계정이나 로그인 세션의 값과 만료된 일반 초안은 진입/검사 시 제거한다. 고객 원문·주문 정보·첨부파일·토큰은 보관하지 않는다. 운영자 작성 문구, 대상 식별자, 비교용 버전, 템플릿 편집값과 불확실한 저장 요청만 보관한다. 길이·형식·최대 50개 편집 초안·전체 크기를 검증하고 불필요한 필드를 버린다.

로그아웃·계정/세션 변경 시 기존 CS 공통 정리 신호로 새 저장소도 지우고 열린 편집기를 잠근다. 닫힌 행의 편집기도 정리 신호를 받으며, 같은 탭의 다른 편집기가 더 최근 초안을 만들면 이를 조용히 덮어쓰지 않고 복구를 요구한다. 저장소 사용 불가 시 현재 화면 편집은 허용하되 복구가 안 된다는 안내를 표시한다. 단건 공개 답변은 고정 요청의 동기 보관 성공을 확인하기 전에는 서버로 전송하지 않는다.

## 최신 저장본과 성공 판정

- 공개 답변 편집을 열거나 복구할 때 서버에서 최신 원문·답변·상태와 단조 revision을 함께 읽는다. 저장 시 DB가 revision을 원자적으로 비교하며, 응답 유실은 계정·대상·문구·revision이 결속된 같은 operation의 영수증으로 확인한다. 계정·대상이 맞는지 확인하고, 읽기 실패나 변경이 있으면 작성 문구를 유지하면서 저장을 잠근다. 변경된 원문과 현재 답변을 본 후 **현재 저장본 확인 · 작성 문구 유지**를 눌러야 다시 저장할 수 있다. 자동 답변 전송은 없다.
- 공개 상품문의/리뷰 템플릿은 기존 revision 검사와 삭제/복구 계약을 사용한다. 저장 결과의 대상·표면·문구·revision을 확인한 항목만 초안에서 지운다. 다른 편집 초안과 실패 문구는 남는다. 전송 결과가 불확실하면 편집을 잠그고 최신 저장본을 읽어 비교한다. 이 비교는 작업 영수증이 아니라 현재 저장된 내용의 일치 확인이다.
- 일반 고객문의 템플릿은 기존 작업 UUID와 요청을 전송 전에 보관한다. 새로고침 후에도 같은 요청 결과를 먼저 조회하며, 미저장이 확인된 경우 같은 UUID로 재시도한다. 작업 영수증으로 성공을 확인한 항목만 지우고, 이후 목록 조회가 실패해도 저장 실패로 표시하지 않는다. 상세 계약은 [템플릿 관리](inquiry-reply-template-management.md)를 따른다.
- 다른 담당자의 템플릿 변경은 현재 편집값을 덮어쓰지 않는다. 최신 저장본 비교 후 운영자가 명시적으로 교체하기 전까지 기존 revision을 유지한다.

**단건 답변 후속 보완:** 공개 상품문의·리뷰 단건 저장에는 [원자적 버전 검사와 요청 영수증](cs-single-reply-cas.md)을 추가했다. 기존 2인자 writer는 외부 직접 호출을 봉인하고 내부 일괄 처리에서 유지한다. 여러 기기 간 초안 동기화와 브라우저 탭 세션 종료 뒤 복구는 제공하지 않는다.

## 초기 초안 복구 검증

격리된 로컬 Supabase에 공개 상품문의·리뷰 각 22건과 표면별 템플릿 22개를 만들고 실제 Chrome으로 확인했다.

| 시나리오 | 결과 |
| --- | --- |
| 공개 답변 새로고침 → DB의 합성 원문/답변 변경 → 명시 복구 | 최신 원문·답변을 읽어 표시, 기존 작성 문구 보존, 확인 전 저장 비활성화 |
| 공개 답변 20번째 → 다음 페이지 21번째 → 이전 항목 | 건별 초안 분리 및 이전 작성 문구 복구 |
| 리뷰 템플릿 2개 편집 → 페이지 이동·새로고침 | 두 항목 보존. 한 항목 충돌 후 명시 교체/저장 시 다른 초안만 남음 |
| 상품문의 템플릿 390px 새로고침 복구/저장 | 문서 390/390, 모달 368/368, 버전 2 저장 |
| 일반 고객문의 템플릿 탭 오프라인 전송 → 새로고침 → 복구 | 입력 잠금과 요청 보존, 온라인에서 미저장 확인 후 같은 요청으로 버전 2 저장, 감사 작업 1개 |
| 부매니저 합성 계정 로그아웃 → 주매니저 합성 계정 로그인 | 이전 작성 문구 미노출·복구 버튼 0개, 서버에 저장한 문구만 표시 |

관련 Vitest **15개 파일·101개 테스트**, 변경 파일 ESLint, 전체 `npm run typecheck`를 통과했다. 저장소 손상/만료/인증 전환, 최신 읽기 실패·늦은 응답, 서버 결과 불일치, 불확실한 요청 복구·목록 조회 실패를 포함한다. 이번 브라우저 검수에서는 고객 답변 저장을 누르지 않았으며 합성 템플릿만 저장했다. 합성 고객의 직원 답변 메시지·인앱 알림·메일은 모두 0건이다.

화면·SHA-256·코드 일치·검증 결과 (`output/cs-editor-drafts-qa-20261014/manifest.json`), 브라우저 관찰 (`output/cs-editor-drafts-qa-20261014/browser-readbacks.json`), DB 저장 결과 (`output/cs-editor-drafts-qa-20261014/db-readback.json`)를 보존했다. 직접 확인한 화면 6개를 통과 처리했다. 합성 고객/상품/주문/문의/리뷰/템플릿/업무 알림은 모두 정리하고 저장 작업 감사는 남겼다. 본인 전용 4347 런타임과 탭을 종료했으며 화면 크기·오프라인 설정을 복원했다. 이 초기 초안 복구 검수에는 새 SQL migration·운영 변경·배포·실제 고객 발송이 없었다. 이후 단건 답변 CAS의 신규 migration·DB/API/UI 검증은 [후속 보완 기록](cs-single-reply-cas.md)에 분리했다.
