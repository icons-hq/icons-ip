# 쿠폰 중복 사용·배송비 쿠폰

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

구현과 격리 SQL·HTTP, 실제 브라우저 저장/선택 및 거래확정 암호화 XLSX 검증을 마쳤다. 전체 어드민 공통 검사 결과는 [전체 작업 기록](full-admin-implementation-20261016.md)을 따른다. 운영 정책 활성화·운영 DB 적용·배포·실제 결제는 수행하지 않았다.

## 적용 계약

- 스토어 중복 사용과 배송비 쿠폰은 기본 꺼짐이다. 관리자는 상품 쿠폰 최대 1~5장과 배송비 쿠폰 사용 여부를 설정하며, 배송비 쿠폰은 주문당 1장이다. 여러 쿠폰을 함께 쓰려면 스토어 중복 정책과 선택한 모든 쿠폰의 중복 허용 조건을 충족해야 한다.
- 쿠폰 정의에 상품 금액 또는 선결제 배송비의 할인 대상과 중복 허용 여부를 저장한다. 한 장이라도 발급한 뒤에는 이 두 조건과 코드형/고객지정 발급 방식을 바꿀 수 없다. 다른 조건은 기존 revision 검사를 거친다.
- 일반 장바구니 주문서는 고객이 상품 쿠폰 순서를 직접 선택한다. 기간·복수구매 할인 후 남은 상품 금액에 선택 순서대로 정액·정률 할인을 적용하고, 배송비 쿠폰, 적립금 순으로 계산한다. 자동 최적 조합을 임의로 선택하지 않는다.
- 최소 주문금액은 복수구매 할인 후·쿠폰 할인 전의 대상 상품 소계다. 뒤 쿠폰의 정률 할인 기준은 앞 쿠폰을 뺀 대상 상품 잔액이다. 상품 할인은 품목 잔액을 넘지 않고 온라인 최소 결제금액 1,000원을 유지한다.
- 배송비 쿠폰은 대상 상품이 포함된 이행 묶음의 선결제 기본·지역 운송비에만 적용한다. 설치비·착불 운송비는 제외한다. 원 운임과 차감액을 따로 보존하고 주문·배송 건의 배송비는 실제 차감 후 금액이다.
- 주문 당시 각 쿠폰의 순서·조건·배분·금액을 보존한다. 견적 이후 쿠폰 조건 또는 중복 정책이 달라지면 새 견적을 요구한다. 같은 요청은 같은 주문으로 복구하고 다른 주문 키로 보유 쿠폰을 중복 사용하지 못한다.
- 첫구매 쿠폰 여러 장을 사용하는 주문도 하나의 첫구매 예약을 가진다. 전액 취소 시 사용 원장 전체를 `released`로 남기고 각 보유 쿠폰과 적립금을 기존 계약대로 복원한다. 복원된 쿠폰은 현재의 기간·자격·대상을 다시 검사한다.
- 장바구니의 미리 선택 슬롯은 기존 상품 쿠폰 1장이다. 새 주문서의 명시적 조합은 별도 견적에 저장한다. 기존 선물·정기배송과 이전 주문서는 기존 단일 상품 쿠폰 계약을 유지하며 배송비 쿠폰을 상품 할인으로 해석하지 않는다.
- 고객 영수증은 상품 할인과 배송비 할인을 분리하고 쿠폰별 적용 순서를 보여준다. 거래확정 엑셀은 차감 후 배송비, 설치비 포함 금액, 배송비 쿠폰 차감액과 별도 쿠폰 사용 시트를 제공한다.

## 검증

- `supabase/tests/coupon_combinations.sql`: 기본 꺼짐, 정책 재시도, 순차 정액/정률 할인, 설치비·착불 제외, 대상 상품 배송 묶음, 첫구매 복수 쿠폰, 최소 결제액, 적립금 결합·복원, 발급 후 조건 고정, 견적 변경 거절과 권한을 롤백 검증했다.
- 예시: 상품 25,000원 + 운송비 7,000원 + 설치비 2,400원 − 상품 쿠폰 3,000원 − 남은 상품 10% 2,200원 − 운송비 50% 3,500원 = 결제 25,700원.
- `coupon_combination_concurrency.py`: 같은 주문 요청 12회는 주문 1건·사용 원장 3건, 서로 다른 주문 키 8개는 1개만 성공했다. 첫 주문 취소 후에도 적용 3건·복원 3건을 혼합하지 않았다.
- `coupon_combination_http.mjs`: 실제 합성 계정 로그인·쿠폰 정의 생성·코드 발급·조건 변경 거절·주문 12회 재시도·비소유자 읽기 차단을 검증했다. 관리자 목록, 주문서, 쿠폰함, 주문 상세 HTML 200과 새 표시를 확인했다. HTML 검사는 픽셀·브라우저 상호작용 검증을 대신하지 않는다.
- 실제 SQL 견적·주문 영수증을 앱의 금액 파서에 통과시켰다. 타입 검사·관련 ESLint와 변경 관련 테스트를 통과했다. HTTP에서 발견한 관리자 정책 조회의 읽기 전용 트랜잭션 충돌은 후속 migration `20261016085500`으로 수정하고 재검증했다.
- 근거는 `output/smartstore-full-admin-20261016/coupon-*.json`·로그와 `coupons-applied.json`에 보존했다.

2026-10-16 후속 실제 검증: 관리자 정책 저장, 고객 상품/배송비 조합 선택과 주문/관리자 표시를 확인했다. 별도 합성 거래확정 주문을 관리자 목록에서 검색해 암호화 XLSX를 실제 다운로드하고 복호화·재열람했다. 품목 2행·주문 1행·쿠폰 3행의 상품 25,000원, 상품할인 5,200원, 차감 후 배송/설치비 5,900원, 배송비 쿠폰 3,500원, 결제 25,700원이 DB와 일치했다. 파일 해시와 감사 기록도 대조했다(`coupon-combination-settled-verification.json`). 이 파일의 네이티브 Excel 앱 열람은 Mac 잠금으로 실행하지 않았으며 프로그램의 암호 해제/셀 재조회 검증이다.
