# 클레임 처리 현황 요약

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14. 기존 취소·반품·교환 상세의 단일 응답에 있는 처리 단계·회수·환불/교환 배송 기록을 상단에 모았다. 별도 조회나 DB 변경은 없다. [후속 분류](sales-remaining-scope.md)의 작은 일반 UI 보완이며, 이 카드 배치를 원본의 미확인 상세 화면과 동일하다고 주장하지 않는다.

## 표시와 이동

- **현재 처리 단계:** 기존 업무 라벨을 사용한다. 보류이면 보류 전 단계와 사유, 그 외에는 최근 변경 시각을 표시한다.
- **회수 확인:** 회수 기준 미확인을 명시한다. 출고지 정책에서는 확인된 출고지 수/전체 수와 서버의 전체 회수 판정을 각각 표시한다. 회수 불필요 취소와 레거시 입고 기록도 구분한다.
- **환불 기록:** 원장 존재, 접수 시각, 완료 시각을 사용한다. `stage=completed`나 원장 `status=done`만으로 완료 시각을 채우지 않는다. 완료 상태지만 시각이 없는 기존 원장은 **환불 완료 시각 미기록**으로 표시한다.
- **교환 배송:** 재출고와 교환품 배송완료 시각을 나누어 표시한다. 재출고 처리완료를 배송완료로 간주하지 않는다.
- 링크는 기존 처리 영역과 환불 내역으로 이동한다. 키보드 Enter로 해당 영역에 초점이 이동한다. 새 제출 버튼·연쇄 처리·일괄 환불은 없다. 기존 전체 주문/전액 계약과 회수·환불 액션의 가드를 유지한다.

사용자·운영 DB·결제사·네이버 데이터는 변경하지 않았다. 전체 빌드·타입검사의 마지막 통합 스냅샷은 이 UI 추가 전 기준이므로 이후 통합 검증과 구분한다.

독립 검토에서 레거시 회수의 `collectionComplete`가 이전 방식의 가드 통과값임을 확인했다. 입고가 없는 반품·교환을 완료로 보이지 않도록 실제 `collectedAt`을 표시 근거로 바꾸고 두 회귀를 추가했다. 수정 재검토의 잔여 P1/P2는 없다.

## 반품 1건 작업 구역 — 2026-10-15

반품 상세의 기존 검토·승인, 연락처와 회수 확인, 필요 시 보류, 카드팩·환불 원장과 환불 처리를 하나의 단계별 작업 구역에 배치했다. 각 입력과 처리 컴포넌트는 한 번씩만 표시하고 기존 액션·권한·확인·증빙·응답 불확실 시 복구 절차를 유지한다. 취소·교환 상세는 기존 배치를 유지한다.

다음 확인 항목은 서버에서 읽은 단계와 회수·환불 증빙으로 정한다. 보류 중인 경우에만 보류 해제를 안내하며, 보류 사유가 없는 건은 회수 이후 환불을 확인한다. 레거시 입고는 `collectedAt`, 환불 완료는 실제 원장의 `completedAt`을 확인한다. 화면 갱신만으로 포커스를 이동하지 않고 **다음 작업 보기**나 단계 버튼을 누르면 해당 제목으로 이동한다. 열어 둔 입력이나 불확실 요청의 복구 조작을 다른 단계가 자동으로 가로채지 않는다.

이 작업은 한 화면의 단계별 처리다. 하나의 제출로 수거·보류·환불을 연쇄 실행하거나 반품 비용을 청구·공제하지 않는다. 변경 범위와 검증은 이번 UI 변경 manifest (`output/claim-return-workspace-implementation-20261015/manifest.json`)를 따른다. 위 2026-10-14 브라우저 캡처는 변경 전 근거이며 이번 배치의 시각 검증으로 사용하지 않는다.

후속 전체 타입검사 (`output/claim-return-workspace-integration-20261015/typecheck-result.json`), 새 복사 앱 빌드 (`output/claim-return-workspace-browser-qa-20261015/build-result.json`), 실제 브라우저 검증 (`output/claim-return-workspace-browser-qa-20261015/browser-result.json`)을 완료했다. 1440×1000·390×844에서 네 단계와 다음 작업 이동, 키보드 포커스, 운영 메모·보류 사유의 미저장 입력 유지, 보류 창 열기·닫기, 취소·교환 기존 배치를 확인했다. 연락처 정정은 이 제한된 검증 서버에 기능 설정이 없어 비활성 안내만 확인했으며 실제 회수·환불·보류 확정은 제출하지 않았다. 환불 원장 없는 반품과 완료 시각 없는 취소를 구분했고, 철회 후 조작 차단은 집중 테스트 근거로 남긴다.

검증 전후 기존 업무·Auth 행 변경은 0건이다. 사전 기준선에 없던 검증 운영자 1개만 별도로 추적해 권한·비밀번호·세션을 회수했으며 소유 브라우저·서버·임시 파일도 정리했다. 정리 스크립트의 첫 시도는 계정 정지 사유 누락으로 반영되지 않았고, 기존 제약을 만족하도록 보완한 뒤 같은 계정을 회수했다. 최종 검토 (`output/claim-return-workspace-browser-qa-20261015/root-final-review.json`)와 정리 보완 기록 (`output/claim-return-workspace-browser-qa-20261015/operator-retirement-repair-review.json`)에 근거를 남겼다. 전체 앱 테스트와 351개 DB 적용 체인은 이 UI 후속 뒤 다시 실행한 것으로 세지 않는다.
