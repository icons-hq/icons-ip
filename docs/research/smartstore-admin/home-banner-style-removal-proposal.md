# 프로모션 배너 딤·텍스트색·삭제 계약 제안

migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14 KST. 이 문서는 구현 전에 조사한 원본 근거와 승인된 계약을 보존한다. **계약 검토 후 구현·격리 검증을 완료했으며 [실제 구현과 검증 결과](home-banner-style-archive-parity.md)를 따른다.** 이미 완료한 10개 한도·선택형 제목/내용·대체텍스트·링크 없음·CAS는 [기존 배너 계약](home-promotion-banner-parity.md)을 유지한다.

제안은 `hero`에 표시 옵션 두 개를 추가하고, 배너 삭제를 **기록과 이미지를 남기는 보관 방식**으로 구현하는 것이다. 삭제된 배너는 10개 한도에서 제외하고, 복구는 한도를 다시 확인한 뒤 비노출 상태로 한다. 다른 큐레이션 종류의 삭제는 이번 범위에 넣지 않는다.

## 원본에서 확인한 사실과 미확인 경계

로그인된 [스마트스토어 홈 전시관리](https://sell.smartstore.naver.com/d/v2/display-config/home)의 기존 8번째 배너를 펼쳐 읽었다. 라디오·입력값·노출 여부를 바꾸지 않았고 저장·적용·삭제·업로드를 실행하지 않았다. 관리 화면과 공식 도움말용 소유 탭 2개는 종료했다.

| 항목 | 확인한 사실 | 근거 |
| --- | --- | --- |
| 이미지 딤 선택 | `적용안함`, `흰색`, `검정색`; 실제 input name은 `imageDimType`, value는 `NONE`, `WHITE`, `BLACK` | 현재 DOM 값 (`output/home-banner-style-removal-contract-20261014/source-controls.json`), 현재 화면 (`output/home-banner-style-removal-contract-20261014/source-banner-controls.png`) |
| 텍스트색 선택 | 제목과 내용에 공통 적용하는 `흰색`, `검정색`; name `textColor`, value `WHITE`, `BLACK` | 같은 DOM·화면. 기존 228 캡처 (`output/smartstore-reference-20261012/store/228-display-banner-alt.jpg`)와도 일치 |
| 딤의 목적 | 배너 제목·내용을 이미지 위에서 읽기 쉽게 하는 기능 | [공식 프로모션 배너 도움말 17545](https://help.sell.smartstore.naver.com/faq/content.help?faqId=17545), 읽기 기록 (`output/home-banner-style-removal-contract-20261014/official-promotion-help-dom.txt`) |
| 텍스트색·위치 | 공식 안내는 선택한 흰색/검정색으로 이미지 중앙에 제목·내용을 표시한다고 설명 | 같은 공식 도움말. 이번 작업은 색 선택을 이식하며 ICONS의 기존 문구 위치·이미지 크롭은 유지하는 안 |
| 개별 배너 삭제 진입점 | 배너 행마다 `삭제` 버튼이 있으며 이미지별 `삭제` 버튼과 별개 | 현재 배너 DOM (`output/home-banner-style-removal-contract-20261014/source-controls-dom.txt`), 기존 행 목록 캡처 (`output/smartstore-reference-20261012/store/218-display-promotion-edit.jpg`) |
| 딤 수치·동작 세부 | 투명도 숫자 입력은 확인되지 않음. 원본의 정확한 opacity, 제목이 없을 때 적용 여부, 저장 후 PC/모바일 결과는 미확인 | 라디오 선택·저장은 실행하지 않았음 |
| 삭제 확정·복구 | 첫 삭제 클릭이 확인창을 여는지, 즉시 임시 제거하는지, 최종 적용 후 삭제되는지 및 복구 경로는 미확인 | 삭제 버튼을 누르지 않았으며, 열린 공식 도움말에 이 경계의 설명이 없었음 |

아래 투명도·기존 표시 호환·논리 삭제·복구 정책은 **ICONS에 제안하는 계약**이다. 확인하지 않은 네이버 저장 동작으로 설명하지 않는다.

## 구현 전 코드에서 확인한 경계

- [`HeroCarousel`](../../../components/wc/HeroCarousel.tsx)는 문구가 있을 때만 검정 그라데이션을 만들고, [`wc-home.css`](../../../app/styles/wc-home.css)는 하단 40%에 끝점 opacity `.45`, 흰 문구를 적용한다. 이미지 전용 배너에는 이 그라데이션이 없다. 임의의 전역 CSS 변경으로 기존 배너가 달라지면 안 된다.
- [`home_curations` 저장 공용 구현](../../../supabase/migrations/20261020085320_home_free_product_collections.sql)은 종류별 payload 허용 키, 현재 `store.manage`, operation ID 영수증, 구성별 잠금, `updated_at` CAS, PC·모바일 업로드 claim을 함께 처리한다. 현재 hero payload에는 딤·텍스트색 키가 없다. 이전 13인자 RPC와 새 CAS RPC는 같은 비공개 구현을 이용한다.
- [배너 개수 trigger](../../../supabase/migrations/20261020085316_home_promotion_banner_settings.sql)는 비노출·예약·종료 포함 hero 10개를 제한한다. 기존 초과 행은 수정할 수 있다. 현재 삭제·보관 필드는 없다.
- [`lib/catalog.ts`](../../../lib/catalog.ts)의 공개 loader는 로그인된 스태프도 실행한다. 스태프용 RLS 읽기 정책과 공개 정책이 OR로 적용되므로, 공개 정책만 고치고 loader의 필터를 빠뜨리면 삭제 상태가 공개 화면에 다시 섞일 수 있다.
- [`goods_photo_references`](../../../supabase/migrations/20261020085238_goods_relation_visual_compositions.sql)는 현재 보관 여부 없이 모든 curation 행의 이미지 참조를 본다. [업로드 cleanup](../../../supabase/migrations/20260717110001_admin_artwork_upload_storage.sql)은 `attached` claim의 공개 파일을 지우지 않고 staging만 정리한다. 삭제를 파일 삭제·claim 재사용으로 연결하면 이 계약이 깨진다.
- 전체 홈 순서에서 프로모션 배너는 개별 ID가 아닌 고정 `hero` 영역이다. 배너 한 장의 삭제에 전체 레이아웃의 순서·노출 스위치·revision을 수정할 이유가 없다. [전체 순서 모델](../../../lib/home-layout.ts)

## 표시 옵션의 최소 계약

| 항목 | 제안 |
| --- | --- |
| 저장 필드 | 기존 hero payload에 선택형 `image_dim: none\|white\|black`, `text_color: white\|black`만 추가한다. 다른 종류에는 이 키를 허용하지 않는다. 숫자·임의 CSS·임의 색상 문자열은 받지 않는다. |
| 새 배너 기본값 | `image_dim=none`, `text_color=white`를 명시해 저장한다. 문구 유무 때문에 선택값을 자동 변경하지 않는다. |
| 기존 배너 호환 | `image_dim`이 없는 기존 배너는 현재 하단 그라데이션 규칙을 유지한다. 편집기에만 `기존 표시 유지`를 보여주고, 건드리지 않으면 키를 계속 생략한다. `text_color` 생략은 현재 흰색 표시를 유지한다. 기존 null/빈 payload에 기본 키를 일괄 주입하거나 migration으로 덮어쓰지 않는다. |
| 명시적 적용안함 | `none`은 새 딤 레이어와 기존 자동 그라데이션을 모두 끈다. 운영자가 선택한 결과와 미리보기가 같아야 한다. |
| 흰색·검정색 딤 | 이미지 전 영역에 흰색 또는 검정색을 **opacity 0.35**로 적용하는 안이다. 원본 실측값이 아닌 ICONS 고정값이며 슬라이더는 추가하지 않는다. 제목·내용이 없어도 선택한 딤은 적용한다. |
| 텍스트색 | 제목과 내용만 `#FFFFFF` 또는 `#000000`로 표시한다. 화살표·진행바·정지 버튼·포커스 표시에는 색을 전파하지 않는다. |
| 렌더링 | 원본 이미지 위·문구 아래에 `aria-hidden`이고 클릭을 받지 않는 딤 레이어를 둔다. 대표 이미지 원본, PC/모바일 이미지 선택, 비율·크롭·문구 위치·5초 전환·정지 및 reduced-motion 동작은 유지한다. |
| 미리보기·입력 보존 | 실제 공개 renderer를 공유한다. 문구·대체텍스트·링크 없음과 독립된 설정으로 취급하고, 딤·색 변경으로 다른 필드나 후보·아트워크를 지우지 않는다. 실패·충돌·결과 불명확 상태에서도 같은 입력/요청을 보존한다. |
| 검증 | JS와 DB에서 키·타입·열거형을 함께 확인한다. 기존 요청에 없던 옵션을 서버 정규화 과정에서 추가하지 않아 과거 operation ID의 request payload 비교가 그대로 성립해야 한다. |

`기존 표시 유지`는 호환을 위한 ICONS 편집기 항목이며 네이버에서 확인한 네 번째 딤 선택지가 아니다. 원본의 중앙 문구 배치까지 바꾸는 작업은 이번 제안에 포함하지 않는다.

## 삭제는 보관과 복구로 구현

물리 삭제 대신 기존 행에 nullable `archived_at`을 추가하는 안을 권장한다. 이 필드는 이번에는 **hero에만** 설정할 수 있고, 보관된 행은 반드시 `enabled=false`이도록 DB 제약으로 제한한다. 이는 현재 상품·IP 등의 보관 패턴과 같은 방식이며, 이전 저장 요청이 삭제된 ID를 다시 만드는 문제를 피한다. [기존 보관 모델](../../../lib/admin/catalog-archive.ts)

| 상태 변경 | 저장·공개·한도 계약 |
| --- | --- |
| 삭제 | 저장된 hero의 `archived_at`을 기록하고 `enabled=false`로 바꾸며 `updated_at`을 증가시킨다. ID·제목·내용·PC/모바일 이미지 경로·링크·기간·개별 순서·기존 감사는 남긴다. 공개 홈과 일반 구성 목록에서 제외하며 10개 등록 한도에서도 제외한다. |
| 삭제한 배너 조회 | `store.manage` 사용자에게 별도의 `삭제한 배너` 목록을 제공한다. 제목이 없으면 기존 썸네일·등록시각으로 구분한다. 읽기와 복구만 제공하고 삭제 상태에서 일반 편집·유형 변경은 허용하지 않는다. 다른 종류의 구성까지 휴지통을 확장하지 않는다. |
| 복구 | 삭제된 같은 ID의 행을 복구한다. 복구 시 살아 있는 hero 수가 10개 미만이어야 하며, **비노출 상태**로 복구한다. 문구·이미지·기간·개별 순서는 유지한다. 운영자가 현재 기간과 미리보기를 확인하고 별도 저장으로 노출을 켠다. |
| 한도에 도달한 복구 | 새 배너 추가와 같은 공통 잠금·한도 검사를 거쳐 거절한다. 삭제 상태·원본 이미지·감사를 그대로 보존하고 기존 배너를 삭제하거나 수정하도록 안내한다. |
| 기존 10개 초과 데이터 | 적용 시 삭제·보관·변환하지 않는다. 기존 배너 수정·비노출·삭제는 허용한다. 새 추가·복구는 살아 있는 hero 수가 10개 미만일 때만 허용한다. |
| 전체 홈 레이아웃 | 고정 `hero` 영역의 순서·노출 스위치와 revision을 유지한다. 전부 삭제하면 slide 0개이므로 영역 자체가 나오지 않는다. 복구가 전체 영역의 숨김을 해제해서는 안 된다. |
| 파일·공용 사진 | Storage 원본·공용 사진·다른 구성의 이미지·`attached` claim을 삭제하거나 `verified`로 되돌리지 않는다. 삭제한 배너도 이미지 참조를 유지하므로 기존 참조 검사에서 빠뜨리지 않는다. 복구 시 기존 경로를 그대로 쓰며 재업로드·claim 재소비를 요구하지 않는다. |
| 보존 기간 | 이번 계약은 자동 만료·영구 삭제를 두지 않는다. 데이터와 파일은 보존하며, 향후 실제 정리가 필요하면 별도 보존·참조·복구 계약으로 다룬다. 이 삭제는 공개 홈에서의 제거이며 이미 공개된 파일 URL의 회수 기능은 아니다. |

### 삭제 확인 화면

일반 구성 편집기의 **저장된 프로모션 배너**에서만 `배너 삭제`를 제공한다. 아직 저장하지 않은 새 배너는 기존 초안 취소를 사용한다. 확인창에는 대상 썸네일·제목과 아래 내용을 보여준다.

> 이 배너를 삭제할까요? 홈에서 사라지고 등록 개수에서 제외됩니다. 삭제한 배너 목록에서 복구할 수 있습니다.

미저장 편집이 있으면 해당 내용이 저장되지 않는다는 문장을 추가한다. `취소`와 `배너 삭제`를 분리하고 확인창의 최종 버튼에서만 요청한다. 요청 중 중복 버튼을 막는다. 실패·충돌이면 입력을 버리거나 목록에서 먼저 제거하지 않는다. 이 확인창은 원본에서 확인하지 못한 ICONS의 제안이다.

### 권한·영수증·동시 저장

- 새 삭제/복구 RPC는 `store.manage`의 현재 상태를 확인하고, 기존 actor/membership fence 이후 operation ID 잠금 → 구성 ID 잠금 → 행 잠금 순서를 공유한다. 10개 풀에 들어오거나 나가는 변경은 기존 `home_promotion_banner_count` 잠금으로 직렬화한다. 일반 저장·유형 변경·직접 권한 writer의 trigger까지 같은 한도 계약을 적용한다.
- 삭제/복구 요청은 operation ID, 구성 ID, `expected_updated_at`, 목표 보관 상태만 받는다. 현재 상태가 다른 오래된 요청은 `PT409`로 거절한다. 새 작업 감사는 `admin.home_curation.archived` / `admin.home_curation.restored`와 정확한 request·before·after를 기록한다. 기존 `upserted` 영수증을 수정하거나 삭제하지 않는다.
- 같은 operation ID·같은 actor·같은 request는 이전 결과를 그대로 돌려주고 재변경하지 않는다. 다른 request로 재사용하면 operation conflict다. 권한 회수는 이 영수증 반환보다 먼저 검사한다.
- 삭제 뒤 **새 operation ID의 일반 저장**은 구 RPC·새 RPC 모두 `curation_archived`로 거절한다. 삭제 이전에 성공한 저장의 동일 영수증 재확인은 과거 성공을 반환해도 행을 복구하거나 `enabled`를 되돌리지 않는다. 복구 뒤 예전 삭제 영수증을 재확인해도 다시 삭제하지 않는다. 화면은 영수증만으로 현재 노출 상태를 가정하지 않고 현재 목록을 다시 읽는다.
- 두 탭 저장↔삭제는 같은 구성 잠금/CAS로 한 요청만 먼저 확정된다. 먼저 저장되면 오래된 삭제를 거절하고, 먼저 삭제되면 오래된 저장을 거절한다. 삭제/복구↔새 배너 추가는 공통 한도 잠금으로 10개 초과를 방지한다. 이 변경에서 전체 홈 레이아웃 행을 함께 잠그지 않는다.
- 일반 저장의 claim 처리 전에 삭제 상태를 검사한다. 거절된 저장/삭제/복구가 업로드 claim·이미지 참조·감사 일부만 남기는 일이 없도록 한 DB 트랜잭션으로 끝낸다. 복구는 원본 이미지 검증을 새로 소비하는 저장 함수에 억지로 위임하지 않는다.
- 신규 함수는 PUBLIC·anon·authenticated·service_role의 기본 EXECUTE를 먼저 봉인하고 필요한 롤에만 부여한다. 내부 helper·변경 함수·RLS의 operator contract를 갱신해 coverage로 검증한다.

## 구현 시 영향 범위와 검증 순서

1. `lib/home-hero.ts`, `lib/admin/curations.ts`, `curation-editor.ts`, `lib/home-catalog.ts`, `lib/catalog.ts`, `HeroCarousel`/`wc-home.css`에 표시 옵션·기존 생략값 호환을 연결한다. [`CurationSection`](../../../components/admin/sections/CurationSection.tsx)의 두 선택 UI와 미리보기가 같은 모델을 쓴다.
2. CLI로 새 migration을 만든다. `archived_at`/hero-only/보관 시 비노출 제약, 공개 RLS와 공개 loader의 명시적 `archived_at is null`, 관리자 기본 목록/삭제 목록, 저장의 보관 상태 거절, 생성·복구 상한 trigger, 삭제/복구 RPC·감사·권한 등록을 한 단위로 검토한다. 기존 migration과 영수증 원문은 바꾸지 않는다.
3. UI의 삭제·복구 확인과 명확한 실패 상태, 동작 후 현재 목록 재조회를 연결한다. 삭제/복구 성공 후 공개 홈과 관리자 경로를 재검증한다. `hero` 전체 레이아웃을 자동 저장하거나 공용 이미지의 보관/삭제 API를 호출하지 않는다.
4. SQL은 표시 열거형/타입/타종류 거절, 기존 payload·긴 문구·영수증 보존, 익명/스태프 동일 공개 숨김, 10개 한도·초과 legacy 편집/삭제, 복구의 비노출·원본 보존, 새·옛 RPC의 삭제 행 저장 거절, 이전 save/archive receipt 재생의 무변경, 권한 회수, 이미지/claim/공용 참조 보존을 검사한다. 모든 적용 전은 disposable clone이며 기존 개발 DB reset은 하지 않는다.
5. 실제 경합은 저장↔삭제 양방향, 같은 삭제 operation ID, 서로 다른 삭제 CAS, 복구↔추가의 9→10 경쟁, 동일 배너 삭제↔복구, 권한 회수↔삭제/복구를 `pg_blocking_pids`로 확인한다. 전체 순서의 독립 저장도 영향을 받지 않는지 확인한다.
6. Chrome에서는 새/기존 배너, 세 딤×두 텍스트색, 문구 없음/링크 없음/대체텍스트, PC/MO 이미지와 crop 보존, 삭제 취소/확정·목록/공개 재조회·등록 수 감소·복구 후 비노출, 두 탭 충돌·결과 불명확 재확인을 검증한다. 실패 입력·소유 fixture·탭·런타임을 정리한다.

## 검토할 선택

- 표시 필드의 생략은 기존 표시를 유지하고 명시적 선택만 새 딤으로 전환한다. 신규 기본은 딤 없음·흰 문구이며, 흰색/검정색 딤의 고정 투명도는 0.35로 제안한다.
- 삭제는 hero 전용 논리 보관이며 등록 10개 한도에서 제외한다. 원본·영수증·공용 참조는 보존한다.
- 복구는 한도 재검사 후 같은 ID를 비노출로 복구한다. 자동 영구 삭제나 별도 보존 기간은 두지 않는다.

공용 사진/저장 담당의 별도 읽기 검토에서 과거 receipt 무변경 재생, 삭제 행의 유형 변경 차단, 보관 시 비노출 제약, 모바일 이미지까지의 참조 유지가 일관된다는 확인을 받았다. 해당 제약을 이 안에 포함했다.

위 선택은 검토 후 구현됐다. `59922`를 포함한 적용 범위·순차 적용의 제약과 최종 검증 증거는 [구현 보고](home-banner-style-archive-parity.md)에 기록한다.
