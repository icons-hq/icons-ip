# 타겟 세그먼트 대응 계약

migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

기준일: 2026-10-13. 원본은 `output/smartstore-reference-20261012/store/manifest.json`의 채택 캡처 178–199를 직접 대조했다. 네이버에서 신규 저장·즐겨찾기·발송을 실행한 기록은 없다. 이 문서는 원본에서 확인한 흐름과 ICONS의 데이터 정의를 구분한다.

## 원본에서 확인한 흐름

- 잠재·방문·관심·구매·충성의 5고객군, 고객군별 목적, 상세 타겟, 상세 조건과 세그먼트명 순서다. 이름은 50자 이내다. 고객군 수·전월 대비·13개월 차트와 최종 조건 요약이 있다(178–183).
- 관심 고객은 장바구니 미구매·찜 미구매·미사용 쿠폰, 상품 범위는 전체·분류·선택 상품이다. 찜 기간 미설정이면 **사용 시점에 찜한 상품이 남아 있는 고객**을 대상으로 한다(188–189, 199).
- 구매·충성은 구매 이력, 최근 1·3·6개월 첫구매, 마지막 구매 후 3·6개월, 재구매·최근 1·3개월 재구매 조건이 목록에 보인다(192–198). 확인하지 않은 세부 조건의 조합이나 산식을 원본의 확정 계약으로 보지 않는다.
- 목록은 고객군·상세 타겟·ID·이름 검색, 기본 세그먼트 구분, 상세 보기와 사용 진입점을 제공한다. 즐겨찾기는 최대 3개다(196–199). 원본의 기본 21개 목록에는 네이버 멤버십·쇼핑라이브/숏클립 조건도 포함된다.

## ICONS에서 가능한 조건

| 조건 | 현재 근거 | 대응 |
| --- | --- | --- |
| 가입 회원 중 첫구매 대상 | `profiles.onboarded_at`, `private.customer_has_valid_goods_payment` | 방문 여부와 구분해 이름을 명시한다. |
| 현재 장바구니·찜 이후 미구매 | `cart_items`, `wishlists`의 현재 행과 `created_at`, 유효 주문·상품 항목 | 현재 남은 행을 사용한다. 등록 이후 같은 상품의 유효 결제가 있으면 제외한다. 수량 변경일을 새 담기 시점으로 추정하지 않는다. |
| 미사용 쿠폰 | `user_coupons`의 상태·사용 시작·만료, 현재 쿠폰 상태 | 현재 사용 기간 안의 미사용 쿠폰 보유자다. 주문 최소금액 충족이나 실제 할인 적용을 뜻하지 않는다. |
| IP 알림 구독 | `ip_follows.notify_drops/notify_events` | 스토어 전체 구독이나 광고 수신 동의로 바꾸어 해석하지 않는다. |
| 구매·최근 첫구매·휴면 구매·재구매 | 유효 주문 상태와 본인 `paid` 결제·주문 총액 일치 | 기존 쿠폰의 구매 판정과 맞춘다. 기간은 기존 ICONS 리포트와 같은 주문 생성일의 KST 기준이다. 전체 기간 재구매는 서로 다른 유효 주문 2건 이상이다. 최근 1·3개월 재구매는 기간 시작 전 첫구매가 있고 최근 기간에도 다시 구매한 회원이다. 기간 내 주문 2건과 다르다. |
| 현재 등급·연령대 | `profiles.loyalty_grade`, 자가 입력 `birth_date` | 등급을 새로 재산정하지 않는다. 성별은 추정하지 않는다. 생년월일 원문은 세그먼트 API에서 반환하지 않는다. |
| 방문·미방문·유사 방문·영상 시청 | 선택 동의한 익명 방문 원장은 있으나 회원별 방문 데이터와 연결하지 않으며 영상 시청 원장은 없음 | 회원 연결·추가 수집/동의/보존 계약이 필요한 일반 기능이다. 익명 방문 세션을 고유 고객수로 바꾸거나 미집계를 0으로 표시하지 않으며 로그인 시각을 방문으로 대체하지 않는다. |
| 성별 | 별도 선택 동의를 받은 고객 통계 전용 비공개 값 | [성별·연령 분석](customer-demographics.md)에만 사용하며 세그먼트 조건이나 개인별 고객 API에 연결하지 않는다. 이름·연락처에서 추정하지 않는다. |
| 네이버 멤버십·플랫폼 고객 추정 | ICONS가 보유하지 않는 네이버 전용 데이터 | 네이버 전용 제외다. 일반 방문 기능의 미구현과 구분한다. |

집계 모수는 일반 회원(`profiles.role=user`) 중 가입 완료·필수 약관 동의·자가 입력 생년월일 기준 만 14세 이상이며 현재 이용 정지나 탈퇴 fence가 없는 계정이다. 운영자 계정과 미가입완료 회원은 제외한다.

유효 주문은 `paid/confirmed/shipping/delivered/done`이며 주문·구매자·금액이 일치하는 `paid` 결제가 있는 경우다. 취소·완전 환불로 이 조건을 벗어나면 다음 계산에 반영된다. 현재 cart/wishlist/등급으로 과거 상태를 역산하지 않는다.

## 저장·추정·재사용 경계

- **세그먼트는 조건식이다.** 조건 버전, 정규화 원문, SHA-256, 이름, revision을 저장한다. 기본 조건은 직접 수정하지 않고 복사하여 재사용한다. 삭제는 보관 처리로 조건·감사 근거를 보존한다.
- **추정은 특정 시각의 관찰이다.** DB 기준시각, 조건 hash, 일치 회원수와 그중 현재 마케팅 수신 동의 회원수를 저장한다. 고객 ID 목록·이메일·생년월일은 브라우저에 반환하지 않는다. 실제 발송수·전환수로 표시하지 않는다.
- 이름 저장은 최근 15분 안에 같은 운영자가 확인한 동일 조건의 추정을 연결한다. 저장 이후 대상 고객수는 달라질 수 있다. 재확인은 별도 UUID로 새 관찰을 만든다.
- 월별 추이는 동일 조건 hash로 실제 확인한 snapshot만 사용한다. 관찰하지 않은 월은 값 없음이며 0이 아니다. 누락된 13개월을 현재 데이터로 소급 생성하지 않는다.
- 재사용 시에는 저장된 조건을 다시 계산한다. 실행용 내부 resolver는 현재 마케팅 동의 `true`, 온보딩·계정 상태·탈퇴 차단·필터를 재확인한다. 현재 장바구니/찜 제거, 구매·쿠폰 사용·동의 철회가 반영된다. 고정 명단이나 오래된 추정은 발송 권한이 아니다.
- 기존 전체/IP 대상 인앱 공지는 별도 서비스 공지 계약이다. 이 단위에서 외부 발송이나 예약을 실행하지 않는다. 후속 마케팅 발송기는 현재 권한·채널·동의를 다시 검사하고 실제 발송 결과를 별도로 기록해야 한다.
- 즐겨찾기는 운영자별 3개다. actor fence 안에서 개수를 검사하고 저장해 동시 요청으로 상한을 넘지 못한다. 세그먼트 관리·추정·조건 조회는 `marketing.manage`로 보호한다.

## 검증 상태

2026-10-13 격리 로컬 환경에서 다음을 확인했다. 운영 환경 적용·외부 메시지 발송은 실행하지 않았다.

- SQL: 9개 대상, 취소 주문 제외, 현재 찜 이후 구매 제외, 하위 분류, 기간형 재구매, 수신 동의 철회와 고정 관찰값 분리, 다른 운영자의 추정 사용 거절, 15분 만료, 신규·수정·보관·멱등·revision 충돌, 기본 조건 수정 금지, 개인 즐겨찾기 3개, 비공개 테이블/함수 ACL을 통과했다. `customer_target_segments.sql`은 트랜잭션 후 rollback한다.
- 동시성: 명시한 로컬 DB를 별도 DB에 복제하여 즐겨찾기 상한, 즐겨찾기→보관, 보관→즐겨찾기, 같은 요청 저장, 같은 revision 수정, 권한 회수→즐겨찾기의 **6개 실제 잠금 대기**와 최종 상태를 확인했다. 검사가 끝나면 복제 DB를 삭제한다. 기존 개발 DB를 reset하지 않는다.
- TypeScript: 규칙·응답 검증, 서버 로더 오류/필터/미관찰값, 액션의 권한·잘못된 입력·불명확한 결과·낙관 충돌을 검증하는 29개 테스트와 중앙 표면 계약 5개 테스트가 통과했다. 관련 파일 ESLint와 전체 `tsc --project tsconfig.test.json --noEmit --incremental false`가 통과했다.
- Chrome: 상품 선택 → 30일·30대 조건 → 추정 → 만료 추정 저장 거절 시 이름 보존 → 재추정/신규 저장 → 이름 수정/재조회 → 조건 복사 → 선택 보관/즐겨찾기 제거 → 즐겨찾기 3개 제한/필터를 확인했다. 수정 취소는 저장된 조건으로 복원된다.
- 화면: 동일 조건으로 실제 관찰한 월만 13개월 기록에 표시하고, 전월 기록이 없으면 비교도 미집계다. 390px 편집 화면의 문서 가로 넘침이 없음을 확인했다. 계정 부매니저는 세그먼트 경로를 직접 열어도 데이터에 접근하지 못했다.

검증 캡처와 식별자는 `output/smartstore-reference-20261013/verification-customer-segments/verification.json`에 남겼다. 최종 저장 화면은 `07-final-saved-detail.jpg`, 모바일 편집 화면은 `05-editor-mobile.jpg`다. 화면의 이름·상품·수치는 격리 로컬 합성 데이터이며 운영 실적이 아니다.

## 적용 단위와 후속 범위

- `20261020085231_customer_target_segments.sql`: 조건·추정·즐겨찾기 원장, 내부 실행 대상 resolver, 8개 관리자 RPC와 권한 계약.
- `20261020085234_customer_segment_update_binding.sql`: 실제 동시 수정 검사에서 발견한 PL/pgSQL 변수/컬럼 이름 충돌 수정. 앞서 적용한 migration을 다시 쓰지 않고 별도 파일로 보존했다.
- 방문 데이터 수집과 외부 마케팅 발송기는 후속 구현이다. 이 단위는 조건 저장·관찰·재사용까지 구현하며, 미수집 방문수를 0으로 대체하지 않는다.
