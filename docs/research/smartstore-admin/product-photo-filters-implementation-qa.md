# 상품 사진 색조 필터·기하 마스크 — 계산 계약과 검증

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14. 기존 사진 편집기에 자체 색조 필터 5개와 삼각형·오각형·육각형·별 마스크를 추가했다. 외부 이미지·LUT·장식 자산이나 생성 모델을 사용하지 않는다. 원본 도구 조사 (`output/smartstore-reference-20261012/product-photo-tools.json`)의 Original을 포함한 29개 필터 이름과 마스크 아이콘은 존재 근거다. 원본 필터의 알고리즘·자산·적용 후 픽셀은 확인되지 않았으므로 같은 필터·같은 결과라고 표시하지 않는다.

## 필터와 수동 보정의 분리

[색조 계산](../../../lib/admin/photo-editor-filters.ts)은 `filter`를 별도로 보관한다. 기본값은 `none`이며 선택값은 `warm`·`cool`·`monochrome`·`sepia`·`faded`다. `filterStrength`는 0~100 정수, 기본 100이다. 선택 필터의 강도는 범위 막대와 숫자로 조절하며 필터를 바꾸거나 해제할 때 마지막 강도를 보존한다. 강도 0은 필터 효과만 정확히 끄고, `none`에서는 강도가 무효다. 필터를 바꾸거나 없애도 밝기·대비·채도·색온도, 자동 명암, 자르기, 방향, 모자이크·텍스트·로고를 변경하지 않는다. ‘원본 보기’는 모든 편집을 일시적으로 숨기고, ‘편집 결과 보기’는 기존 선택으로 복귀한다. ‘편집 시작 상태로 재설정’은 전체 편집을 초기화한다. 취소와 완료 후 상품 저장의 경계는 기존 계약을 유지한다.

합성 순서는 **수정 전 원본 → 자동 명암 → 색조 필터 → 수동 밝기·대비·채도·색온도 → 선명도·블러·비네팅 → 모자이크 → 로고·텍스트 → 방향·자르기 → 테두리·마스크**다. 미리보기만 최종 결과를 축소한다. 필터 선택은 직전 미리보기나 저장 전 결과에 누적하지 않고 원본에서 다시 계산한다.

감마가 적용된 8bit RGB에서 아래 식을 사용한다. 각 단계의 결과는 반올림한 뒤 0~255로 제한한다. alpha는 유지하며 alpha 0인 픽셀의 숨은 RGB도 변경하지 않는다. 필터 결과를 먼저 반올림·제한한 다음 기존 수동 보정을 적용한다.

| 선택 | 채널 계산 |
| --- | --- |
| 필터 없음 | 입력 RGB 유지 |
| 따뜻하게 | `R′=1.04R+6`, `G′=G+1`, `B′=0.94B−4` |
| 시원하게 | `R′=0.96R−4`, `G′=G+1`, `B′=1.04B+6` |
| 흑백 | 세 채널 모두 `0.2126R+0.7152G+0.0722B` |
| 세피아 | `R′=0.393R+0.769G+0.189B`, `G′=0.349R+0.686G+0.168B`, `B′=0.272R+0.534G+0.131B` |
| 바랜 색감 | `R′=0.82R+32`, `G′=0.82G+29`, `B′=0.82B+24` |

강도 `S`는 위 프리셋을 반올림·제한한 채널 `F`와 해당 단계 입력 채널 `C`를 `round(C + (F−C)×S/100)`으로 혼합한다. 100은 원래 프리셋 결과와 같고 0은 입력을 그대로 유지한다. 혼합 뒤 수동 보정을 적용하며 alpha를 조절하는 기능은 아니다. [NAVER 공통 포토에디터 안내](https://help.naver.com/service/5622/contents/15337?lang=ko&osType=PC)는 필터의 투명도 조절 막대를 설명하지만, 이 문서의 RGB 혼합식과 내부 계산이 같다는 뜻은 아니다.

이 식은 ICONS의 고정 프리셋 계약이다. 사진의 실제 색·제품 색상 재현을 보증하는 색 관리 프로필은 아니다. 필터 없음 또는 강도 0과 다른 도구의 기본값에서는 기존 무변경 완료의 `null` 반환과 재압축 생략을 유지한다.

## 기하 도형과 안쪽 테두리

[기하 계산](../../../lib/admin/photo-editor-presentation.ts)은 사각 자르기를 마친 최종 캔버스의 중앙 `(W/2,H/2)`과 외접 반지름 `min(W,H)/2`를 사용한다. 첫 꼭짓점은 위쪽이며 삼각형·오각형·육각형은 같은 반지름에서 등각으로 배치한 정다각형이다. 비정방형 사진에서도 도형을 늘려 찌그러뜨리지 않는다. 별은 위쪽부터 외측·내측 꼭짓점 10개가 교대하며 내측 반지름은 외측의 45%다. 각 도형은 위치·방향을 따로 이동하지 않는 중앙 고정 마스크다.

폴리곤 테두리는 윤곽에 두께의 두 배인 선을 round join으로 그린 뒤 바깥 마스크를 한 번 적용한다. 바깥쪽 절반이 제거되어 도형 안의 선분 거리 기준으로 일정한 두께가 남는다. 별의 오목한 모서리도 작은 별을 단순 축소해 뺀 테두리와 구분한다. 기존 원형·둥근 사각형 테두리의 evenodd 안쪽 윤곽 계산은 유지한다.

- 두께는 0~64px 정수이며 실제 상한은 `min(64, floor(min(W,H)/2))`다. 1px 사진의 테두리는 0이다. 도형의 안쪽 공간보다 두꺼우면 도형 전체가 테두리 색으로 채워질 수 있다.
- 최종 캔버스 크기는 유지하고 도형 밖만 투명하게 만든다. 마스크만 적용하면 기존 alpha와 외곽 coverage를 곱하고, 테두리는 선택색을 source-over로 합성하므로 의도적으로 불투명도를 더할 수 있다.
- 마스크 선택은 JPEG도 PNG로 출력한다. 필터만 적용한 JPEG는 기존 JPEG 품질 0.92 정책을 유지한다. 이미지 업로드 단계의 별도 정규화는 이전 계약과 같다.
- 자르기 조작 중에는 테두리·마스크를 잠시 숨기고 확정 뒤 새 크기로 적용한다. 미리보기와 파일은 같은 원본 해상도 합성 경로를 사용한다.

Canvas의 경계 안티앨리어싱·부분 alpha 양자화는 브라우저 구현을 따른다. 서로 다른 브라우저의 가장자리 픽셀까지 완전히 같다고 보장하지 않는다. 저장소 원본은 보존하며 이 도구를 원본 삭제나 개인정보 제거 기능으로 설명하지 않는다.

## 자원과 검증 경계

기존 입력·출력 5MiB, 각 변 4096px, 전체 400만 픽셀 상한을 유지한다. 색조 필터는 기존 픽셀 블록을 제자리에서 바꾸며 별도 전체 크기 배열을 추가하지 않는다. 도형은 최대 10개 꼭짓점과 Canvas 경로로 계산한다. 기존 렌더 큐·yield·취소 검사·늦은 결과 폐기·canvas와 bitmap 해제를 유지한다. 네이티브 디코드·인코드 자체의 즉시 중단은 보장하지 않는다.

최종 사진·가이드 관련 14파일 372테스트와 변경 TS/TSX ESLint, 전체 `tsc --project tsconfig.test.json --noEmit --incremental false`가 통과했다. 필터·마스크 순수 모듈과 자동 수평·좌표 통합의 별도 읽기 검토에서 추가 P1/P2는 발견되지 않았다. 강도·수동값/crop/로고 보존, RGB/alpha/블록 계산, PNG 전환, 1px/최대 두께, 4MP 취소·다음 요청 복구를 포함한다. 마지막 가이드 갱신 후 확인한 재현 가능한 테스트 결과 (`output/product-photo-filters-qa-20261014/final-tests.json`)에는 가이드 회귀 검증도 함께 담았다.

**실제 Chrome PC 1440px·모바일 390px, 저장·재열기와 독립 픽셀 검산을 완료했다.** 최종 manifest (`output/product-photo-filters-qa-20261014/ui-manifest.json`)는 실제 runtime의 사진 관련 14파일, 합성 원본·저장 파일·직접 비전 검수의 정확한 SHA-256을 결속한다.

- 실제 UI·저장 결과 37개 (`output/product-photo-filters-qa-20261014/independent-pixel-result.json`)는 11,792,412픽셀에서 모든 RGBA 채널 차이가 0이다. 최종 소스의 Chrome Canvas 직접 계산 38개 (`output/product-photo-filters-qa-20261014/final-native-independent-pixel-result.json`)는 4,500,040픽셀 차이가 0이다. 후자는 실제 앱 클릭과 구분하며 필터별 강도 0/25/50/100과 도형별 0/8/64px 테두리를 포함한다. oracle은 제품 모듈을 import하지 않고 RGB 식·역변환·ray casting·선분 거리를 별도로 계산했다.
- 경계 안티앨리어싱 2px와 임의 회전의 비균일 원본·로고 경계는 제외 수를 기록했다. 전체 픽셀 무조건 일치로 표현하지 않는다. 초기 4MP 진단의 로고 바깥 2px 제외 누락은 oracle을 수정했고 실제 제품 코드는 바꾸지 않았다. 이전 실패 기록은 진단 자료로만 남겼다.
- 저장·재열기 (`output/product-photo-filters-qa-20261014/save-reopen-and-final-reproduction.json`)는 별 마스크, 회전/반전/crop, 모자이크/로고/텍스트, JPEG→PNG 결과와 직접 미리보기의 RGBA가 일치했다. 최종 소스의 기본 강도 결과도 이전 UI 결과와 바이트가 같았다. 공유 원본 보존 (`output/product-photo-filters-qa-20261014/ui-save-readback.json`)과 강도 0의 무업로드 완료도 확인했다.
- 4MP+1MP 로고 실측 (`output/product-photo-filters-qa-20261014/ui-final-4mp-performance-and-save.json`)은 자동 명암·시원하게 강도50·밝기20·6도·별/흰32px를 함께 적용했다. 미리보기190.9ms, 최대 프레임 간격17.5ms, 완료 렌더268.3ms, 업로드까지712.9ms였고 최종 저장은2000×2000 PNG다. 반복 벤치마크가 아닌 한 번의 비감속 측정이며 자동 명암 캐시가 준비된 상태다. JS heap 기록은 브라우저/GPU 총메모리가 아니다.
- 최종 소스 취소 검증 (`output/product-photo-filters-qa-20261014/ui-final-source-cancellation.json`)은 실제 픽셀 읽기 후 미리보기·640px 분석 중 취소와 네이티브 인코딩 시작 후 취소를 확인했다. 늦은 Blob은 반영되지 않았고 기존 경로·업로드 수·해제 후 object URL 상태를 유지했다. 네이티브 인코딩 자체를 중단한 것으로 설명하지 않는다.
- 390px에서 완료/취소 버튼의 하단12px 잘림을 발견해 sticky footer의 하단값을0으로 수정했다. 이후44px 버튼 전체가 dialog 안에 들어오며 수평 넘침은0이다. 직접 비전 기록 (`output/product-photo-filters-qa-20261014/vision-review.json`)은 수정 전 캡처를 승인 대상에서 제외한다.

검증은 승인된 격리 로컬 DB·합성 상품에 한정했다. 전용 fixture 정리 (`output/product-photo-filters-qa-20261014/retirement-result.json`)는 상품8개·사진6개·IP 보관과 재고0·이미지 연결 제거, 전용 actor 권한·세션 회수를 확인했고 원본 Storage·이력·다른 fixture를 보존했다. runtime 정리 (`output/product-photo-filters-qa-20261014/runtime-cleanup.json`)는4340/4341 종료와 임시 자격자료 제거를 확인했다. 운영 DB·PG·배포 검증은 수행하지 않았다. 원본 서비스 전체29개 효과·자산 재현이나 모든 브라우저의 보간 동일성을 보증하지 않는다.
