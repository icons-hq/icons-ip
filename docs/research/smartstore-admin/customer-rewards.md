# 등급 주문 적립과 BEST 보상

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-16 사용자 승인: 금액·기간·보상 정책은 관리자 설정으로 제공하고 기본 자동 지급은 꺼둔다. 기존 적립금의 사용·원장·환불 계약을 재사용한다.

## 동작

- `/admin/settings/store-credits`에서 기본 정책과 등급·BEST 보상을 설정한다. 계정·실제 로그인 세션·revision·요청 ID를 검사하고 감사 이력을 남긴다. 기본 적립금이 꺼져 있으면 새 자동 보상을 켤 수 없다.
- 등급별 값은 0~100% 최종 적립률이다. 기본 정률/정액을 대체하며, 배송비·사용 적립금을 제외한 상품 결제액에 적용한다. 기본 주문당 상한·보유 한도·유효기간을 유지한다. 관리자 고객등급 표에서 현재 적립률과 설정 링크를 제공한다.
- 주문 생성 시 등급·정책 revision과 유효 적립 정책을 주문에 저장한다. 견적 후 정책이나 등급이 달라지면 새 견적을 요구한다. 주문 생성 이후 변경은 이미 약속한 적립을 바꾸지 않는다. 기존 `done` 전이의 멱등 적립을 사용한다.
- BEST는 리뷰별 최초 지급 1회다. 초기 설정은 비활성, 금액/유효기간/회수 기준은 미설정이다. 활성 이후 새 선정만 당시 정책으로 작업을 만든다. 기존 선정을 소급 지급하지 않는다.
- 선정 해제·리뷰 내용/공개 상태 변경·구매 무효화·삭제 때, 지급 당시 `keep`은 지급분을 유지하고 `revoke`는 회수한다. 이미 사용한 부분은 향후 적립금에서 상계하며 현금 청구·결제사 환불액 차감은 만들지 않는다. 해제 후 재선정해도 추가 지급하지 않는다.
- 별점은 보상 자격 조건이 아니다. 실제 지급된 공개 리뷰에는 혜택 고지를 표시하며 회수 후에도 이력을 표시한다. 기존 리뷰 이벤트와 함께 혜택을 받은 경우에도 공개 응답은 리뷰당 한 건이다.

## 처리와 실패

선정 트리거는 immutable 작업만 기록한다. 선정 RPC가 적립금 계정 잠금을 직접 취하지 않도록 분리했다. worker는 주문→계정→BEST 주문 advisory→리뷰/선정/보상 순으로 잠그고, 리뷰별 unique 지급 행과 기존 적립금 lot을 함께 확정한다. 보유 상한에 도달한 부분은 지급하지 않으며 실제/예정 금액을 기록한다. 실패 작업은 횟수와 SQLSTATE만 기록해 재시도한다.

리뷰 상세는 선정 성공과 지급 결과를 별도로 표시한다. 지급 응답이 늦거나 실패해도 선정 성공을 취소로 표시하지 않는다. `보상 처리 결과 확인`은 멱등 worker와 readback을 사용한다. `/api/cron/customer-rewards`는 정확한 `CRON_SECRET` Bearer 인증 후 service-role 전용 RPC를 호출한다. Vercel 설정의 매분 일정은 코드 준비 상태이며 운영 배포·스케줄 등록 완료를 뜻하지 않는다.

## 검증

- `supabase/tests/customer_rewards.sql`: 기본 꺼짐, 필수 값, 계정/세션, CAS·요청 재실행, 1점 지급, 소급 미지급, 중복 방지, 미사용/사용분 회수, 빠른 해제·재선정, 지급 유지 정책, 설정 변경 전 작업 보존, 상한, 삭제·공개 고지·권한 검증. 트랜잭션 rollback.
- `supabase/tests/customer_grade_rewards_checkout.sql`: 실제 v2 견적→주문→결제 finalizer→거래확정. 견적 후 등급 변경 거절, 주문 이후 변경 보존, 10,000원 상품에서 적립금 1,000원 사용 후 9,000원 × 3% = 270원 1회 지급. 배송비 3,000원 제외. 트랜잭션 rollback.
- `supabase/tests/customer_reward_concurrency.py`: 이름·컨테이너 ID를 검증한 일회용 로컬 DB만 사용한다. 같은 작업의 동시 처리와 구매 환불 상태 변경/보상 처리의 경합을 검사한다. 실제 결제사 환불을 실행하는 검사가 아니다.
- 앱 관련 7개 파일 35개 테스트, 전체 타입 검사와 범위 ESLint 통과. 실제 관리자 화면의 정책 저장과 모바일 1점 리뷰 선정→1,000원 지급을 DB 원장 1건과 대조했다.
- 근거: `output/smartstore-full-admin-20261016/sql-customer_rewards.log`, `sql-customer_grade_rewards_checkout.log`, `reward-concurrency.json`, `reward-browser-readback.json`, `local-customer-rewards-saved-1440.*`, `local-best-review-paid-390.*`.

운영 DB 적용·실제 고객 지급·운영 cron 실행은 하지 않았다. 전체 어드민 통합 검증은 계속 진행 중이다.
