# 마케팅 메시지의 원본 확인과 ICONS 적용

migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-16 후속: 메시지당 쿠폰 1개 첨부와 운영자 본인 테스트 수신을 추가했다. 현재 쿠폰 이름·할인액·발급 상태를 카드로 표시하고 `쿠폰 받기`는 기존 발급 RPC의 자격·기간·한도·회원당 중복 검사를 사용한다. 메시지 등록 자체는 쿠폰을 자동 발급하지 않는다. 발행/worker는 현재 첨부 쿠폰의 중지·종료 상태도 확인한다.

본인 테스트는 저장한 메시지의 revision과 로그인 계정·세션에 결속한다. 수신자를 외부 입력으로 받지 않으며 현재 운영자 본인 알림함에만 `[테스트]` 알림을 등록한다. 내용 사본과 이미지 참조를 보존하고 고객 회차/수신자/성과 집계와 분리한다. 테스트 화면의 쿠폰 받기는 미리보기이며 실제 쿠폰을 발급하지 않는다. 계정 변경·권한 회수·다른 회원의 읽기는 차단한다. 네이버·이메일·SMS 발송을 추가한 기능이 아니다.

격리 DB의 `marketing_coupon_test_receipts.sql`과 기존 `marketing_in_app_campaigns.sql`이 통과했다. 첨부·실제 고객 발급 1회·중지 반영, 본인 수신/중복 요청/계정·revision 충돌/권한 회수, 고객 통계 분리, 저장본 변경 후 테스트 내용 보존과 이미지 참조를 확인한다. 관련 앱 7개 파일 26개 테스트, 전체 타입 검사와 범위 ESLint가 통과했다. Chrome에서 쿠폰 첨부 초안 저장→본인 알림 등록→수신 화면 열기를 PC·390px로 확인했고, DB 재조회 결과 본인 테스트 1건·고객 발송 회차 0건·쿠폰 발급 0건이었다. 모바일 편집 문서 폭 380px/뷰포트390px로 가로 넘침이 없었다. 근거는 `output/smartstore-full-admin-20261016/`의 `sql-marketing_coupon_test_receipts.log`, `marketing-test-browser-readback.json`, `local-marketing-*.png`, `marketing-mobile-layout.json`이다. 운영 배포·운영 발송은 하지 않았다.

2026-10-13 기준. 원본은 `output/smartstore-reference-20261012/store`의 승인된 캡처 41–50, 51c, 54–59를 직접 확인했다. 네이버 원본에서 메시지를 저장·결제·예약·발송하지 않았다.

## 확인한 원본

- 고객 세그먼트와 예상 고객수 선택, 즉시·일시 예약·주 1회 반복 발송, 동일 메시지의 기수신 고객 또는 읽음 고객 제외.
- 설명형(본문 16줄), 이미지형(8줄), 상품목록형(2줄·상품 3개), 상품카드형(2줄·상품 6개), 링크 버튼 최대 2개.
- 발송 이력의 상태·대상·일자 검색, 복사·예약 취소·삭제·다운로드. 원본의 전환·클릭 통계는 자체 계측을 전제로 한다.

## 현재 코드와 구현 계약

기존 `/admin/messaging/notifications`의 서비스 공지는 마케팅 동의를 검사하지 않는 별도 계약이다. 이를 마케팅 발송에 재사용하지 않는다. 새 기능은 `/admin/marketing/messages`에서 `marketing.manage` 권한으로 관리한다. 채널은 ICONS 인앱 알림이며 외부 이메일·문자·네이버 메시지를 보내지 않는다.

메시지, 예약 회차, 회차별 수신자 원장을 분리한다. 발행 후 대상 조건·내용·일정을 고정한다. 회차 실행 시 원본 세그먼트가 수정·삭제되었으면 확인 필요 상태로 중단하며 자동으로 다른 조건을 적용하지 않는다. 복사는 새 메시지로 작성한다. 세그먼트의 15분 이내 본인 예상치 확인을 발행 조건으로 삼되 예상치는 발송 보장이 아니다.

실행 시 현재 발행자 권한, 마케팅 동의, 일반회원·온보딩·14세 이상·정지·탈퇴 펜스, 실제 세그먼트 조건을 다시 검사한다. 계정 펜스와 프로필 잠금을 확보한 뒤 알림 등록과 수신자 결과를 같은 트랜잭션에서 확정한다. 회차 시작 때 후보를 고정하고, 이후 조건이 맞지 않는 고객은 제외한다. 회차 처리 도중 새로 조건에 들어온 고객을 추가하지 않는다.

즉시는 등록 후 바로 처리를 시도한다. 예약·반복은 서버 작업이 처리하며 활성 배포 전에는 운영 실행을 보장하지 않는다. ICONS 운영 정책으로 한국 시각 08:00–20:00에 등록하며, 예약 시각부터 1시간이 지나도록 시작하지 못한 회차는 기한 지남으로 기록한다. 반복 기간은 최대 1년, 매주 선택 요일·시각이다. 이는 확인한 원본을 바탕으로 정한 자체 제한이며 법률 규정이나 원본의 최대 기간이라고 표시하지 않는다.

결과는 실제 인앱 등록 수, 읽음 처리 수, 조건 변경 등 제외 수, 대상 0명, 예약 취소, 기한 지남, 확인 필요로 구분한다. `read_at`은 알림 열기/읽음 처리 기록이다. 외부 전달·사람이 읽었음·클릭·구매 전환을 의미하지 않는다. 기수신/읽음 제외는 같은 메시지의 이전 회차에 한정한다.

이미지는 기존 검증 업로드(정적 JPEG·PNG·WebP, 5MB 이하)를 재사용한다. 상품은 현재 공개·비성인 상품만 표시하고 버튼은 사이트 내부 경로만 허용한다. 상품 카드의 이름·가격·판매 여부는 열람 시점의 현재 정보다. 회원이 삭제되면 수신자 연결은 제거되며 원장에는 이메일이나 프로필 사본을 저장하지 않는다.

외부 이메일은 동의 철회 링크, 발송 직전 수신자 검증, 자체 원장과 공급자 이벤트 연계가 별도로 완성된 후 진행한다. 기존 인증·주문 이메일의 발송 허용 상태를 마케팅에 적용하지 않는다.

## 구현과 검증

- `20261020085242_marketing_in_app_campaigns.sql`을 OWN·FRESH 격리 로컬 DB에 적용했다. 실제 운영 DB·운영 cron·외부 발송은 변경하지 않았다.
- SQL 기능 검증은 네 가지 템플릿·작업 멱등·revision·동의 철회·권한 회수·세그먼트 변경·기수신/읽음 제외·취소·보관·고객별 읽기 격리·20시 경계·1시간 시작 기한을 확인하고 롤백한다.
- 복제 DB의 실제 경합 10건은 중복 발행/worker, revision 충돌, 동의 철회 양방향, 권한 회수, 조건 변경, 취소 양방향, 잠금 대기 중 실제 기한 경과를 검증했다. 서비스는 잠금 획득 후의 DB 시각을 사용한다.
- 100명 실제 알림 등록 배치에서 전체 세그먼트 resolver 호출은 1회였다. 합성 데이터의 `EXPLAIN ANALYZE` 실행 시간은 8.745ms이며 운영 규모의 처리 시간을 의미하지 않는다.
- Chrome 실제 UI로 설명형·이미지형 각 1건을 합성 고객에게 등록하고 열어 읽음 수 1건씩을 확인했다. 상품 카드형 주간 5회차와 상품 목록형 일시 예약 1회차는 저장 후 전부 취소했다. 상품 목록의 3개 제한·순서 변경, 검증 이미지의 복사, 만료 예상치의 발행 차단과 입력 보존, 엑셀 재열람도 확인했다.
- 관리자 작성/상세와 고객 상세를 390px에서 확인했다. 부매니저의 직접 경로는 404로 차단됐다. 최종 합성 고객 동의는 미동의로 복구했고 대기/처리 중 회차는 0건이다. 증거는 `output/smartstore-reference-20261013/verification-marketing-messages/verification.json`에 파일 해시와 함께 보존했다.
