# 카테고리 템플릿

migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14 구현·격리 로컬 검증 완료. 스마트스토어의 네 단계 카테고리 선택과 템플릿 목록을 ICONS의 기존 카테고리 트리에 연결했다.

## 원본과 적용

로그인된 원본의 카테고리 템플릿에서 네 단계 선택, 목록·등록 버튼과 말단 분류 선택을 직접 확인했다. 원본에 등록하거나 저장하지 않았다. 기존 원본 (`output/smartstore-reference-20261012/catalog-cs/92-template-category-bottom.jpg`)과 이번 `output/product-templates-qa-20261014/source-category-selected.png`, `source-category.txt`, `source-manifest.json`을 근거로 한다. 네이버 분류·모델 데이터는 복제하지 않는다.

- 상품관리 → 카테고리 템플릿에서 현재 트리의 사용 가능한 마지막 단계 분류를 등록한다. 이름·코드 검색, 20건 페이지, 현재 페이지 선택, 보관·복구를 제공한다.
- 상품 편집의 카테고리 템플릿에서 선택하면 대표 카테고리 입력이 바뀐다. 기본 상품을 저장해야 적용된다. 추가 카테고리와 기존 상품의 분류를 일괄 변경하지 않는다.
- 분류 자체 또는 상위 분류가 보관됐거나 활성 하위 분류가 생기면 템플릿은 사용 불가로 표시한다. 선택·복구를 막으며 기존 상품의 분류를 몰래 바꾸지 않는다.
- 기존 카테고리 이름·경로 변경을 조회에 반영한다. 템플릿의 보관과 카테고리 자체의 보관은 별개다.

## 저장·권한 계약

[migration](../../../supabase/migrations/20261020085313_catalog_category_templates.sql)은 private 테이블과 목록·일괄 저장 RPC를 추가한다. `catalog.manage`를 현재 시점에 검사하며 새 함수는 공개 역할·익명·로그인 사용자·service role에서 모두 봉인한 뒤 필요한 RPC만 authenticated에 허용한다. 1~100개 작업을 UUID 순서로 정렬하고 기존 카테고리 트리 잠금과 행 잠금을 사용한다. 버전 충돌이면 전체를 되돌리며 같은 요청 ID와 같은 내용은 저장된 결과를 반환한다. 권한 철회 후 재시도도 거절한다.

화면은 충돌 시 선택을 보존하고 최신 목록을 명시적으로 조회하게 한다. 결과가 불명확한 요청은 편집을 잠그고 동일 요청 결과를 확인한다. 조회 응답의 역전으로 최신 입력을 덮어쓰지 않는다. 마지막 페이지의 항목을 모두 보관하면 앞 페이지로 이동한다.

상품 선택기는 상품 폼 밖에 표시한다. 검색창 Enter는 검색만 수행하며 상품 저장을 호출하지 않는다. 대표 카테고리를 바꾼 직후에는 해당 카테고리의 속성 정의·저장값 조회가 완료될 때까지 기본 저장·공개를 막아 이전 카테고리의 속성을 함께 저장하지 않는다.

## 검증

- OWN/FRESH 두 격리 DB에 동일 migration을 적용했고 ledger 원문과 SHA-256 `8e7523d1c4ee39956de70e2d0a27badab4ee41d04e9c83f8317b1588530558c6`가 일치했다.
- [기능 SQL](../../../supabase/tests/catalog_category_templates.sql)과 [동시성 검사](../../../supabase/tests/catalog_category_templates_concurrency.sh)를 두 DB에서 통과했다. 실제 잠금 대기를 확인한 10개 교차 실행은 같은 요청, 버전 충돌, 하위 분류 생성·분류 보관, 권한 철회·재시도, 겹치는 일괄 작업의 전체 롤백을 포함한다. 임시 복제 DB는 검사 후 제거한다.
- 관련 단위·서버 액션·클라이언트·상품 저장 경계 검사 9파일 56개, TypeScript·ESLint를 통과했다. 통합 CI에 기능 SQL과 동시성 검사를 연결했다.
- Chrome에서 등록·보관·복구, 21건의 20/1 페이지, 코드 검색 1건, 두 탭의 오래된 버전 충돌과 선택 보존을 확인했다. 상품에서 템플릿을 골라 저장한 뒤 DB의 대표 카테고리가 선택값과 같은 것을 확인했다.
- 390×844에서 목록·네 단계 트리·상품 선택기를 검사했다. 전체 문서는 가로로 넘치지 않았고 긴 표·트리는 내부 가로 스크롤과 키보드 이동을 유지했다. 검색 Enter 후 선택기가 열린 채 결과 1건이 표시됐고 중첩 form은 0개였다.
- `output/product-templates-qa-20261014/category-verification.json`과 `category-ui-manifest.json`에 DB readback·검사 로그·직접 검토한 캡처의 해시를 기록했다. 소유한 합성 상품·IP·템플릿·분류를 제거하고 감사 기록은 보존했다. 임시 모바일 뷰포트를 복원했다.

운영 DB·네이버 데이터·실제 주문·결제·고객 메시지·배포는 변경하지 않았다. 직접 URL의 비허용 역할 검사는 SQL·서버 액션·메뉴 접근 검사로 확인했으며 별도 비허용 역할의 Chrome 로그인 검증은 이번 항목에서 실행하지 않았다.
