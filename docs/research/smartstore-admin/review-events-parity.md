## ICONS 계약

사용자의 전체 기능 확장 범위에서 기존 v1의 리뷰이벤트 보류를 해제한다. 모든 리뷰 작성자에게 주는 기본 포인트는 도입하지 않는다. 사전에 공지한 이벤트의 수동 선정자에게 기존 적립금을 지급한다. 별점은 응모 자격·자동 선정·지급 조건이 아니며, 운영자는 선정 사유를 남긴다.

- 제목·내용·대상 500개·KST 날짜 범위·시작 후 조건 잠금·배너 스타일은 확인한 원본을 따른다. 예정 선정수는 1~1,000명이며 금액과 유효기간은 기존 적립금 상한·현재 정책을 따른다. 1,000명 상한과 고객당 이벤트 1회 지급은 ICONS 운영 계약이다.
- 진행 중 이벤트에 해당하는 유효 구매 리뷰가 **새로 작성될 때** DB가 한 이벤트에 자동 응모시킨다. 서버 확정 결제·배송완료/거래확정·배송 후 90일·주문 구성·현재 공개 상품/IP·판매제한 없음과 완료취소/반품 제외를 다시 검사한다. 기존 리뷰를 편집해서 응모하거나 과거 리뷰를 소급 편입하지 않는다.
- 최고 금액→먼저 시작→이벤트 UUID 순으로 한 이벤트를 선택한다. 응모 시각·당시 대상·혜택·유효기간·이벤트 버전을 원장에 고정한다. 이후 상품 분류 변경이나 리뷰 편집으로 응모 이벤트를 교체하지 않는다.
- 응모 마감 후 공개된 유효 리뷰를 운영자가 선정한다. 선정 후 본문·사진·상태가 변경되면 재확인하기 전에는 발표하지 않는다. 같은 고객의 여러 리뷰를 한 이벤트에서 중복 선정할 수 없다.
- 발표일 이후 권한 있는 운영자가 **발표 및 지급**을 명시적으로 실행한다. 네이버 자동 지급을 구현한 것으로 표시하지 않는다. 대상·잔액·정책을 재검사하고 전체 지급과 결과 발표를 한 트랜잭션에서 확정한다. 한 명이라도 지급할 수 없으면 전체 지급·발표가 롤백되고 입력과 선정은 남는다. 재시도는 같은 요청의 결과를 돌려준다.
- 리뷰 삭제·블라인드 또는 원구매의 완료취소/반품·환불은 미지급 선정 자격과 공개 당첨 표시를 없앤다. 기지급 혜택은 해당 지급 lot과 그 복원 후손만 회수한다. 이미 사용·선점·상계한 부분은 기존 원장의 미래 적립 상계로 처리하며 현금 청구나 PG 환불액 변경은 없다. 복원·리뷰 수정만으로 다시 지급하지 않는다.
- 이벤트 시작 전에는 보관/복구할 수 있다. 응모 이후 이벤트·금융 이력은 삭제하지 않는다. 리뷰 본문은 별도로 복제하지 않고 현재 리뷰를 읽으며, 삭제 후에도 금융 식별자·금액·사유는 보존한다.
- 고객 공개 표면은 공지·현재 공개 상품·현재 공개 당첨 리뷰만 반환한다. 내부 고객/주문/작업 ID·잔액·운영자 정보를 노출하지 않는다. 혜택 받은 공개 리뷰에는 이벤트 혜택 제공 이력을 구별해 표시한다.

## 권한과 무결성

이벤트 등록/조회/선정은 `cs.manage`, 발표·지급·수동 회수는 기존 적립금과 동일한 `marketing.manage` 조건(이전 호환 모드에서는 admin 전용)을 사용한다. private 원장은 RLS와 직접 접근 봉인을 적용하고 공개/본인 RPC의 반환값을 별도로 정의한다. 새 함수의 PUBLIC/anon/authenticated/service_role 실행 권한을 모두 명시적으로 회수한 후 필요한 역할만 연다. 모든 helper·trigger·RPC를 권한 계약 registry에 등록한다.

권한 fence→이벤트/요청→리뷰·원주문→정책→정렬한 적립금 계정→지급 행 순서로 잠금을 설계한다. 취소/환불의 기존 주문→적립금 계정 순서를 역전하지 않는다. 자동 회수는 이벤트 편집 잠금을 얻지 않고 계정→지급 행→해당 lot 순서로 처리하여 발표·삭제·환불과 직렬화한다. 기존 결제 확정·환불·리뷰 작성 RPC의 고객 계약은 유지한다.

## 구현과 검증 (2026-10-13)

격리 DB에서 입력 상한/기간, 시작 후 잠금, 대상/공개 게이트, 중복 최고혜택 tie-break, 1점 리뷰 자격, 수정·삭제·숨김·환불, 현재 역할/회수, 동일 요청·CAS·고객 1회, 지급 실패 전액 롤백, 사용/복원 후 lot 회수와 미래 상계, 전체 원장 금액 보존을 검증한다. 실제 두 연결에서 중복 발표, 선정 변경, 리뷰 숨김/삭제, 권한 회수, 환불/주문 사용과 지급 경합을 검증한다.

PC·390px에서는 등록→목록/편집 재조회, 응모/선정→발표 및 실제 원장 지급→공개 결과→회수 재조회를 확인한다. 장기간의 상태 전이는 합성 fixture에서 날짜를 전환한 사실을 기록하고 실제 날짜가 경과한 것처럼 보고하지 않는다. 운영 DB·배포·외부 메시지·원본 네이버 저장·실결제는 수행하지 않는다.

- 실제 Chrome에서는 부매니저가 상품 G2·예정 2명·1인 1,000원·10일·강조형 이벤트를 저장하고 다시 열었다. 합성 고객이 390px에서 1점 리뷰를 등록해 자동 응모됐으며, 부매니저는 선정만 저장하고 지급 버튼은 비활성인 것을 확인했다. 정매니저가 예정 수보다 적은 1명에게 발표·지급을 확정한 뒤 새로고침했다.

## 목록·응모 XLSX (2026-10-13)

- `cs.manage`가 있는 운영자는 목록과 이벤트별 응모 결과를 최대 10,000행까지 내려받는다. 지급·회수 권한은 확장하지 않는다. 적용한 검색어·상태·날짜 기준/기간을 보존하고 현재 페이지와 무관하게 전체 결과를 포함한다. 목록은 등록 시각 내림차순, 응모는 응모 시각 내림차순이며 같은 시각은 각각 ID 오름차순이다.
- 데이터 시트와 내려받기 정보 시트에 조회 범위·정렬·KST 조회/생성 시각·건수·파일 취급 안내를 기록한다. 이벤트당 또는 응모당 한 행이다. 응모는 저장된 선정·선정 후 리뷰 변경·현재 자격·지급/회수/만료와 당시 혜택을 구별한다. 회수된 지급도 누적 지급 수에 포함하고 기지급 응모는 재선정할 수 없다고 표시한다.
- 리뷰 본문·사진 URL·회원/주문 ID·이메일·연락처·운영자 선정/회수 사유를 파일에서 제외한다. 공개 닉네임·상품·리뷰/응모 식별자는 업무 확인에 필요한 범위로 포함한다. 검색어는 파일의 조회 정보에 남지만 감사 기록에는 원문 대신 존재 여부·길이만 남긴다.
