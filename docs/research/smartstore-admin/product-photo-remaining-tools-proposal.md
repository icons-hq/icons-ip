## 최초 세 가지 계약 — 구현 완료

1. **테두리:** 적용 안함 또는 단색, 색상과 정수 두께만 둔다. 완성 사진의 안쪽에 그려 출력 크기를 늘리지 않는다. 두께 상한은 `min(64, floor(min(W,H)/2))px`로 제안하며, 1px처럼 상한이0인 사진에서는 테두리를 적용하지 않는다. 그림자·종이 질감·외부 여백은 제외한다.
2. **도형 마스크:** 적용 안함·원형·둥근 사각형. 최종 사진 중앙에 고정한다. 원은 반지름 `min(W,H)/2`의 정원이고 둥근 사각형의 반지름은 짧은 변의10%다. 사각 캔버스 크기는 유지하고 도형 밖만 투명하게 만든다. 별·다각형은 이 최초 범위에서 제외했으며 후속 기하 마스크 계약으로 구현했다.
3. **자동 명암:** 켜기·끄기 한 항목으로 제공한다. 수정 전 원본의 alpha 가중 밝기 히스토그램에서1%·99% 분위수를 구해 공통 RGB 범위를 늘린다. 자동 화이트밸런스·내용 인식·항상 더 좋은 사진을 보장하는 보정으로 설명하지 않는다.

자동 명암의 최소 계산안은 `Y=round((54R+183G+19B)/256)`의256개 구간에 alpha 정수값을 더하는 방식이다. 이는 감마가 적용된 RGB에서 계산한 밝기 지표다. 누적 가중치가 각각 전체의1%·99%에 처음 도달한 구간을 `L,H`로 두고 각 채널을 `round((C-L)×255/(H-L))` 후0~255로 제한한다. alpha는 유지하고 alpha0인 픽셀은 집계·변경하지 않는다. 전체가 투명하거나 `H-L<16`이면 원본을 유지한다. 이 값들은 구현 시 검증할 **ICONS 제안값**이며 원본 서비스의 알고리즘을 추정한 값이 아니다.

히스토그램은 수정 전 전체 원본에서 한 번 계산해 세션에 보관한다. 잘린 영역이나 직전 미리보기를 입력으로 되먹이지 않는다. 사용자는 미리보기에서 켜기·끄기를 비교하고 수동 밝기·대비로 조정한다.

## 좌표·투명도·자르기 계약

처리 순서는 **자동 명암 → 선택 색조 필터·강도 → 기존 밝기·대비·채도·색온도 → 선명도 → 블러 → 비네팅 → 모자이크 → 텍스트·선택 이미지 → 회전·반전·수평 보정·사각 자르기 → 테두리·도형 마스크 → 미리보기만 축소**로 제안한다. 기존 계산과 검증은 [사진 편집](product-photo-editor-implementation-qa.md), [선명도·블러·비네팅](product-photo-effects-implementation-qa.md)을 따른다.

- 기존 텍스트·모자이크와 선택 이미지는 EXIF 방향을 반영한 원본 좌표에 둔다. 사진과 함께 회전·반전되고 자르기에 의해 잘린다. 자동 명암도 원본 전체 기준이다.
- 테두리와 도형 마스크는 **사각 자르기를 마친 최종 사진 좌표**에 둔다. 자르기 크기가 바뀌면 중앙·반지름·허용 두께를 다시 구한다. 자르기 영역을 조절하는 동안에는 테두리·마스크를 잠시 숨기고, 확정 후 결과를 다시 보여준다.
- 마스크만 적용할 때는 `출력 alpha = 입력 alpha × 도형 coverage`다. 기존 투명 부분을 불투명하게 채우지 않는다. 도형 밖은 RGBA0으로 만든다. 저장소의 원본 파일은 계속 보존하므로 이를 원본 삭제나 개인정보 제거 기능으로 설명하지 않는다.
- 테두리는 선택 도형을 따라 안쪽에 그린다. 원형 마스크에 사각 테두리가 남지 않는다. 원본과 테두리를 먼저 source-over 합성하고 외곽 마스크를 한 번 적용한다. 테두리·선택 이미지는 의도적으로 alpha를 더할 수 있으므로 기존 보정의 전수 alpha 보존 검사와 구분한다. [Canvas 합성 규칙](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/globalCompositeOperation), [경로 clipping](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/clip).
- 원형·둥근 모서리처럼 투명 영역을 만드는 선택은 JPEG 입력도 **PNG로 출력**한다. 흰 배경을 몰래 채우지 않는다. 투명 영역을 만들지 않는 테두리만 적용하면 기존 JPEG 출력 정책을 유지할 수 있다. 인코딩 MIME과 실제 Blob 형식을 대조하고 실패 시 기존 사진을 유지한다. [Canvas PNG 출력 계약](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob).
- 모든 신규 도구가 꺼져 있으면 기존 결과·출력 형식·무변경 완료 판정을 유지한다. 미리보기와 최종 파일은 같은 원본 해상도 합성 결과를 사용한다. Canvas 경계의 안티앨리어싱까지 서로 다른 브라우저에서 완전히 같다고 보장하지 않는다.

## 이미지·템플릿 서명의 분리

**텍스트 서명 엔진은 새로 만들지 않는다.** 이름·저작권 문구·색·크기·위치는 기존 일반 텍스트가 처리한다. 모서리 배치, 불투명도, 반복 사용은 추가 편의 기능이며 현재 기능이 이미 지원한다고 표시하지 않는다. 원본 서명 모드의 한 종류 제한 때문에 기존 일반 텍스트를 지울 이유도 없다.

이미지 서명은 사용자가 선택한 PNG·JPEG·WebP 한 장을 로고로 합성하며 [별도 구현·검증](product-photo-logo-implementation-qa.md)을 마쳤다. 최초 범위는 한 장·최대100만 픽셀·각 변2048px·5MiB 이하, 원본 비율을 유지하는 크기·위치·불투명도다. 헤더 검증 후 브라우저에서 디코드하고 외부 URL 입력이나 별도 자산 업로드는 받지 않는다. 완료 시 합성 결과만 기존 저장 경로로 업로드한다. 현재 원본 로더는 저장된 상품 사진 경로용이므로 로컬 파일 검증·교체·해제를 위한 별도 경계가 필요하다.

템플릿은 둘로 나눈다. 단순 위치·크기·색의 프리셋은 기존 텍스트와 이미지 도구를 재사용할 수 있다. 장식 글꼴·아트타이포·스티커·낡은 종이 등은 배포 가능한 자산과 이용 범위가 필요하다. 원본 서비스의 미확인 템플릿을 가져오거나 추가 생성 모델을 호출하지 않는다. 첫 범위에는 계정별 템플릿 저장 DB나 여러 상품 일괄 적용도 넣지 않는다.

## 자동 기능의 현재 범위

자동 수평은 [자체 직선 방향 추정](product-photo-straighten-implementation-qa.md)으로 구현했다. 원본 전체의 최대 640px 표본에서 각도를 구하고 −15~15도 직접 조절을 제공한다. 애매한 선·낮은 신뢰도는 현재 각도를 유지하며, 빈 모서리 대신 가장자리를 잘라내고 기존 캔버스 크기·crop을 보존한다. 상품의 사선 모서리와 의미상 수평선을 구분한다고 보장하지 않는다.

자동 모자이크의 대상은 [NAVER 공식 공통 포토에디터 안내](https://help.naver.com/service/5622/contents/15337?lang=ko&osType=PC)의 얼굴이다. 원본 SmartEditor ONE UI의 자동 얼굴 항목도 확인했지만, 스마트스토어에서 검출 후 적용·완료·저장한 결과까지 검증한 것은 아니다. 사용자가 **수동 모자이크만 유지**하도록 정했으므로 얼굴 검출 모델·브라우저 검출 API·자동 적용은 이번 구현에 넣지 않는다. 대상 미확인이나 승인 대기 항목으로 남기지 않는다.

## 4MP·취소·검증 기준

기존 원본·최종 파일5MiB, 각 변4096px, 전체400만 픽셀 제한을 유지한다. 안쪽 테두리·마스크는 캔버스를 늘리지 않는다. 자동 명암 히스토그램은 `Uint32Array(256)`의1KiB이며 누적 alpha 최대 `4,000,000×255`는 UInt32에 들어간다. 도형은 경로로 계산하고 전체4MP 마스크 배열이나 별도 대형 결과 사본을 추가하지 않는 방향으로 구현한다. 이미지 로고의 디코드 RGBA는 최대4,000,000바이트가 추가되며 캔버스·인코더를 포함한 브라우저 총메모리는 별도 실측 대상이다.

긴 픽셀 작업의 yield·취소 검사, 순차 렌더 큐, 늦은 결과 폐기, bitmap·canvas·object URL 해제를 유지한다. 네이티브 디코드·인코드 자체의 즉시 중단은 보장하지 않는다. 로고 교체 실패 시 직전 로고를 유지하고, 취소·재설정·세션 교체 시 참조와 자원을 해제한다. 최종 PNG가5MiB를 넘으면 업로드하지 않고 기존 사진을 유지한다.

구현 완료의 최소 근거는 아래다. 현재 완료된 네 효과의4MP 실측986.3ms는 이전 성능 기록 (`output/product-photo-effects-qa-20261014/4mp-performance.json`)이며 신규 도구의 측정값으로 사용하지 않는다.

- 독립 픽셀 oracle로 히스토그램·분위수·반올림·평탄색·전체투명·부분투명·1×1·1×N·N×1을 검사하고, 끄기/재설정의 정확한 원복을 확인한다.
- 비정사각 원형·둥근 사각·최대 두께·90도 회전·반전·자르기 조합에서 크기·중심·테두리·마스크 경계와 의도된 alpha 변경을 확인한다.
- JPEG에서 마스크 선택 시 PNG 전환, 투명 바깥 RGBA, 파일 초과·인코딩 실패, 로고 디코드 실패·교체·취소 후 늦은 업로드 차단을 확인한다.
- 실제 브라우저에서 원본 해상도 결과와 미리보기, 저장·재열기, 공유 원본 보존,390px 화면과 키보드 조작을 검증한다.4MP와 최대 로고를 함께 사용해 처리 시간·프레임 간격·메모리·취소를 새로 측정한다.

현재 일반 기능의 구현과 실제 QA는 상단의 후속 문서를 따른다. 자체 기하 장식은 별도 13종으로 구현했으며, 원본의 29개 필터·액자 질감·서명 템플릿 10개·아트타이포/말풍선·스티커 전체와 같은 스타일 수·픽셀·알고리즘을 제공한다고 집계하지 않는다. 원본 전용 자산의 사용권은 미확인이며 자동 얼굴 모자이크는 사용자 결정에 따라 제외한다.
