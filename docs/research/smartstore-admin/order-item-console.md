# 상품주문별 조회와 주문 전체 처리

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-13 기준. 원본 스마트스토어 주문통합검색에서 상품주문번호와 주문번호가 별도 열이며 한 주문번호가 여러 품목 행에 연결됨을 로그인된 Chrome에서 확인했다. 원본 거래는 변경하지 않았다. ICONS의 부분취소·부분반품 제외 결정은 유지한다.

## 읽기 계약

- 진입점은 `/admin/sales/orders?view=items`다. 기본 주문별 조회와 탭을 나눈다.
- `order_items.id`가 상품주문 고유번호다. 현재 상품 정보 대신 주문 당시 이름·옵션·옵션코드·직접 입력 옵션·단가·수량을 읽는다.
- `order_shipment_items.order_item_id` 기본키를 통해 해당 품목의 출고지·배송상태·송장만 연결한다. 같은 주문의 다른 품목 송장이 검색 조건과 일치하더라도 함께 노출하지 않는다.
- 품목 수, 중복을 제외한 주문 수, 총 수량을 구분한다. 상태 요약은 상태 조건만 제외한 동일 검색의 품목 수다. 상품금액은 단가×수량이며 쿠폰·적립금·배송비 배분 후의 결제액으로 표시하지 않는다.
- KST 날짜 경계와 실제 결제 증거 날짜, 상세 검색, 서버 정렬, 20/50/100개 목록, 조회항목 설정을 사용한다. `%` 등은 검색 와일드카드가 아닌 실제 글자로 취급한다.
- `sales.read` 권한을 DB RPC에서 확인한다. 계정 주매니저·상품판매 조회 권한이 있는 인플루언서는 조회할 수 있고, 부매니저·물류매니저·일반 고객은 조회하지 못한다. 공개·서비스 롤의 실행 권한도 봉인한다.

## 처리와 엑셀

품목 선택의 발주확인은 신규주문이고 진행 중인 클레임이 없는 행만 받는다. 선택된 품목의 주문번호를 중복 제거하고 기존 `bulkConfirmAdminOrdersAction`에 전달한다. 실행 전 전체 주문 건수와 미선택 품목도 함께 처리된다는 안내를 표시한다. 취소·반품·교환은 기존 주문 상세에 연결하며 부분 금액·수량 처리 API를 새로 만들지 않는다.

상세의 돌아가기 링크는 품목 보기·검색·페이지를 복원한다. 외부 사이트나 허용되지 않은 경로는 복귀 경로로 사용하지 않는다.

전용 XLSX는 같은 조회의 품목을 500개씩, 최대 10,000행까지 읽는다. 페이지 사이 전체 결과의 fingerprint가 바뀌면 건수와 품목 ID가 같아도 409로 생성을 중단한다. 실제 다운로드 전에 기존 감사 RPC가 담당자·조회조건·행 수를 기록한다.

## 검증

| 검증 | 결과 |
| --- | --- |
| 격리 로컬 SQL | 3주문·4품목·2출고지의 품목별 송장, 당시 상품명, 문자 `%`, KST 경계, 결제 증거 없는 날짜 제외, 정렬 후 페이지, 빈 뒷페이지 집계, 권한·ACL 통과 |
| 대량 결과 | 1,005품목을 500/500/5개로 읽는 JSON envelope 검증 통과 |
| 단위·페이지·내보내기 | 관련 6파일 73개 통과. 공통 스타일·가이드 계약을 포함한 8파일 92개 통과 |
| 정적 검사 | 전체 typecheck, 관련 ESLint 통과 |
| 실제 Chrome PC | 4품목·3주문·수량5 확인. 같은 주문의 2품목을 선택해 주문 1건을 발주확인. DB 상태 변경 감사 1건, 금액5,000원 보존, 환불0건 확인 |
| 실제 다운로드 | 브라우저에서 XLSX 다운로드 후 XML을 다시 읽어 품목4행·고유번호·당시명·2개 송장·각 금액과 감사조건을 대조 |
| 실제 Chrome 390px | `ITEM-TRACK-0001` 검색이 해당 품목1개·주문1건·수량2개만 반환. 문서 가로 넘침 없이 표 내부 스크롤. 상세 열기와 같은 품목 목록 복귀 확인 |

근거는 `output/smartstore-reference-20261013/verification-order-items/manifest.json`, `db-readback.json`, `xlsx-readback.json`에 있다. 최종 PC·모바일 캡처의 SHA-256을 manifest에 결속했다. 로딩 중·너비 보완 전·임시 뷰포트 캡처 문제의 이미지는 최종 승인 대상에서 제외했다. 임시 뷰포트는 해제했다.

운영 배포·운영 DB·원본 스마트스토어 저장·실제 PG 거래는 수행하지 않았다. 읽기 RPC이므로 새 쓰기 경합 테스트를 추가하지 않았고, 발주확인은 기존 서버·DB 경로를 사용한다. 실제 암호화 엑셀과 선물 주문 등 별도 미구현 기능은 [판매 기능 대조표](sales-parity.md)에 남긴다.
