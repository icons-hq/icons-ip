이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-13 원본 읽기와 격리 앱 검수 기준이다. 운영 배포·원본 스토어 저장은 실행하지 않았다.

## 기존 세 유형의 ICONS 계약

`/admin/catalog/related-goods`에서 함께 사면 좋은 상품(목록형/이미지형), 유사한 상품(목록형), 코디 상품(이미지형)을 편성한다. 기존 추가구성상품의 옵션 선택·동시 담기와 별도 데이터다. 이미지 태그는 상품 정보와 상세 링크를 제공한다. 상품 카드의 담기 동작은 기존 공개 카드 계약을 따르며, 편성 자체가 주문이나 장바구니 품목을 만들지는 않는다.

- 대표를 포함해 함께 구매 목록형 2~6개, 유사상품 2~10개, 함께 구매 이미지형과 코디는 2~5개를 서로 다르게 선택한다. 대표는 구성 목록에 있어야 하며 위·아래 버튼으로 순서를 바꾼다. 공개 상세에서는 현재 보고 있는 상품을 목록에서 제외한다.
- 제목은 모든 유형에서 1~15자다. 기본 공개 제목은 ‘함께 사면 좋은 굿즈’, ‘유사한 굿즈’, ‘이렇게 함께 연출해요’다. 구매 영역 아래, 상세정보 탭 위에 공개 상품 카드로 표시한다.
- 활성 여부와 한국 시각의 시작/종료를 저장한다. 시작 포함·종료 제외이며 빈 경계는 무제한이다. 기간 제어는 ICONS에서 명시적으로 정한 계약으로, 원본 74~80의 등록일 검색을 전시 기간 저장 근거로 세지 않는다.
- 초안·판매 제한 상품도 미리 편성할 수 있고 기존 보관 상품 참조는 보존한다. 공개 조회는 상품과 IP가 공개·미보관이고 `sale_restriction='none'`인 항목만 남긴다. 대표가 비노출이거나 대표 포함 공개 상품이 2개 미만이면 편성 전체를 숨긴다. 품절은 공개 카탈로그의 탐색 계약에 따라 품절 표시와 함께 유지한다.
- 유사상품·코디·함께 구매 이미지형은 모든 구성 상세에서, 함께 구매 목록형은 대표 상세에서만 보인다. 여러 편성이 있으면 함께 구매→유사상품→코디, 생성 순서로 표시한다. 예약 전시와 종료, 카드의 가격·공급 변경 시각에 열린 상세를 다시 읽는다.
- 이미지형과 코디는 검증 업로드 1장·대체 설명 1~120자·편성 설명 최대 90자를 저장한다. 원본 이미지 비율을 유지하며 상품당 태그 1개, 최대 5개를 붙인다. 태그 없는 직접 선택도 허용한다. 좌표는 0~10000 정수(0~100%)로 저장하고 클릭·터치·드래그·방향키(1%, Shift 10%)·수치 입력으로 편집한다. PC/모바일 미리보기와 공개 화면은 같은 좌표 컴포넌트를 사용한다. 터치 영역은 44px이고 가장자리에서 화면을 벗어나지 않게 안쪽으로 제한한다.
- 새 이미지 업로드 성공 시 태그 좌표를 초기화하고, 실패하면 기존 이미지·좌표를 유지한다. 구성에서 상품을 빼면 해당 태그도 제거한다. 비공개 상품의 태그는 공개 응답에서 제외하며 현재 보고 있는 상품 태그는 현재 상품 안내를 제공한다. 코디→함께 구매 이미지형은 이미지·좌표를 유지하고, 목록형 전환은 이미지 연결을 제거한다.
- 편성 제목·연결 상품명·상품코드·상품번호 검색, 유형·전시상태 필터, 20/50/100개 목록과 페이지 조회를 제공한다. 검색 `%` 등은 와일드카드로 해석하지 않는다.

## 저장·공개 경계

`goods_relations`, `goods_relation_members`, `goods_relation_hotspots`는 `catalog.read` 읽기 RLS만 열고 직접 쓰기를 막는다. `admin_save_goods_relation_composition`은 `catalog.manage`·유형·개수·중복·대표·시간·이미지·좌표를 검사하고, 같은 편성/요청 잠금과 revision 비교로 충돌을 `PT409`로 거절한다. 구성·태그 교체와 before/after 감사는 한 트랜잭션에서 확정한다. `operation_id` 재시도는 같은 내용에서 같은 결과를 돌려주고 다른 내용은 거절한다. 저장 후 같은 revision을 다시 읽은 경우에만 UI가 저장 완료로 표시한다.

새 이미지의 claim은 현재 운영자의 검증·미만료·미소비 업로드여야 한다. 이미 같은 편성에 연결된 이미지 유지에는 새 claim을 요구하지 않아 다른 권한 있는 운영자도 수정할 수 있다. 두 편성이 같은 새 이미지를 동시에 소비하면 한 편성만 성공한다. 기존 `admin_save_goods_relation`는 목록형 호환을 유지하되 이미지형 덮어쓰기를 거절한다. 새 함수의 네 역할 ACL을 명시적으로 봉인하고 권한 registry/정책 추적에 등록한다.

`get_good_relation_compositions`는 익명 공개 조회를 허용한다. 활성·시간·상품·IP 조건을 DB에서 검사한 제목·유형·현재 공개 구성 ID·이미지·공개 태그·다음 경계만 반환하며 내부 버전·운영자 정보는 내보내지 않는다. 상품 카드는 선택 ID를 직접 전행 조회하고 기존 `toGood`의 옵션 가격·할인·재고 계산을 재사용한다. 카탈로그의 첫 1,000행에 포함되지 않는 상품도 편성 조회 대상이며 불완전한 조회는 오류로 구별한다. 기존 공개 RPC는 목록형 호환용으로 보존한다.

초안 상품의 URL 변경은 기존 `admin_save_good` 계약을 유지한다. 대표·구성과 태그의 복합 FK가 `ON UPDATE CASCADE`로 따라가며 공개 상품 URL 잠금은 바뀌지 않는다. 참조 FK 누락은 독립 검토에서 발견해 원 migration을 보존한 후속 migration으로 수정했다.

## 검증

- 실제 Chrome: 함께 구매 구성/대표/3→2 순서 저장→공개 카드·가격, 유사상품 저장→다른 구성 상세에 상호 노출, 두 탭의 먼저 저장/오래된 수정 충돌·입력 보존·최신 편성 재열기를 확인했다.
- 실제 Chrome에서 한국 시각 11:51 시작·11:54 종료를 UI로 저장했다. 열린 공개 상세는 시작 전 비노출→11:51 이후 자동 노출→11:54 이후 자동 숨김이 되었으며, 각 경계 확인 사이에 공개 탭을 수동 새로고침하지 않았다. 검수 후 기간을 비운 활성 편성으로 다시 저장했다.
- 390px: 편성 폼·상품찾기·공개 상세에 문서 가로 넘침이 없고, 구성 표는 내부 스크롤한다. 저장바를 하단 업무 도구 위로 올려 저장/목록 버튼 가림을 수정했다. 공개 페이지의 번역 확장 프로그램이 추가한 HTML 속성에서 발생한 hydration 경고는 앱 변경과 분리해 기록했다.

- 이미지/코디 코드 검증: 관련 8파일 125테스트, 변경 12파일 ESLint, 전체 typecheck 통과. 동시 작업 중인 마케팅 색상 토큰/상세전시 가이드 등록의 전역 계약 2건은 해당 담당자에게 전달하여 통합 단계에서 재검증한다.
- 이미지/코디 추가 검증: 격리 SQL에서 좌표 범위·형식·중복·회원 외 태그·검증 claim 소유/재사용·기존 이미지 타 운영자 유지·공개 태그 필터·상품 URL cascade·기간·기존 목록 저장 호환을 확인했다. 복제 격리 DB의 실제 2연결 경합에서 같은 요청 1회 감사, stale revision 한 건 거절, 같은 새 이미지 한 번 소비를 확인했다.
- 실제 Chrome에서 업로드→상품 3개(공개 2개/비공개 1개) 연결→수치/키보드 좌표 이동→저장·재조회·공개 태그 2개를 확인했다. 390px 터치 드래그로 70%/30%를 저장하고 DB/public 재조회가 일치했다. 충돌 시 제목·좌표 입력 보존과 최신 열기, 코디→함께 구매 이미지형 전환 시 좌표 유지·대표 외 상세 노출, PC/모바일 미리보기를 확인했다. 이미지형 편성의 예약 시작·종료 사이 수동 새로고침 없이 공개 상세가 비노출→노출→비노출로 바뀌었고, 검수 후 기간을 비운 활성 코디 편성으로 복구했다.

목록형의 브라우저 화면·DB 읽기·파일 해시는 기존 검수 manifest (`output/smartstore-reference-20261013/verification-related-goods/manifest.json`), 이미지·코디 추가 증거는 시각 편성 manifest (`output/goods-relation-visual-qa-20261013/manifest.json`)에 기록한다. 원본 좌표 편집·모바일·저장 결과, 운영 배포·실결제·네이버 저장은 완료로 세지 않는다.

## 목록 엑셀 (2026-10-14)

목록과 같은 `catalog.manage` 화면 권한으로 현재 검색어·유형·전시상태의 전체 페이지를 최대 2,000개 편성까지 내려받는다. 내부 `catalog.read` RPC의 권한과 기존 목록 접근 범위는 변경하지 않았다. 편성 요약, 각 편성의 구성 상품, 조회 정보의 세 시트이며 구성 순서·대표 상품·현재 공개 가능 여부·KST 기간과 조회 조건을 기록한다. 상품명·코드·ID는 수식으로 해석되지 않는 문자열이고 선행 0을 보존한다. 반입용 양식이나 보존된 과거 기록은 아니다.

각 페이지 100개씩 전량을 두 번 읽어 개수·중복·페이지·순서와 모든 반환값을 대조한다. 변화·불완전 조회·상한 초과는 파일을 내보내지 않고 재조회를 안내한다. 이 검사도 단일 DB 시점의 원자적 스냅샷을 보장하지 않으며 파일에 이 한계를 적는다. 필터 변경/이탈 시 진행 중인 다운로드를 취소하고 늦은 응답으로 다른 조건의 파일을 내려받지 않는다.

실제 Chrome·다운로드 근거 (`output/goods-relations-export-qa-20261014/manifest.json`): 2페이지에서 전체105편성/210상품행, 전시중53편성/106상품행, 빈 조건0행의 파일을 내려받았다. 실제 파일을 ExcelJS로 다시 읽어 독립 기대값과 4,582셀·전체 ID 순서를 대조했다. 390px에서 문서390/390과 표 내부 스크롤, 연결 실패 문구→복구 후 재다운로드를 확인했다. 단위 검사에서 2,000편성/20,000상품행의 끝 행 재열기, 필터/순서/공개값 변경·페이지 축소·중복·조회 실패·권한·수식 유사 원문을 검증했다. 관련7파일60검사·수정 파일 ESLint 통과, 네이티브 Excel 앱 열기는 미실행이다. 소유105편성/210참조를 정리한 뒤 원래3편성 전체 행이 유지됨을 확인했다.

## 다른 구성 상품의 독립 계약

`other_composition`은 같은 관리 원장을 쓰는 별도 목록형이다. 운영자가 2~10개와 상품별 선택 표시값을 지정하며 `/admin/display/detail?tab=otherComposition`에서 기본 꺼짐의 별도 section으로 노출한다. 공개 현재 상품과 후보가 공개 조건을 충족하면 비공개 대표가 있어도 노출한다. 이 예외는 기존 세 유형의 대표 공개 게이트를 바꾸지 않는다. 자세한 저장·공개·미리보기·검증 상태는 [다른 구성 상품 계약](other-composition-implementation-qa.md)을 따른다.
