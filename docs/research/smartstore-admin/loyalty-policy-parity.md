# 고객등급 조건과 혜택 연결

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

기준일: 2026-10-13. 원본의 금액/상품 주문 항목 수와 혜택 연결을 조사하고, 사용자가 선택한 **기존 등급명과 재산정 시점 유지**에 맞춰 구현한다.

## 유지하는 정책과 변경 범위

- WELCOME·SILVER·GOLD·PLATINUM과 최근 90일 창을 유지한다. 원본의 SILVER·GOLD·VIP·VVIP 또는 다음 달 1일 일괄 산정으로 바꾸지 않는다.
- 관리자(admin)가 `/admin/marketing/customer-grades`에서 세 승급 등급의 사용 여부와 금액 또는 상품 주문 항목 수 조건을 설정한다. 조건은 SILVER부터 연속 활성화하며 같은 기준을 사용하는 상위 등급의 값은 더 커야 한다. 두 기준을 모두 쓰면 OR이고 충족한 최고 등급이 산정값이다.
- 금액은 기존과 동일하게 최근 90일 `orders.created_at`과 paid·confirmed·shipping·delivered·done 상태의 총 청구액이다. 할인·배송비가 반영된 주문 총액이며 결제일 기준이나 상품금액 기준으로 바꾸지 않는다. 티켓 주문은 포함하지 않는다.
- 상품 주문 항목 수는 `order_items` 행 수다. 한 주문서에 두 조합이면 2건이고, 같은 항목에서 수량 5개는 1건이다. 취소 주문과 창 밖의 주문은 금액·항목 수에서 함께 빠진다.
- 정책 저장은 전체 회원 등급을 즉시 변경하지 않는다. 기존 paid/canceled 전이와 수동 재산정 때 적용하며, 최근 90일의 최신 수동 보정 하한을 보존한다. 자동 등급 사용을 끄더라도 별도 수동 보정을 금지하지 않는다.
- 혜택은 기존 쿠폰 정의의 등급 연결을 사용한다. 등급별 연결 목록에서 수정하거나 해당 등급이 선택된 새 쿠폰을 등록한다. 기존 staff의 쿠폰 편집 권한과 주문당 1장, 점프 승급 시 중간 등급 혜택, 동일 코드 재발급 금지, 기간/대상/한도 검사, 강등 시 기존 보유 유지도 보존한다. 정책 저장·혜택 연결만으로 소급 발급하지 않는다.

원본의 중복·장바구니·배송비 쿠폰 및 등급별 적립금 자동 지급은 이 단위에 포함되지 않는다. 기존 주문당 한 장과 적립금 원장 계약을 별도 변경하지 않았으며 이들 차이를 전체 기능 완료로 세지 않는다.

## 저장과 읽기

`loyalty_settings`는 RLS를 켜고 Data API 직접 읽기·쓰기를 봉인한다. admin 전용 읽기/저장 RPC에서 활성 역할, 탈퇴 쓰기 차단, 입력, revision, operation UUID를 확인한다. 행 잠금으로 동시 저장을 직렬화하고 같은 요청 재시도는 최초 결과를 반환한다. 이전 값·새 값·기준 revision·결과와 행위자를 감사 로그에 남긴다.

마이페이지는 인자를 받지 않는 본인 전용 `get_my_loyalty_status()`에서 금액·항목 수·정책 버전을 함께 받는다. Data API 행 수 제한과 고정 임계값 복제를 없애고 같은 정책으로 다음 등급 안내를 계산한다. 조회 실패는 과거 임계값이나 실적 0으로 대체하지 않는다.

## 검증

- 새 정책 SQL: 1,001개 주문 집계, 수량5/항목1 구분, 90일·취소 경계, 고객/직원/정지 관리자 접근 거절, 직접 접근 봉인, OR 조건, 설정 검증, 동일 UUID 재생·409 충돌, 정책 저장의 재산정/발급 없음, 감사 1회, 정책 버전 이력, 수동 하한 및 만료를 격리 DB에서 통과했다.
- 기존 `loyalty_grades.sql` 전체를 새 migration 위에서 통과해 결제/취소 전이, 점프 승급 쿠폰, 수동 보정, 재시도·누락 복구를 확인했다.
- TypeScript: 정책 파싱, 남은 금액/항목 수·충족 최고 등급, 조회 실패, 로그인 전 차단, 새 마이페이지 안내, 관리자 action/폼·쿠폰 초깃값 관련 검사를 통과했다.
- 실제 Chrome에서 등급 행표와 조건 수정창, 금액 7종·항목 수 5종 프리셋/직접 입력 전환값 보존, 취소 시 원래 조건 복원, 금액 OR 항목 수 예시 산정을 확인했다. 두 탭의 이전 버전 저장은 거절하면서 입력을 보존했고, 최신 정책을 따로 비교한 뒤 같은 입력으로 저장했다. 오프라인 실패 때 입력을 잠그고 같은 UUID 요청을 다시 보내 저장을 확정했다.
- SILVER 혜택 등록 링크에서 실제 쿠폰 선택값이 SILVER로 전달되는 것을 확인하고 합성 쿠폰을 저장·재조회했다. 최종 정책은 버전4이며 마이페이지에 변경된 금액/굿즈 주문 항목 수 안내가 함께 표시됐다. 실제 저장 3건을 동일 UUID로 재생해도 최신 정책·감사 건수·보유 쿠폰 수는 바뀌지 않았고, 검수 중 등급 변경·승급 알림·합성 쿠폰 발급은 모두 0건이었다.
- 390px에서 문서 폭 390px, 조건 수정창 내부 폭/스크롤 폭 356px로 가로 넘침이 없었다. 판매자 업무 도구는 화면 하단 788~844px에 유지됐다. 최종 등급 표 (`output/smartstore-reference-20261013/verification-loyalty-policy/16-final-grade-rows-desktop.jpg`), 모바일 수정창 (`output/smartstore-reference-20261013/verification-loyalty-policy/14-condition-dialog-mobile.jpg`), 화면·DB 확인 및 SHA-256 (`output/smartstore-reference-20261013/verification-loyalty-policy/manifest.json`).

검증은 격리된 로컬 DB와 합성 데이터에서 수행했다. 운영 DB와 배포는 변경하지 않았다.
