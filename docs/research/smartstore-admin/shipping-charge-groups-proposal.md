# 배송비 묶음그룹

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14. 원본에서 확인한 범용 쇼핑몰 기능을 현재 거래 모델에 연결하는 계약을 정하고 구현 중이다. 구현·DB 적용·배포 완료 기록이 아니다. [구조 결정](../../adr/0023-shipping-charge-groups.md)과 [배송정보 템플릿](shipping-template-parity.md)의 수량별·선결제/착불 정책 복사를 구별한다.

## 원본에서 확인한 것

등록 화면 (`output/smartstore-reference-20261012/catalog-cs/82-delivery-bundle-create.jpg`)과 템플릿 선택창 (`output/smartstore-reference-20261012/catalog-cs/89-template-delivery-bundle-picker.jpg`)은 이름·사용 여부·기본 그룹·최소/최대 부과·지역 추가료와 상품의 묶음그룹 선택을 제공한다. 원본 계정에 저장하거나 실제 주문을 만들지는 않았다. 원본의 그룹명·금액·주소는 ICONS 기본값으로 복사하지 않는다.

- [공식 계산 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=4601)는 같은 스토어·배송방법의 최소/최대 부과, 무료배송 또는 조건부 무료 충족의 우선 적용을 설명한다. 서로 다른 상품의 수량을 합친 반복 부과 예시도 있다. 단순히 현재 상품별 배송비 중 최소·최대를 고르는 것으로는 그 예시와 일치하지 않는다.
- [조건부 무료 금액 기준](https://help.sell.smartstore.naver.com/faq/content.help?faqId=4008)과 ICONS의 기존 가격 기준은 별개다. ICONS는 이미 확정한 **기간 할인 후 소계 S**를 유지한다. 이를 네이버의 판매가 기준과 완전히 동일하다고 표현하지 않는다.
- [상품 배송정보 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3937)는 네이버 추가상품을 반복 수량에서 제외한다. ICONS의 추가 구성 굿즈는 독립 가격·옵션·재고를 가진 별도 굿즈이므로, 같은 배송비 묶음그룹에 명시 배정하고 실제 구매했다면 그룹 수량에 포함한다. 관계 표시만으로 구매 수량을 빼지 않는다.
- [지역 추가료 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3373)는 기본 배송비 면제와 지역 추가료를 구별하며, 기본료의 수량별 반복 횟수로 지역 추가료를 곱하지 않는다. ICONS의 주소 판정 자료와 실제 금액은 기존 물류사 근거·정책 확인 절차를 따른다.
- [다른 출고지의 묶음 불가](https://help.pay.naver.com/faq/content.help?faqId=11310)와 [한 장바구니 주문의 묶음](https://help.pay.naver.com/faq/content.help?faqId=11309)을 기준으로 한다. 이미 생성된 별도 주문을 합치는 기능은 이 범위가 아니다.

여러 수량 구간의 일반화·선결제와 착불의 혼합 배분은 현재 확보한 공식 원문만으로 원본 동등성을 확정하지 않았다. 아래 접합 규칙은 ICONS의 기존 거래 계약을 유지하기 위한 자체 설계이며, 실제 네이버 거래를 검증한 결과와 구별한다.

## 유지할 경계

**배송비 묶음그룹**은 재편성 가능한 배송비 설정이다. 전시용 그룹상품, 분리된 옵션의 경제적 정체성을 유지하는 구매 합산군, 물리 발송과 운송장을 소유하는 배송 건과 구별한다.

- 같은 주문·출고지의 정책 소유 상품만 같은 그룹으로 계산한다. 구매 합산군 자식은 원상품의 배정을 공유하고 독립 배정하지 않는다.
- 기존 미배정 상품의 배송비는 기존 규칙을 유지한다. 새 그룹·기본 그룹을 만들었다는 이유로 기존 상품을 자동 편입하지 않는다.
- 배송용 수량과 금액 합계는 그룹 안의 **실제 구매 선택**에서 구한다. 전시 구성, 미구매 상품, 복수구매 할인 범위·누적 구매 제한에 이 합계를 사용하지 않는다.
- 물리 배송 건은 계속 주문·출고지당 하나다. 요금 그룹 수를 운송장 수나 포장 수로 해석하지 않는다.
- 이미 확정한 주문·품목·배송비 배분·착불 의무·환급은 불변이다. 그룹 수정 후 과거 주문을 재계산하지 않는다. 주문 전체 취소·반품과 온라인 원결제 전액 환급을 유지한다.
- 그룹에 속한 신규 주문은 확정 견적 경로로만 생성한다. 구형 주문 경로가 새 그룹을 무시하고 다른 금액으로 주문하는 우회는 막는다.

## 계산 계약

구매 합산군의 실제 선택을 원상품별로 먼저 모은다. 원상품별 가격·할인 계산은 현재 계약을 유지하고, 배송용으로만 명시 그룹의 `Q_group`과 `S_group`을 별도로 만든다.

1. 활성 수량 정책이 있으면 그 정책을 그룹 전체 수량으로 평가한다. 기존 기본 배송비 유형을 수량 정책보다 먼저 무료로 판정하지 않는다.
2. 활성 수량 정책이 없으면 무료·개별·출고지 정책의 유효 기본료를 구한다. 그룹 안의 출고지 정책 상품은 그룹의 S로 조건부 무료 기준을 판단한다.
3. 유효 무료 또는 충족한 조건부 무료가 하나라도 있으면 그룹 기본료는 0이다. 아니라면 그룹별 최소/최대 설정으로 후보 기본료를 선택한다.
4. 그룹 기본료는 각 원상품의 S 비중으로 정수 배분한다. S 합계가 0이면 수량 비중을 쓴다. 기존 최대 나머지 방식과 안정적인 ID 동률 규칙을 사용한다. 같은 합산군의 실제 상품으로 나누는 현재 배분도 유지한다.
5. 지역 추가료는 별도로 계산한다. 그룹 무료 판정을 지역 추가료 면제로 자동 확장하지 않는다.
6. 상품별 확정 선결제/착불 선택에 따라 배분액을 H와 D로 합산한다. 혼합 선택을 임의로 선결제에 몰거나 다른 주문으로 나누지 않는다. 0원 착불도 현재 수납 계약 준비 조건을 유지한다.

온라인 결제는 계속 `T = S - V - C - R + H`이고 D는 외부 수납 의무다. 총 배송비만 같아도 H/D가 다르면 같은 견적이 아니다. 고객에게 각 금액을 보여주고 주문 생성 직전에 전체 계약을 다시 대조한다.

| 합성 사례 | 결과 |
| --- | --- |
| 같은 그룹 A 기본료 3,000원, B 5,000원 | 최소 3,000원 / 최대 5,000원 |
| 유효 무료 A와 유료 B | 두 계산 방식 모두 기본료 0원; 지역 추가료는 별도 |
| A 2개 고정 2,500원, B 2개마다 3,000원·2개 구매 | 그룹 수량 4개로 평가하여 최소 2,500원 / 최대 6,000원 |
| S가 같은 A 선결제·B 착불, 그룹 기본료 5,000원 | H 2,500원 / D 2,500원 |
| 동일 구매 합산군의 두 상품을 같은 수량으로 줄 분할 | 합산군·그룹 수량과 총 배송비 유지 |

## 지역 추가료 접합

기존 출고지 지역 정책 상속과 그룹의 명시 정책을 구별한다. 기존 `per_shipment`는 물리 배송 건당이라는 뜻을 유지한다.

- **출고지 정책 상속**: 같은 출고지의 상속 그룹과 미배정 상품을 기존 출고지 지역 정책으로 함께 판단한다. `per_shipment`를 그룹 수만큼 반복 부과하지 않는다. 무료 기준에 따른 지역료 면제는 이 상속 부분집합의 유효 정책 유형 소계로 판단하며, 명시 그룹 지역 정책 대상의 금액은 포함하지 않는다. 그룹 기본료 무료와 출고지 지역료 면제는 서로 다른 판정이다.
- **그룹 정책 지정**: 지정 그룹은 원상품별로 기존 출고지 지역료 대상에서 제외하고 그룹의 확인된 지역표로 추가료를 그룹당 한 번만 부과한다. 기본료 반복 수량을 지역료에 곱하지 않는다.
- 주소 판정·택배사·적용 기간·미기재 지역·배송 불가·개별 확인·0원과 미확인을 기존 지역 정책과 같은 수준으로 검증한다. 유효하지 않거나 만료된 그룹 지역 정책을 출고지 정책이나 0원으로 조용히 대체하지 않는다.
- 운영자가 실제 계약에 맞는 부과 단위와 근거를 확인한 뒤 명시 적용한다. 기존 지역표·금액을 자동 복제하거나 활성화하지 않는다.

한 출고지의 여러 그룹·상속과 명시 정책이 섞인 사례를 정수 검산하고, 새 그룹이 전혀 없는 입력은 기존 계산 결과와 정확히 대조한다.

## 운영과 동시 변경

그룹에는 출고지·이름·사용 여부·기본 선택·계산 방식·지역 설정을 두고, 정책 버전과 배정 revision을 보존한다. 기본 선택은 신규 입력의 선택 편의이며 기존 상품의 자동 재가격을 뜻하지 않는다. 원상품의 출고지 변경과 그룹 배정 변경은 같은 검증 경계를 통과해야 한다. 연결 상품이 있는 그룹은 사용 중지·보관할 수 없으며 상품을 먼저 명시 이동·해제한다. 기본 그룹은 사용 중인 그룹만 지정한다. 보관해도 과거 정책 버전과 주문 근거는 삭제하지 않는다.

그룹 관리, 개별 상품 배정, 템플릿의 유지/해제/지정, 최대 100개 상품 미리보기·적용을 연결한다. 정책 소유자가 아닌 합산군 자식에는 원상품과 적용 범위를 표시한다. 기존 템플릿에 새 배정 지시가 없으면 현재 배정을 유지한다.

쓰기에는 현재 권한·실행자·세션, 고정 UUID·입력, 기대 revision과 잠금을 적용한다. 다른 계정/세션의 요청 복구는 거절하며 응답이 사라지면 같은 요청의 결과 조회·재시도·종료를 제공한다. 새로고침 복구 정보에는 정책 원문이나 주소·계약 근거를 저장하지 않는다. 그룹 사용 중지나 삭제를 기존 상품에 대한 조용한 요금 변경으로 처리하지 않는다.

확정 견적에는 그룹·배정·배송·지역·수납 정책의 버전과 계산 근거를 결속한다. 그룹 수정·재배정·출고지 변경과 견적/주문 생성이 경합하면 공통 잠금 순서로 직렬화하고 오래된 견적은 갱신을 요구한다. 같은 주문 생성 키의 이미 성공한 결과 복구는 유지한다.

## 구현과 검증 범위

DB 계산·버전·배정·멱등 RPC를 먼저 구현하고 엄격한 서버 DTO와 운영 UI를 연결한다. 공개 상품의 조건 안내, 장바구니·선물·정기배송의 확정 견적, 배송비 절약 추천, 주문·클레임·정산 조회도 같은 계산·스냅샷을 사용해야 한다. 새 필드가 없는 과거 주문은 계속 읽고, 과거 값을 현재 정책으로 채우지 않는다. private 계약·지역 원문을 공개 주문 JSON이나 선물 구매자 응답에 노출하지 않는다.

검증은 최소/최대·무료 우선·반복/2·3구간·0원·큰 수량, 가족과 그룹 합산 분리, 선결제/착불·지역 정책 혼합, 구형 주문 거절, 신규/과거 주문 스냅샷, 그룹 변경과 주문 생성 경합, 권한·세션·응답 유실, PC/390px 저장·재조회에 집중한다. 기존 미배정 계산은 같은 입력의 기존 결과와 대조한다. DB는 소유 격리 환경에서 검사하며 운영·Preview 활성화와 실제 물류사·PG 실행은 포함하지 않는다.
