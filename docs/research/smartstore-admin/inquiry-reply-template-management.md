# 일반 고객문의 답변 템플릿 관리

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-13 구현·격리 로컬 검증 기준이다. 운영 환경에 배포하거나 고객에게 답변을 발송한 결과가 아니다.

## 보존한 계약

- 기존 `inquiry_reply_templates`의 ID·제목·본문·생성자·생성/수정 시각과 staff 공유 소유 모델을 유지한다. 공개 상품문의·리뷰의 `cs_reply_templates`로 데이터를 옮기거나 개인별 템플릿으로 바꾸지 않는다.
- 제목 40자·본문 2,000자, 기존 문의 답변 폼의 길이 판정을 유지한다. 유형은 상품·배송·반품·교환·환불·기타이며 기존 행의 기본 유형은 기타다.
- 템플릿 관리와 실제 답변 발송은 별도다. 기존 `admin_answer_inquiry`의 메시지·인앱 알림 원자 처리와 이후 개별 메일 발송 경로는 변경하지 않는다.

## 추가한 동작

문의 상세의 **답변 템플릿 불러오기**에서 유형·제목·삭제 여부를 조회하며, 20개씩 페이지를 이동한다. 템플릿 등록은 현재 답변을 초안으로 가져오고 이후 제목·본문을 편집한다. 불러오기는 현재 답변 뒤에 추가하며 합친 길이가 제한을 넘으면 원문을 유지한다.

수정은 저장 당시 revision을 검사한다. 다른 담당자가 먼저 고친 경우 입력을 보존하고 최신 저장본을 별도로 비교한다. 운영자가 **편집 문구를 최신 저장본으로 바꾸기**를 누르기 전에는 편집 문구를 덮어쓰지 않는다. 검색·다른 템플릿 선택·편집 닫기·관리 창 닫기 동안 각 편집 초안을 보존한다. 2026-10-14부터 계정·로그인 세션별 탭 저장소에 편집값과 불확실한 요청을 보관하여 페이지 이동·새로고침 뒤 명시 복구한다. 현재 검색에 없는 편집 항목도 초안 목록에서 다시 열 수 있다. 성공이 확인된 항목만 지우며, 보존·만료·인증 경계와 실제 QA는 [CS 편집 초안 복구](cs-editor-drafts.md)를 따른다.

삭제는 `archived_at`을 기록하며 같은 관리 창에서 복구한다. 생성·수정·삭제·복구는 실제 활성 직원, 작업 UUID, 템플릿 ID, 예상 revision과 정규화 입력을 감사에 남긴다. 같은 작업의 재실행은 원래 결과를 반환하며, 과거 저장이나 삭제 요청을 재생해도 최신 수정·복구를 되돌리지 않는다. 구형 무버전 upsert와 물리삭제 RPC의 실행 권한은 닫고 미사용 서버 액션을 제거했다.

쓰기 뒤에는 별도 RPC로 저장된 결과를 읽는다. 전송 결과가 불확실하면 입력·요청 번호를 잠그고 같은 요청 결과를 먼저 확인한다. 재조회는 쓰기와 같은 작업 잠금을 기다리므로 아직 실행 중인 요청을 미저장으로 판단하지 않는다. 미저장이 확인되면 같은 요청으로 재시도할 수 있다.

## 검증

- [`admin_inquiry_reply_template_management.sql`](../../../supabase/tests/admin_inquiry_reply_template_management.sql)은 rollback 가능한 격리 트랜잭션에서 기존 행 기본값·작성자 보존, 직원 공유 수정, stale revision, 잘못된 유형/길이/추가키, 삭제 중 수정 거부, 삭제/복구, 과거 작업 재생, 다른 직원의 작업 영수증 접근 거부, 정지 직원·일반 고객·직접 DML·구형 writer 권한 거부를 검사했다. 템플릿 작업 전후 문의 메시지·알림·메일 원장 수가 같음을 확인했다.
- 도메인·서버 액션·클라이언트 동작 테스트에서 실제 답변 길이와 추가 삽입, 별도 결과 조회, 버전 충돌과 불확실 응답 구분, 각 초안의 닫기/검색/행 전환 보존, 전송 실패 이후 동일 작업 재시도, 저장 완료 뒤 목록 조회 실패 처리를 확인했다.
- Chrome 실제 화면에서 합성 문구 v1 등록 → 다른 탭의 v2 수정 → 기존 탭의 오래된 편집 거부 및 문구 보존 → 최신 저장본 비교 → 탭 오프라인 전송 실패/입력 잠금 → 온라인 복원/미저장 확인 → 같은 요청으로 v3 저장 → 삭제 v4 → 복구 v5를 수행했다. 유형/제목 검색과 기존 답변 뒤 삽입도 확인했고 답변 발송 버튼은 누르지 않았다.
- 전용 합성 문구 22개에서 1페이지 20개와 2페이지 2개를 실제로 조회했다. 390×844에서 문서 폭/스크롤 폭은 390/390이며 템플릿 목록 대화상자는 368/368, 편집 대화상자는 358/358로 가로 넘침이 없었다. 탭별 화면 크기·네트워크 재현 설정은 모두 복원했다.

합성 화면·DB readback과 SHA-256 목록은 `output/smartstore-reference-20261013/verification-inquiry-templates/`에 보존한다. 원본 네이버에서 실제 템플릿 생성·수정·삭제는 실행하지 않았다. 실제 고객 답변/메일 발송, 배포, 다중 사용자 동시 실행의 부하 검증은 이번 범위에 포함하지 않는다.
