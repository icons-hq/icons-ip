# 상품·그룹상품 목록 일괄 변경

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-16 구현·격리 DB·실제 관리자 화면 검증 완료. 운영 DB 적용·배포는 수행하지 않았다.

원본 그룹상품 목록의 펼친 도구모음(`output/smartstore-full-admin-20261016/source-groups-expanded-mid-1440.*`)에서 확인한 전시·판매·할인·판매가·기간·배송 변경과 그룹 해제를 목록 선택에 연결했다. 영구 삭제는 기존 보관·복원 계약으로 제공하며 재고·진행 거래 등의 기존 보관 조건을 유지한다.

- 상품 또는 그룹을 선택하고 변경 내용을 입력한 뒤, 서버가 확인한 개별 상품 목록과 전후 값을 비교한다. 한 번에 개별 상품 100개까지이며 그룹은 현재 구성원을 펼쳐 이 한도를 검사한다.
- 전시/미전시, 판매 재개/중지, 보관/복원, 기본 판매가 지정·정액/정률 인상·인하, 옵션별 정액/정률 기간 할인·중지, 일반 판매기간·제한 해제와 그룹 연결 해제를 지원한다. 판매가 변경은 옵션 추가금액·재고를 보존하며 비율 계산의 원 미만은 버린다. 새 할인은 기존 활성 할인과 겹치면 전체 거절한다(2026-10-27부터는 아래 갱신대로 해당 상품만 건너뛴다).
- 가격·재고·옵션·그룹 구성·할인 상태를 비교 시점에 고정한다. 15분 만료 및 변경 여부를 잠금 획득 후 다시 확인하고, 기존 공개/KC·보관·그룹·예약판매 검증을 통과한 전체 트랜잭션만 반영한다.
- 확인 창에서 대상·변경 내용 확인을 선택해야 저장할 수 있다. 요청번호를 현재 계정·로그인 세션과 함께 보존하고 결과가 불명확하면 조회 또는 미처리 종료만 제공한다. 종료된 요청과 거절된 요청은 재실행하지 않는다.
- 배송 변경은 선택한 상품번호를 배송정보 템플릿 화면으로 전달한다. 템플릿의 기존 출고지·실제 운임·합산군 소유권·버전 비교와 원자 적용을 그대로 사용하며 상품을 자동 추가하지 않는다.

## 2026-10-27 갱신 — 건너뛰기·IP 전체 할인·목록 바로 수정

10/14 실사용 QA 회의(A9·A10, D10 ①) 후속. migration `20261027150100_goods_bulk_ip_discount.sql`.

- 즉시할인 비교는 상품별 건너뛰기 사유(`price_period_overlap` 겹치는 활성 할인, `price_period_variant_inactive` 사용 옵션 없음, `goods_bulk_price_invalid` 할인가 1원 미만·판매가 이상)를 미리보기에 고정한다. 확정은 나머지 상품에만 적용하고 영수증 `skipped`에 목록을 남긴다. 모두 건너뛰면 비교 자체를 거절한다(`goods_bulk_all_skipped`). 선택 상품·그룹·IP 모두 같은 규칙이다.
- `kind='ip'`는 IP 하나를 비교 시점의 보관하지 않은 전체 상품(최대 1,000개, 초과는 `goods_bulk_target_limit`)으로 펼친다. 할인 등록·중지만 허용한다. 상품 목록에 IP 필터를 걸면 'IP 전체 즉시할인'으로 진입한다.
- 할인 등록·중지의 비교 지문은 상품 판매가·IP·보관과 옵션 ID·가격·보관, 기간 할인 원장만 본다(`goods_bulk_price_fingerprint`). 판매로 인한 재고 변동은 수백 개 상품의 IP 할인을 거절시키지 않는다. 다른 명령의 지문은 그대로다. 이 migration 전에 저장된 할인 비교는 변경으로 판정돼 다시 비교를 요구한다.
- 할인 중지 비교는 상품별로 꺼질 진행·예정 기간 할인(건수·할인가 범위·기간)을 `discounts`로 보여 준다. IP 전체 할인뿐 아니라 상품별로 걸어 둔 할인도 함께 꺼지므로 확인 문구로 알리며, 진행·예정 할인이 없는 상품은 `no_active_discount`로 건너뛴다(모두 없으면 `goods_bulk_no_active_discount`). 개별 할인만 보호하는 범위 축소는 할인 출처를 기록하지 않는 현재 원장에서 구분할 수 없어 하지 않았다.
- 판매가 변경은 진행 중이거나 예정된 기간 할인이 있는 상품이 있으면 비교 단계에서 `active_price_period_requires_reset`로 거절한다(확정 시 옵션가 보호 트리거와 같은 조건을 미리 확인). 운영자 문구는 할인을 먼저 중지하라고 안내한다.
- 목록 바로 수정(A9)은 새 쓰기 경로 없이 판매가·판매상태를 상품 1개짜리 일괄 변경으로, 재고수량을 기존 `admin_adjust_stock`으로 처리한다. 판매가·판매상태는 미리보기의 현재 값이 목록에서 본 값과 다르면 확정하지 않고 요청을 종료하며(seal), 재고는 본 수량을 기대값으로 보낸다. 감사·멱등·결과 조회는 기존 경로의 것을 쓴다. 재고는 사용 옵션이 정확히 하나인 상품만 셀에서 고친다(옵션 재고는 옵션 단위이고, 여러 옵션의 합계를 한 칸에서 나누는 규칙을 만들지 않는다). 판매가 바로 수정은 상품 편집기의 '판매가'와 같은 뜻일 때만 연다: 상품 할인(`compare_at_price`, 편집기의 판매가=정가)이 있으면 상품 수정의 판매가로 안내하고, 진행·예정 즉시할인이 있으면 할인 중지 후 변경하도록 이유를 보인다. 이 판단은 페이지 상품(최대 100개)만 읽는 `admin_goods_list_price_states`(`catalog.read`, migration `20261027150200`)가 준다.
- 검증: `goods_list_bulk_operations.sql`(겹침 건너뛰기·나머지 적용·전부 건너뜀 거절로 갱신), `goods_bulk_ip_discount.sql`(105개 확장·보관/다른 IP 제외·건너뛰기 2종·판매 재고 변동 무시·옵션가 변경 거절·IP 다중/가격 명령/보관 IP 거절·1,000개 초과 거절·감사 1건·ACL).
