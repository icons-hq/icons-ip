# 상품 제공 방식·선결제 비용·디지털 파일

상품별 제공 방식과 보호된 파일 제공의 구현·격리 DB/Storage·실제 브라우저 검증을 마쳤다. 디지털 교환은 사용자 선택에 따라 재다운로드와 문의·취소/환불 심사로 확정했다([정책 후속](customer-demographics.md)). 운영 배포·실제 결제·실제 고객 파일 업로드는 수행하지 않았다.

## 계약

- 상품별로 택배·퀵·방문수령·직접배송·화물 중 허용 방식을 저장한다. 배송없음 직접전달과 디지털 다운로드는 별도 제공 구분이다. 택배 외 실물 방식은 해당 출고지의 실제 담당·인계·예약·수령·취소 조건이 활성 상태여야 선택할 수 있다.
- 새 운임은 상품별 주문 1회 또는 개당 금액이다. 설치비는 개당 금액이며 항상 선결제한다. 기존 택배 착불·수량·지역·묶음 배송비 계산은 보존한다. 방문수령·직접전달·디지털은 운임·설치비가 0원이다.
- 견적 이후 설정이 달라지면 주문 생성을 거절하고 새 견적을 받는다. 선택 방식별로 배송 건을 나누며 주문 당시 파일·운임·정책을 보존한다. 결제 후 방식 변경은 고객 요청과 기존 비용 유지 동의를 기록하며 배송없음·디지털은 방식 변경 대상에서 제외한다.
- 퀵·직접배송·화물은 인계와 수령을 분리한다. 방문수령·직접전달은 실제 인계와 주문자 전용 일회 확인값으로 완료한다. 택배 송장·발주 파일로 비택배 완료를 위조하지 않는다.
- 디지털 파일은 PDF·ZIP·PNG·JPG·MP3·MP4·TXT, 개당 50MB·상품당 10개다. 업로드 세션·크기·MIME·파일 시그니처·SHA-256을 확인한다. 백신 검사·압축 해제·스트리밍 상품은 포함하지 않는다.
- 파일은 비공개 버킷에 보존한다. 고객 직접 Storage 읽기와 공개 URL은 차단하고 영구 또는 서명된 다운로드 URL을 발급하지 않는다. 서버가 구매자·현재 세션·승인 결제·현재 클레임/환불·구매 당시 파일을 전송 전에 재검증한다. 다운로드 시작은 제공 이력이며 고객 기기의 저장 완료를 증명하지 않는다.
- 동일 전송 요청은 같은 이력으로 재시도한다. 취소·환불 검토 중과 환불 후 새 전송은 차단한다. 이미 고객 기기로 전송한 파일을 원격 삭제하지는 않는다. 제공 후 취소를 자동 거절하지 않고 관리자 심사로 접수한다. 디지털 선물 전달은 제공하지 않으며 결제 계정만 파일을 받는다.
- 사용하지 않는 업로드는 만료 후 기존 상품 미디어 정리 cron에서 제거한다. 상품·주문·제공 이력이 참조하는 파일은 정리하지 않는다. 탈퇴 거래 증거에는 파일 ID·형식·크기·해시·제공 시각과 비용만 보존하며 파일명·비공개 경로·세션·자유서술은 복제하지 않는다.

## 검증 근거

- `supabase/tests/fulfillment_checkout.sql`: 같은 출고지의 방식 분할, 선결제/착불 설치비 분리, 견적 변경 거절, 디지털 주소 없음, 권한·구매자·만료 세션, 제공 이력 멱등, 제공 후 취소 심사, 5개 실물 방식 인계/일회 수령, 탈퇴 최소 증거를 롤백 트랜잭션에서 확인했다.
- `supabase/tests/fulfillment_download_integration.mjs`: 실제 격리 Storage 업로드·검증·구매·35바이트 및 상한 50MiB(52,428,800바이트) 파일 전송과 해시를 확인했다. 파일 교체 후 과거 주문의 원 파일 재다운로드도 검증했다. 같은 요청 13회 전송은 제공 원장 1건이고, 다른 계정·익명·직접 Storage·공개 URL은 차단됐다. 취소 요청 중 차단과 요청 종결 후 복구를 확인했다. 외부 PG 호출은 없다.
- `fulfillment-contract-readback.json`의 실제 주문 영수증·파일 목록·배송 건을 앱 파서에 통과시켰다. 실제 구매자 주문 HTML 200과 파일 패널을 확인했다.
- 관련 15개 파일의 120개 테스트와 타입 검사가 통과했다. 이후 UI 문구·파생 상태 수정에 대한 최종 검증은 별도로 기록한다.

- 실제 PC·390px에서 상품 제공 방식 설정·파일 업로드/검증·저장, 구매자 파일 받기와 관리자 제공 이력 조회를 확인했다. 구매 당시 파일 유지·비택배 인계/수령·제공 후 취소 심사는 각 UI/SQL 근거를 구분한다. 관리자 디지털 주문에 파일별 제공 횟수·최초/최근 시각을 표시하며 원본 파일 경로와 전송 세션은 노출하지 않는다. `final-interaction-readback.json`과 보존한 `qa-ui/` 캡처, [전체 검증 기록](full-admin-implementation-20261016.md)을 따른다.

## 남은 확인

대용량 파일의 배포 환경 전송 검증이 남아 있다. 작업 전용 새 DB의 404개 순서 적용 및 이행·쿠폰을 포함한 통합 SQL 검증은 통과했다. 로컬 50MiB 전송 성공을 배포 환경 전송 검증으로 간주하지 않는다.

배송정보 템플릿에서도 수령 방식·선결제 운임·설치비를 유지하거나 명시적으로 변경할 수 있다. 변경 전후 파일 연결과 수령 버전을 확인하고 선택 상품 전체를 원자 적용한다. 실제 등록·적용·응답 유실 복구·47,000원 고객 견적은 [배송 템플릿 기록](shipping-template-parity.md)에 있다. 디지털 파일 자체는 상품별 검증 업로드로 관리한다.
