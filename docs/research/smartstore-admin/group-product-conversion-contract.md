# 그룹상품과 옵션별 상품 전환

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14 구현·격리 DB 통합·실제 로컬 화면 검증 완료. 사용자는 **원본처럼 옵션을 별도 상품으로 전환**하고 **기존 상품의 합산 조건을 유지**하도록 확정했다. 전환·합산·실물 재고 추적·공통 편집과 공개 탐색/리뷰를 구현했다. 운영 적용·배포는 실행하지 않았다. [구조 결정](../../adr/0022-group-products-from-variants.md), [기존 옵션 계약](../../adr/0015-goods-variants.md)을 함께 따른다.

## 원본 근거

로그인된 원본의 그룹상품 소개와 [공식 그룹상품 매뉴얼 공지](https://sell.smartstore.naver.com/#/center-notice/detail/100015261)를 직접 읽었다. 첨부 `스마트스토어센터_그룹상품_매뉴얼_2025.11.12.pdf`는 102쪽이며, 내려받은 바이트·페이지 추출·화면·해시를 원본 기록 (`output/smartstore-reference-20261014/group-products/source.json`)에 보관했다. 등록·그룹 설정·해제·원본 데이터 변경은 실행하지 않았다.

- 5~9쪽: 각 판매옵션은 별도 상품과 상세페이지를 가진다. 같은 그룹의 다른 판매옵션을 고르면 해당 상품 상세로 이동한다.
- 12~13쪽: 리뷰는 그룹 단위로 함께 노출한다. 기본 상품 정체성이 같고 판매옵션이 다른 상품을 묶으며, 네이버 검색 인기도는 별도 노출 그룹 기준이다.
- 17~27쪽: 그룹 공통정보와 개별정보를 나눈다. 그룹명은 40자, 카테고리별 판매옵션 조합은 최대 20개 또는 100개이며, 원본 표준 옵션명은 네이버가 제공한다.
- 58~62쪽: 전체 상품 목록과 그룹 목록을 구분하고, 그룹 행을 펼쳐 개별 상품을 조회·수정한다. 그룹 공통정보는 그룹 편집에서 다룬다.
- 68~71·78·97쪽: 선택한 첫 옵션은 원상품번호를 유지하고 나머지 옵션은 새 상품번호를 받는다. 기존 옵션 정보는 제거되며 선택하지 않은 옵션도 제거된다. 기존 주문·리뷰는 원상품번호에 남고 옵션 가격을 개별 판매가로 옮긴다.

원본의 30일 해제 제한·네이버 검색 사전/순위·AI 전환 추천·외부 채널 검수는 ICONS에 그대로 적용하지 않는다. 원본 저장 결과와 계정별 모든 카테고리 조합은 미확인이다.

## 확정한 방향

1. 그룹과 각 판매옵션은 별도 식별자를 가진다. 그룹명과 판매옵션 값은 선택·탐색에 사용하고, 실제 구매는 각 상품의 기존 주문 계산·재고·공개 조건을 따른다.
2. 원상품별 첫 선택 옵션은 기존 상품번호와 옵션번호를 유지한다. 다른 선택 옵션은 새 상품과 기본 옵션을 만들며, 기존 옵션은 주문 이력의 정체성으로 보존한다.
3. 현재 할당 재고는 같은 전환 트랜잭션에서 이관하고 전후 수량·판매 단위 대응을 기록한다. 복사로 재고를 두 배로 만들지 않는다. 미선택 옵션은 판매 중지하며 보유 재고를 지우지 않는다.
4. ERP 코드·바코드는 현재 연결의 유일성을 유지해야 한다. 새 판매 단위로 이동한 연결의 이전 값과 대상은 별도 이력으로 보존하며, 과거 주문·개인정보·금액 스냅샷은 재작성하지 않는다.
5. 리뷰의 작성자·주문 자격·원래 상품은 그대로 두고 그룹의 공개 리뷰 집계에서 함께 읽는다. 비공개/숨김/탈퇴 등 현재 공개 규칙을 우회하지 않는다.
6. 전환 전 비교와 최종 서버 검증은 같은 필드 범위를 사용한다. 변경·결제 경합·같은 요청 재시도·계정/권한 변경·응답 유실을 DB에서 처리한다.
7. 새 상품의 KC·공개·이미지 출처 계약을 우회하지 않는다. 전환으로 무엇이 복사되고 무엇을 다시 확인해야 하는지 확정 전에 표시한다.
8. 사용자가 선택한 **기존 상품의 합산 조건 유지**에 따라 같은 원상품에서 분리한 상품의 복수구매 할인·주문 수량 제한·누적 구매 제한·수량 운임은 원상품 기준으로 계산한다. 과거 구매량도 포함하고, 표시 그룹에서 제외해도 합산 관계를 끊지 않는다. 개별 가격과 주문 상품번호는 그대로 사용하며 같은 주문 행에 할인을 중복 적용하지 않는다.

## 구현 계약과 확인 범위

| 항목 | 현재 구현 계약 |
| --- | --- |
| 옵션 정체성 | `goods_variant_identity_immutable`와 주문/장바구니의 `(variant_id, good_id)` 복합 참조를 보존한다. 첫 선택 이외의 현재 재고를 새 단위로 옮기며 불변 전환 대응 원장을 남긴다. |
| 재고·반품·교환 | `order_item_physical_unit`은 원주문/마지막 교환 출고를 반환하고 `resolve_goods_stock_successor`는 그 단위의 현재 재고를 찾는다. 반환 차수별 영수증으로 한 번만 복원하고, 그룹 교환은 현재 그룹의 선택 단위로 차감한다. 과거 주문·ERP 스냅샷과 실제 출고 명칭은 분리해 조회한다. 일반 구매·재고조정은 전환 대응을 자동 적용하지 않는다. |
| ERP·공급가 | ERP 코드/바코드는 전체 옵션에서 유일하다. 공급가는 별도 권한과 사적 이력이므로 일반 전환 응답/감사에 금액을 노출하지 않는다. |
| 상품 정책 | 선택 옵션의 가격·기간 가격·직접입력·검증된 이미지와 안내를 보존한다. 수량 제한·복수구매 할인·수량 운임은 영구 원상품 합산 관계를 읽는다. 예약판매 설정·진행 중 정기배송·미결제 선물/주문·미확정 결제는 전환을 차단한다. 일반 복제의 신규 재고 0 계약과 분리한다. |
| 공통 편집 | 이름·판매옵션 값과 공통 상품 정체성의 소유권, 개별 가격/재고/배송과의 구분을 DB·폼 양쪽에서 맞춘다. |
| 공개 탐색·리뷰 | 판매옵션별 상세 이동과 현재 공개 후보를 제공한다. 그룹 리뷰는 현재 공개 범위의 전체 집계·페이지를 한 RPC에서 계산하며 원주문 상품명/옵션명을 보존해 표시한다. 조회 실패를 0개 리뷰로 표시하지 않는다. |
| 기존·신규 경로 | 기존 상품의 선택 전환과 새 그룹의 등록, 그룹별 조회/펼침·공통 수정·구성 추가/제외·그룹 해제를 연결한다. 해제로 기존 옵션 구조를 자동 복원하지 않는다. |

## 검증 기준

2026-10-14 통합 실행은 기존 결제·환급·탈퇴 보존 검사부터 무통장 환급, 그룹 전환, 합산 조건, 반품/교환 재고 승계와 공통 편집까지 같은 disposable DB에서 통과했다. 그룹 실제 HTTP 19건, 전환 잠금 경합 10건, 합산 경합 2건, 재고 경합 4건과 공통 편집 경합 5건을 포함한다. 통합 결과 (`output/group-integration-final-20261014/financial-group-combined-result.json`)는 원본 전체 migration 원장 보존과 복제 DB 제거를 확인한다. 앱 전체 단위 테스트 8,923건, typecheck와 로컬 전용 환경 빌드도 통과했다.

검증한 migration 네 개를 OWN·FRESH·CANON 로컬 검증 환경에 순서대로 적용했다. 각 환경의 기존 업무 테이블 268개의 행, 기존 migration 본문, owner·ACL·RLS를 보존했고 새 스키마·권한 등록과 DB별 검증 해시를 커밋 전후 확인했다. OWN (`output/group-named-qa-20261014/plan-e79bc0109cf34823be7d7028871b9783/own-apply-result.json`), FRESH (`output/group-named-qa-20261014/plan-e79bc0109cf34823be7d7028871b9783/fresh-apply-result.json`), CANON (`output/group-named-qa-20261014/plan-e79bc0109cf34823be7d7028871b9783/canonical-apply-result.json`). 최초 적용 도구의 이름 해석 오류는 전체 롤백·보존 재조회 후 수정했으며, 수정 도구의 실제 적용 및 해시 위조 거절도 복제 DB에서 검증했다. 적용된 SQL 본문은 이 과정에서 변경하지 않았다.

실제 관리자 화면에서 3개 옵션 중 2개 전환, 확정 응답 유실 후 결과 재조회, 그룹명·순서 수정, 공통정보 저장, 그룹 해제와 기존 상품 재구성, 목록 행 펼침과 개별 편집 진입을 확인했다. 공통정보 저장 완료 안내가 새로고침 뒤 사라지던 문제와 그룹 해제 뒤 남던 공통정보 링크를 수정하고 회귀 검증했다. 390px에서 페이지 가로 넘침 없이 내부 표를 스크롤할 수 있다.

로그아웃한 공개 상세에서 빨강·파랑 상품 이동과 그룹 후기 1건을 확인했다. 기존 구매 당시 상품명·파랑 옵션은 그대로 표시된다. 정상 로컬 구매자 세션의 주문서는 빨강 1개·파랑 2개에 상품금액 34,000원, 복수구매 할인 3,000원, 배송비 6,000원, 최종 37,000원을 표시했고 합산 4개는 주문당 최대수량으로 차단했다. 이 확인에서 추가 주문·결제는 만들지 않았다. 최종 재조회와 화면 해시 (`output/group-browser-qa-20261014/final-browser-readback.json`)는 현재 가격 10,000/12,000원, 판매 재고 7/11개와 미선택 보관 재고 13개, 과거 주문·품목·후기 해시 보존을 포함한다.

검증 뒤 그룹을 정상 해제하고 상품·IP를 비공개로 바꾸었다. 재고가 남은 상품의 보관 RPC가 `good_has_stock`으로 거절되어, 재고를 없애지 않고 비공개 초안으로 보존했다. 출고지는 비활성화했고 합성 계정 2개의 권한·세션·자격증명을 정리했다. 정리 결과 (`output/group-browser-qa-20261014/retirement-result.json`)는 기존 284개 업무 테이블의 기존 행, 전체 migration 원장·본문, 전역 설정, 합성 주문·후기와 재고 총 31개 보존을 확인한다. 임시 서버 정리 (`output/group-browser-qa-20261014/runtime-cleanup.json`)도 완료했다.

- 소유한 disposable DB에서 기능·권한·세션·멱등·실제 PostgREST 오류 상태를 검증한다. 기존 개발 DB를 reset하지 않는다.
- 같은 옵션 중복 전환, 재고 조정/주문 생성과 전환의 양방향 경합, ERP 충돌, KC·공개 전환, 중간 실패의 전체 rollback을 검증한다.
- 전환 전후 합산 재고와 과거 주문·환불·리뷰·감사 행을 대조한다. 이후 반품과 교환을 실행해 실제 재고 귀속까지 검증한다.
- 실제 관리자 화면의 선택·비교·확정·재조회·실패 복구·390px, 공개 상세 이동과 리뷰 집계를 검증한다.
- 합성 자료는 정상 운영 경로로 판매 중지하며 재고가 없는 경우에만 보관한다. 기존 전역 설정과 다른 작업의 자료를 보존한다. 운영 전환·배포·외부 거래는 실행하지 않는다.
