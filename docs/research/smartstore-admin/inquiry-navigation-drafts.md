# 고객문의 상세 이동과 미저장 문구 복구

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

고객문의 목록의 제목 모달과 문의번호 전용 상세에서 이전·다음 문의로 이동한다. 상태·유형·접수일·검색 대상/검색어·목록 수를 그대로 유지하며, `admin_search_inquiries`의 미답변 우선·대기 시작/최근 메시지·ID 순서를 사용한다. 페이지의 처음/마지막에서는 같은 RPC로 인접 1행을 읽는다. 현재 문의가 응답 후 필터에서 빠지거나 현재 페이지에 없으면 잘못된 순번을 표시하지 않고 이동을 비활성화한다. 목록과 경계 조회 사이의 동시 변경으로 현재 ID가 다시 반환돼도 자기 자신으로 연결하지 않는다.

작성 중인 답변과 내부 메모는 계정·로그인 세션·문의·입력 종류별로 분리한다. 상품 편집용 `localStorage` 자동저장과 별개인 `sessionStorage`를 사용하며, 새로고침·페이지/문의 이동 후 **초안 복구**를 눌러 되살린다. 기존 고객 메시지·주문 정보·첨부파일·토큰은 저장하지 않는다. 첨부파일은 다시 선택해야 한다. **초안 버리기/작성 문구 지우기**, 답변 발송·내부 메모 저장 성공은 해당 초안을 지운다. 발송 실패에는 문구를 보존한다.

복구 유효기간은 마지막 편집부터 24시간 미만이다. 이는 저장소의 시간 기반 자동삭제를 의미하지 않는다. 만료·손상된 값은 다음 문의 진입이나 복구 검사에서 제거되며 브라우저의 탭 세션 종료 시에도 정리된다. 새 로그인은 같은 계정이어도 이전 로그인 세션 초안을 복구하지 않는다. 서버 액션 로그아웃은 브라우저 SDK 인증 이벤트가 오지 않을 수 있어 어드민 Header와 공개 화면의 공통 로그아웃 처리에서 먼저 CS 초안을 지운다. 본문·사용자 ID·토큰이 없는 동일 출처 BroadcastChannel/스토리지 신호를 받아 다른 탭도 자기 `sessionStorage`를 정리하고 열린 편집기를 잠근다. 로그아웃 요청 자체가 실패해도 이미 지운 초안은 복구되지 않는다. 브라우저 저장소를 사용할 수 없으면 편집은 가능하나 복구가 안 된다는 안내를 표시한다.

## 검증

- 2026-10-13 격리된 로컬 합성 문의 22건으로 Chrome의 모달 20/22↔21/22, 전용 상세 페이지 경계, 모든 조회 조건 유지, 답변/내부 메모 분리, 새로고침 후 명시 복구를 확인했다.
- 내부 메모 저장 성공 후 해당 입력·저장소가 비고 답변 초안은 남는 것을 확인했다. 고객 답변·메일은 발송하지 않았다.
- 다른 계정과 원래 계정 재로그인 시 복구 버튼 0개·빈 답변, 다른 탭에서 로그아웃 시 두 탭의 CS 저장소 0개와 편집 비활성화를 확인했다.
- 390px 화면에서 document clientWidth/scrollWidth 모두 390px, 열린 문의 모달 clientWidth/scrollWidth 모두 358px였다.
- 도메인·기존 상세·인증 경계 테스트 37개, 관련 ESLint, 전체 typecheck 통과. 실제 QA manifest (`output/inquiry-drafts-qa-20261013/manifest.json`).

일반 고객문의 템플릿 편집 초안과 공개 상품문의/리뷰 답변의 새로고침 복구는 2026-10-14 [CS 편집 초안 복구](cs-editor-drafts.md)로 확장했다. 두 저장소는 같은 로그아웃·계정 전환 정리 신호를 따른다. 원본 네이버 고객문의에 답변을 쓰거나 전송하지 않았다.
