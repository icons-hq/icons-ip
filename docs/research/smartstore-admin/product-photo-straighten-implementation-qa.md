# 상품 사진 자동 수평 — 계산·좌표 계약과 검증

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14. 원본 자르기·회전 도구 조사 (`output/smartstore-reference-20261012/product-photo-tools.json`)의 자동 수평 버튼을 일반적인 로컬 직선 방향 추정으로 구현했다. 원본 서비스의 내부 알고리즘·적용 결과는 확인되지 않았으므로 동일 알고리즘이라고 표현하지 않는다. 얼굴·물체·수평선의 의미를 인식하거나 생성 모델을 호출하지 않는다.

## 선택과 원복

색상 보정의 ‘자동 수평 맞춤’은 수정 전 원본의 직선 방향으로 보정 각도를 제안·적용한다. 사용자는 결과를 보고 ‘수평 보정 각도’에서 −15~15도를 0.1도 단위로 직접 조절하거나 ‘수평 보정 해제’로 0도로 돌린다. 기울일 때 빈 모서리가 생기지 않게 중앙을 확대하여 가장자리를 잘라내고 기존 캔버스 크기는 유지한다. 기존 사각 자르기의 비율과 좌표는 유지한다.

분석 결과가 애매하거나 선이 부족하면 현재 각도를 유지하고 직접 조절하라는 안내를 보여준다. 이미 수평에 가까우면 0도로 맞춘다. 필터·수동 보정·기존 레이어·crop을 초기화하지 않는다. 같은 원본에서 자동 분석을 반복해도 이전 결과에 추가 회전하지 않는다. ‘원본 보기’·전체 재설정·취소·완료 후 상품 저장은 [사진 편집 계약](product-photo-editor-implementation-qa.md)을 따른다.

## 분석 입력과 계산 경계

[분석 모듈](../../../lib/admin/photo-editor-straighten.ts)은 브라우저에서 디코드한 원본을 종횡비를 유지한 최대 640px 표본으로 읽는다. EXIF 방향을 반영한 원본이며 색조·마스크·crop·로고·텍스트가 들어간 미리보기를 입력으로 사용하지 않는다. 완료한 분석 결과만 편집 세션에 캐시한다.

밝기 표본에서 Sobel 방향 성분을 구한 뒤 수평·수직에 가까운 에지를 골라 가중 Hough 투표를 한다. −15~15도의 0.5도 후보를 검사하고 인접 최고점으로 보간하여 0.1도로 반올림한다. 가까운 최고점 주변을 제외한 경쟁 후보와 전체 중앙값을 비교해 방향이 명확한 경우에만 적용한다. 표본의 짧은 변이 24px 미만이거나 에지가 부족한 경우, 후보가 허용 범위 끝에 있는 경우, 자동 보정을 위한 확대가 1.5배를 넘는 경우는 무적용이다. 이는 알고리즘의 휴리스틱 경계이며 실제 상품의 의미상 수평을 보증하지 않는다.

표본의 alpha 128 미만인 3×3 주변은 선 근거에서 제외한다. 따라서 투명하게 잘라낸 사진의 외곽선을 사진 속 수평선으로 간주하지 않는다. 원본 분석은 렌더와 같은 큐에서 실행하고 행·각도 후보 사이에 양보·취소를 검사한다. 취소한 분석과 세션 종료 후 결과는 각도나 파일로 반영하지 않는다.

## 합성 좌표와 레이어

90도 회전·반전을 적용한 전체 캔버스 크기를 `W,H`, 수평 보정 각도의 절댓값을 `a`라고 하면 빈 모서리를 덮는 확대율은 다음과 같다.

`zoom = max(cos(a) + H/W × sin(a), cos(a) + W/H × sin(a))`

원본 해상도에서 색조·수동 보정·효과·모자이크·로고·텍스트를 합성한 뒤, 90도 회전·반전 → 중앙 기준 수평 보정·확대 → 기존 사각 crop을 적용한다. 테두리·기하 마스크는 crop 후 최종 캔버스 기준이다. 출력 크기·400만 픽셀 한도는 늘어나지 않는다. 확대와 임의 각도의 재표본화는 브라우저 Canvas 보간을 따른다.

레이어는 계속 원본 픽셀 좌표로 저장한다. 미리보기의 선택 윤곽과 드래그·방향키 입력은 같은 변환과 역변환을 사용한다. 사각 레이어는 네 꼭짓점, 원 모자이크는 48개 원주점을 변환해 표시하므로 임의 각도에서 축 정렬 사각형으로 잘못 표시하지 않는다. 좌우·상하 반전은 수평 보정 각도의 부호도 바꿔 사용자가 보는 전체 사진을 반전한다. 자동 분석의 각도 역시 현재 두 반전의 홀짝에 맞게 부호를 바꾼다.

임의 각도를 적용한 사진의 경계·텍스트·레이어에는 보간에 따른 변화가 생길 수 있다. 다른 브라우저의 보간 픽셀까지 동일하다고 보장하지 않는다. 원본 저장 객체는 수정하지 않는다.

## 검증 상태

최종 사진·가이드 관련14파일372테스트, 변경 ESLint와 전체 타입검사가 통과했다. 분석·크기·각도 validation, 수평/양방향/불명확/범위 초과 표본, 역변환·회전·반전·crop, 분석 캐시·큐·취소, 레이어 윤곽과 수동 UI를 검사한다. 최종 소스·증거 manifest (`output/product-photo-filters-qa-20261014/ui-manifest.json`)에 실제 runtime의14파일과 결과를 SHA-256으로 묶었다.

**실제 Chrome PC·390px에서 양방향 자동 보정, 반복 실행, 레이어 좌표, 저장·재열기,4MP·취소를 검증했다.** 실제 자동 보정 기록 (`output/product-photo-filters-qa-20261014/ui-auto-results.json`)에서 합성 +6도/−6도 격자는 각각−6도/+6도로 맞춰졌고 반복해도 동일한 PNG였다. 평탄색은 직접 설정한3도를 유지하고 선 부족 안내를 보였다. 사전 순수 계산과 구분한 실제 앱 결과다.

독립 레이어 검산 (`output/product-photo-filters-qa-20261014/independent-layer-geometry-result.json`)은 원 모자이크48점과 로고 네 꼭짓점을 자체 affine 식으로 대조했다. 네 윤곽의 정규좌표 최대 차이는3.33×10⁻¹⁶이며 Shift+방향키의 표시상 이동은 원본 정수좌표 반올림 허용 안에서 일치했다. 기존 레이어와 crop을 둔 채 필터·자동 수평을 바꿔도 원본 필드는 보존했다. 회전/반전/각도/crop 뒤 저장한220×260 PNG는 재열기 결과와 모든 RGBA가 같다.

픽셀 검산 (`output/product-photo-filters-qa-20261014/independent-pixel-result.json`)은 제품 코드를 import하지 않는 역변환·색조·도형 거리 계산을 사용한다. 로고/텍스트 경계와 Canvas 보간 경계를 별도로 제외하고, 정방형4MP 결과까지 검사했다. 4MP+1MP 로고의 실제 성능·인코딩 시작 후 취소·모바일 footer 수정과 fixture/runtime 정리는 [공동 최종 QA](product-photo-filters-implementation-qa.md)를 따른다. 불명확한 실사진의 의미상 수평, 운영 배포, 브라우저 간 경계 픽셀 동일성은 검증 범위 밖이다.
