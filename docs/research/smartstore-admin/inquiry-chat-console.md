# 실시간 상담 콘솔

migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

2026-10-20 로그인된 스마트스토어 `/#/talktalk/chat`의 대화 목록과 선택 대화 화면을 확인하고, ICONS의 기존 고객문의 데이터에 같은 상담 작업 흐름을 추가했다. 메뉴와 화면 이름은 **상담하기**(`/admin/cs/chat`)다. 네이버 톡톡 계정·메시지 서버·구매이력과 연결된 기능으로 표시하지 않는다.

## 화면과 처리

- 좌측: 대화 내용·닉네임·문의번호 검색, 전체·대기·진행중·완료, 담당자·최근 1주일/1개월/전체·읽음 여부·최신/오래된 대화순 필터, 안읽은 메시지 집계, 페이지 이동.
- 중앙: 고객과 운영자의 좌우 말풍선, 시스템 안내, 서명된 첨부 이미지, 사진 첨부, 기존 답변 템플릿을 사용하는 자주 쓰는 문구, 답변 전송, 확인 후 상담완료.
- 우측: 실제 문의 제목·유형·접수/첫 답변 시각, 담당자 변경, 권한 있는 구매이력/연결 주문, 태그 추가·삭제, 같은 고객의 최근 20개 이전 대화, 고객에게 보이지 않는 내부 메모. AI 요약이나 추정 태그는 생성하지 않는다.
- 작은 화면: 대화 선택 전 목록, 선택 후 대화를 우선 표시하고 목록 복귀를 제공한다. 고객 정보와 내부 메모는 대화 아래에서 이어서 볼 수 있다.

`open`은 답변을 기다리는 대기, `answered`는 운영자 답변 후 추가 질문을 받을 수 있는 진행중, `closed`는 기존의 재개 불가 종결 계약에 해당하는 완료다. 조회와 표시만 새 콘솔이 소유하고 답변·이미지 검증·담당자 변경·내부 메모·종결은 기존 `inquiry-actions`와 RPC를 공유한다. 답변 전송은 기존 인앱 알림·이메일 계약을 유지하며, 상담완료는 답변 전송과 분리한다. 운영자별 세션 초안과 답변 템플릿 복구를 재사용한다.

## 검색·읽음 계약

`admin_inquiry_chat_console`은 현재 `cs.manage` 권한을 검사한다. 검색은 제목·고객 닉네임·문의번호·고객/운영자/시스템 대화 본문에 적용하고 내부 메모는 검색 대상으로 섞지 않는다. 담당자와 마지막 대화 시각 기준 기간을 먼저 적용한다. 그 범위의 상태별 건수와 안읽은 고객 메시지 수를 반환하고, 선택 상태·읽음 필터·정렬을 적용한 다음 페이지를 자른다. 기본 최근 1주일은 현재 시각으로부터 7일이다. 목록은 30건 단위다.

읽음은 `private.inquiry_chat_reads(actor_id, message_id)`에 운영자별로 저장한다. 대화창이 실제 표시된 탭에서 렌더된 고객 메시지 ID만 `/api/admin/inquiry-chat/read`로 보낸다. 서버는 같은 출처·로그인·`cs.manage`·현재 화면의 운영자 ID를 확인하고, DB는 모든 메시지가 지정 문의의 고객 메시지인지 확인한 뒤 멱등 기록한다. 메시지를 읽은 시각만으로 처리 범위를 넓히지 않으므로, 조회 이후 도착한 메시지는 타임스탬프나 UUID 정렬이 같아도 안읽음으로 남는다. 다른 운영자의 읽음 상태는 바꾸지 않는다.

읽음 원장은 고객에게 공개하지 않으며 본문·이메일·연락처를 복제하지 않는다. 고객 메시지 또는 운영자 계정 삭제 시 FK cascade로 정리된다. private 테이블은 RLS를 켜고 모든 클라이언트 역할의 직접 접근을 차단한다. 두 RPC만 인증된 운영자의 해당 업무 권한을 검사해 접근한다. 읽음 저장은 고객 알림·이메일을 만들지 않는다.

태그는 운영자가 명시적으로 입력하는 1~20자 문구이며 대화당 최대 10개다. `private.inquiry_chat_tags`에 저장하고 `admin_update_inquiry_chat_tag`는 현재 운영자 바인딩·`cs.manage` 검사·문의 행 잠금 뒤 해당 태그의 추가/삭제만 수행한다. 같은 의도의 재시도는 중복 저장이나 중복 감사를 만들지 않는다. 상담 상태·기다린 시간·고객 메시지는 바꾸지 않는다. 태그 검색도 페이지를 자르기 전에 적용한다. 이전 대화는 동일한 `user_id`의 다른 문의만 반환하며 다른 고객 대화나 주문정보를 합치지 않는다.

## 배포와 검증

앱 코드와 `20261020085524_inquiry_chat_console.sql`, `20261020085526_inquiry_chat_tags_and_history.sql`을 함께 적용해야 한다. 읽기 RPC가 없거나 응답이 유효하지 않으면 정상 빈 상담함으로 표시하지 않고 조회 실패를 반환한다. 운영DB 적용은 별도 승인 범위다.

관련 자동 검증은 `lib/admin/inquiry-chat.test.ts`, 읽음 API 테스트, 화면 렌더 테스트, 기존 답변/템플릿 회귀, `supabase/tests/inquiry_chat_console.sql`이다. SQL은 격리 DB에서 실제 역할로 검색·정렬·페이지·담당자·읽음 분리·미표시 메시지 보존·권한·최소 ACL을 검증하고 전체 fixture를 rollback한다.

외부 네이버 톡톡 연결, 네이버 자체 구매이력, AI 요약과 파일 일반 첨부는 구현하지 않는다. 사진은 기존 문의 첨부 계약을 따른다. 개인정보가 있는 네이버 원본 상담 화면과 메시지는 합성 fixture나 저장소 증거로 복제하지 않는다.
