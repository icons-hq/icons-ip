이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14 KST. `hero` 큐레이션의 등록 한도, 제목·내용, 이미지 대체텍스트, 링크 없음을 보완했다. OWN/FRESH 격리 DB와 별도 로컬 런타임 `4322`에서 검증했다. 운영·Preview에는 적용하지 않았다.

## 원본에서 확인한 계약

- 기존 원본 캡처 `output/smartstore-reference-20261012/store/218-display-promotion-edit.jpg`는 프로모션 이미지 최대 10장과 비노출 항목도 유지하는 등록 목록을 보여준다. `228-display-banner-alt.jpg`는 링크 없음, 대체텍스트 설정, 화면 문구를 각각 분리한다.
- 14일 로그인된 원본의 활성 8번째 배너를 새 탭에서 다시 읽었다. 저장된 화면 제목·내용은 공란이고, 이미지 배너는 미리보기에 노출됐다. 제목은 40자, 내용은 150자·최대 3줄이며 DOM의 `required`는 false였다. 대체텍스트를 펼치면 별도 제목 40자·내용 150자가 나타나고 이 입력에도 필수 속성이 없었다.
- 추가 원본 증거는 `output/home-promotion-banner-qa-20261014/source-fields.json`, `source-alt-fields.json`과 같은 이름의 캡처다. 입력 설정을 펼치는 범위만 조사했으며 원본 저장·적용은 실행하지 않았다.

## 구현 계약

- 프로모션 배너는 비노출·예약·종료를 포함해 등록 10개까지 허용한다. 새 배너와 다른 종류에서 배너로 바꾸는 저장에 DB의 공통 개수 잠금을 적용한다. 기존 배너가 10개를 초과하더라도 수정·비노출은 허용하며, 공개 소비자는 기존 정렬 순서대로 활성 배너 최대 10개를 표시한다.
- 배너의 제목·내용은 선택항목이다. 새로 입력하거나 바꾼 제목은 40자, 내용은 150자·최대 3줄이다. 기존 120자 제목·200자 내용은 이전 저장값과 같을 때만 그대로 유지한다. 브라우저 표시와 DB 검사는 유니코드 코드포인트 기준이며, 새 textarea 값의 CRLF는 LF로 정규화한다. 변경하지 않은 기존 긴 내용은 숨은 원문을 인코딩해 전송하고 실제 DB 이전값 비교를 통과한 경우에만 보존한다.
- 대체텍스트 설정과 별도 제목·내용을 payload에 저장한다. 설정함의 공란도 허용한다. 설정을 끄면 과거 대체텍스트 입력은 저장하지 않는다. 공개 이미지의 `alt`에 제목·내용을 전달하며 화면의 제목·내용과 섞지 않는다.
- `link_path=null`은 배너만 허용한다. 이 배너는 `a` 요소나 가짜 링크를 만들지 않는다. 이미지 전용 배너는 빈 제목·카피·그라데이션을 추가하지 않으며, 링크가 있으면 비어 있지 않은 접근 가능한 이름을 제공한다. 다른 큐레이션 종류는 제목과 안전한 내부 링크의 기존 필수 조건을 유지한다.
- PC·모바일 이미지, 기존 크롭 비율·자동 넘김·모션 및 포커스 제어를 유지했다. 관리 화면의 미리보기와 공개 홈은 같은 배너 모델·렌더러를 사용한다. 링크가 없는 배너는 커뮤니티·카드 리워드 목적지 필터에서 제거하지 않는다.
- 새 편집기는 `admin_save_home_curation`으로 저장본 `updated_at`을 원자적으로 비교한다. 충돌하면 입력을 유지하고 저장을 잠그며, 운영자가 최신 저장본을 명시적으로 불러온다. 결과가 불명확하면 최초 FormData와 operation ID를 보존해 같은 요청만 재확인한다.
- 기존 13인자 `admin_upsert_home_curation`은 이전 호출 계약과 멱등 영수증을 유지한다. 두 공개 RPC는 권한·감사·아트워크 claim 처리를 같은 비공개 구현에 위임한다. 권한의 현재 상태를 멱등 영수증보다 먼저 검사한다. 기존 API 호출은 저장본 시각 비교를 요구하지 않으며 새 편집기에서 CAS를 적용한다.

## 실제 검증

- 관련 8개 파일 **176개 테스트**, 대상 ESLint, 전체 `tsconfig.test.json` 타입검사, 변경 diff 공백 검사를 통과했다.
- OWN/FRESH에서 기능 SQL과 권한 계약 검사를 롤백했다. 40/150 유니코드 경계, 선택형 공란, 잘못된 대체텍스트, 링크 없음, 다른 종류의 필수 제목/링크, PC·모바일 claim, CAS, 과거 동일 요청의 무변경 재생, 권한 철회 후 재생 거부, 비노출 포함 10개와 한도에서의 기존 수정에 통과했다. 기존 postgres 소유 RPC에서 새 helper를 실제 호출하는 회귀도 포함한다.
- 적용 전 복제 DB에서 기존 **11개 배너와 120/200자 문구**를 준비한 뒤 마이그레이션을 실행했다. 기존값·비노출·이전 RPC 재생이 보존되고 신규 추가와 변경한 긴 문구는 거절되는 것을 양쪽 복제에서 확인했다.
- 서로 다른 실제 DB 연결 9개 경합에서 `pg_blocking_pids`로 대기를 관찰했다. 동일 요청, 생성·수정 CAS, 링크 제거와 옛 저장, 권한 철회 전후 저장·재생, 9→10 추가, RPC와 권한 있는 직접 writer의 개수 경합이 모두 통과했다. 후속 오류 코드 변경 뒤 FRESH 복제 9개도 다시 통과했다.
- 기존 `home_curations`, `home_curation_latest_goods`, `home_sales_and_review_curations`, `home_product_mosaic` SQL을 FRESH의 명시적 legacy-fixture wrapper로 실행해 모두 통과했다. 기존 RPC 내부 문자열 검사는 wrapper 위임과 공용 구현의 잠금을 함께 검사하도록 갱신했다. 테스트용 lease·trigger는 종료 시 제거했다.
- 실제 Chrome에서 문구·대체텍스트·링크 없음 저장 후 DB와 공개 DOM을 다시 읽었다. textarea 150자 안에 줄바꿈이 있는 경우에도 DB가 LF 150자로 저장했다. PC와 390px에서 실제 `currentSrc`가 각각 다른 이미지이고 로드가 완료됐다. 링크 없는 배너의 anchor는 0개였다.
- 두 창의 저장 충돌에서 기존 입력이 보존되고 버튼이 잠겼다. 명시적 다시 불러오기는 먼저 저장된 문구로 복구했다. 모바일에서 문구와 대체텍스트를 해제해 이미지 전용 배너를 저장했다. 링크를 다시 지정하면 공개 DOM에 `프로모션 배너 1 보기`라는 이름이 생겼다.
- 10개 등록에서 새 배너 선택이 비활성화되고, 기존 배너의 수정·비노출은 저장됐다. 390px 관리·공개 화면의 문서 폭은 380px로 페이지 가로 넘침이 없었다. 비노출은 페이지의 상품 영역 로딩 완료까지 확인한 뒤 배너 0개를 검사했다. 최초 로딩 중 캡처는 최종 증거로 사용하지 않았다.
- 배너 합성행·관련 감사행·업로드 claim·Storage 복사본을 모두 정리해 각각 0건을 확인했다. 복제 DB, 소유 브라우저 탭과 기기 크기 설정도 정리했다. 기존 공용 이미지와 다른 작업의 fixture는 보존했다.

## 실제 브라우저에서 발견하고 수정한 충돌 응답

첫 마이그레이션은 stale CAS를 SQLSTATE `40001`로 반환했다. 로컬 PostgREST 14.14가 같은 요청을 반복 실행해 화면에는 결과 불명확 상태가 남았다. 데이터 덮어쓰기는 발생하지 않았다. [Supabase 공식 장애 문서](https://supabase.com/docs/guides/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions-77326b)와 DB 반복 로그로 원인을 확인했다.

이미 적용한 원문은 유지하고 후속 마이그레이션에서 해당 업무 충돌만 `PT409`로 바꿨다. 열어 둔 화면의 같은 요청 재확인은 0.484초의 도구 호출 안에서 충돌 안내까지 반환했고 입력은 유지됐다. 최종 기능 SQL은 메시지뿐 아니라 `PT409` 자체를 확인한다.

| `20261020085316_home_promotion_banner_settings.sql` | `1c9d6fb398aa866904ebf43edd980db87229288890ad16dcfe89fc88ab4aabab` | 두 DB의 `statements[1]` 원문 일치 |
| `20261020085318_home_curation_conflict_response.sql` | `6951eedc96ca36b9a3768be81cbbcdb5e396703100bfbaa36cc54e70421fdcae` | 두 DB의 `statements[1]` 원문 일치 |

증거는 `output/home-promotion-banner-qa-20261014/`의 `ui-manifest.json`, `function-definitions.json`, SQL·동시성 로그, DB 재조회 JSON과 캡처에 있다. 다섯 관련 함수의 최종 정의 SHA·소유자·ACL은 양쪽 DB에서 일치한다.

## 남은 경계

- 실제 Chrome은 주매니저 세션에서 검증했다. 스토어 관리 권한이 없는 별도 브라우저 세션은 사용하지 않았고, 해당 거부·철회·동일 요청 재생은 SQL 및 액션에서 검증했다.
- 이 단위 후 [딤·텍스트색·배너 보관/복구](home-banner-style-archive-parity.md)를 추가 구현했다. 비노출은 등록 수에 포함하고 삭제한 배너는 제외하며, 복구는 한도 검사 후 비노출로 돌아간다.
- 콘솔의 번역 확장 HTML 속성 hydration 경고와 `chrome-extension://` 출처 TypeError는 별도 확장 노이즈로 기록했다. 운영·Preview 배포와 실제 스크린리더 기기 낭독 검증은 실행하지 않았다.
