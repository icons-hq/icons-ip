# 반품·교환 배송비 청구·입금·반환

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-16 사용자 승인 정책에 따른 일반 클레임 비용 업무다. 네이버페이 환불 차감이나 자동 계좌이체와 연결하지 않는다. 기존 주문 전체·전액 환불 계약과 운영 확인액 메모를 보존한다.

## 계약

- 정책 기본값은 꺼짐, 반품·교환 기본 안내 금액은 미설정이다. 설정을 켜도 개별 합의와 담당자 확인 없이는 청구를 생성하지 않는다. 안내 금액은 폼의 초깃값이며 적용 금액을 강제하지 않는다.
- 청구 시 금액·실제 납부 대상(원 구매자 또는 요청자)·고객 안내·고객 합의 근거·당시 법인계좌·정책 버전을 보존한다. 같은 요청의 활성 청구는 한 건만 허용한다. 주문 금액·배송비·결제·환불 원장은 변경하지 않는다.
- 상태는 입금 대기 → 고객 입금 알림 → 실제 입금 확인이다. 고객 알림은 수납이 아니다. 담당자만 전액·실제 시각·증빙 참조를 확인해 수납을 기록한다.
- 미입금 청구는 취소/면제할 수 있다. 받은 비용을 취소하거나 요청 철회·거부·유형/사유 변경이 있으면 반환 대기로 남는다. 취소된 청구의 뒤늦은 입금도 반환 대기다. 실제 송금 증빙 후에만 반환 완료로 바뀐다. 자동 송금·은행 조회를 하지 않는다.
- 새 청구를 꺼도 기존 수납 확인·취소·반환은 가능하다. 고객 계정 탈퇴 신청 뒤에는 새 청구를 막고 기존 반환 의무를 처리할 수 있다. 미입금·입금 알림·반환 대기는 계정 삭제 보류 의무이며 기존 법정 기록 저장소에 비식별 거래 요약을 보존한다. 연락처·은행 계좌·자유 입력 근거·세션은 이 요약에서 제외한다.
- 원 주문 환불에서 차감하거나 배송비 미입금 때문에 클레임 권리를 자동 차단하지 않는다. 실제 은행 거래와 창고·PG 연동은 별도 운영 확인이다.

## 화면·권한

- 반품/교환 목록 → 배송비 정책(`/admin/sales/claims/returns/fee-policy`), 입금·반환 목록(`/admin/sales/claims/returns/fees`) → 요청 상세.
- 목록은 상태별 건수·50건 페이지·요청 상세 연결을 제공한다. 고객 계좌·내부 합의 원문은 목록에 없다.
- 고객 주문 및 선물 화면은 종료된 요청까지 본인에게 청구된 전체 내역을 조회한다. 선물의 다른 납부 대상 비용과 내부 합의/거래 근거는 반환하지 않는다.
- 현재 로그인 세션·판매 관리 권한·대상 계정 잠금을 검증한다. 주문→배송→요청→청구 원장을 잠그고 요청/원장 버전 비교 및 작업 UUID로 중복을 막는다. 응답 불명 시 같은 요청으로 결과를 확인한다. 같은 작업의 고정 영수증으로 성공을 확인한 뒤 현재 청구를 다시 읽어, 그 사이 발생한 취소·반환 상태를 화면에 반영한다.

## 검증

- 격리 로컬 DB의 `claim_fees.sql`: 기본 꺼짐, 합의 청구, 중복 재조회, 고객 알림/수납 분리, 금액·시각 검증, 면제 후 늦은 입금, 반환, 사유 변경, 선물 납부자 격리, 내부 근거 비공개, 전체 주문 이력, 반환 목록, 계정 삭제 보류·거래 요약 및 삭제 신청 후 기존 반환 처리, 원 주문 금액 보존을 통과했다.
- `claim_fees_concurrency.py`: 동일 청구 12회가 한 원장·한 작업으로 귀결되고, 같은 버전의 입금 확인 8회는 1회 저장·7회 충돌로 끝난다. 주문 결제·배송비·환불 원장은 그대로다.
- 관련 앱/가이드 테스트 111개·타입 검사·ESLint 통과. 재시도 시 최신 상태 재조회, 조회 실패 시 같은 작업 유지, 서버 충돌·권한 오류와 구매자 전용 보고 경로도 검사했다.
- 실제 Chrome에서 정책 기본 꺼짐→합성 계좌 등록→정책 저장→6,000원 합성 청구→구매자 입금 알림→관리자 입금 확인→취소·반환 대기 목록→반환 완료의 5개 사건을 UI와 DB로 대조했다. 구매자와 관리자 PC/390px, 상태 필터·요청 상세 연결·표 내부 가로 스크롤을 직접 확인했다. 구매자에게 내부 상담 참조는 노출되지 않았다.
- 최종 원장은 `refunded`, 별도 비용 6,000원, 열린 비용 의무 0건이다. 원 주문은 배송 중·결제 완료·10,000원·배송비 0원·환불 원장 0건을 유지한다. 이 수치는 합성 검증이며 실제 입금이나 송금을 수행한 결과가 아니다.
- 근거는 `output/smartstore-full-admin-20261016/claim-fees-*` 및 `local-fee-*`. 운영 배포·운영 DB·실제 고객 청구·은행 송금은 수행하지 않았다.
