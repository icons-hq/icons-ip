# 판매방해 고객 복수등록

migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-13 현재 코드·원본 화면·소유 격리 환경 검수 기준. 운영 저장과 운영 DB 변경은 실행하지 않았다.

## 확인한 원본

`output/smartstore-reference-20261012/sales/09-black-consumer-clean-full.jpg`, `09-black-consumer-other.jpg`, `09-black-consumer-controls.json`에서 다음을 확인했다.

- 구매자 ID 또는 상품주문번호 입력 방식을 선택한다.
- textarea에 줄바꿈 또는 쉼표로 복수 대상을 입력한다. 1회 100개, 네이버 고객 ID 총 2,000개, 입력창 3,000자 안내가 있다.
- 공통 사유는 구매의사 없는 반복구매·언어폭력·영업방해·기타이며 상세 사유 입력이 있다.
- 등록, 조건 조회, 선택건 해제 진입점이 있다. 현재 관찰한 등록 표면에는 파일 업로드가 없다.
- 실제 등록/해제, 중복 입력 오류, 부분 실패 결과는 실행하지 않아 **원본 미확인**이다. 아래 사전확인·부분 결과 계약은 기존 ICONS 제한 원장을 보존하기 위한 구현 선택이다.

네이버 ID와 상품주문번호는 ICONS 회원 UUID/정확한 이메일, ICONS 전체 주문번호로 대응했다. 네이버 총 2,000명 제한은 기존 ICONS 원장에 없는 제공자 제한이므로 도입하지 않았다. 회원 UUID 100개와 긴 이메일 100개가 들어가도록 입력 상한은 26,000자이며, 각 식별자는 254자 이하다. 파일 업로드는 추가하지 않았다.

## 동작 계약

1. **대상 확인.** 입력 1~100개와 공통 사유·상세 근거를 서버에 전달한다. 동일 텍스트뿐 아니라 UUID/이메일 별칭, 같은 고객의 여러 주문도 중복으로 분류한다. 주문번호 모드는 소유자를 읽고 해당 주문을 근거로 남긴다. 이 단계는 실제 구매제한을 등록하지 않는다.
2. **행별 상태.** 등록 가능, 중복 입력(앞선 행 번호), 형식 확인, 미존재, 모호한 이메일, 운영 계정, 기존 구매제한을 구분한다. 이메일이 여러 회원과 일치하면 임의로 한 명을 선택하지 않는다. 공통 사유가 모든 등록 가능 고객에게 적용된다는 확인을 받는다.
3. **고정 입력.** private 요청 기록에 확인한 대상·사유·실행자를 저장한다. 입력을 수정하면 새 대상 확인이 필요하다. 확인한 운영자만 15분 안에 등록할 수 있으며 다른 운영자는 결과를 조회할 수 있다.
4. **실행.** 기존 단일 등록 RPC를 재사용한다. 등록 가능 고객의 주문 생성 advisory lock을 UUID 순서대로 잡아 다른 일괄 등록과의 잠금 순서를 통일한다. 제한 범위는 기존의 신규 굿즈 주문만이며 주문·결제·환불 원장, 로그인·티켓·게임, 계정 정지는 바꾸지 않는다.
5. **부분 결과.** 사전 제외 행은 등록하지 않는다. 확인 이후 기존 제한이 생기면 제외, 고객 자격 또는 근거 주문 소유자가 달라지면 미등록으로 남기고 나머지 정상 대상은 등록한다. 예상하지 못한 DB 오류는 그 실행 전체를 롤백하며 성공으로 표시하지 않는다.
6. **결과 재조회.** 등록 응답 뒤 별도 조회로 완료 기록과 현재 제한/해제 상태를 읽는다. 응답이 불확실하면 입력을 잠그고 같은 요청의 결과부터 조회한다. 결과 조회는 동일 요청의 진행 중 트랜잭션을 기다린다. 아직 prepared이면 같은 요청으로 다시 등록할 수 있다.
7. **재생과 해제.** 동일 요청은 저장된 결과를 재사용한다. 해제된 고객을 같은 등록 요청으로 다시 제한하지 않는다. 미등록 대상만 새로 확인할 수 있으며, 기존 제한의 사유를 덮어쓰거나 자동 해제하지 않는다. 결과 링크로 같은 요청을 다시 열 수 있다.

## 선택 해제 확장 — 2026-10-13

원본 목록의 `선택건 해제하기`와 체크박스를 대응했다. 2026-10-13 추가 원본 열람에서 미선택 실행은 “해제할 정보를 선택해주세요.”로 거절됨을 확인했으며 실제 선택 해제는 실행하지 않았다. 현재 페이지에서 활성 기록을 최대100개 선택하고 공통 해제 사유·범위를 확인한다. 다른 담당자가 이미 해제한 기록과 찾을 수 없는 기록은 결과에서 구분하며, 이전 해제 사유를 덮어쓰지 않는다. 한 고객에게 나중에 새로 등록한 구매제한은 이전 요청 재실행으로 해제되지 않는다.
