# 혜택 리포트 구현·검증

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-12 조사·구현. 원본 `store/32-benefit-report-top.jpg`부터 `34-benefit-report-bottom.jpg`까지의 혜택이름·혜택종류·타겟팅 대상·기간·일주월·조회/초기화·결과표·엑셀 구조를 대응했다.

## 구현 범위

- 혜택/마케팅 → 혜택 리포트에서 쿠폰 ID/이름, 정액/정률, 첫 구매/재구매 대상, 시작일/종료일, 일/주/월과 직전 동일 기간을 조회한다.
- 발급수, 현재 결제가 유지되는 기간 사용수·할인금액·주문금액, 복구수, 같은 기간 발급 집단의 현재 사용률을 제공한다. 쿠폰이름은 기존 주문별 사용 상세로 연결하고, 발급수는 발급 ID·KST 일시·현재 결제 사용 집계 여부의 발급 상세로 연결한다. 선택 후 사용/발급 상세를 전환한다.
- 기간은 KST 양끝 날짜 포함·최대 366일이다. 주는 월요일 시작이며 일부 주·월은 조회기간 안의 사건만 합산한다. 검색 필터는 현재 쿠폰 정의 기준이다.
- 적립금 탭은 권한을 가진 관리자에게 실제 지급내역 콘솔을 연결한다. 쿠폰과 적립금을 같은 성과 산식으로 합치지 않는다.
- 엑셀은 화면 조건의 전체 결과를 내보낸다. 혜택·선택쿠폰 사용 상세·발급 상세 각각 10,000행 상한을 넘으면 조회조건 축소를 안내한다. 요약, 혜택별 현황, 추이, 비교 추이, 선택한 사용 상세, 조회 기준을 포함하며 발급 상세 선택 시 같은 조건의 전체 발급 시트를 추가한다.

## 검증

- 격리 DB 계약 테스트: 1,002장 집계로 1,000행 절단 없음, KST 자정 경계, 기간 전 발급분 사용, 결제 대기 제외, 기간 전 적용분의 복구, 문자 그대로의 `%` 검색, 할인종류 필터, 상세 총개수/페이지, 366일/무한 날짜 거부, 비staff·anon·service_role 실행 경계 확인.
- 실제 Chrome → 격리 Next 앱: 발급 2장·결제 사용 2건·쿠폰 할인 3,000원·주문금액 12,000원·복구 1건·발급 집단 사용률 50%를 DB와 대조했다. 이전 기간 발급 1장과의 비교도 일치했다. 사용 상세에서 결제 완료2/결제 대기1/복구1과 주문 링크를 확인했다.
- 실제 엑셀 다운로드를 재열어 같은 조회조건·2장·2건·3,000원·12,000원·사용률0.5를 확인했다. 모든 시트를 렌더링해 식별자 열 잘림을 수정했고, 수식으로 해석될 수 있는 이름도 문자열로 저장됨을 검사했다.
- 390px에서 화면 전환 애니메이션 종료 후 문서 가로 넘침 없음(문서380px/뷰포트390px), 표는 내부 스크롤. 데스크톱·모바일 증거는 `/tmp/icons-admin-ui-qa-20261012/benefit-report-real.jpg`, `benefit-report-mobile.jpg`다.

2026-10-14 발급 건별 읽기 상세의 로컬 DB·PC/390px·6개 실다운로드 45,050셀 대조와 권한 오류 복구를 추가로 확인했다. 최신 계약과 한계는 [발급 상세 구현·검증](coupon-issuance-read-detail-proposal.md)을 따른다.

## 남은 차이

원본의 상품중복/배송비 할인 쿠폰과 특정 고객그룹은 별도 구현할 기능이다. 발급기간과 사용기간 분리 및 발급일+N일 만료는 후속으로 구현·검증했으며 [쿠폰 기간 확장](README.md#쿠폰-기간-확장)을 따른다. 원본 빈 목록의 실제 행별 drilldown 결과는 해당 네이버 계정에서 확인할 데이터가 없어 직접 검증하지 못했다. 운영 배포·운영 DB 적용은 실행하지 않았다.
