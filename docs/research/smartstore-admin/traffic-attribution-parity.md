# 방문·유입·마케팅 링크 성과 계약

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

조사일은 2026-10-13 KST다. 실제 로그인된 [방문 분석](https://sell.smartstore.naver.com/#/insight/store-analytics/visit)에서 건수/고객수 조회와 마케팅링크 구분 열을 확인하고, [공식 스토어분석 가이드 공지](https://sell.smartstore.naver.com/#/center-notice/detail/200000859)에 연결된 2026-10-07 PDF를 읽었다. 원본 계정의 저장·링크 발급·발송은 실행하지 않았다. 원본 매출·고객 수치는 구현 데이터로 옮기지 않는다.

## 원본에서 확인한 일반 기능

- 1일·7일·30일·직접 기간, 직전·전년 비교, 건수/고객수, 채널·분류·상품·브랜드·최대 3단계 방문 경로, 지표 카드·순위·일/주/월 추이·표·엑셀을 제공한다. 고객수 모드에서는 직접 기간 및 표의 일별 확장이 제한된다. 공식 가이드 8~14쪽과 현재 화면을 대조했다.
- 방문 리포트는 상품 상세를 조회한 상품만 집계한다. 홈이나 쇼핑스토리만 보고 이탈한 경우는 방문수에서 제외한다. 상품 상세 직전 경로 중 구매 전 마지막 경로에 전체 판매성과를 배분한다. 마케팅링크 구분은 경로 안의 링크 유입 여부다. 공식 가이드 29~30·43쪽과 현재 표를 확인했다.
- 원본 상품결제건수는 주문이 아니라 상품 단위다. 총 판매금액·상품결제건수에는 이후 취소·반품도 포함되고 순 판매금액은 환불을 제외한다. 쿠폰 할인과 배송비는 원본 판매금액 산식에서 제외된다. ICONS의 실제 결제금액과 같은 숫자라고 가정하지 않는다. 공식 가이드 42쪽.

원본 증거와 해시는 `output/smartstore-reference-20261013/traffic-reference/manifest.json`에 있다. PDF 42~43쪽은 일부 표 머리글 글꼴이 로컬 렌더에서 누락되어, 읽히는 정의 본문과 실제 화면의 지표명을 함께 확인했다.

## 작업 시작 시 구현과 격차

`/m/[token]`은 조사 시작 시 공개 대상 확인 후 내부 화면으로 이동시키며 허용된 UTM 5개만 전달한다. 방문·클릭·전환 원장은 없었다. 기존 판매/고객 리포트는 주문·회원 원장으로 계산하므로 방문수의 대체 자료가 아니다. 가입 시점도 방문 시점으로 쓰지 않는다. 광고비 원장·외부 분석 연동도 없어 비용·ROAS를 계산할 근거가 없다.

## ICONS의 독립 측정 계약

1. **공개 이용과 선택:** 스토어 열람은 로그인 없이 유지한다. 별도 `analytics-v1` 안내에 동의한 브라우저에서만 수집하며 마케팅 정보 수신 동의를 분석 동의로 사용하지 않는다. 거부해도 구매와 공개 열람을 이용할 수 있다. 작은 설정/배너가 선택을 보존하고, 철회 즉시 추가 수집·주문 귀속을 중단하고 현재 세션을 폐기한다.
2. **최소 항목:** 공개 화면 유형과 대상 ID, 알려진 채널 분류, 발급된 마케팅 링크 ID, 서버 관측 시각과 짧은 임의 방문 세션만 보관한다. 전체 URL·referrer 쿼리·검색어·IP 주소·User-Agent·회원 ID를 수집하지 않는다. UTM은 알려진 source/medium 값만 정규화하며 campaign/term/content 원문은 저장하지 않는다.
3. **방문 단위:** 30분 동안 활동이 없거나 24시간 상한·KST 날짜 경계에 도달하면 새 방문 세션이다. 페이지 열람·상품 상세 열람·방문 세션을 구분한다. 같은 사람의 여러 브라우저·다른 세션을 연결하지 않으며 세션을 고유 고객수로 표현하지 않는다.
4. **링크와 귀속:** 사용 가능한 링크의 실제 목적지 페이지가 열린 관측을 링크 유입으로 센다. 프리패치와 HTTP 리다이렉트 요청만으로 클릭을 확정하지 않는다. 주문 생성 시 동의가 유지된 현재 세션의 마지막 외부/링크 경로를 본인 주문에 한 번 고정하며 다른 주문·세션으로 덮어쓰지 않는다.
5. **전환:** `payment_attempts`와 해당 `payments`, 서버 최종 확정의 `confirm_approved` 근거가 일치할 때만 결제 전환이다. 카드는 토스·코페이 승인, 무통장은 같은 주문·결제 시도의 `bank_transfer_confirmations`와 공통 finalizer의 승인 원장을 모두 요구한다. 입금 접수나 확인 필요 상태만으로는 전환을 만들지 않는다. 고객 성공 URL·콜백 payload·pending 주문은 전환 근거가 아니다. 해당 방문에서 주문을 만들고 7일 내 확정된 건을 방문일에 귀속한다. 주문 결제 건수·결제 전환 세션·전환율(전환 세션/방문 세션)·실제 결제금액·완료 환불금액을 분리한다. 금액은 배송비·할인·적립금이 반영된 실제 결제금액이며 원본 상품 판매금액과 산식이 다르다. 전액 적립금 등 실제 결제금액 0원 주문과 티켓 결제는 이 전환 리포트에 포함하지 않는다.
6. **보존과 미측정:** 사건·세션·주문 연결 원자료는 오늘을 포함한 한국 날짜 기준 최근 90일, 개인/주문/세션 식별자를 제거한 일별 집계는 13개월 보관한다. 원자료 보존 종료 시 집계는 최종 관측 시각을 함께 저장하고 그 이후의 늦은 환불까지 최신값인 것처럼 표시하지 않는다. 수집 시작 전·비활성·장애/관측 공백·보존 만료·미래는 0과 구분하며, 전년 비교도 같은 규칙을 적용한다.
7. **권한과 경계:** 운영 통계는 `stats.read`로 제한하고 원자료를 관리자에게 직접 반환하지 않는다. 수집/정리는 봉인된 서버 전용 RPC를 사용한다. 입력 크기·같은 출처·세션당/전체 속도·멱등 사건·세션 토큰 재생·공개 대상·주문 소유자·철회와 수집의 경합을 검증한다. 기존 결제 finalizer의 금전·재고 처리를 변경하지 않는다.

## 활성화와 현재 상태

기존 개인정보처리방침의 2026-08-22 공개 버전을 보존한다. 새 선택 동의 안내와 정책 반영 준비 문서를 별도로 만들며, 수집 설정은 기본 비활성이다. 격리 OWN/FRESH 검수에서만 명시적으로 활성화한다. 운영 정책 발행·운영 수집 활성화·외부 분석서비스 연결을 수행한 것으로 기록하지 않는다.

## 구현과 검증 결과

- `/admin/stats/traffic`, `/admin/stats/marketing`에 기간·직전/전년 비교·일/주/월 추이·항목 상세·한글 검색·엑셀을 연결했다. `stats.read`를 화면과 RPC에서 검사한다. 공개 페이지의 별도 선택 안내와 설정, 서버 소유 세션, 주문 생성 시 자동 연결, 보존 cron을 구현했다.
- `20261013104526`, `20261013113930`, `20261013115203`을 OWN/FRESH에 각 1회 적용하고 ledger의 전체 SQL SHA-256을 저장소 파일과 대조했다. 기본 비활성을 확인했고 OWN만 잠시 검수에 사용한 뒤 다시 비활성으로 돌렸다. FRESH는 계속 비활성이다. 운영 DB·정책 발행·운영 수집은 변경하지 않았다.
- 독립 검토에서 정상 전액 환불의 `payments.refunded` 포함과 철회 시 세션의 마지막 대상/토큰 해시 완전 삭제를 보강했다. 실제 취소 finalizer를 통해 gross 유지·완료 환불 증가·net 감소를 검증했다. IP의 공개 slug가 내부 ID와 다른 경우도 실제 변경 RPC와 관측 조회로 확인했다.
- SQL 회귀는 선택/권한/본인 주문/다른 세션 덮어쓰기/정확한 사건 재시도/미입금 제외/실제 결제 확정/철회/보존/속도 제한을 검증한다. 무통장은 실제 `admin_confirm_bank_transfer_deposit`에서 승인된 경우와 확인 기록이 있어도 `needs_review`인 경우를 구분한다. 별도 복제 DB에서 8개의 실제 잠금 경합을 관측했다.
- 실제 Chrome에서 거부 시 원장 0 → 별도 동의 → 마케팅 링크 목적지 → 다른 상품 상세 → 주문 생성 시 자동 귀속을 확인했다. 합성 카드 주문 4,800원과 무통장 주문 4,900원을 만들고 각각 서버 확정 경로를 거친 뒤, 같은 링크의 방문 1세션·결제 2건·실제 결제금액 9,700원·전환율 100%가 관리자와 엑셀에서 일치했다. 카드 승인 값은 합성 입력이며 외부 PG와 실제 송금은 실행하지 않았다.
- 전년 비교의 수집 전 기간은 미측정으로, 주별 날짜는 해당 주의 시작일로 표시했다. 한글 `소셜` 검색과 특정 마케팅 링크 상세, 실제 다운로드한 3시트 XLSX의 조회 조건/수치도 확인했다.
- 390px에서 관리자와 선택 안내의 가로 넘침이 없었고, 모바일 키보드로 철회했다. 이후 세션·사건·주문 연결은 모두 0, 두 주문은 결제 확정 상태를 유지했으며 다음 공개 방문도 수집되지 않았다. 모바일 에뮬레이션의 포인터 좌표가 다르게 전달되어 키보드 동작으로 검수했으며, 이를 터치 입력 검증으로 기록하지 않는다.
- 관련 Vitest 47개, 전체 TypeScript 검사와 대상 ESLint, OWN/FRESH SQL 및 권한 메타데이터 검사를 통과했다. 실제 브라우저에는 번역 확장프로그램이 HTML 속성을 추가하면서 생긴 hydration 경고가 있었으며 애플리케이션 오류와 구분했다.

실행 증거와 합성 금액, 최종 비활성·원자료 삭제 상태는 `output/smartstore-reference-20261013/traffic-analytics/manifest.json`과 `final-db-readback.json`에 있다. PNG는 직접 시각 검토하고 해시로 결속했다. 검수용 4331 서버는 종료하고 임시 복사본을 삭제했으며, 브라우저 크기와 생성 탭도 정리했다.
