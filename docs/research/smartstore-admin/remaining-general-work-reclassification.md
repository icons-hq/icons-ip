migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14. 기존 원본 캡처·빈 상품등록 양식·현재 코드만 읽어 재분류했다. 초기 재분류는 읽기 전용으로 수행했고 이후 독립 구현의 완료 근거를 해당 항목에 연결했다. 원본의 화면 존재, ICONS에서 같은 목적을 수행할 수 있는지, 추가 구현의 필요성을 각각 구분한다. 완료 링크가 없는 아래 후보는 착수·완료를 뜻하지 않는다.

2026-10-15 물류 운영 결정도 반영한다. 남양주·김포 담당자가 어드민의 창고 양식 엑셀을 내려받아 자체 WMS에 입력한다. 운송장 발급·회수 접수·배송추적 API와 운송사 이벤트 기반 배송완료 자동 동기화는 제외하며, 공급자 API·계약 확인을 후속 개발 대기로 두지 않는다. [현재 출고 파일·회신 등록](../../runbooks/warehouse-export.md)의 구현과 두 창고의 실제 WMS 수용 확인은 별도다.

## 우선 제안의 후속 완료: 판매상품 전체 결과 조회와 엑셀

**21위 이후 상품의 전체 조회·반출을 구현하고 로컬 검증을 완료했다.** 초기 대조에서 없던 경로를 별도 읽기 RPC·페이지·전체 XLSX로 연결했다. [계약과 검증](sales-goods-ranking-parity.md). 새 수집·고객 개인정보·금전 정책·외부 계약을 필요로 하지 않는다.

## 구현과 별개인 검증·결정

- [기존 카테고리별 상품·상단 전시](category-display-composition-proposal.md)는 분류/수동 연결·PC/모바일 배너·현재 상품 영상·추천상품의 구현과 로컬 검증을 마쳤다. 상품분류와 독립된 전시 이름·계층도 후속 구현했으며 실제 저장·공개/보관·동시 수정·응답 유실 복구와 기존 상품/ERP 보존을 확인했다. 원본의 모든 저장 분기까지 동일하다는 뜻은 아니다.

- [대표 이미지](store-profile-parity.md)와 [적립금 파일 입력](store-credit-parity.md)은 실제 Chrome 파일 선택·검증·PC/390px 검수를 마쳤다. 대표 이미지는 정상 CAS로 기존 이미지와 같은 바이트를 새 경로에 복원했고, 적립금 지급/회수는 실행하지 않았다. 이후 잠금을 해제한 Mac의 네이티브 Excel에서 암호화 반품 목록·거래확정 원본·재발급 파일 3개 (`output/smartstore-reference-20261014/encrypted-xlsx/native-excel-verification.json`)를 실제 열어 암호·시트·행수·금액을 대조했다. 이 세 파일 외 모든 워크북의 네이티브 검증까지 완료했다는 뜻은 아니다.
- 쿠폰 발급 건별 상세는 구현·로컬 검증을 완료했다. [해당 문서](coupon-issuance-read-detail-proposal.md)의 최신 결과를 따르고 새 미구현 후보로 중복 배정하지 않는다.
- [판매 후속](sales-remaining-scope.md)의 전체 주소/지역 변경, PG 실제 수집·은행/세무 원문과 외부 실행 계약은 해당 선행 조건을 유지한다. 물류는 창고 양식 엑셀 제공으로 범위를 확정했으며 운송사 API 계약·자동 발급/회수/추적을 미구현 필수 항목에 다시 넣지 않는다. 기존 일반·김포 21열·서원 7열의 출력·회신 등록 검증과 실제 남양주·김포 WMS 인수는 [런북](../../runbooks/warehouse-export.md)에 따라 구분한다. 2026-10-14 포함이 확정된 선물 주문·복수구매 할인·착불/수량별 배송비·정기배송은 공통 거래 계약·SQL·실제 고객/관리자 화면의 로컬 검증을 마쳤다. 실제 외부 결제와 운영 배포는 별도이며, 부분취소·부분반품의 확정 제외도 유지한다.
- 현재 자료에 누락이 없다는 전수 완료 판정은 하지 않는다. 확인하지 않은 원본 저장/모든 하위 상태를 완료에 넣거나, 추상적인 기능명을 근거 없이 구현 의무로 늘리지 않는다.
