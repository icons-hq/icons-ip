# 본문 공통 서식·개인 템플릿 구현과 검증

migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

검증일: 2026-10-14 KST. 상품 상세설명과 쇼핑스토리에 공통 서식과 본인 전용 템플릿을 연결했다. 검증은 명시한 로컬 DB와 OWN 4320에서 수행했으며 운영·Preview 배포는 하지 않았다. 증거 목록과 SHA-256은 manifest (`output/admin-body-template-qa-20261014/manifest.json`)에 있다.

## 편집 계약

- 공통 서식은 왼쪽/가운데/오른쪽 정렬, 12·14·16·20·24·32·40px, 굵게·기울임·밑줄·취소선, 인용 5종, 구분선 8종이다. `lib/content-format.ts`의 닫힌 `data-icons-*` 값만 허용한다. 임의 CSS·class·이벤트를 허용하는 기능이 아니다.
- 상품의 도구는 HTML 입력의 선택 범위에 안전한 조각을 넣는다. 스토리 정렬·크기는 커서 문단 또는 실제 선택 내용이 있는 문단에, 강조는 선택한 글에 적용한다. 강조 버튼은 적용형이며 같은 버튼으로 해제하는 토글은 아니다.
- 스토리의 블록 삽입은 선택 전·후 노드를 보존하면서 문단 최상위 경계에 넣는다. 다음 문단의 첫 글자 앞에서 선택이 끝나면 그 문단에는 서식을 적용하지 않는다. 인용 변환은 선택한 내부 글·서식·이미지를 보존한다.
- 전체 서식 편집에 브라우저 기본 실행 취소 이력이 유지된다고 보장하지 않는다. 개인 템플릿에는 별도의 직전 적용 되돌리기를 제공한다.
- 두 편집기의 저장·미리보기·공개 본문은 기존 허용 목록과 공통 서식을 함께 검사한다. 상품의 안전한 외부 링크·호스팅 이미지 규칙과 스토리의 내부 공개 링크·검증 업로드 이미지 규칙은 각각 유지한다.

## 개인 템플릿

한 운영자의 상품·스토리 편집기가 같은 개인 원장을 사용한다. 이름은 1~50자, 원문과 정리 후 본문은 각각 Unicode 30,000자 이하이며 글이 없는 본문은 저장하지 못한다. 모든 이미지, 문서 제목, 관련상품, 전시기간은 템플릿에 포함하지 않는다. 상품의 호스팅 이미지도 제외한다. 상품에서 보존한 외부 링크는 스토리에서 읽거나 적용할 때 제거하고 안내한다. 원장 자체는 읽기만으로 변경하지 않는다.

사용 중과 보관함을 합쳐 50개까지다. 삭제 대신 보관·복구를 제공하며 보관된 이름·본문도 수정할 수 있다. 보관된 항목은 문서에 적용할 수 없다. 한도에 도달하면 기존 항목을 수정해 재사용한다. 템플릿 선택·수정·저장만으로 문서 본문이 바뀌지 않는다. 선택 위치 삽입 또는 전체 교체를 명시적으로 실행해야 하며 전체 교체에는 별도 확인이 있다. 적용 뒤 다른 본문 편집이 없을 때만 직전 본문을 그대로 복구한다.

상품 HTML의 기존 한도는 UTF-16 길이 30,000이다. 따라서 이모지처럼 Unicode 문자 수와 UTF-16 길이가 다른 긴 개인 템플릿은 저장 가능해도 상품 적용에서 거절될 수 있다. 그때 기존 상품 입력은 유지한다.

템플릿 편집·불명확 요청은 새로고침/탭 닫기 경고로 보호한다. 같은 계정의 모달을 닫았다 다시 열면 편집을 유지한다. 계정·세션·문서 대상·기존 본문 또는 저장 중 상태가 바뀐 뒤 도착한 응답과 적용은 폐기한다. 단일 요청은 저장 후 목록 재조회가 끝날 때까지 유지한다. 확정 SQL 거절 외의 통신 오류와 알 수 없는 응답은 같은 operation과 payload로 확인한다. 저장 영수증은 받았으나 재조회가 달라지면 현재 편집을 보존하고 최신 저장본을 비교하게 한다.

## DB·서버 경계

`20261020085339_admin_body_templates.sql`의 고정 SHA-256은 `ec605b961ebc6426c0711d88c50bbeec571a57bc0803ec6cbc8fc3919ade8266`이다. 비공개 테이블 1개와 함수 12개를 추가한다. `auth.uid()` 소유자와 `expectedActorId`가 일치해야 하며 상품은 `catalog.manage`, 스토리는 `store.manage`를 각각 검사하는 8개 wrapper를 사용한다. 관리자도 다른 사람의 템플릿을 열 수 없다.

테이블 RLS와 직접 접근 차단, 함수별 네 롤 revoke 후 필요한 authenticated grant, 소유자별 quota 잠금, revision CAS, operation replay를 적용했다. 읽기는 STABLE·실제 읽기 전용 트랜잭션에서 동작하며 audit/advisory lock을 만들지 않는다. 공통 감사 로그에는 템플릿 이름·본문 대신 요청 SHA-256·ID·버전만 남긴다. DB의 최소 HTML 방어와 별개로 서버 읽기·쓰기 및 최종 적용에서 목적지별 sanitizer를 다시 사용한다. 템플릿 변경으로 상품·스토리의 미저장 폼을 재검증하거나 저장하지 않는다.
