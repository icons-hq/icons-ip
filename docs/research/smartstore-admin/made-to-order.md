# 주문제작 납기와 처리

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

사용자 확정: 운영자가 실제 제작 시작·완료를 기록하고 상품별 납기를 설정한다. 제작 시작 후에도 취소를 접수하여 검토한다.

## 계약

- 상품별 기본 꺼짐이며 1~365일, 달력일 또는 토·일/직접 설정한 휴무일 제외 기준을 설정한다. 자동 공휴일 조회는 없다. 결제 확인일 다음 날부터 계산하여 마지막 날 한국 시간 자정 전을 발송 예정 기한으로 표시한다.
- 주문서에 공개 안내와 납기를 표시하고 주문 품목에 당시 정책을 고정한다. 현재 상품 설정 변경은 기존 주문·교환 재제작의 납기를 바꾸지 않는다. 예약판매와 동시에 설정할 수 없다.
- 실제 결제 승인 근거가 있는 주문만 시작·완료할 수 있다. 주문/배송/클레임/제작 잠금, 현재 운영자·세션·권한, 수정 버전과 요청 UUID로 중복 처리와 오래된 요청을 차단한다. 기록 시각은 잠금을 획득한 이후의 서버 시각이다.
- 제작 완료 전 출고 파일 생성·출고 표시·발송·교환 재출고를 차단한다. 완료는 발송 처리와 별개다. 목록의 제작 건수·완료 건수·예정일을 표시한다.
- 발주확인 후에도 발송 전 주문제작 취소를 접수할 수 있다. 제작 시작 후 접수는 자동 환불하지 않으며 검토 중 제작 진행을 차단한다. 일반 주문의 취소 범위는 보존한다.
- 교환의 전체 실물 회수 이후 별도 재제작 작업을 생성한다. 원 제작 이력은 보존하고 재제작 완료 후 재출고한다.
- 고객 조회에서 내부 작업 근거·운영자·세션을 제외한다. 계정 삭제 시 거래 근거로 보존하는 구조화 요약에서도 자유문구를 제외한다.

## 검증

- 격리 SQL: 납기/휴무일, 주문서 변경 감지, 원 계약 고정, 결제 근거, 제작 전 출고 파일·발송 거부, 중복 재시도, 취소 검토/자동 환불 없음, 교환 회수→재제작→재출고, 다른 고객 차단, 삭제 요약·ACL 통과.
- 실제 DB 경합: 동일 시작 요청 12회에 하나의 영수증·이력, 서로 다른 완료 요청 8회 중 1개 저장/7개 충돌. 완료 후 취소도 검토 접수되며 환불 원장 0건.
- 주문·거래·리뷰 관련 앱 검사 59개 및 타입 검사 통과. 완료 상태에서 새 작업 입력을 숨기고 고객 취소 안내를 후속 수정했다.
- 실제 Chrome의 합성 구매자 주문에서 7일 납기를 확인했다. 관리자 화면에서 시작·완료를 각각 저장한 뒤 DB의 완료 상태/revision 3/이력 2건과 배송 준비 상태를 대조했다. PC·390px 표시를 검사했다.
- 근거: `output/smartstore-full-admin-20261016/production-*`, `local-production-*`, `review-production-browser-readback.json`. 실제 제작·배송 업체·운영 DB에 연결하지 않았다.
