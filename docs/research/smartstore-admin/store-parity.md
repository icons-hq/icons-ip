# 스토어·혜택·마케팅·분석·판매자 정보 대응 조사

migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

조사일: 2026-10-12~13 KST. 로그인된 스마트스토어센터를 읽기 전용으로 조사했다. 이 문서는 원본 UI/UX와 기능을 ICONS에 대응하기 위한 차이 목록이며, 아래의 기존 코드가 있다는 사실을 기능 동등성이나 배포 검증으로 보지 않는다.

물류 운영 범위는 2026-10-15 사용자 결정으로 갱신했다. 남양주·김포 담당자가 창고 양식 엑셀을 내려받아 자체 WMS에 입력한다. 운송장 발급·회수 접수·배송추적 API 및 운송사 이벤트 기반 배송완료 자동 동기화는 구현 대상에서 제외하며 공급자 API 확인 대기로 남기지 않는다. [현재 출고 양식·회신 등록](../../runbooks/warehouse-export.md)의 코드·파일 검증과 두 창고의 실제 WMS 인수는 구분한다.

## 증거와 조사 경계

- 증거: `output/smartstore-reference-20261012/store/manifest.json`. 각 캡처에 URL, 실제 확인한 상태, SHA-256, 채택 여부를 기록했다. `accepted: false`는 화면 전환 전·안내 겹침·클릭 미반영 등으로 해당 상태의 증거에서 제외한 캡처다.
- 처음부터 하단까지 확인한 메뉴: 혜택 조회/수정, 혜택 등록, 혜택 리포트, 고객등급, 마케팅메시지 등록/조회, 마케팅 링크, 스토어 전시관리 5개 표면, 쇼핑스토리 목록/등록, 기본정보, SNS, 요약/실시간/판매/방문/검색/고객 리포트, 고객현황, 판매자 정보, 매니저 관리, 타겟 세그먼트 생성/조회, 포인트 지급관리/지급폼/지급내역.
- 전시 편집기는 고정된 구성 목록과 개별 스크롤 편집 패널을 가지며 스토어 미리보기도 별도로 스크롤한다. 모든 라디오 조합·상품 검색 조합·모든 도움말까지 완료한 것은 아니다. 남은 하위 상태는 아래에 명시했다.
- 저장, 등록, 적용, 삭제, 메시지/초대 발송, 결제/충전, 동의, 권한 변경, 계약 신청은 실행하지 않았다. 입력 폼/선택창을 열고 닫는 범위까지 조사했다.
- 스토어 전시 카테고리의 전시방식·추가·삭제·이동은 **실시간 저장**이라고 명시된다. 이 동작은 클릭 검증에서 제외했다. 반품택배사 슬롯의 `택배사 변경`도 확정 경계로 두었다.
- 매니저·담당자·사업자·계약정보는 화면 구조 확인에 사용했다. 보고 문서에는 개인 연락처·계약번호·계좌를 재기재하지 않는다.

### 최신 기록으로 바로잡은 항목

- 쇼핑스토리·마케팅 링크·세그먼트·인앱 메시지 예약/반복·방문/결제 귀속을 초기 조사 때의 미구현 상태로 남기지 않는다. 현재 증거와 한계는 각 기능의 연결 문서를 따른다.
- 공통·상품목록·상품상세 후속 설정과 PDP 선정 BEST는 각각 실제 저장·공개 재조회를 확인했다. 홈 상품형 베스트리뷰와 PDP 선정 BEST는 선정 기준·최소 개수·표시 위치가 다르다.
- 쿠폰 기간 분리·상대 만료, 혜택 리포트, 적립금 지급/원장은 실제 격리 UI/DB 검증을 마쳤다. 지급 화면의 CSV/XLSX 파일 입력 (`output/store-credit-file-ui-qa-20261014/manifest.json`)도 실제 PC/390px에서 확인했으며 해당 검수에서는 지급·회수를 실행하지 않았다. 원본 전체 필터의 동등성은 미확인으로 유지한다.
- 판매원장 리포트에 남은 축과 새 방문 분석의 직전/전년 비교·상품/분류/링크 집계를 구분한다. 운영 수집 활성화·원격 공급자 검증은 수행하지 않았다.

## UI 복제에 반영할 구조

1. 일반 콘솔: 짙은 전체폭 상단, 짙은 좌측 메뉴, 밝은 회색 캔버스, 흰색 각진 패널, 헤더/검색/결과툴바/표/푸터의 순서다. 목록은 통상 내부 가로·세로 스크롤과 별도 페이지네이션을 가지며, 빈 목록도 표 높이를 유지한다.
2. 동작마다 모두 큰 초록 버튼을 쓰지 않는다. 검색/확정은 녹색, 등록/설정 진입은 회색 또는 테두리 버튼, 취소/초기화는 흰색이 반복된다. root가 상품 조회 화면에서 측정한 기준은 검색 배경 `#00c73c`, 테두리 `#00ae34`, 높이40px, 글자14px, radius0이다. 현재 `wc-admin.css`의 `--wc-accent`는 `#00c73c`로 반영했다. 색상 토큰 적용만으로 개별 폼/표의 검수가 끝난 것으로 보지 않는다.
3. 일반 설정폼은 왼쪽 라벨 열과 오른쪽 입력 열, 행 경계선, 필수점, 조건부 라디오/토글 확장, 하단 중앙 확정/취소를 사용한다. 모달도 표/조회/페이지네이션을 재사용한다.
4. 전시 편집기는 별도 표면이다. 55px 상단 아래 약70px 아이콘 레일, 약260px 구성 목록, 약500px 설정 패널, 스토어 미리보기가 분리된다. 선택 구성은 연녹색 배경이고 미리보기 대상 영역도 강조된다. 일반 CRUD화면만 다듬어서 전시 편집기 구현 완료로 볼 수 없다.
5. 분석은 기간/비교/기준 선택 → 지표 카드 → 순위 → 트렌드 → 상세표 순서다. 표뿐 아니라 화면 전체의 정보 순서·빈값·도움말·단위·모드별 비활성 규칙을 대응한다. 예: 고객수 모드에서 배송유형·임의기간 비활성, 배송유형 모드에서 고객수 비활성.
6. 목록/입력/하위모달/미리보기/확정 후 readback을 별도로 검증해야 한다. 이번 원본 조사에서는 외부 확정은 하지 않았으므로 저장 후 동작까지 검증됐다고 말할 수 없다.

## 미확인 상태와 후속 검증

- 혜택/스토리/메시지 목록에 결과0개인 경우가 있어 실제 행 수정·복사·중지·예약취소 결과는 확인하지 못했다.
- 등록폼의 모든 상품검색·필터·기간·등급 조합, 반복된 동일형 배너/상품블록, 모든 툴팁/예시를 전수 순회한 것은 아니다. 제품별 독립 동작은 구현 시 해당 상태와 함께 추가검증한다.
- 전시 편집기의 PC/전체보기, 이미지 편집기의 모바일/PC 전환, 일반 상품선택·상세검색 유형, 홈 상품디자인3종, 메뉴상세12개, 숏클립/AiTEMS 패널을 추가 확인했다. 이미지 파일업로드·편집적용, 상품선택 등록, 실시간 저장되는 전시분류 추가/삭제/이동/방식변경과 최종적용은 실행하지 않았다. 상품검색의 모든 필터 조합·페이지·동일형 슬롯을 모두 반복하지 않았고 홈의 모든 도움말을 열지는 않았다. 변경 선택은 최종적용 없이 페이지를 이동해 폐기했다.

## 구현한 전시 편집 단위

`CurationScreen`/`CurationSection`을 구성 목록→입력→미리보기로 교체하고 `admin-store-editor.css`에 격리했다. 현재 RPC 필드와 권한 검사를 유지하며, 수동 상품선택/순서, PC·모바일 이미지, 노출 상태/기간, 실패 시 입력 보존을 연결한다. 미리보기는 공개 `Home`을 스크립트 없는 390/1212px 프레임에서 렌더하고 저장 액션은 공개 홈·해당 편집 경로·공지 스트립 캐시를 갱신한다.

합성 데이터 fixture에서 제목 변경→미리보기, 실제 기기별 이미지 전환, 전체보기, 저장 실패 시 제목·유형·연결화면 보존, 미저장 이동 경고, 상품 검색·2페이지·선택·순서 변경을 확인했다. 1280/768/390px에서 페이지 가로 넘침이 없고 모바일 상품 표는 대화상자 내부에서 가로 스크롤한다. React 자동 폼 초기화가 실패 후 select 표시값을 바꾸는 문제와 대화상자 제목 대비를 수정하고 재검수했다. 이 브라우저 검증은 외부 저장을 차단한 fixture이며 운영 저장·Storage 업로드 결과를 증명하지 않는다.

추가한 `best_tab` 최신 등록순 자동 모드는 3–10개 설정을 RPC payload에 저장하고 공개 카탈로그의 실제 등록시각 내림차순으로 매번 상품을 조립한다. 초안·보관·제한 등 기존 공개 카탈로그 제외 상품을 되살리지 않는다. 등록시각 없는 행은 넣지 않고 부족한 수량을 가짜 상품으로 채우지 않는다. 수동 목록과 자동 규칙은 함께 저장되지 않으며, 편집기 미리보기도 같은 공개 후보를 사용한다. 관련 정규화·공개 로더·미리보기 테스트와 DB 계약 테스트를 추가했다.

전체 홈 순서는 고정영역과 기획전별 렌더 키를 가진 별도 원장으로 구현했다. 이후 판매량 BEST·베스트리뷰에도 독립 렌더 키를 추가했다. 최초 설정 전에는 기존 순서를 유지하며 새 기획전은 마지막에 추가한다. staff 검증·수정 버전·멱등·감사를 가진 RPC로 배열 전체를 저장하고, 공개 읽기는 현재 노출 가능한 키만 반환한다. 합성 fixture의 기획전 이동·히어로 숨김→저장→새로고침→현재 공개 홈 미리보기 및 390px 화면을 확인했다. 격리 DB에서 기본 순서, 저장·재조회, 중복 요청, 잘못된 배열·없는 기획전·이전 버전 거부, 공개 최소 노출, 새 기획전 추가, 오래된 참조 무시, 권한과 감사 테스트가 통과했다.

격리 DB에 연결한 실제 Next 앱에서도 저장을 검증했다. 최신 등록순3개와 직접 선택 `g2 → g1` 구성을 브라우저로 저장한 뒤 DB payload·새로고침 재조회가 일치했다. 인기템을 카테고리 BEST 위로 옮기고 카테고리 BEST를 숨겨 적용한 결과 공개 홈에는 인기템만 나타났으며, 다시 노출한 뒤에도 인기템→카테고리 BEST 순서가 유지됐다. 전체 순서 원장의 revision은 0→1→2로 증가했고 공개 RPC는 숨김 키를 제외했다. 증거는 `/tmp/icons-admin-store-qa-20261012/27-actual-latest-saved.png`부터 `30-actual-public-reordered.png`까지다. 이는 로컬 격리 환경의 저장·공개 렌더 검증이며 운영 배포·Storage 업로드 검증은 아니다.

현재 공개 `Home`은 `hero`/`editor_pick`/`band_banner`/`best_tab`/`benefit`/`sales_best`/`review_best`/`product_mosaic`를 그린다. `notice_strip`은 전역 셸에 반영된다. `announcement`/`featured_ip`는 로더가 보존하지만 현재 홈 본문이 소비하지 않으므로 편집기에서 가짜 노출 미리보기를 제공하지 않는다. 새 구성 선택에는 현재 렌더되는9종을 제공하며 기존2종의 편집은 보존한다. 쇼핑스토리는 별도 원장과 고정 홈 영역으로 후속 구현했다. 이후 [프로모션 배너](home-promotion-banner-parity.md), [자유상품 리스트·풀이미지](home-free-products-contract.md), [배너 스타일·보관](home-banner-style-archive-parity.md)도 개별 범위의 구현·검증을 마쳤다. 상품분류와 독립된 [전시 트리](category-display-composition-proposal.md)는 후속 구현·로컬 검증을 마쳤다.

독립 구성 `sales_best`·`review_best`를 추가해 기존 수동/최신 상품모음과 분리했다. 판매량은 승인시각의 KST 당일·이전1/7/30일, 실제 판매수량, 취소/환불/완료반품 제외, 품절 포함을 따른다. 부족할 때의 인기도는 ICONS의 실제 양수 찜 수로 대응하며 0판매·0찜 상품을 채우지 않는다. 한 기간 또는 네 기간 탭과 기본 기간을 저장한다. 리뷰는 최근7일 후보·평균3점 이상·자동 최대6개·최종4개 미만 숨김을 구현했고, 수동 최대20개는 원본 확인값이 아닌 ICONS 운영 한도다. 대표 공개 후기 본문·닉네임·작성일과 평균/개수를 함께 그린다. 홈 대표후기는 [현재 유효한 선정 BEST를 먼저](home-review-best-priority-implementation-qa.md) 고르고, 없으면 전체 공개 후기를 사용하며, 두 경우 모두 평점·[도움수](home-review-helpful-priority.md)·작성시각·ID 순서로 고른다. 같은 선정 원장을 사용하는 [PDP 이미지 영역](product-detail-review-best-implementation-qa.md)의 토글·최소 3개·무작위 조건은 홈에 적용하지 않는다. 상품 선정·평균·개수는 유지하며 하루 한 번 배치 대신 요청마다 검수 상태를 반영한다. [도움 표시·철회](review-helpful-parity.md)와 [홈 대표 후기의 도움수 반영](home-review-helpful-priority.md)은 각 문서에 기록한 범위의 구현·로컬 검증을 마쳤다.

두 신규 구성은 입력·미리보기·개별 저장·전체 순서/노출·공개 홈에 연결된다. 격리 DB 테스트에서 승인시각 경계·계좌이체·주문/결제 사용자 및 금액 일치·제외조건·공개/숨김 후기·대표 후기·신규 payload·구성종류 일치·권한·멱등을 확인했고, 공개 로더/렌더까지 포함한 관련10파일172테스트가 통과했다. 13일 실제 Chrome에서 4탭/기본월간·1기간실시간, 자동리뷰6개·수동3개 전체숨김·4개(4→1→2→3) 순서, 리뷰 상세탭 바로가기, 새 영역 순서/숨김·복원, PC/390px 공개 렌더까지 확인했다. 저장 payload와 공개 집계를 DB에서 다시 대조했다. 증거는 `output/smartstore-reference-20261012/verification-store-branding/manifest.json`의 05–12이며, 잘못된 스크롤 위치의 캡처는 미채택으로 구분했다.

## 남은 후속 범위

[현재 모델 재대조](remaining-general-work-reclassification.md)는 원본 2페이지 실증과 ICONS TOP20 제한을 근거로 **판매상품 전체 결과 조회·같은 조건 엑셀**을 독립 단위로 좁혔고 [구현·로컬 검증](sales-goods-ranking-parity.md)을 완료했다. 전체 일별표는 이미 있고, 개별 상품 일별 펼침 결과는 원본 미확인이다. [시간대 집계](sales-hourly-read-proposal.md)도 현재 주문 생성시각·조회시점 유효 상태·주문 총액을 유지하는 별도 조회로 구현했다. 완료 KST 정시까지만 합산하고 상품TOP10에만 IP를 적용하며, 같은 상품 ID의 비교값을 읽는다. 전용 XLSX/API나 방문·검색·전환 수집 확장은 포함하지 않는다.

공통 테마색·검색 표시, 상품목록과 상세 표시/구매·탐색/미디어/PDP BEST, 쇼핑스토리, 마케팅 링크·세그먼트·인앱 예약/반복, 별도 동의 기반 방문·결제 귀속과 상품 안내/이벤트 템플릿은 위에 연결한 범위의 격리 검증을 마쳤다. 전체 이식 완료를 뜻하지 않는다.

정사각 대표 이미지는 미구현 항목에서 제외한다. [현재 입력 폼](../../../components/admin/screens/StoreBrandingForm.tsx)·[저장/공개 계약](../../../lib/store-branding.ts)이 있고 [실제 업로드 API·DB·Server Action·푸터 HTML 검증](store-profile-parity.md)을 마쳤다. 2026-10-14 실제 파일 선택·폼 저장/삭제/재등록·PC/390px 시각 검수도 완료했다. 기존 첨부 경로 재사용을 막는 정상 writer 계약 때문에 복원은 기존 콘텐츠와 같은 바이트를 새 경로로 올려 수행했으며, 수정시각·감사를 역조작하지 않았다. 고객센터 노출위치 안내창은 별도로 PC/390px 검증 완료다.

## 네이버 전용과 범용 기능의 구분

네이버 로고·Npay/톡톡/네이버 멤버십·쇼핑라이브·검색노출/가격비교 채널·N배송·AiTEMS 엔진·네이버 수수료와 광고 계약은 그대로 연결할 수 없는 전용 서비스다. 이 때문에 화면 전체를 제외하지 않는다. 로고→ICONS, Npay포인트→적립금, 톡톡 메시지→지원하는 마케팅 채널, 채널/유입통계→ICONS 수집데이터처럼 범용 목적을 대응하고, 지원하지 않는 외부 연동은 그 상태와 요구 연동을 명시한다.

초기 원본 조사는 2026-10-12~13, 현재 구현 요약은 2026-10-14 작업 트리 기준이다. 운영 DB 스키마/배포/실제 데이터 수집의 동등성 검증은 이번 조사의 범위에서 실행하지 않았다.

### 공개 메뉴 로컬 검증 (2026-10-13)

`output/smartstore-reference-20261012/verification-store-navigation/manifest.json`에 PC·390px 캡처와 SHA-256을 기록했다. 메뉴명 21자 거절과 입력 보존, 20자 한글·영문 경계, 이름/숨김/순서 저장·재조회, 실제 이벤트 경로 이동, 공개 모바일 전체 메뉴와 기능 게이트 적용을 확인했다. 긴 이름이 기존 GNB와 모바일 전체 메뉴를 넘기는 문제는 실제 화면에서 수정·재확인했다. 격리 DB에서는 공개 최소 projection과 저장 감사3건을 대조했다. 권한·잘못된 값·중복 요청·충돌·다른 설정 섹션과의 버전 충돌은 SQL/단위 검증이며 강제 동시 충돌과 전송 실패는 실제 브라우저에서 재현하지 않았다. 운영 환경에는 적용하지 않았다.

### 자유상품 모자이크 로컬 검증 (2026-10-13)

원본280에서 실제 8개 상품 위치와 상품 없는 위치의 잔여 이미지를, 281의 공식 도움말 [자유상품 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=17548)에서 모자이크 최대8상품·구성 최대5개를 확인했다. 원본의 8개 전체 배치·최소상품수·비공개 상품 처리 결과는 확인하지 못했다. ICONS는 1·6번 큰 이미지의 7열2행, 모바일 가로스크롤, 누락/비공개 위치 유지, 유효상품0개 전체 숨김을 명시적 정책으로 적용한다. WebP 지원도 기존 ICONS 업로드 계약이다.

`verification-store-mosaic/manifest.json`은 16개 캡처 중 실제 설명과 일치하는 10개를 채택하고 잘못된 스크롤의 6개를 제외했다. 합성 이미지8장 업로드·claim 연결, 제목11자 거절/8위치 입력보존, 900KB 초과 선택 거절, 1/2위치 교환·3번 상품 해제·8번 비공개·7번 품절, PC/390px 공개·상세 이동, 전체순서/숨김 저장·복원, 새 비노출 구성 저장 뒤 편집 선택 유지를 확인했다. 최종 공개 링크는6개이고 모자이크는 기존7영역 뒤에 있으며 빈 비노출 검증 구성1개를 별도로 남겼다. 모바일 문서폭390px·내부그리드771.33px이고 뷰포트 재정의는 모두 해제했다.

최종 관련10파일127단위·test tsconfig·ESLint가 통과했다. 공개 Home/CSS의 나머지3파일은63개 통과, 병렬 작성 중이던 운영자 CSS 토큰1개 실패를 root가 수정해 해당 경계를 다시 통과했다. fresh DB의 공통409·홈순서·모자이크3개 SQL, 최대5개 동시경합 및 fixture 정리도 통과했다. 통합에서 발견한 모자이크 migration의 전체순서 충돌40001 회귀는 적용된 파일을 보존하고 `20261020085210_home_layout_mosaic_conflict_http409.sql`로 PT409만 복구했다. 두 격리 DB에서 함수/ACL 동일성을 검증했고 운영에는 적용하지 않았다.
