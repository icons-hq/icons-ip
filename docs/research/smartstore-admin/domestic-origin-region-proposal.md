# 원산지 국내 상세지역 — 원본·공식 데이터 검토

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-14. 공식 원본 조사 후 아래 범위의 정적 사전·기존 도우미 확장과 실제 로컬 저장 검증을 완료했다. DB 모델·writer·migration·운영 데이터는 변경하지 않는다. 기존 [국가·지역 찾기](origin-country-finder-proposal.md)의 국내 상세지역 후속이며, 추가 조사에서 배포용 공식 CSV 원본까지 확보했다.

**선택 도구는 시·도 → 시·군·구 두 단계로 구현할 수 있다.** 추가 조사에서 공공데이터포털의 국토교통부 전국 법정동 CSV를 무로그인·무키로 실제 확보했다. 이 파일은 이용허락범위 제한 없음을 명시하며, 시·도 16개와 세종 중복 단계·공백을 정리한 시·군·구 후보 268개가 행정안전부 2026-10-12 시행 파일의 해당 계층과 일치한다. 따라서 두 단계 명칭 도우미의 배포 사전 후보로 이 CSV를 권고한다. 하위 읍·면·동·리에는 차이가 있어 전체 주소 원장으로는 채택하지 않는다. 아래는 법률 판단이 아니라 원본에 게시된 조건과 실제 파일 분석 결과다.

## 스마트스토어에서 확인한 범위

기존 66번 캡처는 모달 열기 전 화면이고, 67번은 수입산 상태다. 두 캡처만으로 국내 단계 깊이를 증명할 수 없어 [상품 일괄등록](https://sell.smartstore.naver.com/#/products/bulkadd)의 원산지 찾기를 다시 열었다. 조회창의 선택만 사용했고 확인·등록·업로드는 누르지 않았다. 닫은 뒤 원래 0건 목록을 확인하고 소유 탭을 종료했다. 이번 증거 목록 (`output/domestic-origin-reference-20261014/manifest.json`)

현재 파일 `jscode20261012.zip`의 SHA-256은 `3702ee001f131968983fbba1e08c6bffc89f6ee4377de327e5eff6946b1098d7`, 말소 포함 ZIP은 `1594c1da830a75cad9c555492f7b5bb7a362565cf100feca6f2d15dd9a2f51b0`다. 개별 URL·크기·내부 파일은 다운로드 기록 (`output/domestic-origin-reference-20261014/official-downloads.json`), 추출값은 분석 JSON (`output/domestic-origin-reference-20261014/snapshot-analysis-latest.json`)에 있다.

CSV 일반구는 `수원시영통구`처럼 붙어 있으므로 배포 시 표시명을 만들 때 같은 CSV의 부모 시 명칭과 공식 코드 계층을 이용해 `수원시 영통구`로 구성한다. 다른 자료의 이름을 무단 보충하는 방식이 필요하지 않다. 세종은 `3600000000`의 첫 단계만 쓰며 CSV의 `세종시` 하위 행을 두 번째 선택에 중복 노출하지 않는다.

CSV 생성일자 최대값은 6월 30일이므로 이를 7월 개편의 법적 시행일로 읽지 않는다. 두 단계 코드·명칭 일치 검증 결과만 이번 UI 후보의 근거로 사용한다.

## 승인된 구현 계약

기존 [원산지 필드](../../../lib/goods-notice.ts)와 [엑셀 제조국 매핑](../../../lib/admin/goods-workbook.ts)은 `noticeOrigin` 문자열을 공유한다. [현재 도우미](../../../components/admin/CountryNameFinder.tsx)의 명시 적용 방식에 국내 상세지역을 추가하는 정도가 적합하다.

1. 상품 원산지 찾기에 국내 상세지역 선택을 추가한다. 시·도만 적용하거나 시·군·구까지 좁힐 수 있으며, 세종은 시·도에서 끝낸다. 읍·면·동·리와 개별 주소는 넣지 않는다.
2. 최종 적용 문자열은 예를 들어 `대한민국(경기도 수원시 영통구)`로 미리 보여준다. 이 표기 방식은 ICONS 제안이며 스마트스토어의 공식 출력값으로 주장하지 않는다. 사용자가 확인한 뒤 기존 입력 한 칸에만 적용한다.
3. 내부 공식 코드는 사전의 식별·계층 검증에만 사용한다. 상품에 지역 FK나 코드 형식을 강제하지 않고, 기존 `국산`·과거 지역명·복수 지역 등 자유문구도 유지한다. 폐지명을 새 명칭으로 자동 바꾸지 않는다.
4. 엑셀 헤더·스키마·반입 계약은 그대로 둔다. 국내 상세 문구를 엑셀에 넣는 기능까지 택한다면 명시 복사만 제공하고, 제조국과 원산지의 법적 동일성을 판단하지 않는다.
5. 배포 사전은 공식 URL·기준일·원본/파생 SHA·이용조건을 고정하고 수동 갱신한다. 실행 중 외부 API 호출·키·새 DB는 필요 없다. 공개·보관·저장 중 잠금과 KC 재검토는 기존 원산지 writer를 그대로 따른다.

배포용 입력은 이용허락범위가 명시된 국토교통부 CSV를 고정하고, 행안부 최신 파일은 두 단계 코드·명칭을 대조하는 검증 자료로만 사용하는 방안을 권고한다. 원본 CSV·메타데이터는 `vendor/korean-legal-regions/20260729`, 결정론적 추출은 `scripts/generate-korean-regions.py`에 보존한다. 런타임은 두 단계의 파생 사전 `lib/admin/korean-regions-data.json`만 사용한다. 현재 `noticeOrigin` 자유문자열 계약도 그대로다.


## 구현·검증 완료

`CountryNameFinder`에서 국가·지역과 국내 상세지역을 구분한다. 시·도만 선택하거나 일반구까지 선택한 최종 문구를 확인한 뒤 기존 입력에 적용하거나 엑셀 제조국용으로 복사한다. UI는 기존 `admin-country-finder.css`를 확장했고 배포 데이터는 16개 시·도·268개 하위 후보의 파생 사전만 포함한다. 원본·출처·이용조건·SHA는 [고정 자료](../../../vendor/korean-legal-regions/20260729/README.md), 재생성은 [추출 스크립트](../../../scripts/generate-korean-regions.py)로 관리한다.

검증 기록 (`output/domestic-region-qa-20261014/verified-checks.json`)의 별도 로컬 4350에서 실제 브라우저와 DB를 대조했다.

Console에는 기존 번역 확장의 HTML 속성 주입에 따른 hydration 경고와 확장 `startsWith` 오류가 있었고 도우미 오류·프레임워크 오류 화면은 없었다. API·DB는 승인된 합성 QA 환경만 사용했으며 전용 상품 2개·IP·KC 검토 흔적·임시 런타임·앱 탭·viewport를 정리했다. 공공 CSV 조사 탭 1개는 브라우저 focus 명령 시간 초과로 명시 종료하지 못했고 강제 종료하지 않았다. 이 기능에 필요 없는 서버 임시저장 재검증은 별도 판매기간 migration의 optional revision 회귀 보정 담당 검증으로 분리했으며, 기존 실패 SQL 테스트를 변형하지 않았다. 전체 통합 build는 root의 최종 통합 검증에서 수행한다.
