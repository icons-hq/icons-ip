# 발송 전 주문 배송지 변경

migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-13. 스마트스토어의 일반 배송지 수정 기능을 ICONS의 주문 전체·출고지별 배송비 계약에 연결했다. 운영 DB·배포·원본 주문 변경은 수행하지 않았다.

## 원본 확인과 적용 범위

[공식 도움말 3583](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3583)은 판매자의 발송 전 수정과 구매자의 발주확인 전 수정을 구분하며, 같은 주문의 일부 상품이 이미 발송됐다면 주문 전체 배송지 수정을 막는다. 실제 원본 목록에서 배송지 변경 진입을 확인했으나 별도 수정 팝업의 본문은 열리지 않아 원본 입력 배치를 확인했다고 주장하지 않는다.

[공식 도움말 4655](https://help.sell.smartstore.naver.com/faq/content.help?faqId=4655)의 지역 추가료는 최초 결제 기준이다. ICONS는 기존 결제와 다른 배송비를 몰래 덮어쓰거나 추가 결제를 만들지 않는다. 지역이 바뀌면 현재 배송 가능 여부와 주문 당시 출고지별 금액을 대조해 같은 금액으로 배송할 수 있을 때만 수정한다. 다른 금액이 필요하면 저장을 거절하고 고객지원 협의로 넘긴다.

## 저장 계약

- 주문 상세의 `배송지 수정·이력`은 `sales.manage` 권한이 필요하다. 결제완료·발주확인 주문만 수정하며 모든 배송건에 같은 주소를 적용한다.
- 수령자·연락처·우편번호·기본/상세 주소·배송 메모, 고객 합의 근거 500자, 주문 전체 변경 동의를 받는다. 우편번호 5자리와 정규화된 연락처·길이·제어문자를 서버와 DB가 검사한다.
- 배송건 누락, 출고지시 전달·송장·실제 발송 이력, 진행 중인 클레임을 검사한다. 이력은 현재 상태를 되돌렸다는 이유로 무시하지 않는다.
- 우편번호 또는 정규화된 기본 주소가 바뀌면 출고지 정책 잠금 아래 현재 지역 견적을 계산한다. 주문 당시 기본 운임·무료 기준·소계를 유지하며 각 배송건과 전체 배송비가 모두 같아야 한다. 퀵·방문수령과 근거가 부족한 과거 주문은 지역 변경을 차단하되 연락처·상세주소·메모 수정은 허용한다.
- `orders.address_revision`은 실제 주소 변경 때만 증가한다. 다른 담당자의 변경은 `PT409`로 거절하고 입력을 보존한 채 최신 주소와 다시 비교한다. 최신 정보를 읽은 뒤에는 동의를 다시 받아야 한다.
- actor fence→operation UUID→주문→정렬된 배송건→출고지 share 순서로 잠근다. 같은 UUID는 같은 담당자·주문·예상 revision·주소·사유일 때만 재사용한다. 응답이 불확실하거나 읽기 결과가 아직 없으면 최초 본문을 고정한 채 같은 내용만 재시도한다.
- private `order_address_changes`에 이전/이후 주소·사유·새 지역 견적을 보존한다. 일반 감사 로그에는 변경 필드명·동의·배송건 수만 남긴다. 원 담당자만 요청 영수증을 조회할 수 있으며 판매관리 담당자는 주문의 최근 20개 이력을 조회한다.
- 결제·배송비·쿠폰·적립금 snapshot은 변경하지 않는다. 배송건 `updated_at`을 갱신해 이전 주소로 내려받은 출고지시 파일을 뒤늦게 전달 완료로 기록하지 못하게 한다.

## 검증

`20261020085247_admin_order_address_changes.sql`을 OWN/FRESH 격리 DB에 적용했다. 두 DB의 기능 테스트는 PostgREST와 같은 `LOAD 'safeupdate'` 조건에서 통과하고 fixture를 롤백한다. 역할·ACL·재전송·다른 actor·잘못된 본문·CAS·동의·출고/클레임/지역·과거 견적·기존 금액 불변을 포함한다.

별도 복제 DB에서 실제 잠금 대기를 관측한 경합 10건이 통과했다: 같은 요청, 다른 담당자의 같은 버전, 다른 본문의 요청번호 재사용, 저장 중 결과 읽기, 출고지시 전달 우선, 주소 수정 뒤 오래된 출고지시 확인, 발송 우선, 클레임 우선, 지역 정책 변경 우선, 권한 회수 우선. 복제만 제거하며 기존 개발 DB를 초기화하지 않는다.

```sh
docker exec -i supabase_db_<격리DB> psql -X -U supabase_admin -d postgres -v ON_ERROR_STOP=1 < supabase/tests/admin_order_address_changes.sql
SUPABASE_DB_CONTAINER=supabase_db_<격리DB> ORDER_ADDRESS_TEST_SCOPE=isolated-local bash supabase/tests/order_address_concurrency.sh
```

모델·서버·액션·컴포넌트 이벤트 회귀 테스트 12개가 통과했다. 미확정 전송→빈 읽기→같은 내용 재시도, 지연 입력·동일 렌더의 연속 제출 차단, 미확정 이후 재시도 오류에도 고정 유지, 다른 본문의 응답, 충돌 후 입력/동의/버전 재확인을 검증한다. 브라우저 네트워크 장애를 주입한 것은 아니며 실제 세션 경합과 컴포넌트 이벤트로 해당 상태를 확인했다.

실제 Chrome의 합성 주문으로 추가료 지역 변경의 거절, 입력 보존, 동일 배송비 지역 저장, 390px 연락처·메모 저장, 최근 이력 펼침/끝까지 스크롤, 두 탭 충돌·최신 주소 비교·동의 재확인·재저장을 확인했다. 390px에서 문서 폭은 390px, 대화상자는 370px였다. 임시 viewport 설정을 모두 해제했다.

증거 manifest (`output/smartstore-reference-20261013/verification-order-address/manifest.json`)에 직접 본 PNG의 SHA-256과 채택 여부를 기록했다. DB 재조회 (`output/smartstore-reference-20261013/verification-order-address/db-readback.json`)는 저장 4건·감사 4건, 모든 합성 주문의 결제액 25,000원/배송비 5,000원과 출고지별 2,000원/3,000원 유지, 환불 0건과 일반 감사 로그의 주소/자유 사유 부재를 확인한다.

구매자의 직접 배송지 수정, 배송 중 변경·택배사 통지, 교환 재배송/회수 주소 수정은 이 단위에 포함하지 않는다. 해당 기능은 별도 원본·진행 단계 계약을 확인해 연결한다.
