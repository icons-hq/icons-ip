# 스토어 전시 설정 구현·검증

migration 파일 경로는 [배포 매핑](../../../supabase/manifests/admin-rollout-migration-map.json)을 반영했다. 아래 과거 검증·적용 기록은 당시 원본 DRAFT 기준이며 이번 운영 배포의 성공을 뜻하지 않는다.

이 문서의 `output/`·임시 경로는 내부에 보존한 로컬 검수 근거의 파일 참조이며, 해당 자료와 비공개 원본 캡처는 저장소에 첨부하지 않는다.

2026-10-13 격리 로컬 Supabase와 실제 Next 화면에서 저장·공개 재조회·모바일·원복을 확인했다. 네이버 원본과 운영 환경에는 쓰지 않았다. 원본 대조는 [표시 설정 조사](store-presentation-parity.md)를 따른다.

## 완료 범위

`/admin/display/settings`의 공통 테마·홈 검색과 상품목록을 각각 저장한다. `store.manage`가 필요하며 두 영역은 서로 다른 revision을 가진다. 저장할 때 현재 권한, 예상 revision, 고정 operation UUID를 검사하고 감사 결과를 한 번만 남긴다. 네트워크 결과가 불분명하면 입력과 요청 ID를 고정해 같은 요청으로 확인한다.

공통 테마는 원본 14색과 기존 ICONS 기본색, GNB 기본형/컬러형, 홈 본문 검색 배너를 제공한다. 공개 헤더와 홈에만 연결하며 어드민 색상은 유지한다. 어두운 색의 전경색은 팔레트별 WCAG AA 대비 검사를 통과했다. 홈 검색은 기존 `/search?q=…`로 이동하며 상단 검색 아이콘은 별도로 유지한다.

상품목록은 아래 항목을 공개 굿즈샵·NEW·BEST·IP 굿즈·검색·찜·관련상품에 연결한다.

| 항목 | 구현 계약 |
| --- | --- |
| 이미지 비율 | 정사각형 또는4:5. 잘리지 않게 원본 비율을 유지한다. 스토리 섹션이 직접 저장한 비율은 우선한다. |
| 추가 이미지 | 대표와 기존 추가이미지 최대9장, 총10장. 버튼은 상세 링크 밖에 있으며 키보드로 선택 가능하다. 같은 이미지 주소는 중복하지 않는다. |
| 색상칩 | 상품 편집의 별도 운영 패널에서 이름1~30자와6자리 hex를 최대20개 저장한다. `catalog.manage`를 재검사하며 옵션명으로 색을 추측하지 않는다. 옵션·재고는 바꾸지 않는다. |
| 설명 | PC에서 실제 상세정보의 텍스트 최대240자, 두 줄 표시. HTML은 태그/script/style 제거 후 엔티티를 한 번만 해석한다. 일반 텍스트의 `< >`·`&amp;` 문자는 보존한다. |
| 담기 | 기존 장바구니와 옵션 재고 검사를 사용한다. 여러 옵션·직접입력은 상세 선택, 최소수량2개 이상은 상세 수량 선택으로 연결한다. BEST·스토리 관련상품은 제외한다. |
| 태그 | BEST/NEW만 표시·숨김. 품절·할인·다른 배지는 유지한다. |

홈 큐레이션과 어드민 미리보기의 별도 디자인은 유지한다. 상품별 선택 메타데이터가 없으면 대표이미지와 기존 가격·상태만 사용한다. 메타데이터 조회 실패도 기존 카드의 기본 표시는 유지한다.

## 데이터 경계

- `private.store_presentation_settings`와 `private.goods_listing_colors`는 RLS를 켜고 PUBLIC·anon·authenticated·service_role의 직접 접근을 모두 봉인했다. 읽기/쓰기 RPC에 필요한 실행 권한만 부여했다.
- 공개 설정은 값만 반환하며 revision·감사·사업자·계좌 정보는 싣지 않는다. 루트 셸은 쿠키 없는 공개 로더와300초 캐시를 사용하고 저장 성공 후 `updateTag`로 바로 갱신한다.
- 공개 목록 메타데이터 RPC는 요청당 최대1,000개 ID를 받고 실제 상품과 IP의 공개·보관·판매제한 게이트를 다시 검사한다. 추가 경로9개·설명240자·색상20개만 반환한다. 서버는 정규 상품 아트워크 경로만 공개 이미지로 변환한다.
- 최초 색상 행도 CAS에 참여한다. 미공개 상품 ID 변경에는 FK cascade로 색상과 revision을 보존한다. 별도 저장은 기본 상품 폼 입력을 저장하지 않는다.
- `20261020085235_store_presentation_settings.sql`과 후속 `20261020085239_goods_listing_description_format.sql`을 OWN/FRESH 격리 DB에 적용했다. 후속 migration은 기적용 원본을 보존하고 설명 형식 projection만 보완한다.

## 검증

단위·렌더·서버 액션·카탈로그·용어·CSS 경계 12파일109테스트, 전체 TypeScript 검사와 관련 ESLint를 통과했다. 전체 빌드와 전체 저장소 테스트는 상위 통합 검증에서 수행한다.

SQL은 형식·추가키·중복색상·고정색·수정충돌·동일요청 재시도·영역 독립·권한회수·단일감사·비공개 상품/IP/판매제한·미공개ID 변경·일반/HTML 설명을 검증했다. 테스트 자료와 설정은 트랜잭션으로 롤백했다.

별도 복제 DB에서 실제 대기 잠금을 관측한 경합7개를 통과했다.

1. 같은 영역의 같은 revision 수정: 한 요청만 성공.
2. 같은 operation UUID 재시도: 같은 결과와 감사1개.
3. 다른 관리자·다른 영역 저장: 첫 영역이 잠긴 동안 두 번째 저장 완료.
4. 최초 색상행 동시 생성: 한 요청만 성공하고 나머지는 충돌.
5. 색상 저장과 미공개ID 변경: 저장 후 새 ID로 색상 보존.
6. 같은 UUID를 다른 영역에 재사용: 요청 충돌.
7. 권한 회수 후 대기 중 저장: 권한 오류로 거절.

실행기는 `SUPABASE_DB_CONTAINER=supabase_db_<격리DB> STORE_PRESENTATION_TEST_SCOPE=isolated-local bash supabase/tests/store_presentation_concurrency.sh`이다. CI는 scope를 `ci`로 지정한다. 실행기는 명시한 로컬 컨테이너에서 별도 DB를 복제하고 종료 시 해당 복제만 제거한다.

## 실제 화면과 원복

증거는 `output/smartstore-reference-20261012/verification-store-presentation/`의 PNG·manifest·SQL·단위 로그에 있다. manifest는 각 파일 URL·SHA-256·크기·검수 채택 여부를 가진다.

- 공통 컬러형·갈색·홈 검색을 저장하고 공개 홈 헤더와 별도 검색창, 실제 검색 결과1개를 확인했다.
- 상품목록4:5·추가이미지2/2·명시 검정칩·PC 설명·NEW 숨김을 확인했다. 카드에서 담은 합성 상품1개를 `cart_items`로 읽고 화면에서 제거해0개로 돌렸다.
- BEST5카드의 담기0개, 스토리 관련상품의 담기0개와 품절 유지, 전역 정사각형 복원 후에도 스토리 지정4:5 유지까지 확인했다.
- admin390px와 공개 검색390px는 `scrollWidth=clientWidth=380`이었다. 모바일에서는 설명이 `display:none`이고 이미지·색상·담기는 유지됐다.
- 찜 목록에서 기존 모바일100%폭 담기와 하트가 합쳐408px로 넘치는 문제를 발견해 해당 목록의 flex 폭만 보완했다. 재검증은380/380으로 통과했다. 검증용 찜은 제거했다.
- 공통·상품목록 설정은 시작값으로 복원했다. 두 revision은2이며, 합성 상품의 갤러리·설명·배지는 저장해둔 원본과 정확히 일치한다. 색상은 빈 목록(revision2), 장바구니0개·검증 찜0개다. `final-database-readback.json`으로 확인했다. 감사 이력은 유지했다.

미리보기 대비 수정전·색상 저장중·모바일 넘침 수정전 화면은 완료 근거에서 제외했다. 캡처 중 관측한 hydration 경고6개는 모두 브라우저 확장의 `data-immersive-translate-page-theme` 속성 추가에 따른 차이였다. 애플리케이션 설정이나 확장은 변경하지 않았다. 임시 CDP viewport/media override는 모두 해제했다.

상품상세 띠배너·리뷰요약·추천모듈 운영 설정, 홈 일반 자유상품 디자인, 전시 전용 분류, 등급·방문 집계는 이 단위에 포함되지 않는다. 원본 최종 저장과 운영 배포는 미실행이다.
