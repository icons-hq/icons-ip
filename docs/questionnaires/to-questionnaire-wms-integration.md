# ICONS ↔ WMS 연동 사양 확인서

**목적:** ICONS 자사몰과 김포 창고 WMS 사이의 출고·운송장 연동을 개발하기 위해, 붙을 수 있는 연동 표면과 상품 코드 체계를 확정합니다. 이 답에 따라 구현 방식이 갈리며, 답이 오기 전에는 어느 쪽도 착수할 수 없습니다.

> **상태: 2026-08-20 작성.** [#177](https://github.com/icons-hq/icons-ip/issues/177)의 개발 측면을 분리한 문서입니다.
> 출고 마감 시각·배송비·반품 주소 같은 **운영 절차**는 [first-sale-logistics-wms.md](first-sale-logistics-wms.md)에서 별도로 묻고 있습니다.

**보내는 사람:** ICONS 개발팀
**답변 담당:** WMS 전산·연동 담당자
**답변 사용처:** ICONS 출고 연동 모듈 설계와 개발 착수 판단에 사용합니다. 외부에 공개하지 않습니다.

## 배경

ICONS는 자체 개발한 커머스(자사몰)이며, 현재 주문 정보를 창고에 넘기는 경로가 시스템화되어 있지 않습니다. 지금은 운영자가 ICONS 화면을 보고 수령인·주소·품목을 WMS에 다시 입력합니다. 이 이중 입력을 없애고, 나아가 출고 지시 전송과 운송장 회수를 자동화하려 합니다.

ICONS 쪽 설계는 이미 정해져 있습니다 — **연동 방식이 무엇이든 하나의 인터페이스 뒤에 어댑터로 붙입니다.** 그래서 필요한 것은 "무엇이 가능한가"이지 "무엇을 해달라"가 아닙니다. API가 없어도 파일 교환이면 파일로, 그것도 없으면 정해진 양식의 수동 다운로드·업로드로 구현합니다. **어느 쪽이든 개발은 가능하니 실제 상황을 있는 그대로 알려주시면 됩니다.**

## 답변 방법

**회신 희망일:** `[기입]` · **예상 소요:** 10분 · **문항 10개**

착수 판단에 필요한 최소 항목만 담았습니다. 반품 회수 연동, 재고 대조, 출고 취소 처리는 이 답을 받은 뒤 방식에 맞춰 따로 여쭙겠습니다.

부분 답변도 유효합니다. `모름 / 확인 담당자 / 확인 예정일`로 남겨 주시면 그대로 반영합니다. 확실하지 않은 항목은 건너뛰지 마시고 불확실하다고 표시해 주세요 — 추측한 답이 잘못된 구현으로 이어지는 것이 가장 비쌉니다.

**계정·비밀번호·API 키는 이 문서에 적지 마십시오.** 자격 증명이나 대외비 문서가 필요하면 전달 채널만 알려주시면 됩니다.
