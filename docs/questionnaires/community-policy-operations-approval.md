## Context

정책 초안은 NAVER의 문서 계층과 게시 유지·단계 제재·이의 절차를 참고하되 ICONS의 팬 커뮤니티와 현재 `staff`·`admin` 권한에 맞게 작성했습니다. 현재 코드는 일반 신고 접수, 신고 상태 변경, 포스트·댓글 숨김, 계정 정지 일부를 제공하지만 법정 권리신고, 양쪽 통지, 이의·복원과 전용 증거 보존 흐름은 아직 없습니다. 이 확인서는 법률 판단이 아니라 실제 운영 가능 여부와 담당자를 확정합니다.

## 책임과 연락 체계

### 커뮤니티 정책의 최종 운영 책임자는 누구입니까?

> 역할·담당자: `ICONS 커뮤니티·권리보호 최고관리자` 1명. 실제 운영 계정과 자연인은 공개 시행 전에 지정한다.
>
> 승인 권한 범위: 일반 content hide/restore, 임시 account restriction, 사건 배정. 영구 해지·법정 원본 열람·외부 반출·legal hold release는 독립 재검토자가 없으면 실행하지 않는다.

### 일반 신고를 매일 확인할 1차 담당자는 누구입니까?

> 역할·담당자: 자동 moderation queue가 접수·중복·긴급 category를 분류하고 최고관리자가 1차 확인한다.
>
> 확인 가능 시간대: KST 매일 10:00·17:00 정기 확인. 긴급 queue는 즉시 알림. 실제 알림 수신이 검증되지 않으면 신규 community write OFF.

### 야간·휴일 긴급 사건을 받을 당직 또는 상향 체계가 있습니까?

> 있음 / 없음: 자연인 당직은 **없음**. 그래서 긴급 category 신고 시 자동 임시 비공개와 write freeze를 사용한다.
>
> 1차 연락 역할: 최고관리자에게 push/SMS/업무 이메일 중 검증된 2개 채널로 상향한다. 채널이 2개 미만이면 community write를 열지 않는다.
>
> 응답 목표: 자동 제한 5분 이내, 최고관리자 확인 4시간 이내. 생명·신체 위험은 즉시 관계기관 신고 안내와 서비스 범위 내 차단.

### 법무·수사기관 대응으로 상향할 담당자는 누구입니까?

> 내부 역할: 최고관리자가 사건을 freeze하고 최소 evidence를 보전한다.
>
> 외부 법무 연락 경로: 현재 상시 자문 없음. 법원·수사기관·저작권/명예 분쟁·영구 해지 판단은 검증된 외부 법률 채널이 생기기 전 최종 확정하지 않는다.
>
> 상향 조건: 법정 서식, 수사/법원 요청, 아동·성착취·불법촬영물, 신체위협, 대규모 개인정보, 반복 이의, 영구 계정해지, 외부 반출.

## 접수 경로

### 일반 회원 신고는 현재 인앱 신고 폼을 기본 경로로 사용합니까?

> 승인 / 변경 필요: **승인.** 로그인 회원의 일반 신고는 인앱 form이 기본이다.
>
> 추가로 받을 필수 항목: 신고 category, target content, 선택적 설명, 긴급 여부. 법률평가·주민번호·과도한 신분정보는 요구하지 않는다.

### 비회원·권리자용 권리침해 접수 채널은 무엇으로 운영합니까?

> 공개 이메일 / 웹 폼 / 기타: **비로그인 웹 form**을 기본으로 하고 검증된 업무 이메일은 보조 채널로 둔다.
>
> 실제 담당 연락처: `/legal/rights-protection`. 이메일·전화는 #87에서 실제 수신 가능성이 검증된 뒤만 표시한다.
>
> 접수 확인 방법: 제출 즉시 opaque 사건번호와 접수시각을 보여주고, 검증된 회신 채널로 같은 번호를 보낸다.

### 공개 권리보호 안내 경로를 `/legal/rights-protection`으로 확정합니까?

> 확정 / 다른 경로: **`/legal/rights-protection` 확정.**
>
> 푸터 외 추가 노출 위치: community 메뉴·각 content 신고 menu·로그인/탈퇴 상태 page·법정 문서 index.

### 커뮤니티 운영 정책 경로를 `/legal/community`로 확정합니까?

> 확정 / 다른 경로: **`/legal/community` 확정.**
>
> `/community` 외 추가 노출 위치: 푸터·가입 동의·작성 composer·제재/신고 결과·권리보호 안내.

## 처리 목표 시간

### 생명·신체 위험과 불법촬영물등을 인지 즉시 제한·상향할 수 있습니까?

> 가능 / 불가능: 자동 임시제한·상향은 가능, 최종 법적 판단은 자연인 담당 없이는 불가능.
>
> 현실적인 응답 목표: 신고 후 5분 내 임시 접근제한, 4시간 내 최고관리자 확인, 관계기관 인계가 필요한 경우 즉시 시작.
>
> 필요한 추가 인력·도구: emergency category queue, kill switch, 이중 알림, restricted evidence vault. 이 도구와 실제 수신자 검증 전 community write OFF.

### 개인정보 대량 노출·구체적 폭력 위협·사기를 접수 당일 검토할 수 있습니까?

> 가능 / 불가능: 자동 임시제한과 당일 최고관리자 검토를 조건으로 가능.
>
> 현실적인 응답 목표: 접수 즉시 임시 제한, KST 기준 8시간 이내 1차 판단.
>
> 필요한 추가 인력·도구: severity rule, duplicate cluster, rate-limited alert, audit queue. 고위험 자동 영구삭제는 금지한다.

### 일반 신고를 1영업일 안에 분류하고 3영업일 안에 1차 결정할 수 있습니까?

> 가능 / 불가능: 가능한 목표로 승인하되 queue SLA monitor가 전제다.
>
> 현실적인 목표: 1영업일 내 분류, 3영업일 내 1차 결정·통지. backlog가 10건 또는 oldest 1영업일을 넘으면 신규 write를 일시 중단한다.
>
> 예상 월 신고량 또는 산정 근거: 실측 전 0~20건/month capacity로 제한한다. 첫 90일 실제치를 보고 재산정한다.

### 일반 제재 이의를 3영업일 안에 재검토하기 시작할 수 있습니까?

> 가능 / 불가능: 시작 목표는 가능하나 독립 reviewer가 없으면 최종 재결정은 보류한다.
>
> 현실적인 목표: 접수 3영업일 내 재검토 시작, 10영업일 내 결과 또는 지연사유 통지.
>
> 원결정자와 분리할 재검토 담당자: 실제 제2 reviewer 지정 전에는 원결정 유지가 아니라 콘텐츠를 비공개 보류하고 영구 계정제재를 확정하지 않는다.

## 법정 권리사건 담당과 달력일 커버리지

### 명예·사생활 침해 요청의 접수·판정·통지를 누가 담당합니까?

> 최초 접수자: rights-protection web form과 자동 case queue.
>
> 1차 판정자: 커뮤니티·권리보호 최고관리자. 자동화는 명백한 target 일치와 임시제한만 수행한다.
>
> 신청자·게시자 통지 담당자: notification service가 versioned template로 발송하고 최고관리자가 결과를 확인한다.
>
> 개인정보를 최소화한 게시판 공시 문구 승인자: 최고관리자. 문구는 정책에 versioned 상수로 고정한다.
>
> 게시판 공시 실행자·시점: moderation RPC가 접근제한 commit과 같은 transaction/outbox에서 즉시 생성한다.
>
> 야간·휴일 대체 담당자: 자연인 대체자는 없음. 자동 임시제한·이중 알림으로 대응하고 최종 판정은 다음 검증된 review window까지 보류한다.
>
> 법무 상향 조건·연락 역할: 사실관계 다툼, 재개 요구, 영구 삭제/해지, 수사·법원, 손해배상 위협은 최고관리자가 외부 자문을 요청한다. 자문 채널 미확정 중에는 공개 복원·영구제재를 하지 않는다.

### 저작권 복제·전송 중단·재개 요청의 각 단계를 누가 담당합니까?

> 중단 요청 접수·형식 확인자: 지정 수령인과 rights queue가 법정 서식·대상·권리/대리권 첨부 여부를 확인한다.
>
> 중단 판정·실행 승인자: 커뮤니티·권리보호 최고관리자. 형식상 완결된 요청은 우선 임시 중단하고 실체 판단은 분리한다.
>
> 법무가 확정한 대상에게 중단요청서 사본·재개요구 안내를 보낼 담당자: notification service + 최고관리자 검수.
>
> 재개 요청 접수자: `/legal/rights-protection` 전용 form과 지정 수령인.
>
> 3일 이내 정당성 판정자: 최고관리자와 독립 reviewer. 독립 reviewer가 없으면 재개를 확정하지 않고 외부 법률 검토로 상향한다.
>
> 정당하다고 인정한 경우 권리주장자에게 재개요구 사실·예정일을 통지할 담당자: 최고관리자 승인 뒤 notification service.
>
> 재개 실행 담당자: scheduled moderation worker가 승인된 예정일·legal hold·법원명령을 재확인한 뒤 실행한다.
>
> 야간·휴일 대체 담당자: 자동 deadline alert·임시 중단 유지. 실제 대체 reviewer가 지정되기 전 신규 community write는 활성화하지 않는다.

### 법무가 수령인 공지 의무를 확정하면 누구를 지정하고 어떤 업무 연락처를 공개합니까?

저작권법 시행령 제44조 적용 시 `/legal/rights-protection`에 수령인의 성명·소속부서명, 전화·팩스·이메일, 우편 수령 주소를 누구나 쉽게 찾을 수 있게 표시해야 합니다. 실제 값은 법무의 OSP 유형 판단 뒤 확정합니다.

> 지정 수령인·소속부서: `ICONS 권리보호 수령인 / 서비스 운영`. 법이 개인 성명을 요구하므로 실제 자연인 지정 전에는 placeholder를 공개하지 않는다.
>
> 공개 업무 전화·팩스·이메일: #87에서 실제 수신·보존·휴일 전달을 검증한 업무 연락처만. 값을 발명하지 않는다.
>
> 공개 우편 수령 주소: 사업자등록·우편 수령이 확인된 주소만. 현재 미확정.
>
> 주 담당자 부재·휴일 대체 담당자: 실제 제2 자연인 또는 계약 법무 수령대행이 필요하다. 미지정 동안 정책 공개 시행·신규 write 금지.
>
> 변경 공지 승인자·갱신 목표시간: 최고관리자, 변경 전 또는 인지 4시간 내 route·footer·서식·provider 설정을 원자 갱신한다.

### 법무가 승인한 달력일 기한을 휴일에도 지킬 운영 체계가 있습니까?

현재 정책 초안에는 저작권 중단일부터 3일 이내 통지, 중단 통지 후 30일 이내 재개 요청, 재개요구를 받은 날부터 3일 이내 정당성 결정, 정당하다고 인정한 경우 7일 이후 14일 이내의 재개예정일과 권리주장자 통지 같은 달력일 절차가 포함돼 있습니다. 최종 기한은 법무 확인서 답변을 따릅니다.

> 가능 / 불가능: 현재 자연인 대체자가 없어 **완전한 시행은 불가능**. 자동 접수·임시중단은 가능하다.
>
> 휴일 모니터링 시간대: 자동 queue는 24/7, 자연인 확인은 KST 10:00·17:00. 달력일 법정 판단은 대체 reviewer 지정 전 열지 않는다.
>
> 자동 알림·상향 도구: 24h/12h/4h deadline alert, missed-SLA kill switch, 이중 채널, immutable audit.
>
> 주 담당자 부재 시 인수인계 방법: 사건번호·deadline·최소 evidence·현재 조치를 capability-bound queue로 넘긴다. 원문을 메신저로 복사하지 않는다.
>
> 현실적으로 지키지 못하는 기한과 필요한 조치: 3일 정당성 판단과 휴일 통지를 보장할 대체자가 없다. 실제 수령인·backup 지정 전 community write를 비활성화한다.

## 제재와 복원

### `안내·주의 → 콘텐츠 제한 → 일시 정지 → 계속 정지·계약 해지` 단계를 승인합니까?

> 승인 / 수정 필요: **승인.** content 조치와 account 제재를 별도 축으로 기록한다.
>
> 추가·삭제할 단계: “자동 임시제한(판단 전)”을 content 제한 앞에 추가한다. 영구 해지는 독립 재검토/법적 근거 없이는 금지한다.

### 긴급·명백한 불법행위에는 앞 단계를 생략하는 기준을 승인합니까?

> 승인 / 수정 필요: 승인. 생명·신체, 아동·성착취, 불법촬영물, 대량 개인정보, 구체적 사기/계정탈취만 allowlist한다.
>
> 즉시 정지 승인 역할: 자동 rule은 content 임시제한·최대 24시간 mutation freeze만 가능. account 계속 정지는 최고관리자 승인.
>
> 사후 검토 기한: 4시간, 늦어도 24시간. 지연 시 content는 비공개 유지하되 계정 freeze는 권리 경로를 제외하고 최소화한다.

### 일시 정지의 기본 기간표가 필요합니까?

> 필요 / 사건별 판단: 예측 가능성을 위해 기본 기간표 필요.
>
> 위반 유형별 기본 기간: spam/도배 24시간→7일→30일; 괴롭힘·사칭 7일→30일; 개인정보 노출·사기 30일; 신체위협·불법물은 content 즉시 제한 후 account 상태를 사건별 판단. 영구 해지는 독립 review 필수.
>
> 예외 승인 역할: 최고관리자 + 독립 reviewer. 독립 reviewer 없이는 더 긴 제재로 상향하지 않는다.

### 잘못 숨긴 포스트·댓글을 복원할 최종 승인자는 누구입니까?

> 역할·담당자: 원결정자와 다른 reviewer가 승인하고 restore worker가 실행한다. solo 상태에서는 대상 ID 불일치·중복 처리 같은 명백한 기계적 오류만 versioned rule과 감사기록으로 최고관리자가 정정할 수 있다. 사실·권리 판단이 필요한 복원, 영구 제재, 정책 예외는 독립 reviewer가 지정될 때까지 비공개 보류한다.
>
> 작성자·신고자 통지 방법: 작성자에게 복원·사유·이의 경로, 신고자에게 개인정보를 드러내지 않는 처리 완료 사실만 인앱 우선으로 통지한다.

## 통지와 이의

### 조치·보완·기각·복원 결과를 어떤 채널로 통지합니까?

> 인앱 알림 / 이메일 / 둘 다 / 기타: **인앱을 authoritative 채널**, 검증된 이메일을 보조로 사용한다. 계정 없는 권리자는 web status+이메일.
>
> 채널별 담당 시스템: durable notification outbox가 in-app을 먼저 commit하고 #191 dispatcher가 이메일을 소비한다.

이메일을 선택하면 Production 발송은 #191의 Send Email Hook withdrawal fence, provider 호출 전 durable intent, idempotency/event reconciliation과 처리자 승인을 통과해야 합니다. HTTP 2xx 또는 앱 `sent`만으로 법정 통지 도달을 단정하지 않습니다.

> 이메일 provider 실패·bounce·delivery event 미수신 시 재시도·수동 통지·법무 상향 담당자: #191 processor가 24시간 idempotency window 안에서만 재시도하고 최고관리자에게 상향한다. window 뒤 자동 재발송 금지.
>
> 법정 기한 전에 인앱·우편 등 대체 채널로 전환할 기준: deadline 12시간 전 verified delivery가 없으면 인앱 read receipt를 확인하고, 법이 요구하며 검증된 주소가 있는 경우 등기 등 승인 채널로 전환한다.
>
> 실제 통지 내용 version/hash·provider ID·delivery event의 최소 증빙과 보존 승인자: case ref, template version/hash, channel, recipient provenance digest, accepted/delivery/bounce event·시각. 최고관리자가 category별 법정 TTL을 승인한다.

### 일반 제재 이의 신청을 통지일부터 30일 안에 1회 받는 안을 승인합니까?

> 승인 / 수정 필요: **승인.** 법정 권리사건의 별도 기한은 우선한다.
>
> 기간·횟수 수정안: 통지일부터 30일, 원칙 1회. 새로운 증거·본인확인 오류·명백한 절차 위반은 추가 1회 허용한다.

### 통지를 유예하거나 일부 사실을 가릴 때 누가 승인합니까?

> 승인 역할: 최고관리자. 수사기관 요청이나 신체위험 사건은 외부 법률 상향을 병행한다.
>
> 허용 사유: 수사 방해, 피해자 안전, 미성년자 보호, 다른 이용자의 개인정보, 증거 훼손 위험.
>
> 기록할 근거: 법적/정책 code, 숨긴 필드, 범위, 시작·종료시각, 승인자, review_at. 자유서술만으로 유예하지 않는다.

## 증거와 접근

### 일반 신고 증거를 조회할 수 있는 역할을 어디까지 허용합니까?

> `staff`: 배정 사건의 redacted content·category·상태·deadline만. reporter identity·연락처·원본 첨부는 기본 비공개.
>
> `admin`: purpose/case-bound capability로 필요한 최소 원문을 조회하고 모든 조회를 감사한다. role만으로 전체 사건 조회 불가.
>
> 외부 반출 승인자: 최고관리자+독립 reviewer 2인. 현재 2인이 없으므로 법정기관의 검증된 요청 외 자동 반출 금지.

### 불법촬영물등 원본을 일반 운영자가 복제·다운로드하지 않는 절차를 수행할 수 있습니까?

> 가능 / 추가 도구 필요: **추가 격리 도구가 필요.** 일반 Storage/admin UI로는 시행하지 않는다.
>
> 격리 담당자와 backup: 최고관리자와 실제 지정 backup. backup 미지정 중에는 원본을 열지 않고 content 차단·기관 인계만 한다.
>
> 사건별 `restricted_evidence_reviewer` capability 부여·회수 담당자: 최고관리자가 사건 ID·사유·TTL로 부여하고 1시간 후 자동 회수한다.
>
> 2인 승인·최대 접근시간·조회 감사 기준: 2인 승인, 최대 1시간, download/clipboard 금지, 화면 watermark, actor·case·purpose·fields·시각 감사.
>
> 일반 `staff`·`admin`에게 보여줄 URL·해시·최소 메타데이터: URL·thumbnail·원문 hash 모두 숨기고 case ID, category, blocked 상태, deadline만.
>
> 관계기관 인계 경로: 법정 신고 API/전용 포털 또는 검증된 기관 수신 채널. 일반 이메일·메신저 첨부 금지.

### 이해관계가 있는 운영자를 사건에서 제외할 대체 담당자가 있습니까?

> 있음 / 없음: 현재 **없음**.
>
> 재배정 책임자: 독립 reviewer가 지정될 때까지 이해충돌 사건은 임시 비공개·권리 보존 상태로 두고 영구 제재·복원을 확정하지 않는다.

## 운영 점검

### 월 1회 검토할 운영 지표를 무엇으로 확정합니까?

> 처리 목표 미준수율: 사용.
>
> 반복 위반: 사용하되 account raw ID 대신 purpose-HMAC 집계.
>
> 오판·복원: 사용.
>
> 신고 유형별 추세: 사용, 최소셀 5 미만 비공개.
>
> 추가 지표: oldest queue age, 긴급 자동제한 latency, appeal overturn rate, notification delivery/bounce, restricted evidence access, write kill-switch 시간, 익명화된 user impact.

### 월간 운영 점검 결과를 누가 승인하고 어디에 보관합니까?

> 승인자: 최고관리자. 독립 reviewer가 생기면 분기별 공동 검토한다.
>
> 보관 위치: PII 없는 `docs/operations/community-monthly/` 또는 private 운영 원장. 공개 repo에는 집계·개선 action만 둔다.
>
> 접근 범위: 공개 집계는 최소셀·재식별 방지를 통과한 값만; 사건 단위는 capability-bound private store만.

## 공개 시행

### 정책 §11의 필수 연결이 모두 구현되기 전에는 Draft·미시행으로 유지하는 데 동의합니까?

> 동의 / 일부 선시행 필요: **동의.** Draft 상태에서 법정 절차를 제공 중이라고 표시하지 않는다.
>
> 선시행할 범위와 이유: 기존 공개 읽기·신고·본인 작성물 삭제·권리행사는 유지한다. 모든 post/comment 생성·수정 경로는 실제 자연인 수령인, 대체 reviewer, 이중 알림과 리허설이 확인될 때까지 OFF다. 법정 OSP safe-harbor 충족 주장과 이메일 통지도 하지 않는다.

### 구현 완료 후 운영 리허설에서 반드시 검증할 사건 시나리오는 무엇입니까?

> 일반 신고: 중복 신고→단일 case, 1영업일 분류, content 유지/제한 결정, 양쪽 최소 통지, 90일 expiry.
>
> 긴급 신고: 불법촬영물/신체위협 category→5분 내 임시제한·이중 alert·일반 운영자 원본 접근 0건·기관 인계.
>
> 권리침해 요청: 비회원 form→본인/대리권 최소 확인→조치·게시판 공시·양쪽 통지→저작권 재개요구 3일/7~14일 timeline.
>
> 이의·복원: 원결정자와 분리된 review, 잘못 hide한 content restore, reaction/feed/cache 복원, 양쪽 통지.
>
> 추가 시나리오: 담당자 부재, email bounce, deadline alert 실패, legal hold, 탈퇴한 작성자의 nullable report, 이해충돌, kill-switch rollback.

### 정책 공개 시행을 최종 승인할 사람과 목표일은 무엇입니까?

> 최종 승인자: ICONS 최고관리자. Codex는 구현·검증 증거를 준비하지만 자연인 수령인·연락처를 대신할 수 없다.
>
> 목표일: 캘린더 날짜가 아니라 아래 evidence gate 충족일.
>
> 선행 조건: 실제 수령인+backup·업무 연락처, 신고/권리 form, 자동 임시제한·kill switch, 통지 outbox, nullable moderation, evidence capability, retention purge, SLA alert, 리허설, 법정 문서 version·시행일.

## Anything else?

### 실제 운영에서 예상되는 추가 예외나 제약이 있습니까?

> 추가 제약: solo 운영에서 독립성·24/7 판단을 가장하지 않는다. queue나 알림이 기준을 넘으면 신규 post/comment 작성만 fail closed하고 공개 읽기·본인 작성물 삭제·신고·권리행사·기존 거래 경로는 유지한다.
