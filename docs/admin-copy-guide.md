# 어드민 문구 작성 규칙

어드민(`/admin/**`) 화면의 안내문·칸 이름·입력칸 예시 글·도움말·오류·성공 메시지·확인창·빈 화면 문구와 어드민 가이드(`lib/admin/guide/`)에 적용한다. 읽는 사람은 개발자가 아니라 운영팀·MD다.

계기: 2026-11-19 MD가 상품 49개를 등록하면서 받은 엑셀의 '코드'(ERP 코드)를 옛 '관리코드' 칸에, 바코드를 옛 '판매자상품코드' 칸에 넣었다. 안내문은 "반입된 ERP 품목", "선행 0을 유지", "비워 두면 미설정"처럼 개발 용어로만 쓰여 있었고, 정작 어느 칸이 거래확정 엑셀에 찍히는지는 말하지 않았다. 코드 칸 이름과 잠금은 [ADR-0048](adr/0048-auto-generated-code-labels.md)이다.

## 원칙

1. **정보는 빼지 않고 말만 쉽게 한다.** 제약·예외·결과를 지우지 않는다. 어려운 단어를 운영 어휘로 바꾸고, 긴 문장은 나눈다.
2. **운영자가 할 일과 결과를 쓴다.** 안내문은 "어느 칸에 무엇을 넣는지", "누르면 무엇이 바뀌는지", "결과가 어디(고객 화면·엑셀·메일·주문서)에 보이는지"를 말한다. 시스템 내부에서 일어나는 일(저장 방식·검증 방식·테이블)은 운영자의 행동을 바꿀 때만 쓴다.
3. **헷갈리기 쉬운 칸은 서로 구분해 준다.** 이름이 비슷한 칸(ERP 코드·바코드·상품 자동코드·옵션 자동코드, 판매가·할인가·옵션가)은 각 칸이 무엇이고 어디에 쓰이는지를 한 줄씩 적는다. 받은 파일의 열 이름이 화면 칸 이름과 다르면 어느 열을 어느 칸에 넣는지 적는다.
4. **오류 메시지는 "무엇이 문제인지 + 어떻게 고치는지"를 함께 쓴다.** "입력값을 확인해주세요"로 끝내지 않고, 어느 칸이 왜 안 되는지와 다음 행동(어느 화면에서 무엇을 고친 뒤 다시 저장)을 쓴다. 다시 시도해도 되는지, 새로고침해야 하는지, 담당자에게 알려야 하는지를 구분한다.
5. **같은 대상은 같은 이름으로 부른다.** 화면 칸 이름 = 엑셀 열 이름 = 가이드 이름. 운영팀 어휘는 `lib/admin/vocabulary.ts`(ADR-0014·ADR-0048)와 `CONTEXT.md`를 따른다(어드민 라벨은 상품·옵션·상품 자동코드·옵션 자동코드, 카드·카드팩·티켓은 상품이라 부르지 않는다). 이미 정해 둔 표기(시각은 KST, 받는 사람은 수령인, 운송장·배송비 등)는 `lib/admin/copy-contract.test.ts`가 지킨다.
6. **문체는 지금 어드민과 같은 '~합니다'체.** 한 문장에 한 가지를 말한다. 버튼·칸 이름을 문장에 넣을 때는 화면에 적힌 그대로 쓴다.
7. **입력칸 예시 글(placeholder)은 넣을 값의 예나 출처를 보여 준다.** "미설정"처럼 상태만 말하지 않는다. 예: ERP 코드 칸 "엑셀의 '코드'", 안전재고 칸 "비우면 알림 없음".
8. **시스템이 만드는 값은 입력칸으로 두지 않는다.** 자동으로 만들어지는 코드·번호는 기본으로 잠그고 '자동 생성 · 입력할 필요 없음'을 보인다. 꼭 바꿔야 하는 경우만 '직접 바꾸기' 같은 명시적인 버튼으로 연다(ADR-0048).
9. **바꾸지 않는 것:** 동작·DB·코드 식별자(`data-*` 속성, 상태 값, 함수·테이블 이름)와 올릴 때 읽는 엑셀 머리글, 외부 양식(창고·스마트스토어)의 열 이름은 그대로 둔다. 문구와 표시 순서만 바꾼다. 머리글을 바꿔야 하면 옛 이름도 읽게 한다.

## 용어 대체표

화면·가이드 문구에서 왼쪽 표현을 쓰지 않는다. 코드 주석·개발 문서는 대상이 아니다.

| 쓰지 않는 표현 | 운영 문구 | 메모 |
|---|---|---|
| 선행 0을 유지 | 0으로 시작하는 번호도 앞의 0까지 그대로 저장 | |
| 반입, 반입된, 반입한 | 올린, 불러온(ERP 품목 메뉴에 올린 품목) | 엑셀 '올리기'와 같은 말을 쓴다 |
| 미설정, 비워 두면 미설정 | 비어 있음, 없음, 비워 두면 ~하지 않음 | 비웠을 때 무엇이 달라지는지 쓴다 |
| 스냅샷 | 주문 당시 값, 그때 저장된 값 | |
| 초안(게시 상태가 아닌 뜻) | 저장 전 내용, 불러온 내용, 아직 켜지 않은 설정 | '초안'은 상품·IP의 게시 상태(초안/공개/보관)에만 쓴다(`CONTEXT.md`) |
| 멱등, 중복 요청 무시 | 같은 버튼을 여러 번 눌러도 한 번만 처리 | |
| RPC, DB, 서버, 레코드, 행·필드(데이터 뜻) | 저장, 기록, 칸 | 엑셀·표의 줄·열은 '줄'·'열'로 쓴다 |
| 응답을 확인하지 못했습니다 | 처리 결과를 확인하지 못했습니다 + 다음 행동 | 이미 처리됐을 수 있으면 목록에서 먼저 확인하라고 쓴다 |
| 세션 | 로그인 | |
| 감사 로그, 운영 기록(감사 뜻) | 감사 기록 | 어드민 전체가 '감사 기록'을 쓴다 |
| 판매자상품코드, 관리코드 | 상품 자동코드, 옵션 자동코드 | 2026-11-19 이름 변경(ADR-0048). 예전 엑셀 머리글은 계속 읽는다 |
| 한국 시간, 한국 시각 | KST | `copy-contract.test.ts` #25 |
| 입력값을 확인해주세요(단독) | 어느 칸이 왜 안 되는지 + 고칠 방법 | |
| 정합, 정합화 | 맞는지 확인, 맞추기 | |
| 매핑 | 연결 | |
| 상한·하한 | 최대·최소 | |
| 경합, 동시 변경 | 다른 사람(다른 작업)이 먼저 바꿨습니다 | |
| 식별자, 외부 식별자, UUID, ID | 번호, 코드(무엇의 번호인지) | |
| 프리셋 | 미리 만든 설정, 템플릿 | 화면에 이미 '템플릿'이 있으면 그 이름 |
| 활성화·비활성화 | 켜기·끄기, 사용·중지 | 화면 버튼 이름과 맞춘다 |
| 할당(재고) | 배정, 나눠 주기 | 예약 판매 도메인은 해당 화면 정리 때 함께 본다 |
| 유효하지 않은 | 형식이 맞지 않는, 쓸 수 없는 + 이유 | |

## 고치기 전에 확인할 것

- 테스트가 문구에 묶여 있다. 화면 테스트, 가이드의 오류 인용(`lib/admin/guide/topics/troubleshooting.ts`의 `ADMIN_GUIDE_ERROR_CASES`는 화면 코드 원문과 같아야 한다), `lib/admin/guide/topics.test.ts`의 `repoFile(...).toContain(...)`을 함께 갱신한다.
- 메뉴·화면 이름을 바꾸면 내비(`lib/admin/navigation.ts`)·가이드·업데이트 내역이 같은 이름을 쓰는지 확인한다.
- DB 함수가 직접 돌려주는 오류 문구(`raise exception`)는 migration을 바꿔야 해서 문구 정리 범위 밖이다. 앱이 그 문구를 바꿔 보여 주는 매핑이 있으면 매핑 쪽을 고친다.
